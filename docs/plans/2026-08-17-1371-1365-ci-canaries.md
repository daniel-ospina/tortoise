# CI Canaries #1371 + #1365 — Implementation Plan

> **For Pi:** Use `executing-plans` to implement this plan task-by-task.

**Goal:** Unblock all Python PRs by fixing the two CI canaries: the `test (a)` fast-suite 45m watchdog SIGKILL + orphan cascade (#1371), and the order/state-dependent reaper chaos tests (#1365, superseding #1372).

**Team:** organisation-design-team
**Role:** product-implementer

**Architecture:** Three non-overlapping fixes for #1371 — (A) SLOW_FILES becomes single-source-of-truth data in `config/ci-surfaces.yml` consumed by `tools/ci_selection.py` (tier-1/tier-2 selections exclude them; tier-2 selections split across both matrix halves by parity), (B) an opt-in fire-and-forget `SHUTDOWN SAVE` fast-close at the interpreter-exit seam for ephemeral test-tree embedded servers (durability preserved, ~3-4s/server → ~0.05s), (D) a kill-aware orphan check (rc ∈ {124,137,2} → warn-only). For #1365 — (C) is the same selection fix as (A) (chaos tests then run only in test-slow where they already pass) + (A) a delta-isolation redesign of the chaos tests (own-pid tracking, mid-sweep sentinel, no global pkill, tracked-pid teardown).

## Task 1 — SLOW_FILES single-source-of-truth + selection carve-out

**Intent:** Fix the root cause of the tier-2 PR watchdog failure: the PR selection path runs SLOW_FILES (already in test-slow) a second time in the 45-min fast leg. Making SLOW_FILES data in the manifest and excluding them from tier-1/tier-2 selections removes the duplicate work deterministically.

**Acceptance:** (a) `config/ci-surfaces.yml` gains a top-level `slow_files:` list of exactly the 21 files currently in the workflow `SLOW_FILES` env, stored as BARE names (same convention as `tier1:`/`surfaces:` — the `tests/` prefix is added only at the workflow boundary; the env values are `tests/`-prefixed, so strip the prefix when porting), AND `test_indexes.py` + `test_projection.py` are REMOVED from the `tier1:` list (they remain covered via slow_files → test-slow; without this the `tier1 ∩ SLOW == ∅` gate fails on the current manifest and the existing `test_docs_only_runs_tier1` / `test_onboarding_change_selects_onboarding` tests break); (b) `tools/ci_selection.py` loads slow_files, subtracts SLOW_FILES from the FINAL tier-1 and tier-2 selected sets, adds `slow_files` to EVERY `select()` return dict (push/schedule, shared-module, unknown-path, and tier-2 — or post-process once in `main()`), and its `--integrity` mode fails if: slow_files is empty, any slow file is not in some surface, or any slow file is in the tier-1 set; (c) `tests/test_ci_selection.py` covers: tier-1 ∩ SLOW == ∅, tier-2 ∩ SLOW == ∅ (for a changed-file sample), slow_files output non-empty and complete (21) in BOTH tier-2 AND full/push mode (`select([], "push")["slow_files"]`), full-mode selection otherwise unchanged.

**Files:**
- Modify: `config/ci-surfaces.yml`, `tools/ci_selection.py`, `tests/test_ci_selection.py`

Steps:
1. Add `slow_files:` key to `config/ci-surfaces.yml` (top level, the 21 files from the workflow env).
2. `tools/ci_selection.py`: parse `slow_files`; in `select()` subtract from tier-1/tier-2; emit `slow_files` in the output dict; extend `--integrity` with the three fail-closed checks; bump `SELECTION_FN_VERSION`.
3. `tests/test_ci_selection.py`: new cases per acceptance (c).
4. Run: `uv run pytest tests/test_ci_selection.py -v`.

## Task 2 — Workflow wiring (changes outputs, tier-2 parity split, kill-aware orphan check)

## Task 3 — Fast atexit close for ephemeral embedded servers

**Intent:** Eliminate the ~10-15 min interpreter-exit teardown tail that pushes the fast gate to its ceiling. Root cause measured: redislite `close()` ≈ 3-4s/server (execute_command response-wait on `shutdown(save=True)` + psutil poll); fire-and-forget `SHUTDOWN SAVE` over the unix socket → server death ~0.04s for small graphs with the RDB durability preserved.

**Acceptance:** (a) new `tortoise/embedded_lifecycle.py` with `atexit_fast_close(client) -> bool` gated on `TORTOISE_FAST_ATEXIT=1` + ephemeral test-tree dbdir (realpath-normalized on BOTH sides, reusing `embedded_reaper._is_ephemeral_dir` + `EPHEMERAL_PREFIXES`) + last-client (`client._connection_count() <= 1`, probe-fail treated as last); fire-and-forget `SHUTDOWN SAVE` for ALL eligible clients FIRST, then a single bounded poll for pid death (one deadline, ≤5s total, 20ms interval, SIGTERM fallback — SIGTERM triggers redis's graceful save+shutdown so durability holds) — batching avoids Σ(save) serialization in test-slow's big-graph files; **send-failure invariant**: any failure between the gate check and a successful fire-and-forget send falls through to the existing `_t_close`/`close()` (never skip close); pool disconnect; (b) the three atexit seams register a new `_atexit_close` wrapper that routes through the fast path else the existing `_t_close`/`close` — behavior-identical contract: `_t_close`/`close()`/`__exit__` unchanged, the close-recorder tests in `test_embedded_lifecycle.py` must pass unchanged, and the fast path may only trigger via the atexit-registration seam; (c) `tests/conftest.py` sets `TORTOISE_FAST_ATEXIT=1` via `os.environ.setdefault`; (d) new unit tests `tests/test_embedded_lifecycle_fast_close.py` (ADDED to `RAW_EMBEDDED_ALLOWLIST` in test_embedded_lifecycle.py — it constructs raw embedded servers for the reopen-durability case): ephemeral+flag → fast path (SHUTDOWN SAVE sent, pool closed, `_t_closed` set); non-ephemeral or no flag → normal close; `__exit__` still calls `close()` once with the flag set; reopen durability preserved (fire-and-forget SAVE → reopen → data present); send-failure → normal close still runs; (e) local measurement: the bench script (20 no-path `FalkorDB()` clients leaked in one process, measured to interpreter exit) sets `TORTOISE_FAST_ATEXIT=1` ITSELF before importing tortoise (conftest does not load under `uv run python`); 20 leaked ephemeral servers exit in <5s (was 1m20s).

**Files:**
- Create: `tortoise/embedded_lifecycle.py`, `tests/test_embedded_lifecycle_fast_close.py`

## Task 4 — Chaos test delta-isolation redesign

**Intent:** Make the reaper chaos tests deterministic — assert only on the orphans they themselves spawn, never ambient populations; replace global pkill and blind sleeps with tracked-pid teardown and a mid-sweep sentinel.

**Acceptance:** (a) each chaos test tracks its OWN spawned server pids — the spawned process prints `db.client.pid` (the server pid is on the redislite client, NOT `db.pid`; `db.client.pid` was verified against the installed redislite); (b) assertions target own pids (`own_pid ∈ discover() candidates`, `own_pid ∈ reap() acted list`, reuse the module's existing `_wait_server_exit(pid)` after reaping) — no `candidates[0]`, no global "no candidates remaining"; (c) `test_chaos_reaper_sigkill_mid_sweep_second_run_cleans` spawns the mid-sweep reaper with `--batch-size 5` (so own pids are reached before a dirty runner's ambient residue consumes the batch) and waits for the reaper stderr "killed orphan PID <own>" sentinel before SIGKILL (bounded 30s), then verifies all own pids die after the second reap; (d) the module autouse `_teardown_servers` global pkill fixture and `test_chaos_kills_only_idle_of_20`'s inline global pkill are removed — teardown kills tracked pids directly (SIGTERM→SIGKILL); (e) spawned subprocess env sets `TMPDIR` to a short flat per-test dir (AF_UNIX 108-byte limit; `tempfile.gettempdir()` is cached in the parent — must be set in the child env); (f) module-start stale-residue sweep reuses `test_reaper.py._sweep_stale_residue`; (g) spawn-alive assert (READY line + pid) separates spawn failure from reaper failure; (h) the redesigned tests pass 3× in a row standalone and after `test_chaos_kills_only_idle_of_20`. The new helper is named `_spawn_orphan_pid` (NOT `_spawn_orphan` — that name already exists in `test_reaper.py` with a different signature/return).

## Failure Modes

- Fast path misclassification (user DB at `/tmp/tortoise-*` + flag) → SAVE preserved, so worst case is a non-blocked close; flag is pytest/CI-scoped only.
- `slow_files` output empty → fail-closed integrity guard in `--integrity` + the workflow's test-slow `if: always()`-style guard (empty FILES → exit 0, but the integrity gate already failed the job).
- Tier-2 parity split with odd file count → one half runs 1 extra file; acceptable.
- Chaos sentinel timeout → deterministic failure with a clear message (reaper never started reaping), not a flake.
- Close-recorder tests → fast path is at the registration seam only; `_t_close`/`close`/`__exit__` untouched; unit test pins this.
