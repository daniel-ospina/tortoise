# Duration-Balance the Tier-2 PR Split — Implementation Plan

> **For Pi:** Use `executing-plans` to implement this plan task-by-task.

**Goal:** Make the tier-2 PR split in `python-ci.yml` duration-aware — longest-processing-time (LPT) greedy pack of the SELECTED files across halves a/b using measured per-file durations — so a heavy matched surface can no longer land most of its runtime on one half by parity luck. Deterministic (order-preserving within each half); no new drift-prone manifest.

**Team:** epistemic-team
**Role:** (none set)

## Confirmed Problem (from scoping)

The `test` job's tier-2 branch ("Run fast test suite", the `else` path when `full != true`) splits the SELECTED surface files into halves a/b by positional modulo (`i % 2`) — duration-blind. Heavy fast-gate files measured from real CI `--durations` data (`test_calibration` ~52s, `test_reaper` ~41s, `test_battery_setup` ~26s, `test_main_guards` ~19.5s, `test_ops_safety` ~16.8s) are placed by parity position, so the slower leg can carry ~30-40% more runtime than the faster one on surface-heavy PRs — avoidable PR-latency minutes on the critical path. The static a/b matrix split (#880) applies only to the full-matrix push/schedule path.

## Design Decisions

1. **Durations live in the EXISTING manifest** (`config/ci-surfaces.yml`, new top-level `durations:` map), not a new file — the issue's "third drift-prone manifest" concern is avoided by construction: no new file, and the existing unconditional `--integrity` gate (runs on every event in the `changes` job, fail-closed) is extended one-directionally (duration keys must be classified, non-slow test files). Missing entries are allowed → default weight 2.0s, so new test files need no measurement to land and the split degrades gracefully to count-balance for the unmeasured tail.
2. **LPT greedy pack** (issue's preferred direction): sort selected files by weight DESC (ties → name, deterministic), assign each to the half with the lower current total (tie → `a`). Strictly dominates sorted-then-parity (parity can still cluster two mid-weight files on one half). Fully deterministic → O/I/T indicator (c).
3. **Split computed ONCE in the `changes` job** (only on PR events with `full == false`), passed to the `test` job via new `a_files`/`b_files` outputs — both halves agree by construction, and the split is visible in the audit artifact (`.ci-selection/split.json` sibling to `selection.json`, no clobber).
4. **Seed = 14 measured fast-gate files** (max-per-run aggregation of `--durations=15` output from 3 completed CI runs: python-ci 32193298962 + 32241846147 halves a/b/test-slow, post-merge-validation 32243341350). Heavy-tail focused — the files that can actually tip a half. Caveats documented in scoping: sample truncation possible on failed legs (`--maxfail=20`), top-15 aggregation misses spread-out-heavy files — both acceptable (LPT on the measured tail strictly dominates parity), and future refinements are pure-data PRs.
5. **pyyaml availability on the runner is proven** — the `changes` job already runs `yaml.safe_load` via `tools/ci_selection.py` on every event; `--split` runs in the same job.

## Implementation Steps

### Step 1 — durations map in `config/ci-surfaces.yml`
Add after `slow_files:` (documented with source + default-weight semantics):

```yaml
# #1473: measured per-file durations (seconds) for the tier-2 PR split.
# Source: --durations=15 output of CI runs 32193298962/32241846147/32243341350,
# max-per-run aggregation of call+setup+teardown (heavy tail). Missing files
# default to 2.0s in the split. Keys must be classified, non-slow test files
# (enforced by --integrity).
durations:
  test_calibration.py: 52.1
  test_reaper.py: 41.4
  test_battery_setup.py: 26.0
  test_main_guards.py: 19.5
  test_ops_safety.py: 16.8
  test_audit.py: 14.5
  test_battery_corpus.py: 13.5
  test_a9_direct_edge_traversal.py: 13.2
  test_backup_e2e.py: 13.1
  test_capture_session.py: 10.7
  test_embedded_lifecycle_fast_close.py: 9.1
  test_analyze_scoped.py: 5.2
  test_projection_version_gate.py: 5.1
  test_analyze.py: 3.9
```

### Step 2 — `--split` + integrity rule in `tools/ci_selection.py`
- `split_fast_gate(files, durations, default_weight=2.0)` — pure function, LPT greedy pack; raises `ValueError` on non-list input (guards the `"ALL"` full-mode string); returns `(a_list, b_list)` in assignment order.
- CLI `--split`: reads a JSON list of test files from stdin, prints `{"a": [...], "b": [...]}`; writes `.ci-selection/split.json` (sibling, does not touch `selection.json`).
- `duration_issues(manifest)` — integrity rule: every durations key must be classified (in some surface) and not in `slow_files`; wired into the existing `--integrity` gate (fail-closed like `slow_file_issues`).

### Step 3 — workflow wiring
`changes` job:
- New step `Tier-2 duration split (#1473)` gated `if: github.event_name == 'pull_request' && steps.select.outputs.full == 'false'`: pipes `test_files` JSON into `python3 tools/ci_selection.py --split`, emits `a_files`/`b_files` (space-joined `tests/...` paths).
- Two new outputs: `a_files: ${{ steps.split.outputs.a_files }}`, `b_files: ${{ steps.split.outputs.b_files }}`.

`test` job tier-2 branch (`else` when `full != true`): replace the `i % 2` loop with:
```bash
if [ "${{ matrix.half }}" = "a" ]; then FILES="${{ needs.changes.outputs.a_files }}"; else FILES="${{ needs.changes.outputs.b_files }}"; fi
```
The existing `-z "$FILES"` skip guard and the full-matrix `matrix.files` path are untouched.

### Step 4 — tests (`tests/test_ci_selection.py`)
- `test_split_balances_heavy_files` — seeded LPT puts the heavy files 1-1 / balanced vs parity's worst case.
- `test_split_is_deterministic_and_ties_go_a`.
- `test_split_default_weight_for_unmeasured` — unmeasured files use 2.0s; split still deterministic.
- `test_split_rejects_non_list` — `"ALL"` / string input raises.
- `test_duration_integrity` — classified non-slow keys pass; unclassified key and slow-file key fail.

## Validation

1. `python3 -c "import yaml; yaml.safe_load(open('config/ci-surfaces.yml'))"` — YAML parses.
2. `bash -n` on a dry-run of the tier-2 branch logic (the `--split` JSON → half extraction shell shape).
3. Local simulation: run `--split` on a real surface-heavy selection (e.g. `core` surface = 158 files) and assert max-leg imbalance ≤ parity's, both legs deterministic.
4. `uv run pytest tests/test_ci_selection.py -v` — new + existing tests pass.
5. `python3 tools/ci_selection.py --integrity` — clean with the new durations rule.

## Acceptance Criteria

- [ ] Heavy matched-surface PR no longer dumps its runtime on one half: LPT pack puts measured heavy files on alternating halves (imbalance ratio < parity's on seeded selections).
- [ ] Split deterministic: identical `a_files`/`b_files` across runs for the same selection (ties → `a`; no randomness).
- [ ] No new manifest: durations live in `ci-surfaces.yml`; `--integrity` validates them on every event.
- [ ] Full-matrix path (#880 static halves) byte-identical behavior; test-slow/post-merge untouched.
- [ ] `--integrity` passes; unit tests green; workflow YAML parses.
