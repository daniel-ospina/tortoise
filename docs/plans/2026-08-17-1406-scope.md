# Scope — #1406 Battery Harness Core (task-workflow-standard)

**Epic:** #1402 (docs/epics/1402-eval-battery/04-plan.md §3/§5/§6)
**Level:** task · **Complexity:** standard · **Team:** epistemic-team

## Confirmed Problem

Build the **harness core** for the Agent-Reasoning Eval Battery: an episode
runner (with trajectory logging, seed pinning, model-call outcome tracking,
and batch scenario setup), a CLI with the `run|parity|calibrate|validate-judge|report`
subcommand surface and the plan §6 exit-code contract (0/2/3/4/5), and the
`battery/config/` YAML corpus/thresholds/arms/budget loaders — extending
`tools/longmem_eval` runner patterns, contract-first for child issues
(#1408 arms, #1410 judge gate, #1414 parity, #1415 calibrate/report).

**What this is NOT:** probe logic (R1–R5 = #1409), real arm implementations
(A0–A4 = #1408), corpus content (#1407), judge validation math (#1410),
matched-recall (#1413), report/verdict assembly (#1415), parity runners
(#1414). Those issues implement *to the contracts defined here*.

### Problem diamond (condensed)

- **Alternative framings rejected:** (a) "Build the full battery end-to-end in
  one issue" — violates epic-decompose MECE ownership (child issues exist);
  (b) "Harness = thin wrapper over inspect_ai" — adds a heavy third-party
  runtime dependency for an internal tool when the repo already has a proven
  eval-runner pattern (`tools/longmem_eval/run.py` per-question error isolation
  + report provenance) to extend; (c) "No CLI, just a library" — the epic plan
  §6 Interface table mandates CLI exit codes as part of the contract (E2E-1.4
  asserts exit 5 behaviorally). Confirmed framing = the epic's own §3/§5/§6
  (extend longmem_eval patterns, contract-first).
- **Adversarial checks:** risk that the runner silently swallows failed model
  calls (poisons the battery — the epic's critical bug-pattern flag) → outcome
  enum with `fallback_cached`/`failed` is first-class, never silent. Risk that
  exit codes get invented ad hoc → the enum is the contract, tests assert them.

## Axis Research (Phase 1.5 — external best-practice research)

> **Findings date:** 2026-08-17 · in-repo precedent + 5 external queries (3
> web_search + exa + 1 follow-up). Axes: Architecture (high — from epic
> complexity), Ontology (low — no schema change, epic-verified).

### Architecture axis

**In-repo precedent (codebase-first scan — 4+ examples):**
- `tools/longmem_eval/run.py` — per-question error isolation (try/except per
  question → `failures` list, run continues), checkpoint/resume, backoff retry,
  report provenance block (git sha, model ids, methodology). The battery runner
  reuses: per-scenario isolation, provenance in the artifact.
- `tools/longmem_eval/report.py` — `build_report` aggregates COMPLETED
  outcomes only; failures reported separately (never skew aggregates) — the
  exact E2E-1.5 aggregation-half semantics.
- `tools/judge_harness.py`/`tools/kappa.py` — uniform exit-code pipeline
  convention (0 success / 1 operational / 2 gate-negative under --strict);
  the battery CLI's exit codes extend this convention with 3/4/5 per plan §6.
- `tools/longmem_eval/reader.py`/`judge.py` — provider pattern via
  `tortoise.ingest._PROVIDERS` + `OpenAICompatModel`, env-driven, fail-closed
  when no key, `--mock` offline deterministic doubles. The battery's
  model-call shim mirrors this shape (mock model caller for CI).
- `tests/test_longmem_runner.py` — embedded FalkorDBLite, no Docker;
  `sys.path.insert(0, ...)` import pattern; `shared_embedded_db` fixture.

**External findings (canonical / competitor / pitfalls):**
- **Canonical — Inspect AI (inspect.aisi.org.uk, UK AISI):** eval = Task
  (dataset + solver + scorer); each sample runs as an *episode* whose
  transcript (model calls + tool calls) is recorded and is the unit the
  scorer grades; transcripts are the ground truth for failure diagnosis.
  → Reused: episode executor produces a trajectory that IS the artifact
  source of truth (epic plan §5 "trajectories are the source of truth").
- **Canonical — Anthropic eval engineering ("Demystifying evals for AI
  agents", anthropic.com/engineering):** transcript = complete record of a
  trial (outputs, tool calls, reasoning, intermediate results); each trial
  must be isolated (clean env, no shared state); deterministic graders where
  possible; LLM judges need structured rubrics + calibration + drift
  monitoring; "an eval at 100% tracks regressions but provides no signal".
  → Reused: per-scenario isolated DB namespaces (arm isolation contract);
  mock deterministic agent for harness tests; judge gate lives at #1410 but
  the CLI exit code 2 (gate-blocked) is reserved now.
- **Competitor — TraceCore agent_bench determinism spec
  (github.com/justindobbs/Tracecore):** every episode SHALL accept an
  explicit `seed`; artifacts MUST record `determinism.seed`; replay with same
  inputs must produce identical outputs or hard-fail; model identifiers must
  be pinned and logged; budgets authoritative; "silent fallbacks to live
  systems invalidate determinism". → Reused nearly verbatim: seed pinning
  (`--seed`, recorded in run_artifact), replay/determinism test (E2E-7.1,
  |Δ|≤1e-6), model id recorded in artifact, model-call outcome enum makes
  fallbacks visible, never silent.
- **Competitor — SWE-bench harness (swebench.com/guides/evaluation):**
  per-instance artifacts (`report.json`, `run_instance.log`), instance-level
  result categorization (resolved/unresolved/error), Docker reproducibility;
  three-tier fallback strategy for patch application. → Reused: per-scenario
  `run_artifact.json` + run-level summary; episode outcome categorization;
  fallback semantics mapped to the outcome enum (not silent).
- **Pitfalls — Polarity determinism docs + LangSmith/DeepEval trajectory
  eval:** temperature 0 reduces but does NOT eliminate provider nondeterminism;
  seed = base + index per replica; trajectory (ordered tool calls, plans,
  tokens) is the unit of evaluation for agentic behavior; step-level metrics
  catch failures that final-output metrics miss; judge drift must be monitored.
  → Reused: temp 0 enforced at the model-call layer (S3 surface), seed
  recorded per run, trajectory fields capture tool calls + tokens +
  re-derivations (L-stream instrumentation hooks for #1411), failure-injection
  policy is seed-deterministic so E2E-1.5 tests are reproducible.
- **Disconfirming query (canonical-verification):** what do mature eval
  frameworks (inspect_ai / openai evals / promptfoo) provide that a custom
  harness must rebuild? Finding: sandboxing/parallelism/built-in batching,
  trace viewer UIs, and a large plugin ecosystem. Verdict for this scope:
  none of those are needed by an internal, single-machine, CLI-first battery
  whose determinism + isolation requirements (pinned seeds, per-scenario DB
  namespaces, sealed golds) are tighter than generic runners provide; the
  repo's proven longmem_eval runner pattern covers the mechanics. The
  framework question is closed for #1406; a re-evaluation is justified only
  if #1416's real-run exposes runner-scale limits.

## Solution Approach (solution diamond, condensed)

**Approach A — Flat single module (rejected):** one `battery.py` + argparse.
Fails the epic prototype (§3 `battery/` package tree) and makes child issues
(#1408/#1410/#1414/#1415) collide on one file. Convenience pick, worse outcome.

**Approach B — Package tree per epic prototype (CHOSEN):** `battery/` package
mirroring plan §3, with only the #1406-owned sub-packages implemented now:
`cli.py`, `config/`, `runner/`, plus `arms/base.py` (protocol only —
contract-first; concrete arms are #1408's). Stubs for `parity/`,
`validate-judge`, `calibrate`, `report` subcommands (dispatch-only, exit 1
"not implemented — owned by #N" with a clear message). Child issues fill the
stub bodies to the documented contracts.

**Approach C — External framework (inspect_ai) (rejected):** would provide
task/solver/scorer out of the box, but adds a large runtime dependency and
drags an eval-framework UX into an internal tool; the repo's own runner
pattern (longmem_eval) already covers the needed mechanics. The *patterns*
are imported (see Axis Research), not the dependency.

### Why B is the better outcome

- Contract-first: `ArmAdapter` protocol + model-call outcome enum + exit-code
  enum + artifact schema are defined once, referenced by constant/enum name
  (plan §6 "contracts referenced by constant/enum name, not literal strings").
- Child issues implement to tested contracts instead of reverse-engineering
  the runner.
- Determinism, empty-corpus guard (exit 5), batch-setup, and failure-isolation
  aggregation (E2E-1.5 half) are all proven by tests in this slice — the
  emission half of E2E-1.1.

**Falsification of Approach B:** B is wrong if a child issue discovers the
stub-dispatch boundary or a pinned contract blocks the surface it needs
(e.g. #1408 needing an `ArmAdapter` method this slice omitted, or #1410
needing a different exit-code mapping). Mitigation: stub contracts are
reviewed here (2 verifier gates + code-review) before #1408/#1410 start; a
contract change lands as a deliberate follow-up, never silently.

## Design decisions pinned by this scope (contracts child issues implement to)

1. **Corpus format = YAML** (`battery/config/corpus.yaml`). The epic prototype
   (§3) names `corpus.yaml` for config/; plan §4's "scenario.json" names the
   scenario *entity schema*, which this slice implements as a YAML document
   (one `scenarios:` list). **Full plan §4 entity model locked now** (fields
   validate as optional-for-tier so every family can author): id, tier
   ∈ {probe, stream, differential} (**`Tier` enum in battery/enums.py**:
   1→probe, 2→stream, 3→differential — constant, never literals), family,
   task_type, attack_type, split ∈ {train, waves, held_out} (L2/L3
   contamination control), prompt_pack (typed: list of {role, content}
   turns), gold_ref (path + sha256 into the gitignored `battery/golds/`
   store), k (injection-turn field, pinned per scenario),
   contradiction_pairs (list of {claim_a, claim_b, injection_turn k}),
   evidence_scripts (R3 evidence-tier list). **Validation level pinned:**
   schema-level validation is TYPE-ONLY (field types/enums); tier-mandatory
   enforcement (which fields are required per tier) is #1407-owned — the
   loader rejects type violations, never invented content rules. The schema
   test IS the lock; #1407 authors against it. Extension mechanism for new
   families: new optional top-level keys — a deliberate, reviewed contract
   change, never silent.
2. **Sealed-gold boundary enforced at load time + store layout pinned.**
   corpus.yaml entries carry `gold_ref` (path + sha256), never inline gold
   text. **Two-tier store layout (resolves the gitignore contradiction):**
   `battery/golds/fixtures/` — COMMITTED fixture golds (2 files + README;
   referenced by this slice's smoke corpus and test fixtures);
   `battery/golds/sealed/` — production sealed golds, NEVER committed (NEW
   .gitignore rule `battery/golds/sealed/*` added in this slice; #1407/
   #1416 populate it out-of-band). The loader VERIFIES each gold_ref
   sha256 at load and fails closed (exit 1) on mismatch, missing file, or
   unreadable store — absent = any referenced gold file missing (covers
   dir-exists-zero-files). Loader tests cover: present-verify passes, sha
   mismatch → exit 1, missing file → exit 1. Golds readable ONLY through a
   scoring surface (`Scenario.golds()` — used by scorers); the episode
   context handed to the arm/agent never contains gold text. Test: golds
   absent from every episode context in a mock run.
3. **Scorer injection seam (owned here, production scorers #1409).**
   `battery/runner/scorers.py` defines the `Scorer` Protocol — **an explicit
   supersede of plan §6's Scorer row** (plan: `score(episode_trace,
   rubric_id) -> Score{metric, value, evidence}`; this slice: multi-metric
   `ScorerResult{metrics, ep_outcome}` — #1415 aggregates `metric_values`
   only, so evidence is not carried):
   `score(episode: EpisodeResult, scenario, rubric_id: str | None = None)
   -> ScorerResult{metrics: list[MetricValue], ep_outcome: EpOutcome | None}`;
   `MetricValue = dataclass{metric_id: str, value: float}`;
   `EpOutcome ∈ {converged, non_converged, undec}`. **`EpisodeResult` is
   defined in this slice** (battery/runner/episode.py): dataclass carrying
   scenario_id, seed, arm, episode_trace (turns: role, tool_calls, tokens,
   model_call_outcome, content; n_turns; n_tool_calls; re_derivations;
   total_tokens), model_call_outcomes counts, ep_outcome, ep_surface
   (arm-exposed confidence, if any) — schema-test locked like the artifact.
   `rubric_id` is carried so #1410's judge gate can compose (`judge/gate.py`
   consult before rubric-gated scorers — wired by #1410, seam exists now).
   `ep_outcome: None` means "runner default". The runner accepts `--scorer`
   (repeatable; default `harness`); modules resolve as `battery.<path>`
   (`--scorer probes.r1` → `battery.probes.r1`; fully-qualified allowed;
   `ImportError` → usage error, exit 1). `HarnessScorer` (default, owned
   here) — **metric set pinned: scenario-aggregated {n_turns, n_tool_calls,
   total_tokens, re_derivations} + model_call_outcomes counts
   {ok, rate_limited, timeout, fallback_cached, failed}** — trajectory-
   derived emission values, non-empty under the mock-arm contract (DD6).
   Multi-scorer merge:
   duplicate `metric_id` → hard error at load (fail loudly).
   #1409 plugs R1–R5 scorers into the same seam; #1415 reads `metric_values`.
   `ScoreUnavailable` ships in battery/exceptions.py now (judge failure →
   episode excluded + counted — NOT an exit code; #1410 wires the raise).
4. **run_artifact.json schema v1.0 is pinned** (schema_version field; fields
   enumerated below — the full schema is locked by its validation test, see
   Implementation Plan §schema). Contains: run_id (random-free =
   `{seed}-{arm}-{scenario_id}`), seed, arm, scenario_id, tier, model
   {provider, model_id, temperature:0.0}, determinism {seed,
   execution_order:"sequential", python_hash_seed}, episode_trace {turns
   (role, tool_calls, tokens, model_call_outcome, content), n_turns,
   n_tool_calls, re_derivations, total_tokens}, metric_values,
   model_call_outcomes {ok, rate_limited, timeout, fallback_cached, failed},
   ep_outcome, excluded {count, episode_ids, reason}, setup {mode, round_trips},
   timestamps (recorded, never influence metrics), provenance {git_sha,
   config_files, cal_table_hash}. **Source-of-truth rule (no drift):**
   `metric_values` is the emission container #1415 aggregates; HarnessScorer
   derives its counts FROM the episode_trace/model_call_outcomes fields at
   write time, so trace ↔ metric_values cannot diverge (determinism test
   compares metric_values; the derivation is unit-tested). Schema-validation
   test enforces it (S7 unit layer).
5. **RoundTripCounter attaches at the query-execution boundary** — a proxy
   wrapping `FalkorProjection.g.query` (every call = 1 DB round trip), never
   SDK-method counting. **Pinned number (reconciled): batch = ≤2 round trips
   per scenario (2·N total)** — one parameterized UNWIND query for the
   scenario's points, one for its operators, per scenario namespace
   (isolation preserved; namespaces materialize as `team_<scenario>` graphs
   per the SDK's non-test namespace prefix — documented so scenario ids can
   never collide with provisioned team ids). **Idempotent setup:** the batch
   UNWIND reproduces `create_point`'s dedup-by-content_hash+kind semantics
   (guarded CREATE / MERGE) so a re-run never duplicates nodes — belt-and-
   suspenders alongside per-attempt DB isolation (DD6). **Embedding
   parity:** `create_point` writes `n.embedding` unconditionally;
   the batcher reproduces embeddings via in-process `compute_embedding`
   (vectors passed as UNWIND params — zero extra round trips); **the
   batcher imports compute_embedding at CALL time (in-function, mirroring
   create_point's own in-function import — monkeypatch-seam identical on
   both paths) and reproduces the try/except→None semantics** (so
   equality-or-both-None holds). **The
   equivalence test monkeypatches `compute_embedding` with a fixed
   deterministic stub** (identical vectors to both paths — removes the
   90MB-model load/timing/None-straddle flake from the gate); a separate
   tagged test covers the real model path. Naive path = SDK
   create_point/create_operator per item (verified: 4+ queries per item
   — the N+1 baseline). **Equivalence test (fast-but-wrong batches fail):**
   both paths use a deterministic id scheme (runner assigns ids to scenario
   entities; naive path passes `id=` to create_point, which supports
   explicit ids); comparison keyed on content_hash for points and
   (op_type, source, targets) for operators (operator ULIDs are time-based
   and not injectable — ids normalized); **node properties compared for the
   SDK-set fields the batcher must reproduce: content_hash, status (incl.
   `promote_source` draft→live semantics), direction, label, embedding
   (equality-or-both-None)**; **operator edge fidelity:** input-order idx
   assignment, direction defaults (NAND→unidirectional canonicalization),
   and the SDK's endpoint acceptance set (`(n:Point OR n:Event)`) reproduced
   by the batch operators query. **Validation parity:** the batcher's
   operators query validates endpoint existence within the batch (MATCH
   guards raising the SDK's ValueError class); negative-path equivalence
   test: missing endpoint → both paths fail identically. Scale floor ≥50
   scenarios (~500 items): batch = 2·N vs naive ≫ 2·N. Note: the batch
   path intentionally skips SDK event emission (scratch eval namespace;
   JSONL rebuild not needed) — a documented divergence, not a bug.
6. **Determinism construction (E2E-7.1):** the two passes run in SEPARATE
   subprocesses with `PYTHONHASHSEED=0` pinned (catches set-iteration
   nondeterminism), into distinct `--out` attempt dirs AND **per-attempt
   embedded DB isolation: each subprocess env sets BOTH
   `TORTOISE_DB_URI=""` (falsy — the SDK's URI-first precedence falls
   through to resolve_db_path) AND `TORTOISE_DB_PATH=<attempt tmpdir>`**
   (verified: with URI falsy the SDK honors the env path; this is
   real-run-safe even when the documented `.env` exports a URI — the
   neutralization is asserted by a test). Eliminates cross-run graph reuse
   (duplicate-node ambiguity) and the EmbeddedStoreBusyError daemon hazard.
   **Epsilon contract:** a single comparison epsilon (thresholds.yaml
   `determinism.epsilon`, fixture default 1e-6) applies to all
   `metric_values` (integer metrics: any |Δ| < 1 is equality); per-metric
   epsilons in thresholds.yaml apply to AC-gated metrics only (future #1409
   use). Execution model: sequential by default; per-episode seed = base +
   index (TraceCore `seed = base + index`); scenario/arm iteration sorted;
   set-iteration banned in metric-affecting paths. Failure-injection double
   is seeded BY the episode seed. **Mock arm contract (non-empty
   metrics):** the mock agent emits a fixed seed-derived trajectory (≥1
   turn, deterministic tool_calls + token counts + re_derivations (0 or
   seed-derived) — all four pinned HarnessScorer metrics populated) so
   HarnessScorer metric_values are non-empty and reproducible. Hermetic (mock caller);
   real-API determinism is best-effort (seed/model/temp recorded in
   artifact).
7. **Exit-code boundary conditions (all behaviorally tested here):**
   `ExitCode` enum (0 OK, 1 OPERATIONAL, 2 GATE_BLOCKED, 3 INCONCLUSIVE,
   4 ARM_FAILED, 5 EMPTY_CORPUS) in `battery/enums.py` — **exit 1 is a
   deliberate extension of plan §6's list (0/2/3/4/5), justified by
   in-repo precedent (judge_harness/kappa: 1 = operational) for usage/
   config/stub errors**; the CLI dispatcher catches contract exceptions →
   exit code. **#1406 owns the contract exceptions** in `battery/exceptions.py`
   (single module, pinned): `JudgeGateBlocked`, `InconclusiveRun`,
   `EmptyCorpus`, `ScoreUnavailable`; `ArmUnavailable` lives in
   `battery/arms/base.py`. #1410/#1413 raise/import the shipped classes —
   the mapping test raises them at the dispatch boundary with no
   monkeypatching. Boundary pins: (a) `validate-judge` on a failing rubric
   → exit 2 when #1410 wires the gate (stub now: exit 1 not-implemented;
   gate-blocked trigger is #1410-owned only); (b1) all-episodes-failed
   (episode loop ran) → per-scenario artifacts + summary written, THEN
   exit 4; (b2) **arm-init-failure = adapter load/registration errors only**
   → skip the arm, summary written (arm marked absent), NO episode
   artifacts (documented, not a violation), exit 4 — any `ArmUnavailable`
   raised inside an episode's retrieve/record (INCLUDING the first) is
   episode-level → b1 — no exit-4 path precedes the summary write (tested);
   **setup_scenarios failure is arm-init (b2): skip arm, arm_present=false,
   summary written, exit 4; DB errors raised by the HARNESS batcher itself
   are operational → exit 1**; multi-arm mixed outcome (arm A init-fails,
   arm B completes) → exit 4, absent arm marked, successful arm's artifacts
   still written (fixture-tested);
   (d) isolation breach → complete run, exit 4, flag in artifact (trigger
   wiring = #1408/E2E-3.6; the mapping is contract-only here like 2/3).
8. **AgentContext / Memory dataclasses + exception→outcome mapping pinned**
   in `battery/arms/base.py`: `Memory{id, content, confidence|None, source,
   kind}`, `AgentContext{scenario, episode_seed, prior_memories, user_message}`.
   **ArmAdapter protocol restated from plan §6 (superseded by these
   dataclasses):** `retrieve(context: AgentContext) -> list[Memory]`,
   `record(context, item: Memory) -> None`,
   `isolation_namespace() -> str`, `setup_scenarios(scenarios) -> None`
   (batched/naive per setup mode); `ArmUnavailable` raised by arms — never
   partial-memory returns. Mapping: `ArmUnavailable` during retrieve/record → the runner serves a
   deterministic cached response and records `fallback_cached` (cache
   exists) or `failed` (no cached response). Retry table: rate_limited →
   ≤2 backoff retries then terminal outcome `rate_limited`; timeout → ≤1
   retry then `timeout`; failed/fallback_cached → no retry. Never silent.
   **Episode-level classification (bridge pinned):** an episode whose calls
   end with ANY terminal non-`ok` outcome is excluded from aggregates —
   `fallback_cached` if a cached response was served, else `failed` — and
   counted in the artifact; only all-ok episodes are valid (exit-0
   "≥1 valid episode" boundary uses this). Failure-injection = test-only
   fixture double (documented never wired in production).
9. **CLI flag surface pinned for all five subcommands** (stubs accept-and-
   parse their plan-§6 flags so #1410/#1414/#1415 don't edit the arg surface):
   `run --tier 1|2|3 --arms a0,a4 --seed N (default 0) --mock --batch-setup
   --scorer <mod> --config DIR (default battery/config/) --out DIR (default
   ./battery-out) --max-episodes N`; `parity --arms ... --seed N --mock`;
   `calibrate --print`; `validate-judge --rubric <id>`; `report --out DIR`.
10. **Empty-corpus guard lives in the corpus LOADER** (shared by every
    subcommand — `report` in #1415 inherits it), raising `EmptyCorpus` →
    exit 5 at dispatch level. Tested at loader level, not just in `run`.
11. **Skeleton packages shipped:** `battery/{arms,probes,streams,
    differential,judge,recall,parity,report}/__init__.py` empty modules so
    #1408–#1415 imports resolve and PRs don't collide on `battery/__init__`.
12. **Budget guard (budget.yaml):** `max_episodes`, `max_estimated_cost_usd`.
    Estimate formula pinned: `Σ scenarios × expected_tokens_per_episode(model)
    × price_per_1k(model)` (per-arm constants in arms.yaml; budget.yaml holds
    the caps only). The FULL-corpus estimate gates: the runner refuses to
    start when estimated cost exceeds budget OR `--max-episodes >
    budget.max_episodes` (budget wins — precedence pinned) — exit 1,
    operational. Tested with a fixture. #1416 recalibrates values, not the
    formula.
13. **[cal] table lock:** thresholds.yaml carries the `cal:` section;
    the loader validates the [cal] schema and records `cal_table_hash` (sha256
    of the CANONICAL serialization — rows sorted by (metric, arm), one
    format: `"<metric>|<arm>|<value>"` per line) in artifact provenance.
    **thresholds.yaml top-level keys for this slice: `determinism`
    {epsilon} + `cal` {rows}** (AC-gated per-metric epsilons are added by
    #1409 as new sections). The canonical form makes #1415's re-lock writes
    hash-stable (no false drift). The loader VERIFIES gold sha256 at load
    (fails closed, exit 1) and records cal_table_hash mechanically — the
    lock #1415's print-only re-tune reads.
14. **ep_outcome population contract:** enum {converged, non_converged,
    undec} defined + schema-tested now. **In this slice ep_outcome ≡
    `converged` on every code path** (mock arm exposes no EP surface; the
    artifact's top-level ep_outcome is runner-populated from the episode's
    EP surface when the arm exposes confidence — contract-only in this
    slice). A Scorer may override via `ScorerResult.ep_outcome`. #1409 adds
    the emission test for non_converged/undec (E2E-1.3, loopy-graph
    scenarios) — the EP-surface branch is contract, not dead code, and is
    pinned so a later refactor cannot silently drop it.
15. **Artifact output layout + summary.json schema:**
    `<out>/<attempt_ts>/<run_id>.json` + `<out>/<attempt_ts>/summary.json`.
    attempt_ts is a per-invocation directory stamp (never in run_id —
    run_id stays random-free); the determinism test compares two surviving
    attempt dirs. **summary.json schema v1.0 pinned** (schema-test locked):
    per-arm {arm_id, arm_present, scenarios, valid_episodes, excluded
    {count, episode_ids, reason}}, run-level {exit_code, run_ids,
    artifacts[], seed, timestamp} — #1415 and the exit-4 paths read this
    shape (on arm-init-failure it is the only artifact).
16. **Arm resolution rule + arms.yaml schema (consumed by #1408):**
    `--arms a0,a4` resolves as `battery.arms.<name>` (file-per-arm per plan
    §3; `--mock` supplies `battery.arms.mock`); unknown arm → usage error,
    exit 1. arms.yaml entries: {arm_id, adapter (battery.arms.<name>),
    config {}, price_per_1k_usd, expected_tokens_per_episode} — the
    per-arm cost constants the budget formula uses. #1408 adds adapters;
    the resolution rule + schema are locked here.

## Exit-code contract (plan §6, implemented + tested now)

| Code | Meaning | Trigger (boundary conditions pinned — see Design decision 7) |
|---|---|---|
| 0 | ok | run completed with ≥1 valid episode (incl. runs with SOME excluded fallback/failed episodes — counted, not fatal) |
| 1 | operational error | usage error, missing/invalid config, budget-guard refusal, unimplemented stub subcommand (owned by #1410/#1414/#1415; documented non-exhaustive in plan §6) |
| 2 | gate-blocked | judge-validation gate blocks scoring; `validate-judge` failing rubric (trigger wired by **#1410**; mapping tested now via the shipped `JudgeGateBlocked` exception) |
| 3 | inconclusive | matched-recall INCONCLUSIVE (trigger wired by #1413 via the shipped `InconclusiveRun` exception; mapping tested now) |
| 4 | arm-failed | run-level arm failure: valid-episode count 0 (arm fully down / all episodes failed — NEVER silent exit 0 on empty aggregates), arm-init failure (skip arm, complete run, exit 4, mark absent), isolation breach (complete run, exit 4, flag) |
| 5 | empty-corpus | corpus has 0 scenarios → refuse to start (loader-level guard, E2E-1.4), no artifacts fabricated |

## Acceptance criteria (mapped to issue Indicators)

1. CLI subcommands work with pinned seeds + temp 0 (mock model caller, no keys);
   all five subcommands parse their plan-§6 flags (stubs exit 1 not-implemented).
2. Per-scenario run_artifact.json emitted (schema v1.0 passes its
   schema-validation test); run_id = seed+arm+scenario (random-free);
   model-call outcomes ∈ enum; ep_outcome ∈ {converged, non_converged, undec};
   **episode_trace records the real model calls (turns, tool_calls, tokens,
   per-call outcome) — populated and verifiable under failure injection.**
3. Empty corpus → exit 5 at the loader/dispatch level, no artifact (E2E-1.4).
4. Determinism (E2E-7.1 — joint with #1415 calibration-print half): two
   subprocess runs (PYTHONHASHSEED pinned) same seed → |Δ| ≤ 1e-6 across
   all metric values (single epsilon from thresholds.yaml
   `determinism.epsilon`; integers: |Δ| < 1 = equality).
5. `--batch-setup` → **≤2 DB round-trips per scenario (2·N total)** at the
   query boundary (RoundTripCounter) AND batched graph state == naive graph
   state (equivalence test keyed on content_hash/(op_type,source,targets),
   node-property comparison incl. promote_source status, negative-path
   validation parity); naive path is the per-item baseline. Scale floor ≥50
   scenarios (~500 items): batch = 2·N vs naive ≫ 2·N.
6. Episodes with any terminal non-`ok` call outcome (fallback_cached/failed/
   rate_limited/timeout after retries) excluded from aggregates + counted in
   artifact; all-ok-only episodes are valid; all-episodes-failed → exit 4
   AFTER artifacts written (never silent exit 0; never pre-write); sealed
   golds never reach episode context.
7. Exit codes 0/1/2/3/4/5 asserted behaviorally: 0/1/4/5 end-to-end
   (incl. unknown flag/subcommand → usage error exit 1 — argparse override;
   the default argparse exit 2 is remapped so it can't collide with
   GATE_BLOCKED), 2/3 by raising the shipped contract exceptions
   (`JudgeGateBlocked`, `InconclusiveRun`) at the dispatch boundary — no
   monkeypatching.
8. Budget guard: estimated cost over budget → exit 1 refusal (fixture-tested).
9. Config schema: corpus/thresholds/arms/budget validate; [cal] table locked
   (schema + cal_table_hash in provenance).
