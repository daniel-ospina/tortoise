# #1382 — test_ep_directional cascade tests: draft-status fix

> **For Pi:** Use `executing-plans` to implement this plan task-by-task.

**Goal:** Make the 7 failing EP cascade tests in `tests/test_ep_directional.py` pass locally (and anywhere they run with live FalkorDB), fixing the root cause: points created via the test's `make_point` helper default to `status='draft'` (since #943), and the #780 EP draft filter strips draft inputs — degenerating every IMPL factor below 2 live inputs, so C1/C2 never receive posteriors and `get_conf()` returns its default `0.5` ("C1 should drop: 0.0000").

**Scope extension (reviewer follow-up):** the same root cause affects the sibling EP directional files `tests/test_directional_impl.py` and `tests/test_directional_impl_fix.py`; the live-point sweep is extended to them (same one-helper change), plus two stale assertion ranges recalibrated to the post-#855/#871 engine (see Fix Design).

**Team:** epistemic-team
**Role:** epistemic-team

## Root-Cause Summary (investigation evidence, 2026-08-18)

1. **Dependency hypothesis DISPROVEN.** The issue claimed a numpy 2.5.2 / scipy 1.18.0 / sklearn 1.9.0 behavior change. CI logs for the passing main run (run 32104817894, job `test (a)`) show CI installs the **exact same versions** and reports `1453 passed, 72 skipped` — `test_ep_directional.py` is among the skipped, not passing.
2. **CI skip gap.** The fast-suite `test (a)` matrix job has **no FalkorDB service container**, so every live-FalkorDB-required test (module-level `FALKORDB_AVAILABLE` probe → `pytestmark.skipif`) is silently skipped. The regression went undetected because CI never runs these tests. Filed separately: **#1436**.
3. **True root cause.** Since #943, `sdk.create_point` defaults to `status='draft'`. The #780 draft filter strips draft inputs from operators; IMPL factors with <2 live inputs are excluded (`ep.py:1014 "N/M inputs draft — factor skipped (degenerate, #780)"`). The test's `make_point` created all points as draft; `create_operator` auto-promotes only **sources** (`promote_source=True`), so C1/C2/anchor targets stayed draft forever. EP logs confirm: every IMPL operator skipped with `[live, draft]` inputs.
4. **Precedent.** PRs #1000/#1004 (commits `41b6b7f3`, `9aa2d71a`) fixed the identical bug class in 11 EP test cases (decide/dream/file_human_approval/source_inheritance_own) by passing `status="live"` to `create_point`; `test_ep_directional.py` was missed.
5. **Numeric signature.** Failing values are exactly the default-0.5 arithmetic: `0.0000` drops where C1/C2 were never written; `0.0238 = 0.5238 − 0.5` (t4_mean) in the magnitude test.

## Fix Design

One-helper change in `tests/test_ep_directional.py`:

```python
def make_point(sdk, content, kind="statement"):
    # #943: create_point defaults to status='draft'; the #780 draft filter
    # strips draft inputs, degenerating IMPL factors (<2 live inputs) → zero
    # cascade (#992). The #1000/#1004 sweep migrated 11 EP test cases in
    # decide/dream/file_human_approval/source_inheritance_own to create live
    # points; this file was missed. Target conclusions (C1/C2) are never
    # operator sources, so they were never auto-promoted to live — mark
    # explicitly.
    return sdk.create_point(kind, content, status="live")
```

All point creation in the file routes through `make_point` (verified: only `create_point` call site is the helper), so a single change covers every EP-belief-feeding point. The NAND contradiction source is created via `make_point` too and receives `set_point_baseline` — it becomes live through the operator's `promote_source`, and the explicit `status="live"` is harmless/consistent.

**Extension — sibling files (same pattern):** `tests/test_directional_impl.py` and `tests/test_directional_impl_fix.py` have the identical `make_point` helper; their targets are never operator sources (only the source/defeater are), so they were never auto-promoted to live. Applied the same one-helper change.

**Recalibrated ranges (post-#855/#871 engine):** with live inputs restored, two absolute-range assertions were stale: the engine deliberately does **not** boost NAND messages to weakly-evidenced claims, so a T0 NAND on an unevidenced claim settles at **0.1955** regardless of IMPL support (measured; pure-support reference 0.6533, pure-contradiction 0.1955). Updated:
- `tests/test_directional_impl.py::test_impl_directional_refuted_conclusion` — conclusion band `(0.05, 0.45)` (was floor `> 0.40`; band also catches the 0.5 draft-default prior, so the #943 regression cannot silently re-pass)
- `tests/test_directional_impl_fix.py::test_nand_bidirectional` — claim band `(0.05, 0.50)` (was `(0.50, 0.85)`)

### Rejected Alternatives

- **Pin numpy/scipy older in uv.lock** — rejected: CI installs the same versions and these tests don't run there; the bug reproduces on numpy 2.4.6/scipy 1.17.1 (throwaway venv verification). Pinning would mask the defect and contradict the pyproject floor convention.
- **Add FalkorDB service to CI fast-suite** — rejected as THE fix: doesn't fix the local failing env; it's a real CI-coverage gap, filed as #1436.
- **Change `tortoise/ep.py` / `quadrature.py` numerics** — rejected: not the failing path (factors never run — draft erasure); pure-math suite (`test_ep_quadrature.py` 11/11) passes.
