# #2789 — Implementation Plan

**Issue:** [#2789](https://github.com/daniel-ospina/tortoise/issues/2789) · **Scoping:** `docs/scoping/2026-09-10-2789-one-free-org.md`
**Tier:** Complex · **Chosen design:** webhook-provisioned org (S-B option 2)
**Research path:** in-repo trace only (no third-party API surface added; the only
external contract touched — Stripe Checkout params + event shape — is already
exercised by `tortoise/billing.py` and `tests/test_billing.py`).

---

## Design summary

1. **Entitlement = ownership.** New twin helpers count *owner* memberships in
   non-paying teams, excluding `pending_payment`:
   - `tortoise/supabase_control.py: owned_free_org_ids(cp, user_id) -> list[str]`
   - `tortoise/hosted_api.py: async _owned_free_org_ids(user_id) -> list[str]`
   The existing `count_active_free_memberships` (membership-scoped) is **untouched**
   so the invite-join gates keep their current semantics.
2. **Structured 402.** All three create-org gates raise
   `402 {"code": "one_free_org_limit", "message": "You can only have one free
   organization", "team_id": <owned free org>}`.
3. **Paid-new-org checkout** — `POST /v1/billing/checkout/new-org`
   (session auth, NOT team auth): validate name + price → dup-name 409 → **pre-mint**
   the org id server-side (`uuid4().hex[:26]`) → create a Stripe Checkout session with
   `customer_email` (no customer object), `client_reference_id=<team_id>`,
   `metadata={new_org:1, user_id, org_name, tier, team_id}` → return
   `{checkout_url, team_id}`. Nothing is persisted server-side.
4. **Webhook provisioning** — `checkout.session.completed` with `metadata.new_org=1`
   provisions the org idempotently (TeamMeta-exists probe → skip on replay), then
   applies the existing billing state. Registry (selfhost) lane: the pre-minted id
   rides `team_create(idempotency_key=…)` purely as the replay key — `team_create`
   still mints its own id, so the webhook **adopts the id the lane returns** for
   every later billing/marker/audit write.
5. **Dashboard** — `api()` lifts `detail.code`/`detail.team_id` onto the error; the
   account-menu item pre-checks and opens the new three-option dialog; the dialog's
   third option runs name+plan → checkout; the success return polls for
   `?new_org=<id>` and switches.

## Task 1 — Supabase-lane ownership helper

**Intent:** give the entitlement a lane-correct, ownership-scoped primitive.
**Acceptance:** `owned_free_org_ids` returns only active **owner** memberships of
teams that are not on an active/paid subscription and not `pending_payment`;
non-UUID user ids and dangling memberships return `[]` (never raise).
**Files:**
- Modify: `tortoise/supabase_control.py`
- Test: `tests/test_one_free_org_entitlement.py`

**Steps**
1. Add `_PENDING_PAYMENT_STATUS = "pending_payment"` beside `_BILLING_ACTIVE_STATUSES`
   (with a comment tying it to #2789's rules table).
2. Add `owned_free_org_ids(cp, user_id) -> list[str]`:
   - `_is_uuid` shape gate → `[]`;
   - query `team_memberships` (`select=["team_id","role"]`, filters user+active+team_id neq '',
     `order="created_at.asc"`) — its own query, not a change to `user_memberships`;
   - keep only `role == "owner"`;
   - `team_by_id` → skip `None` (dangling);
   - skip when `subscription_status in _BILLING_ACTIVE_STATUSES`;
   - skip when `subscription_status == _PENDING_PAYMENT_STATUS`.
3. Add `count_owned_free_orgs(cp, user_id) -> int` = `len(owned_free_org_ids(...))`
   (small convenience for parity with the #1877 twin and for readable tests).

## Task 2 — Hosted-api ownership twin + structured 402

**Intent:** one mode-aware entitlement entry point + one machine-readable blocked payload.
**Acceptance:** `_owned_free_org_ids` dispatches supabase/registry and mirrors
`_count_active_free_memberships`' shape (TOCTOU `sleep(0)`, `tier IS NULL` fail-closed,
`role:'owner'`, `pending_payment` excluded). The three create-org gates raise 402 with
the structured detail **in the pinned order** (429 → 409 → 402).
**Files:**
- Modify: `tortoise/hosted_api.py`
- Test: `tests/test_one_free_org_entitlement.py`

**Steps**
1. Add `async def _owned_free_org_ids(user_id) -> list[str]` next to
   `_count_active_free_memberships` (same docstring style; explains *why* it is
   separate from the #1877 helper).
   - supabase: `owned_free_org_ids(get_control_plane(), user_id)` + `await asyncio.sleep(0)`.
   - registry: `MATCH (m:Membership {user_id:$uid, status:'active', role:'owner'})
     WHERE m.team_id <> '' MATCH (t:Team {id:m.team_id})
     WHERE (t.tier='free' OR t.tier IS NULL)
       AND coalesce(t.subscription_status,'') NOT IN ['active','past_due','trialing','pending_payment']
     RETURN m.team_id ORDER BY m.created_at` → list.
2. Add `def _one_free_org_detail(team_id: str | None) -> dict` returning the structured payload.
3. Replace the two `_count_active_free_memberships(...) >= 1` create gates
   (`_create_team_supabase_lane`, `_create_team_registry_lane`) and the
   `create_onboarding_team` gate with
   `_ids = await _owned_free_org_ids(...); if _ids: raise HTTPException(402, detail=_one_free_org_detail(_ids[0]))`.
4. `/v1/teams` list: add `"subscription_status": team.get("subscription_status")` to each
   row (additive; feeds the client pre-check).

## Task 3 — Stripe helper for a not-yet-existing org

**Intent:** a checkout session that binds an org that does not exist yet, without
creating any server-side row or Stripe customer.
**Acceptance:** posts `mode=subscription` + `customer_email` (no `customer`),
`client_reference_id` + `metadata[team_id|user_id|org_name|tier|new_org]`; returns the
session id and url.
**Files:**
- Modify: `tortoise/billing.py`
- Test: `tests/test_one_free_org_entitlement.py` (param-shape assertion)

**Steps**
1. Add `create_checkout_session_for_new_org(self, team_id, price_id, email, *, user_id,
   org_name, tier, success_url, cancel_url) -> tuple[str, str]` returning `(session_id, url)`.
   Document **why** there is no `customer` param (abandoned checkout leaves nothing).

## Task 4 — `POST /v1/billing/checkout/new-org`

**Intent:** the third option's server door.
**Acceptance:** name validation mirrors `POST /v1/teams` (422s); unknown price → 400;
unconfigured catalog → 503; duplicate name → 409 with no Stripe call; happy path →
`{checkout_url, team_id}` and **zero** control-plane writes; the paid path is never
blocked by the free-org entitlement.
**Files:**
- Modify: `tortoise/hosted_api.py`
- Test: `tests/test_one_free_org_entitlement.py`

**Steps**
1. `class NewOrgCheckoutRequest(BaseModel): name: str; price_id: str`.
2. `def _new_org_team_id() -> str`: `uuid4().hex[:26]` (26 hex chars, matches the
   minted-id shape). Pre-minted at request time so it can ride
   `client_reference_id` + `metadata[team_id]`; a session-derived id is circular
   (the id is needed to *create* the session). On the Supabase lane this IS the org
   id; on the registry lane it is the `team_create` idempotency key and the lane's
   own minted id is the effective one.
3. `def _billing_checkout_new_org_sync(user, name, price_id) -> dict`:
   - `PriceCatalog().tier_for_price(price_id)`; reject `free`/`anon` → 400;
   - dup-name guard: supabase `team_by_name`; registry `MATCH (t:Team {name:$name})` → 409;
   - success/cancel URL derived from the existing env helpers, appending
     `new_org=<team_id>` after the session id is known;
   - call the new Stripe helper; return `{"checkout_url":…, "team_id":…}`.
4. `@app.post("/v1/billing/checkout/new-org")` with `Depends(get_current_user)`, mapped
   errors via the existing `_billing_error_to_http`.

## Task 5 — Webhook provisioning (idempotent, both lanes)

**Intent:** a completed checkout yields a fully working paid org; a replay converges.
**Acceptance:** first delivery provisions exactly one team + owner membership + graph and
applies the paid tier; second delivery of the same event changes nothing; the tier from
metadata still applies if `get_subscription` fails; an unknown/absent metadata is loud.
**Files:**
- Modify: `tortoise/hosted_api.py`
- Test: `tests/test_one_free_org_entitlement.py`

**Steps**
1. Factor the supabase lane's eager graph init out of `_create_team_supabase_lane` into
   `def _eager_provision_org_graph(cp, team_id, name, user_id) -> str` (returns `graph_name`)
   and call it from both the create-org lane and the webhook provision.
2. `def _provision_new_org_from_checkout(sdk, team_id, meta) -> str`:
   - supabase: if `team_by_id(cp, team_id)` → return `team_id` (replay no-op);
     resolve the final name (dup → deterministic `f"{name} ({team_id[:4]})"` + warning log);
     `_eager_provision_org_graph`; `provision_team(...)` with the metadata tier's limits;
     on a name-collision exception retry once with the disambiguated name.
   - registry: look up `(name, owner=user_id)` → reuse; else `team_create` (disambiguate on collision).
3. In `_webhook_apply_event`'s `checkout.session.completed` branch: when
   `metadata.new_org == "1"`, provision first and reassign `team_id` to the effective id;
   after the existing subscription block, if no tier was resolved fall back to the
   metadata tier (with `apply_limits`) so a failed subscription fetch cannot leave a paid
   customer on free limits.
4. A per-team `threading.Lock` (`_new_org_provision_lock(team_id)`, backed by the
   `_NEW_ORG_PROVISION_LOCKS` dict) around the provision step —
   the webhook apply runs in a worker thread, so an asyncio lock is not usable.

## Task 6 — Dashboard: pre-check, dialog, purchase flow, return

**Intent:** surface the rule at the moment of intent and make the third option real.
**Acceptance:** at the cap the dialog opens immediately with the issue's copy and exactly
three actions; `Escape`/backdrop = Cancel; focus returns to the blob trigger; the purchase
mode requires name + plan; a structured `one_free_org_limit` from the server opens the same
dialog; `?new_org=<id>` switches to the new org once it exists.
**Files:**
- Modify: `website/apps/dashboard/src/main.jsx`
- Modify: `website/apps/dashboard/src/index.css` (only if a class is required)
- Test: `website/apps/dashboard/src/oneFreeOrgDialog.test.js` (new tripwire)
- Rebuild: `website/apps/dashboard/dist` (`npm run build`)

**Steps**
1. `api()`: when `body.detail` is an object, surface `err.code`, `err.teamId`, and prefer
   `detail.message` as the Error message (keeps `#308` suspension behaviour intact).
2. Account-menu handler: compute `atFreeOrgCap` from `teams`
   (`role==='owner' && !ACTIVE_STATUSES.includes(subscription_status) && subscription_status !== 'pending_payment'`)
   → open the dialog in `limit` mode immediately when at the cap.
3. Dialog gains `createTeamMode` (`'name' | 'limit' | 'purchase'`):
   - `limit`: the issue's headline/body + Cancel / Upgrade current organization
     (`switchTeam(ownedFreeOrgId)` + `setTab('billing')`) / Purchase subscription for a new organization (→ purchase mode);
   - `purchase`: name input + a plan radio list from `planOptions()` filtered to paid
     tiers with a server price id → `POST /v1/billing/checkout/new-org` → popup.
   - keep `autoFocus` on the primary control of each mode and the `#2392` focus restore.
4. Success return: extend the `?session_id` effect — with `?new_org=<id>`, poll
   `/v1/teams` until the org appears, then `switchTeam(new_org)` and strip the param.
5. Copy: replace "The free plan includes one organization. Upgrade an existing
   organization to create more." with the issue's wording; align the Billing-tab
   explanation to "one free organization".
6. No new class on the name `<input>` (the `#2778`/`#2791` tripwire must stay green).
