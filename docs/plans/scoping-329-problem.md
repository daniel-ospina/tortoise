# Issue #329 Scoping — Confirmed Problem Definition (v2, post problem-verify)

## Confirmed Problem Definition

The Tortoise graph engine has multiple unvalidated Cypher-construction, file-handling, credential-routing, and resource-accounting surfaces that allow host-file disclosure, cross-provider API-key disclosure, unbounded graph growth, and (latently) Cypher injection. The issue's headline injection narrative is **largely falsified** by code evidence: filter-key "backtick" injection was never exploitable (`key.replace("_","").isalnum()` rejects all punctuation, values parameterized — intact since initial commit), and `context` f-string interpolation was already fixed in #49 Phase 2 (PR #155; create_point/update_point raise TypeError). The verified tenant-reachable defects are:

1. **[P0] Cross-provider API-key misrouting** — analyze.py:227 `os.environ.get("OPENAI_API_KEY") or os.environ.get("DEEPSEEK_API_KEY")` then always POSTs `Authorization: Bearer {key}` to `https://api.deepseek.com/v1` with `deepseek-chat`. Triggerable by ANY HTTP tenant via `tortoise_analyze` (HTTP_ALLOWED, use_llm=True default). If OPENAI_API_KEY is set (even alongside a DeepSeek key), the OpenAI key is disclosed to DeepSeek. Env provisioning unresolved in-repo (`.env.example` declares neither; deployment envs unverified) — fix regardless (a key must never be sent to a provider that didn't issue it).
   **Fix design:** provider table like ingest.py `_PROVIDERS` — deepseek → (api.deepseek.com/v1, DEEPSEEK_API_KEY, deepseek-chat); openai → (api.openai.com/v1, OPENAI_API_KEY, gpt-4o-mini). `llm_classify` picks deepseek if DEEPSEEK_API_KEY set, else openai if OPENAI_API_KEY set, else None (keyword-only). A key is NEVER sent to a provider that didn't issue it.
2. **[P1] Operator-conditioned host-file disclosure via tenant-set sourcePath** — tenant sets `sourcePath` + `doc_status='captured'` via HTTP `tortoise_create_document`/`tortoise_update_entity` (arbitrary props passthrough → `_persist_extra_props` → `d.sourcePath`); operator runs `tortoise-ingest --upgrade-all` → ingest.py:238-251 `Path(coalesce(d.sourcePath, d.id)).read_text()` reads ANY host file the operator can read → content extracted into the tenant's graph → tenant exfiltrates via search.
   **Containment policy (P1 fix — two-sided):**
   (a) READ SIDE — shared base-dir confinement env `TORTOISE_INGEST_BASE_DIR` covering BOTH `ingest_corpus`/`index_sessions` AND `--upgrade-all`/`_do_upgrade_all`. Resolution rule applies to the **FINAL RESOLVED PATH regardless of source** (the coalesced `sourcePath` OR the `d.id` fallback — `d.id` is TENANT-MUTABLE via `create_document` props `id` override, so it must NOT be trusted as "the document filename"): `os.path.realpath()` BOTH the candidate path AND the base before comparison (symlink-escape-proof); candidate must resolve strictly under base (reject `..` components, absolute-outside-base, and relative paths that escape base when resolved against CWD); anything not provably under base → SKIP + warning, never read. ENV-UNSET DEFAULT = fail-closed skip with a one-time log hint ("set TORTOISE_INGEST_BASE_DIR to enable re-upgrade of relative-path documents"). Positive case preserved: operator's own corpus files under base still re-upgrade (tests MUST set the env and use absolute paths under base to avoid CWD flakiness).
   (b) WRITE SIDE — `sourcePath` AND `id` overrides have no legitimate tenant use (MCP `tortoise_create_document` has no id param; operator flows pass `doc_id` positionally): REJECT `sourcePath` and `id` in `sdk.create_document`/`update_entity` props passthrough at the **SDK boundary** (single choke point covering MCP, future REST, and direct SDK callers; `api.add_document` uses an explicit `source_path` param — unaffected). REST /v1 has NO document endpoint (strict Pydantic models) — no work needed there. Tenant-created Document with `id=/etc/passwd` + `doc_status=captured` → skipped by `--upgrade-all` (regression test). NOTE: `tortoise_create_event` with `props={object:..., objectType:'Document'}` can also mint a `:Document` node with a tenant-chosen id (entities.py `_upsert_event` Document branch) — extend the write-side id validation to that minting path (reject non-safe Document ids), while the READ SIDE (final-resolved-path strict-under-base) remains the security boundary and fails closed regardless.
3. **[P1] Zero per-team node quotas on the HTTP MCP surface** — `_check_team_limit` exists only in REST /v1 (hosted_api.py:503) and fails open (`if not team_id: return`, `except Exception: return`); NO quota check on the MCP path. `tortoise_checkpoint` (1 Point+Event per item, no cap), `tortoise_file_decision` (N options + M evidence + edges), `create_point(dedup=False)` + unbounded `:Tag` MERGEs, `create_document` → unbounded node growth on the shared DB at 100 req/min per key. Rate limiter is per-key, disable-able (`RATE_LIMIT_DISABLED=1`), and NOT a substitute for node quotas.
   **Design constraints (committed defaults):**
   - **Enforcement:** shared fail-closed helper `_enforce_team_limit(team, resource)` (replaces REST fail-open `_check_team_limit`; counting exception → BLOCK, not pass) called pre-write from BOTH REST endpoints AND MCP write tools. **COMPLETENESS RULE: every MCP write tool that can CREATE or MERGE nodes (Points, Events, Subjects, Objects, Documents, Sources, Tags) must call `_enforce_team_limit` pre-write** — enumerated: create_point, create_operator, create_event, create_subject, create_object, create_document, create_source, checkpoint, file_decision, update_entity, update_point, diary_write, mitigate_operator. Edge-only tools (create_edge, supersede, invalidate) are NOT quota-gated (rationale: quota targets node growth; blocking edges at cap is a regression). Same semantics: `MATCH (n) RETURN count(n)` in the team graph vs `max_points` (default 1000). Preserve the `api_keys` special case (registry-graph count vs max_api_keys). 402-equivalent error at cap. Per-write COUNT cost on the hot path = accepted tradeoff (documented); REST and MCP share the same helper.
   - **Counter semantics:** total node count (identical to REST today). Count-before-write may reject a dedup re-submit ONLY when the graph is truly at cap — acceptable (team must upgrade).
   - **Multi-create overshoot:** bounded by per-call batch caps — checkpoint items ≤ 500, file_decision options ≤ 50 / evidence ≤ 100, tags per point ≤ 50 (applies to BOTH create_point AND update_point tag paths). Preserve the `sessions` resource (max_sessions default 1000) in the shared helper.
   - **Durability:** introspective regression test — enumerate HTTP_ALLOWED at runtime, identify node-creating tools from schemas, assert each raises the 402-equivalent at max_points (self-verifying completeness, not list-dependent).
   - **Idempotency-cache safety:** MCP writes never call begin_ingest; no processed-marking before write → no desync. No change to EventAPI idempotency.
   - **Rate limiter is NOT a substitute** (per-key, disable-able, best-effort).
4. **[P1] Filter-key param collision + Unicode-key robustness (tenant-reachable via MCP tortoise_query/tortoise_paginated_query)** — filter key `kind` (single-kind → TypeError at call site), `kind_N` (multi-kind expansion params overwritten → silent wrong IN-clause), `skip`/`limit` (MCP path → TypeError at call site; direct-SDK path → silent rebind of pagination params → corrupted WHERE); Unicode alphanumeric keys (é, 中, ١) pass `isalnum()` and cause per-query errors. Fix: ASCII-only `^[A-Za-z_][A-Za-z0-9_]*$` key validation + reserved-parameter rejection ({kind, skip, limit} ∪ regex `^kind_\d+$`, matching `_expand_kind`'s actual `kind_0..kind_{n-1}` placeholders) with clear ValueError. **Accepted tradeoff:** property names `kind`/`skip`/`limit` used as DATA filters become hard errors (edge case; error message explains). Positive regression: legit ASCII keys (createdAt, pointKind, ...) still produce correct WHERE at both MCP and SDK layers.
5. **[P2] Cross-tenant graph-name enumeration** — `tortoise_list_graphs` (HTTP_ALLOWED) → `db.list_graphs()` returns ALL graph names in the shared DB. Alternatives: (a) remove from HTTP_ALLOWED (kills tool for tenants), (b) scope to team-owned graphs, (c) operator-only. Decide at solution phase.
6. **[P2] analyze() error/cypher disclosure** — analyze() returns raw DB exception text + full rendered cypher to tenants via HTTP tortoise_analyze.
7. **[P2] REST `_check_team_limit` fail-open** — two-sided fix: fail closed on counting errors; align counter semantics with MCP quota.

## Latent defense-in-depth landmines (must fix; stdio=trusted not guaranteed, SDK is public)

8. **[P2] sdk.traverse() unvalidated rel_type (sdk.py:908)** — confirmed injection primitive (empirically executes DETACH DELETE via rel_type); zero production callers today (dead code — only tests call it; MCP tortoise_traverse → navigation.py parameterized). Fix: rel_type allowlist or remove method. NOTE: `_GuardedGraph` bulk-wipe guard does NOT protect against injection inside parameterized queries (any query containing `{` bypasses `_is_bulk_wipe`).
9. **[P2] search_engine label interpolation (run_fts_query:143/209, run_structural_query:305, run_vector_query)** — `entity_type.capitalize()` interpolated as Cypher label without in-function validation; closed upstream by sdk.tortoise_fts_query allowlist today. Fix: in-function entity_type validation (defense-in-depth).
10. **[P2] sdk.py:640-675 operator edge-rename interpolation** — `edge_type`/`rel` interpolated into Cypher. Verdict: 734-742 safe (op_type allowlist); 640-675 latent (requires pre-existing attacker-crafted edge type; current allowlisted creation paths prevent). Fix: validate against known types before interpolation.

## Issue O/I/T items — disposition

- **Filter key backticks**: NOT exploitable (isalnum rejects punctuation). Fixed by item 4 hardening + regression tests.
- **Context f-string interpolation**: ALREADY FIXED (#49 Phase 2). Scope: regression test that create_point(context=) raises TypeError (may already exist — verify).
- **traverse() unvalidated rel_type**: latent landmine — item 8.
- **Path traversal in ingest_corpus**: stdio/operator-only (HTTP-excluded). Scope: path validation for `ingest_corpus`/`index_sessions` directory + progress_file (reject `..`, require absolute, optional base-dir confinement env) — P2 hardening.
- **Path traversal in projection Lite mode**: RESOLVED — FalkorProjection embedded/path mode; relative-path rejection already shipped (#176 Task 7: config.resolve_db_path `_abs` + FalkorProjection hard-reject + RELATIVE_PATH_ERROR). Scope: regression tests for rejection paths + audit `allow_nonstandard_path` escape hatch (currently env/kwarg, operator-only — confirm no tenant reachability).
- **API key → wrong provider**: CONFIRMED — item 1.
- **Stub-node auto-creation flooding**: short-ID Point stubs (edges.py:24-33) are OPERATOR-only (EventAPI path); sdk.create_operator validates inputs exist; MERGE-by-name bounds Subject/Object stubs. The real tenant-reachable flood is item 3 (MCP quota gap). Scope: bound short-ID stub auto-creation — **per-FalkorProjection-instance counter** (process-scoped, the unit of one ingest run), default 500, env override TORTOISE_MAX_AUTOCREATED_STUBS; at-cap behavior = STOP creating stubs + log warning + skip edge creation to missing nodes (fail-safe, no partial edge); legit cross-file wiring below cap still creates stubs. P2 hardening of the operator surface + regression test (boundedness + below-cap legitness).
