# Implementation Plan — Issue #1348: Measure RRF fusion quality levers (pool floor, k sweep, GraphRanker verdict)

> Draft from solution-converge (Phase 5). Pending solution-verify (Phase 5.5) + parallel review gates (Phase 7).

## Problem statement

Three RRF-fusion levers are unmeasured: (1) production pool depth is hardcoded `str_limit = limit * 2` (sdk.py:8725), below the RRF 50–100 consensus sweet spot at typical limits (pool 20 at limit=10); (2) fusion constant k is hardcoded 60 (search_engine.py:633) with no sweep; (3) GraphRanker (#25) is unwired from the fused path and unscorable on the synthetic oracle corpus (all three signals null: random α/β, random edges, dead recency). P@5=0.924 near ceiling at depth 50 means unpaired deltas at n≈100 are unpowered — the measurement must be paired and in-loop.

## Proposed solution (synthesis: A "Fusion-native harness" + B's discipline + env-var convention)

- **Pool floor (prod):** inline `TORTOISE_POOL_FLOOR` env knob (matches the repo's inline env-knob convention; parse with try/except fallback + clamp per the TORTOISE_MAX_FILE_MB precedent) + `pool_size: int | None = None` EXACT-override param on `tortoise_fts_query` (a floor is the right shape for an env default, an exact override for a programmatic caller): `str_limit = pool_size if pool_size is not None else max(limit * 2, pool_floor)` (full-scan exempt). Returned limit unchanged — truncation at sdk.py:8851 precedes EP decoration at 8853+, so decoration is flat (#1353 NOT a dependency). Default 50 is PROVISIONAL (see task 8 precedence).
- **k sweep (eval):** paired in-loop computation. `retrieve_per_strategy` already produces per-strategy ranked lists; compute `rrf_fusion(..., k=20/60/100)` once per query from those identical lists — perfectly paired, tightest CIs, single run. Pure Python over rank positions; no retrieval re-run.
- **GraphRanker leg:** add `"fused_rerank"` to `STRATEGIES` (run.py:75) — real path, in-harness: `GraphRanker.rerank` over the fused pool (scores.rrf drives similarity; graph_boost from confidence + degree). Two arms on the SAME corpus: fused ON vs OFF.
- **Corpus enhancement (default GraphRanker leg):** `generate_oracle_points(..., enhance_signals=True)` — topic-correlated `n.confidence` and topic-correlated operator edges between EXISTING nodes only (no new nodes; no oracle-denominator or FTS/vector input shift). **Byte-identical unenhanced path — rng contract (P1 fix, verified synthetic_corpus.py:485-529):** the posterior draws (alpha/beta at 522-524) are INSIDE the `for i in range(n)` loop on the CONTINUOUS main rng stream — isolating them would shift every subsequent point's retracted/content/embedding/kind draws → byte-identity breaks. Therefore: alpha/beta remain drawn from the MAIN seeded rng in BOTH paths (identical per-iteration draw counts); in enhanced mode, `confidence` is DERIVED from those same drawn alpha/beta values mapped through topic membership; the isolated `random.Random(seed ^ salt)` stream is used ONLY for extra draws (edge selection, noise) that never touch the main stream. Recency stays dead (documented).
  **Confidence construction (P2, verified — posterior draws exist only for with_post points, ~50%):** `with_post = rng.random() < 0.5` — only ~half of live points carry drawn alpha/beta, so a literal "derive confidence from alpha/beta" covers half the corpus; the other half reads flat `coalesce(0.5)`. PIN the construction (P4 fix — ONE choice, not an open option): posterior-bearing points: `conf = clip(0.5 + topic_bias[topic]·0.3 + ((alpha − 20)/40)·0.2, 0, 1)` — noisy per-topic mean spread with overlap (NOT recoverable from topic alone → non-tautological); posterior-less points: `conf = 0.5` (coalesce fallback — simplest rng contract; state the ~half-corpus signal coverage as a report field). Add a non-tautology guard (within-topic confidence spread > 0) and a zero-main-stream-draw-growth test (enhanced point dicts contain no field whose computation consumes the main rng beyond the drawn alpha/beta).
  **Detectability floor — NECESSARY, not sufficient (P1-A fix — verified: oracle grades are QUERY-CONDITIONED and the 100-query mix is balanced across all 24 topics, 2-8 queries each):** a static per-point confidence correlated with topic is query-INDEPENDENT — for a query targeting topic T, boosting by static topic bias helps when bias_T exceeds the pool average and hurts otherwise, netting ≈0 nDCG@10 delta over a balanced mix REGARDLESS of Cohen's d. Therefore: (a) the Cohen's d ≥ 0.8 between-topic spread is necessary but NOT sufficient for a lift; (b) the power-relevant statistic is the per-query correlation between static confidence and oracle grade — report it; (c) the static enhanced arm's expected verdict on the balanced mix is ≈0 with a wide CI — pre-register that interpretation (→ "needs real-EP corpus", NOT "harness-broken" and NOT "graph signal dead").
- **Two-phase sequencing:** Phase 1 = depth×k sweep on the plain committed corpus (baseline comparability, reproduces baseline-embedded-2026-08-17.json); Phase 2 = enhance, then GraphRanker arms. Retrieval metrics are EP-blind (run_fts/vector/structural score text/embedding/kind; rrf_fusion rank-only; EP annotation post-truncation), so Phase-1 metrics are contamination-free by construction — the report declares this.
