# #1536 — E4: S4 merges-not-replaces — Implementation Plan

> **For Pi:** Use `executing-plans` to implement this plan task-by-task.

**Goal:** Stop S4 from silently dropping S2 extraction findings — replace `complete_list = s4` with a deterministic programmatic union (S2 ∪ S4) that preserves S4's gap-review role (corrections + gap additions) while guaranteeing no S2 item is lost.

**Team:** epistemic-team
**Epic:** #1509 — Extractor V3 (Stage 3) · **Epic contract:** 03-scope E4 · **Test alignment:** E2E-5 (early-asserted fact survives the S4 pass) · **Test-design surface:** #1515 surface 15 (pipeline state)
**Dependencies:** E1 (#1533) lands before E4 in lane B (execution order E1 → E3 → E2 → E4). E4's merge is **field-agnostic** — it passes items through by reference, so E1's `when` and E3's `quote`/`search_keys`/`source_turn_id` fields ride through untouched (see Cross-lane interfaces + ⛔ Conditional gate).
**Complexity:** micro (label verified). ~1 helper module + 1 call-site rewrite + ~10 unit/orchestrator tests. No migration, no RLS, no new interface.

**Architecture:** A pure-Python `merge_embed_lists(s2, s4)` performs section-by-section identity-key reconciliation: on key collision the S4 (reviewer, graph-informed) version wins; S2 items S4 omitted are **preserved** (the E4 fix); S4-only items are appended in S4 order. S5's existing link-before-create/content-addressed dedup is the safety net for items S4 intentionally omitted because the graph already has them. No change to prompt contracts, no new graph fields, no new ontology.

## 1. Design decisions

### D1 — The merge is programmatic, not an LLM re-merge
S4's role stays exactly what its prompt says — gap reviewer. The final list is computed in Python by `merge_embed_lists()`. Rationale: the drop bug *is* LLM re-emission (S4 must "re-emit the S2 items you keep", and models silently drop items). A deterministic union makes "no silent drops" a unit-assertable invariant instead of a prompt-quality hope.

### D2 — Identity-key reconciliation; S4 wins on collision, S2 never dropped
Per section, an identity key decides whether an S4 item corresponds to an S2 item:

| Section | Identity key | Why this key |
|---|---|---|
| `entities` | `(norm(name), norm_kind(kind))` | mirrors S5's entity dedup key `(name, kind)` but normalized (S4 re-emission drifts case/whitespace) |
| `events`, `points` | `norm(content)` | mirrors S5's content-address dedup (`point_ids`/`event_contents`) |
| `operators` | `(norm(src), norm(dst), norm(op_type), norm(target.src), norm(target.dst), norm(target.op_type))` | MITIGATES attacks a specific edge — the target edge is part of identity; `strength` is **not** (a re-emitted strength tweak must collapse, S4's value wins) |
| `chain_notes` | `(norm(chain), norm(finding))` | diagnostic records |
| `link_before_create` | `(norm(searched_for), found)` | diagnostic records (S2's is empty — S2 never searches) |

Rules, in order:
1. **Key collision** (both S2 and S4 have the item) → S4's version wins, placed at the S2 item's position. S4 is the reviewer with S3 graph context; its lifecycle/supersedes corrections are the point of its existence (prompt: "corrected where the search results show they already exist").
2. **S2 item with no S4 counterpart** → kept verbatim (this is the E4 fix — the 5K fact S4 forgot to re-emit survives).
3. **S4-only item** → appended in S4's order (gap additions).
4. **Duplicate keys within one side** → first occurrence wins (same rule S5 already applies via `seen_entities`/`point_ids`).

### D3 — Order stability for the owner loop
`result["s2_embed"]` (raw S2) and `result["embed_list"]` (merged) are diffed by the owner loop. Merge preserves S2's item order, replaces in place, appends S4-only items at the end — the diff is deterministic and shows exactly *what S4 added/corrected*, never permutation noise.

### D4 — Field transparency (E1/E3 decoupling)
The merge never rewrites an item dict — items pass through by reference, so unknown fields (E1's `when`, E3's `quote`/`search_keys`/`source_turn_id`, slots, etc.) ride through untouched. The merge only touches the identity key and list membership. **Conditional:** if E1/E3 add *new top-level sections* (not item fields) to the embed-list contract, the section tuple in `merge_embed_lists` + `_s4_merge_stats` must be extended (⛔ Conditional gate).

### D5 — S5's existing dedup is the safety net for *intentional* omissions
S4's prompt tells it to omit items that already exist in the graph ("lifecycle unchanged, do NOT re-create"). When S4 omits such an S2 item, the union re-adds S2's version — and `execute_embed` content-addresses it to the existing id (`_find_point_match` exact → `pid = existing_id`), so no duplicate write occurs. Keeping S2's version is therefore **harmless even when S4's omission was intentional**.

### D6 — Degradation semantics unchanged
- S4 returns empty/only-`chain_notes`/garbage → S2 stands + existing warning (`"S4 returned an empty list — kept S2 output"`). (The `chain_notes`-only case is already excluded by the existing guard, which requires entities/points/events/operators.)
- S4 raises → error appended + S2 stands (existing behavior).
- The one-line `complete_list = s4` replacement is deleted; `complete_list = embed_list` remains the fallback base.

### D7 — Observable no-drop proof
`stats["s4_merge"]` records `{s2_items, s4_items, merged_items, corrected_by_s4, kept_from_s2, added_by_s4}` on the result. `kept_from_s2` is the live-run counter for the E4 property ("N S2 items S4 didn't re-emit were preserved"), feeding M7's self-explanatory report. Additive stats key only — no interface change (⛔ Conditional gate: stats keys are not a graph/capture contract).

### Step 1 — Add `merge_embed_lists` + `_merge_key` + `_s4_merge_stats` (near `run_s4`, after `render_s4_prompt`)

```python
def _merge_key(section: str, item: dict) -> tuple:
    """E4 identity key for embed-list reconciliation (S2 ∪ S4)."""
    if section == "entities":
        return ("entity", _norm(item.get("name")), _norm_kind(item.get("kind")))
    if section in ("events", "points"):
        return (section, _norm(item.get("content")))
    if section == "operators":
        te = item.get("target_edge") or {}
        return ("op", _norm(item.get("src")), _norm(item.get("dst")),
                _norm(str(item.get("op_type"))),
                _norm(te.get("src")), _norm(te.get("dst")),
                _norm(str(te.get("op_type"))))
    if section == "chain_notes":
        return ("chain", _norm(item.get("chain")), _norm(item.get("finding")))
    if section == "link_before_create":
        return ("lbc", _norm(item.get("searched_for")), bool(item.get("found")))
    return (section, json.dumps(item, sort_keys=True, default=str))


def merge_embed_lists(s2: dict, s4: dict) -> dict:
    """Programmatic union of the S2 and S4 embed lists (E4 — merges-not-replaces).

    S4 is the gap reviewer: on identity-key collision its (graph-informed)
    version wins; S2 items S4 omitted are PRESERVED (no silent drops); S4-only
    items append in S4 order. S2 order is preserved in place. Items pass
    through by reference — unknown fields ride through untouched (E1/E3).
    None sections and non-dict entries are tolerated (skipped).
    """
    sections = ("entities", "events", "points", "operators",
                "chain_notes", "link_before_create")
    out: dict = {}
    for section in sections:
        s2_items = [i for i in (s2.get(section) or []) if isinstance(i, dict)]
        s4_items = [i for i in (s4.get(section) or []) if isinstance(i, dict)]
        s4_by_key = {_merge_key(section, i): i for i in s4_items}
        merged: list[dict] = []
        seen: set = set()
        for item in s2_items:
            k = _merge_key(section, item)
            if k in seen:
                continue                      # S2-side duplicate — first wins
            seen.add(k)
            merged.append(s4_by_key.get(k, item))   # S4 wins on collision; S2 never dropped
        for item in s4_items:
            k = _merge_key(section, item)
            if k not in seen:
                seen.add(k)
                merged.append(item)           # S4 gap addition
        out[section] = merged
    return out


def _s4_merge_stats(s2: dict, s4: dict, merged: dict) -> dict:
    """E4 observability: prove 'no silent drops' in a live run (M7-adjacent)."""
    sections = ("entities", "events", "points", "operators")
    s2_n = sum(len(s2.get(s) or []) for s in sections)
    s4_n = sum(len(s4.get(s) or []) for s in sections)
    merged_n = sum(len(merged.get(s) or []) for s in sections)
    s4_keys = {_merge_key(s, i)
               for s in sections for i in (s4.get(s) or [])
               if isinstance(i, dict)}
    corrected = sum(1 for s in sections for i in (s2.get(s) or [])
                    if isinstance(i, dict) and _merge_key(s, i) in s4_keys)
    return {
        "s2_items": s2_n,
        "s4_items": s4_n,
        "merged_items": merged_n,
        "corrected_by_s4": corrected,
        "kept_from_s2": max(0, s2_n - corrected),   # no-silent-drop counter
        "added_by_s4": max(0, merged_n - s2_n),
    }
```

def _pt(content: str) -> dict:

class TestS4Merge:
    def test_s2_item_s4_dropped_survives(self):
        """E2E-5 core regression: an early-asserted S2 point S4 fails to
        re-emit must NOT be lost (complete_list=s4 dropped it pre-E4)."""
        s2 = {"entities": [], "events": [], "points": [
            _pt("my personal best 5K time is 27:12")],
            "operators": [], "chain_notes": [], "link_before_create": []}
        s4 = {"entities": [], "events": [], "points": [
            _pt("single-flash with granularity is the working path")],
            "operators": [], "chain_notes": [], "link_before_create": []}
        merged = v2.merge_embed_lists(s2, s4)
        contents = {p["content"] for p in merged["points"]}
        assert "my personal best 5K time is 27:12" in contents
        assert "single-flash with granularity is the working path" in contents

    def test_s4_correction_wins_on_conflict(self):
        """Same identity key in S2 and S4 → the reviewer's version (graph-
        informed lifecycle/supersedes) wins, and S4's name normalization
        matches S2's (case/space drift is identity, not a new item)."""
        s2 = {"entities": [{"name": "strategy-A", "kind": "core:plan",
                            "lifecycle": "created", "supersedes": None,
                            "note": None}], "events": [], "points": [],
              "operators": [], "chain_notes": [], "link_before_create": []}
        s4 = {"entities": [{"name": "Strategy A", "kind": "core:plan",
                            "lifecycle": "unchanged", "supersedes": None,
                            "note": "already in graph"}], "events": [],
              "points": [], "operators": [], "chain_notes": [],
              "link_before_create": []}
        merged = v2.merge_embed_lists(s2, s4)
        assert len(merged["entities"]) == 1
        assert merged["entities"][0]["lifecycle"] == "unchanged"
        assert merged["entities"][0]["name"] == "Strategy A"

    def test_identical_s4_is_identity(self):
        assert v2.merge_embed_lists(S2_FIXTURE, S2_FIXTURE) == S2_FIXTURE

    def test_empty_s4_returns_s2(self):
        assert v2.merge_embed_lists(S2_FIXTURE, {}) == S2_FIXTURE

    def test_gap_items_appended_after_s2(self):
        def ent(name):
            return {"name": name, "kind": "core:plan", "lifecycle": "created",
                    "supersedes": None, "note": None}
        s2 = {"entities": [ent("A")], "events": [], "points": [],
              "operators": [], "chain_notes": [], "link_before_create": []}
        s4 = {"entities": [ent("B")], "events": [], "points": [],
              "operators": [], "chain_notes": [], "link_before_create": []}
        merged = v2.merge_embed_lists(s2, s4)
        assert [e["name"] for e in merged["entities"]] == ["A", "B"]

    def test_operator_dedup_includes_target_edge(self):
        """Two MITIGATES with identical src/dst but different target edges are
        distinct; a re-emitted operator with the SAME edge collapses (S4's
        strength wins)."""
        op1 = {"src": "p", "dst": "e", "op_type": "MITIGATES",
               "target_edge": {"src": "p", "dst": "e", "op_type": "IMPL"},
               "strength": 0.3}
        op2 = {"src": "p", "dst": "e", "op_type": "MITIGATES",
               "target_edge": {"src": "p", "dst": "e", "op_type": "NAND"},
               "strength": 0.5}
        s2 = {"entities": [], "events": [], "points": [],
              "operators": [op1], "chain_notes": [], "link_before_create": []}
        s4 = {"entities": [], "events": [], "points": [],
              "operators": [op1, op2], "chain_notes": [], "link_before_create": []}
        merged = v2.merge_embed_lists(s2, s4)
        assert len(merged["operators"]) == 2          # op1 collapsed, op2 added
        assert any(o["strength"] == 0.3 for o in merged["operators"])

    def test_none_sections_and_non_dict_entries_skipped(self):
        s2 = {"entities": None, "events": [{"content": "E"}], "points": [],
              "operators": None, "chain_notes": [], "link_before_create": []}
        s4 = {"entities": [None, {"name": "X", "kind": "core:plan",

        assert [e["name"] for e in merged["entities"]] == ["X"]

## 5. ⛔ CONDITIONAL GATE notes

**Gate: open — no ontology, architecture, or interface change in the base plan.** The merge is pure pipeline logic inside `extractor_v2.py`. Explicitly NOT introduced: new kinds, new edge types, new point/event/entity properties, new capture/commit fields, new endpoints, new modules.

Conditions that would open the gate and require a design update *before* merge:

1. **E1/E3 add NEW TOP-LEVEL sections to the embed-list OUTPUT_CONTRACT** (not item fields). Item fields (`when`, `quote`, `search_keys`, `source_turn_id`) pass through by reference (D4) — no gate. But a new top-level array (e.g., a future `entities2`/`events_timeline` section) must be added to the `sections` tuple in both `merge_embed_lists` and `_s4_merge_stats`. Current epic data model (04-plan §4) adds only properties — gate expected to stay closed; verify against E1/E3 PRs.
2. **Any consumer of `result["s2_embed"]` starts treating it as the embed source of truth.** `s2_embed` remains raw-S2 for the owner loop only; the merged list is authoritative. If a downstream (E7 consolidation, capture response) began reading `s2_embed`, that is a bug — flag immediately.
3. **S4's prompt contract changes its "re-emit corrected S2" instruction** (e.g., S4 stops receiving the S2 list). Then the identity-key collision rule (S4-wins) has no basis and the merge must be revisited. Epic does not plan this; gate expected to stay closed.

No migration, no RLS, no `.env` change, no CI change. `uv run pytest` is the only verification surface.

## 6. Open questions

1. **Content-rewrite drift (non-matching key):** if S4's correction *rewrites an item's content* (not just lifecycle/supersedes) so its identity key no longer matches S2's original, both survive the merge and S5 may create two points/events if neither matches the existing graph. The base design accepts this (S4's instruction is to correct lifecycle/supersedes, not rewrite content; S5's graph-side dedup absorbs the common case). **Deferred:** a token-overlap near-match (reusing `_token_overlap`) to collapse such pairs — out of micro scope, revisit if the 50-Q pilot shows duplicate-point drift from S4.
2. **Warn vs. stats on intentional omission:** S4 omits S2 items routinely when the graph already has them (prompt: "do NOT re-create"). The plan records `kept_from_s2` in stats only — no warning — to avoid noise. Confirm the owner prefers no warning for this (an `s4_merge` warning would fire on most sessions).
3. **Operator `strength` policy on collapse:** when S4 re-emits an operator with the same identity key but a different `strength`, S4's value wins (D2). Reasonable — S4 sees graph context — but confirm no case wants "keep the *more conservative* strength". Current plan: S4 wins, documented.
4. **Order of `corrected_by_s4` semantics in stats:** it counts identity-key collisions regardless of whether S4's version actually differs in any field. A pure re-emission (S4 echoes an S2 item unchanged) is counted as "corrected". Cheap and conservative; note in the M7 report gloss if precision is wanted later.
