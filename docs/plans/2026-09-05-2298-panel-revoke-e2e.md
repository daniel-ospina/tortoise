# #2298 — Two-team behavioral e2e leg for graphs-panel key revoke (revokePanelKey)

> Level: task (fallback from complexity:standard — single atomic deliverable, no decomposition)
> Pipeline: task-workflow-standard discipline via project-workflow routing (unfielded issue → complexity fallback).
> Status: scope + plan (combined gate, issue #2298)

## Problem

`revokePanelKey` (main.jsx, #2274 per-graph keys panel) pins `?team_id=` on its
DELETE **statically** (#2230 fix; guarded by the `keyTeamPinsTripwire` unit test
only). No behavioral multi-team e2e proves the panel revoke targets the
SELECTED team: the F10 leg (`test_keys_table_mixed.py::test_two_team_key_writes_pin_selected_team`)
covers the API-Keys-tab writes (revokeKey/renameKey/toggleKeyEnabled) only.
Gap: a multi-membership user whose selected team ≠ first membership revoking
from the per-graph key panel. Without the pin the server session lane resolves
memberships[0] → 403 "Not your API key"; with it the revoke must succeed.

## Verified facts (research stage)

- `revokePanelKey` (main.jsx:3783) builds `const q = (sessionTokenRef.current && _teamAtCall) ? '?team_id=...' : ''`
  and calls `api('/v1/team/keys/${keyId}${q}', {method:'DELETE', useSession:true})`. Pin exists; no src change needed.
- `keyTeamPinsTripwire.test.js` statically pins the `${q}` presence (187-unit suite, must stay green).
- Panel DOM (main.jsx:6261+): `.graph-key-panel`; rows have `Revoke` buttons
  (aria-label `Revoke key <prefix>`); empty state = "No keys for this graph yet — mint one above (shown once)."
- Panel closes on team switch (`switchTeam` → `setPanelGraphId(null)`); `revokePanelKey`
  captures `_teamAtCall` + guards `teamIdRef` after await → no UI-expressible stale-team delete.
  ⇒ The wrong-team negative is a harness/server-contract probe (mock DELETE resolves under the
  pinned team; key not under that team → 403 "Not your API key" — the server's fail-closed detail).
- Data flow: `loadGraphs(teamId)` = GET `/v1/graphs?team_id=`; `graphKeysFor(teamId, gid)` =
  GET `/v1/team/keys?team_id=&graph_id=`; revoke is a SOFT revoke — the server stamps
  `revoked_at` and list reads re-render the row revoked/terminal (never-minted graphs only
  show the empty state; same contract as the sibling single-team panel leg).
- Existing suites are the wiring reference: F10 two-team per-team resolution pattern
  (`test_keys_table_mixed.py`), graphs-tab + panel interactions (`test_graphs_management.py`).

## Test design — `test_two_team_graphs_panel_revoke_pins_selected_team`

Self-contained route handler (F10 pattern) with per-team state:
- teams `[Alpha (team_a, first membership), Bravo (team_b)]`, both role owner.
- GET `/v1/graphs?team_id=` → per-team graphs: Alpha = [default, g_alpha("alpha")],
  Bravo = [default, g_beta("beta")] (custom rows carry Keys).
- GET `/v1/team/keys` (+ optional `graph_id`) → per-team bucket, graph-filtered.
- DELETE `/v1/team/keys/{id}` → resolve the key under the **pinned** team
  (`team_id` param; absent → first membership team_a, mirroring the server's
  memberships[0] resolution). Key present → stamp `revoked_at` + 200 (SOFT
  revoke — the row stays and the panel refresh re-renders it
  revoked/terminal, matching `test_per_graph_key_panel_lists_mints_and_revokes`
  and the real server). Key absent under the resolved team → **403
  {"detail": "Not your API key"}** (server fail-closed twin).
- Zero-mint tripwire (POST /v1/session/key loud 500) + zero `Bearer tt_` requests (session-only posture).

Flow + assertions:
1. Boot shell (cookie session) → Alpha (memberships[0]) selected.
2. Account menu → Bravo; expect the switch read to pin `team_id=team_b`.
3. Open the Graphs tab → Bravo's graphs only (default + beta); Alpha's "alpha"
   row never renders (per-team truth).
4. Wrong-pin negatives (session-shaped probes via in-page fetch — the real
   `revokePanelKey` DELETE rides the session JWT; the probe replays it with only
   the pin diverging, BEFORE the UI delete — both must 403 and mutate nothing):
   - DELETE Bravo's key with NO pin (the exact pre-#2230 panel shape — server
     resolves memberships[0]=Alpha → 403 "Not your API key") ⇒ 403, Bravo's key intact.
   - DELETE Alpha's key pinned `?team_id=team_b` (wrong-team pin) ⇒ 403, Alpha's key intact.
5. Panel revoke on Bravo (owner): Keys on beta row → panel lists Bravo's key →
   confirm (dialog names the row) → DELETE must carry `team_id=team_b` and return
   200 → panel refresh re-lists the row stamped revoked_at → renders
   revoked/terminal (dim, no Revoke button); the never-minted empty state does NOT
   appear.
6. Terminal assertions: Bravo's key stamped revoked_at (row retained; Alpha's
   key untouched, still active); exactly one 200 delete and it pinned team_b;
   zero session-key POSTs; zero key-authed requests.

## Risks / mitigations

- CORS on in-page probe fetches to `https://api.premiselabs.co/**`: existing suites already read
  cross-origin mocked API responses via page.route fulfill (no preflight observed) — probes use the same path.
- Locator ambiguity after the panel opens (a second table in the tab): scope rows to the panel before/after open.
- Flake: all stateful waits use expect(...) with timeouts; dialog handler registered before click (native confirm).
