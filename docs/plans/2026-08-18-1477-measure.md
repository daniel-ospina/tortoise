# CI Timing Measurement Artifact (#1477)

## 1. Problem Statement

`python-ci.yml` runs pytest with `--durations=15` — in-test time only. The post-exit
teardown and the setup/install/cache/pre-cache steps are unmeasured; the #798/#964
history shows they dominate the suite (45–55 min total, watchdog kills at 30/40/46 m
boundaries). There is **no committed, diffable record** of step-level CI timing, so
speed regressions are invisible across merges and every future CI change is judged by
intuition. This plan adds a measurement artifact only — **no behavior change to any
gate** (`python-ci-gate`, per-job timeouts, pytest flags all stay identical).

## 2. Confirmed Problem

No persistent, diffable record of CI step-level timing (checkout / install / cache /
pre-cache / teardown) or flake signal. `--durations=15` covers only in-test time.

## 3. Proposed Solution

**Approach A2 (chosen):** non-gating artifact upload in `python-ci.yml` + a new
`ci-timing.yml` workflow that samples the **latest completed push-to-main Python CI
run** and refreshes committed `docs/ci-timing.md` + `docs/ci-timing.json` on a weekly
schedule / on demand.

```
python-ci.yml (test / test-slow / test-concurrency-falkor / test-track-b jobs)
  └─ NEW: upload /tmp/pytest.log (trackb.log) as pytest-log-<job>[-<half>] artifact
       if: always() · continue-on-error · if-no-files-found: ignore  ← never reds the gate

ci-timing.yml (NEW, schedule weekly + workflow_dispatch)
  measure job:
    1. find latest Python CI run: gh api …/actions/workflows/python-ci.yml/runs
       ?event=push&branch=main&status=completed&exclude_pull_requests=true
       → first with conclusion ∈ {success, failure} (skip cancelled)
    2. actions/download-artifact@v4: pattern pytest-log-* @ run-id (continue-on-error)
    3. python3 tools/ci_timing.py --run-id … :
       a. Jobs API → real per-step durations (steps[].started_at/completed_at)
       b. parse --durations=15 section per log → per-file aggregates
       c. parse summary counts + FAILED/ERROR nodeids → outcome + flake signal
       d. merge with committed history (bounded 52 rows) → candidate flakes
       e. write docs/ci-timing.md (provenance header + tables) + docs/ci-timing.json
    4. upload ci-timing artifacts (md + json)
  refresh job (if: schedule || workflow_dispatch):
    1. download ci-timing artifact from measure
    2. git diff vs origin/main → no change ⇒ exit 0 (zero bot spam)
    3. changed ⇒ push branch chore/ci-timing-refresh-<sha> + gh pr create
       (auto-merge per repo policy; PR-based = branch-protection safe)
```

### Design decisions (with rationale)

| Decision | Choice | Why |
|---|---|---|
| Commit mechanism | Scheduled **PR**, not direct push / per-push bot commit | No main spam; branch protection (`python-ci-gate` required) can't block a PR; auto-merge repo policy; zero PRs when data unchanged |
| Step timing source | **Jobs API** `steps[].started_at/completed_at` on the real run | Measures the ACTUAL checkout/install/cache/pre-cache/pytest/teardown — not a synthetic mirror run (A3 rejected) |
| Run sampling | latest completed `event=push&branch=main` run, prefer success, skip cancelled | Comparable full-matrix data each week; PR smoke runs and nightlies excluded (they'd be non-comparable) |
| Per-file durations | aggregate `--durations=15` slowest tests per job, grouped by file | Exactly what the issue asks (from `/tmp/pytest.log`); **documented bias**: top-15 per job only, mid-slow files invisible, red runs truncated by `--maxfail=20` |
| Flake signal | bounded history (52 rows) of run-level outcome + per-run FAILED/ERROR nodeid lists | Consecutive-run failure-list diff → candidate flakes (pass→fail→pass). Documented **proxy** — per-test rerun-based flake becomes exact when the retry protocol lands |
| Artifact safety | unique names `pytest-log-<job>[-<half>]`, `if: always()`, `continue-on-error`, `if-no-files-found: ignore` | Upload steps added to a required gate can never red it (P1 fix) |
| Token scopes | workflow `permissions: actions: read`; refresh job `contents: write` + `pull-requests: write` | Minimal — no default broad token (P2 fix) |

### Rejected alternatives

- **A1 — bot-commit on every main push** (issue's literal example): spams main; fights
  branch protection + auto-merge queue on every merge. *Better when:* per-merge freshness
  is worth commit noise on a high-velocity main.
- **A3 — standalone mirror-measure job** (re-runs install/cache to time its own steps):
  measures a synthetic second run; inferior data, wasted compute. *Better when:* the Jobs
  API is unavailable.
- **A4 — parse the run's step-log tail** (zero python-ci.yml changes): the step log only
  echoes a 300-line tail — the full `--durations` section lives in the artifact; SIGKILL
  truncation differs; artifact upload is deterministic. *Better when:* modifying
  `python-ci.yml` is politically impossible.

## 4. Implementation Steps

1. `python-ci.yml` — add one upload step per log-producing job (after the run step, before
   the guards): `test` → `pytest-log-test-${{ matrix.half }}`, `test-slow` →
   `pytest-log-test-slow`, `test-concurrency-falkor` → `pytest-log-test-concurrency-falkor`,
   `test-track-b` → `pytest-log-test-trackb` (path `/tmp/trackb.log`). All
   `if: always()`, `continue-on-error: true`, `if-no-files-found: ignore`, 90-day retention.
2. `tools/ci_timing.py` (stdlib-only; subprocess → `gh api`):
   - args: `--run-id`, `--repo`, `--logs-dir`, `--out-dir`, `--max-history` (52)
   - Jobs API: per-step `started_at`/`completed_at` → `duration_ms`; skip steps missing
     `completed_at` (cancelled mid-step)
   - log parser: durations block (`^(\d+\.\d+)s (call|setup|teardown)\s+(\S+)`),
     summary counts (`= N passed…` variants), per-test outcomes (`nodeid PASSED|FAILED|…`)
   - output: deterministic (sorted, stable JSON); md + json; provenance header
     (run_id, sha, created_at, sample_time, event filter, schema_version)
3. `ci-timing.yml` — new workflow per §3; refresh job creates a PR only on content change.
4. `tests/test_ci_timing.py` — canned fixture log + fake `gh` (PATH-stub): durations
   parsing, summary parsing, per-file aggregation, history bounding, no-diff behavior.
   Pre-commit hook auto-registers it in `config/ci-surfaces.yml` (#1429).
5. `docs/ci-timing.md` — initial committed snapshot (generated by the script from a
   fixture, committed once so the refresh PRs have a stable base).
6. `docs/00_index.md` — add `docs/ci-timing.md` row.

## 5. Acceptance Criteria

- [ ] `python-ci-gate` check name, job ids, and pytest flags are byte-identical pre/post
      change (no behavior change to gates)
- [ ] Upload steps: `if: always()` + `continue-on-error` + `if-no-files-found: ignore`,
      unique artifact names — a missing log (early-exit path, cancelled run) can never
      red the gate
- [ ] `tools/ci_timing.py` regenerates md+json from a canned fixture with zero network
      (fake `gh` stub) — covered by `tests/test_ci_timing.py`
- [ ] Red-run and missing-`completed_at` paths handled (recorded with conclusion marker;
      cancelled steps excluded)
- [ ] `docs/ci-timing.md` front matter passes `scripts/check-doc-affiliation.cjs`
- [ ] Workflow YAML parses (`python3 -c "import yaml…"`); `bash -n` clean on run blocks
- [ ] Flake candidates appear in md once history spans ≥ 2 runs

## 6. Testing Strategy

| Layer | Test |
|---|---|
| Unit (fixture) | `tests/test_ci_timing.py` — durations + summary parsing, file aggregation, history bounding, deterministic output |
| Syntax | `python3 -m py_compile tools/ci_timing.py tests/test_ci_timing.py`; `bash -n`; YAML parse |
| Docs | `node scripts/check-doc-affiliation.cjs --files docs/ci-timing.md docs/plans/2026-08-18-1477-measure.md` |
| CI (PR) | tier-1 smoke + matched surface (tools/ + tests/ change); `python-ci-gate` must stay green |

## 7. Runtime Prerequisites

- `gh` CLI pre-installed on ubuntu-latest runners (standard image) with default
  `GITHUB_TOKEN` (`actions: read`).
- `tools/ci_timing.py` stdlib-only (Python 3.12).
- Artifacts retained 90 days (default) — weekly sampling is safe; if the sampled run's
  artifacts are gone, the measure job continues with step-timing-only data and records a
  missing-log note.

## 8. Acceptance / Verification Plan

1. Local: fixture test green; script deterministic (two runs → identical output).
2. PR CI: `python-ci-gate` green; new `tests/test_ci_timing.py` runs on matched surface.
3. Post-merge: `workflow_dispatch` a `ci-timing.yml` run; confirm it finds a completed
   push-main run, downloads artifacts, and the refresh job opens a PR only if the
   committed file changed.
