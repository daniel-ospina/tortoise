# E2 — State-Value Tier-A Extraction (verbatim value retention, value-filter carve-out) Implementation Plan

> **For Pi:** Use `executing-plans` to implement this plan task-by-task.

**Goal:** The KU needle — "my personal best 5K time is 27:12" — survives extraction **verbatim** (value in the point `content` + `quote`, never compressed by the "counts-are-noise" filter), via a Tier-A classification **hint** driven by a master-list user-personal-state vocabulary (personal bests, schedules, preferences) — **no new kind, no per-type pipeline**.

**Team:** epistemic-team
**Issue:** #1534 (E2) · **Parent epic:** #1509 (03-scope E2; 04-plan §4 Data Model Research Notes) · **Test alignment:** E2E-5 · **Test-design ref:** #1515 surfaces 15 (pipeline state), 17 (consolidation)
**Tier:** standard (complexity:standard) · **Dependencies:** E1 #1533 (already in lane before E2), E3 #1535 (already in lane before E2) — neither is implemented by this plan.

**Architecture:** Three coordinated additions to the existing S1–S5 extractor — (1) a **master-list section** (`USER_PERSONAL_STATE`) rendered into S1/S2/S4 prompt context, (2) a **value-filter carve-out + Tier-A classification rule** in the S2/S4 templates + `OUTPUT_CONTRACT` (`tier`, `quote` on points), and (3) a **deterministic S5 pass-through** that writes the Tier-A marker + verbatim `quote` into the Layer-1 payload and through the hosted ingest path. The Tier-A marker is a **classification hint** (Hindsight-validated: extraction-selection guidance only) — it must never become a kind, a per-tier retrieval pipeline, or a per-tier store. Owner invariant honored: extraction **never replaces verbatim evidence** — nothing deletes or mutates the raw transcript; Tier-A verbatim values coexist with it.

## Design Decisions

### D1 — Tier-A = classification hint on the point, not a kind and not a pipeline
The epic's Data Model Research Notes (Hindsight arXiv 2512.12818; EverMemOS; redhat memory-hub survey) resolve the design: the Tier-A marker's value is **(a) extraction-selection guidance** (the value-filter carve-out: don't strip "27:12") and **(b) the verbatim value lives IN the text** (via `quote` + verbatim content). Per-type retrieval (Hindsight) and per-type backends (EverMemOS) are the flagged over-engineering traps.
Consequences, enforced by tests:
- `pointKind` stays `"statement"` for Tier-A points — the marker is a property, never a kind.
- No retrieval code branches on `tier` — `search_graph`, `_derive_queries`, and the R-lane are untouched.
- The marker is **optional/absent by default**: `tier` is emitted on the payload point **only when "A"** (absence = Tier-B default). Zero-diff payloads for non-Tier-A sessions → Layer-1 validation, `client_commit_id`, and E5 supersession behavior are unaffected for existing content.

### D2 — Where the vocabulary lives: a master-list section, not the ontology packs
`build_master_list()` gains a `user_personal_state` section (`USER_PERSONAL_STATE` constant) with the three categories from the issue's review-gate fix — **personal bests, schedules, preferences** — each described as "the VALUE is the fact; retain it verbatim". Rationale:
- The packs (`packs/*/manifest.yaml`) are domain-scoped (dev, marketing, product-strategy, project-management); user-personal-state is cross-domain, user-centric memory. Editing packs = ontology content change = ⛔ gate territory. We do not touch them.
- The section is rendered into S2/S4 prompt context as the **operative criterion for the Tier-A hint** ("a fact matching one is Tier-A → a statement Point with tier:'A'"), with an explicit "these are NOT kinds — do not emit them as entity/event/point kinds" guard.
- `master_kind_forms` iterates a fixed section tuple — the new section cannot leak into the closed-kind set. A negative test locks this in.

### D3 — The value-filter carve-out lives in prompt text (S1 granularity + S2/S4 VALUE FILTER)
The "counts are noise" filter (dev pack granularity: "test counts, commit hashes … ephemeral"; S2 VALUE FILTER STRICT EXCLUSION) targets **process artifacts**. The carve-out is explicit prompt text distinguishing *mechanics tokens* from *state values*:
- **Mechanics tokens (drop):** issue ids, PR numbers, commit hashes, file paths, test counts *as process metrics*, commands, tool calls.
- **State values (keep verbatim):** personal-best times ("27:12"), schedule slots ("gym at 6pm"), preferences ("coffee not tea") — the value IS the fact; never strip/round/paraphrase/summarize.
- A shared constant `STATE_VALUE_CARVE_OUT` is appended to `_granularity_text()` (S1 sees it via its `{memory_granularity}` slot — S1's "RESTATE, DON'T REINVENT" rule then carries the value into the story) **and** to the granularity block inside `_render_master` (S2/S4 see it inside the master list).

### D4 — Verbatim retention = point `content` + `quote`, both model-carried, S5-passed-through
Two carriers, per the epic data model (`quote` is an existing, approved point field, ≤200 chars):
1. **`content`** keeps the exact value: "my personal best 5K time is 27:12", never "user has a fast 5K".
2. **`quote`** carries the verbatim source sentence (the S2/S4 prompt instructs: copy exactly from the story, ≤200 chars).
`execute_embed` currently hardcodes `"quote": ""` on every point — it becomes a pass-through of the embed list's `quote` (truncated to 200). **Fail-loud guard:** a Tier-A point with an empty `quote` produces a warning ("Tier-A point without verbatim quote") — never silent, never blocking (S5's never-block discipline).

### D5 — S4 must re-emit Tier-A points (merge-not-replace at the prompt layer)
E2E-5 asserts the early-asserted fact survives the S4 pass. E2 contributes the **prompt rule** — "a Tier-A state-value point from S2 is NEVER dropped; re-emit it" — plus the existing deterministic backstop (`extract_session_v2` already keeps S2 output when S4 returns an empty list). The general deterministic merge is **E4 #1536's** scope (implemented after E2 in the lane); E2 does not preempt it (Cross-lane 4).

### D6 — The marker must survive end-to-end: `commit_schema` registration + hosted ingest pass-through
`Point` in `commit_schema.py` is `extra="forbid"` — an unregistered `tier` field **fails Layer-1 validation** (the SDK `_commit_session_v2` path validates before POST). And the hosted ingest path (`hosted_api.py` commit reconcile) calls `sdk.create_point(...)` with **explicit kwargs** — `tier` is dropped unless passed. So E2 registers `tier` on the `Point` model (`Literal["A","B"] | None = None`) and threads `tier=pr.point.tier` through both `create_point` call sites. This implements the **approved** "Tier-A marker" field, not a new one — flagged in the Conditional-gate section for transparency. `client_commit_id` is content-addressed (point ids from content) — `tier` is not part of the canonical, so idempotency/parity are unaffected.

### D7 — No S2 input redesign
The issue checklist says "S2 classifies EDUs Tier A/B", but the implemented S2 maps the **compiled S1 story** (the narrative-first contract, design doc §2). E2 implements story-level classification whose statements carry EDU content — the verbatim guarantee comes from D1/D3 (S1 preserve-exactly + carve-out) + D4 (quote pass-through). EDU-granular classification would change S2's input contract and interact with E3's `source_turn_id` mapping — flagged in Open Questions (O1), not silently built.
