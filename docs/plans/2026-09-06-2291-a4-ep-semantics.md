## 0. Problem this plan solves

The A4 treatment arm today (battery/arms/a4_tortoise.py, 172 lines) is a **raw-Cypher mimicry** of the product, not a consumer of it: `setup_scenarios` → `batch_setup(proj, ..., namespaced=True)` drives raw `MERGE` through `FalkorProjection`; `retrieve` runs a bespoke `g.query("MATCH ... LIMIT 20")` with `confidence=None` always; `record` hand-writes `MERGE` point + operator + edge statements with a fresh `LIMIT 5` target pick and a `weight=0.3` mitigation that the engine never reads (annotation-only, #2315). Every R1–R5 metric that touches A4 therefore measures a mock — the differential compares product vs nothing. #2291 swaps the verb channel to the REAL SDK surfaces (sdk.ingest for seeds with batch_id provenance; create_point/create_operator/mitigate/supersede for agent writes with targets from the retrieved closed set; recall_state/tortoise_fts_query/compute_confidence/recall_subgraph for reads) over the SAME #2284 Task-4 `seed_mode` content contract, makes ep_outcome honest (terminal table, never hardcoded), and makes loopy graphs constructible so R3 honest-UNDEC is reachable. Every genuine product gap found is FILED (never absorbed into the harness) — #2315 is the model.

**Falsification (any ⇒ unsolved):**
1. Raw Cypher remains in the real-run A4 write OR read path.
2. A bespoke (non-product) read surface feeds probe-consumed fields on the real path.
3. Seeds land without product-real EP state; the ARM ever passes `require_calibration=False` (product-internal capture-refresh calls are exempt — the ban binds the harness, not the product's own seams).
4. ep_outcome can read CONVERGED without a real engine `converged=True` + non-empty affected set.
5. lp-* loopy graph not constructible → honest-UNDEC unreachable.
6. No lane-matrix doc + enforcement (one access mode per lane).
7. Draft seeds/agent-writes make EP reads vacuous (#780) with no explicit promote step.
8. [cal] ep-variance row absent from thresholds.yaml (mechanism-liveness leg unbuildable).

## 1. Design invariants (binding)

- **One SDK per scenario, same handle for write and read; one file per scenario; db_path = root-dir semantics.** `TortoiseSDK(db_path=<per-scenario tmp DB file>, graph_name=<scenario namespace>, event_log_path=<per-scenario tmp events file>)` created at setup; retrieve/record resolve the scenario's handle. TOPOLOGY (IMPLEMENTED in Task 1 — deviation from the review's N-files pin, justified): the arm keeps ONE store FILE per run (namespace dir, `db_path` unchanged semantics — same as `arms_real`/`seeds` layouts) and opens ONE `TortoiseSDK` handle PER SCENARIO on that file with `graph_name=scenario_namespace(id)` bound at construction (one handle per scenario GRAPH; the SDK's same-process opened-set allows multiple handles on one embedded file — verified in sdk.py `_probe_embedded_busy`/`_mark_embedded_opened`). This satisfies the review's core demands — per-scenario handle isolation, no two writes from different modes, warm-guard visibility (stale pre-fix graphs stay on the SAME store the guard reads — review P1-3's vacuous-green risk is gone WITHOUT layout lockstep churn) — with strictly fewer moving parts than N files. `event_log_path` is PER-SCENARIO (never a shared append file — review P2-3). Redirect-immune: explicit `db_path` ignores `TORTOISE_DB_URI`; stores never touch `tortoise_test_matrix`; env stripped in fixtures. The reference lane's namespaced one-file-many-graphs layout is UNCHANGED (equivalence + warm-guard tests keep their locked lane identity).
- **The reference lane stays, read-only.** #2284 Task-4's hermetic batch raw-MERGE path (`battery/runner/setup.py` + `battery/testing/seeds.py`) remains for (a) the carve-out equivalence tests and (b) content-absence enforcement — NEVER on the real A4 path. Audit allowlists it by name only.
- **seed_mode content contract (Task 4 of #2284) preserved on the ingest channel:** contradiction scenarios seed claim_a + evidence ONLY; ¬A (claim_b / k-turn statement) NEVER pre-seeded — arrives in-context at turn k at run time; warm-store guard via a seeder-owned `seed_manifest` marker refuses a stale PRE-FIX graph in the same namespace (fail-closed BEFORE `batch_id` is minted), while a clean seed_mode graph re-setup accumulates (Task-10 stream default).
- **Seed calibration = baseline-stamped seed bundles + promote + EP compute.** The fail-closed gate (`compute_confidence` → `_ensure_calibrated` → `CalibrationError`) refuses ANY live evidence-kind point (claim_a seeds are `statement`) lacking `baseline_set` — so seeds MUST carry a calibration prop through the ingest/create path (review P1-1: create_point resolves `cred_prior`/credibility-ladder props → `baseline_set: true` even on drafts; alternatively Source-credibilityTier inheritance via `extractedFrom`). Task 2 acceptance names the exact prop after live-code confirmation and asserts the seeded subgraph is product-calibrated BEFORE promotion. Route: `sdk.ingest(bundle, granularity="bulk", promotion_policy="gated")` (baseline props on seed points) → `promote_point` on seed POINTS (operators ride; `promote_point` blocks operators) → product EP compute via `compute_confidence` over the seeded subgraph. Never `require_calibration=False`. Verify-at-scope ordering (Task 2): the verify test proves the route satisfies the gate on the embedded lane; a refuse with the baseline props correctly in place = genuine product gap → FILE (never flag-flip, never re-baseline the gap as expectation); a refuse from a missing/incorrect prop = plan bug → fix the prop, not the product.
- **#901 routing, engine-honored:** truth → NAND the finding (`create_operator("NAND", source, [target], direction="unidirectional")`); relevance → mitigate the OPERATOR (`mitigate_operator(id, reason, strength)`, clamp [0.10, 0.50], idempotent); supersede for replacement (`supersede_point`); `promote_source=True` on the arm's own edges (live sources — #780). Mitigation EP-effect is NOT asserted on claim-EP deltas (pre-registered; annotation-only per #2315).
- **Empty retrieved closed set ⇒ zero writes + honest no-op recorded** (locked regression: `claims[0]` dead by construction can never produce a write). **Closed set carries claims AND operators (review P1-3):** the read mapping surfaces operator ids from the read surface's attachments (recall_state `nands`/`arguments` op ids) as operator-kind `Memory` items so `mitigate_operator` targets resolve against the closed set — never a fresh store probe, never a content-derived guess for planted-graph operators.
- **ep_outcome terminal table (honest, decisive-only consumers):** `converged` (engine `converged=True` AND decisive derivation: `confidences` non-empty AND no vacuous diagnostic — empty `confidences`/vacuous `no_factors`-style run is NEVER decisive) | `non_converged` (engine `converged=False` after decide cap, non-loopy scenario) | `undec` (loopy `task_type` scenario whose decide loop hits the cap without convergence, OR engine diagnostic indicates non-convergence) | `contested` (per-claim variance over the affected set > [cal] ep-variance row — NON-DECISIVE BY CONSTRUCTION even when `converged=True`; numeric converged+variance retained — mechanism convergence ≠ decisiveness; episode-level reduction = MAX variance over the affected `confidences` set, rule pinned in Task 4) | `no-op` | `excluded`. **Disjointness tie-break (review P1-4):** a `(max_iter, converged=False)` run on a loopy-contested scenario reads `undec`, on a non-loopy scenario `non_converged` — scenario `task_type` decides; a repeated-run oscillation probe is the fallback if task_type is ambiguous. R3 ground truth = the non-decisive set {undec, contested} is never CONVERGED; consumers (Task-8 liveness, verify-at-scope, R3 scorer) read DECISIVE within-row outcomes only; verify-at-scope never validates [cal] rows against contested records. Affected-set derivation (review P2-5): decisive = `confidences` non-empty AND no vacuous diagnostic; never a private `_last_affected` read.
- **Decide cap:** `decide_cycles` arm-side per-episode counter, default cap 8; cap-hit ⇒ `non_converged`/`undec`, never forced CONVERGED.
- **thresholds.yaml [cal] ep-variance row** re-locked in this issue and passed EXPLICITLY as `variance_threshold` to the variance read — `tortoise/` defaults (0.04) untouched. Row read-only to #2284 Tasks 7/8 (they consume, never write).
- **Lane matrix documented + enforced** (Task 1): one access mode per lane; tests assert zero raw `proj.g.query` on the real path (allowlist = reference lane only); docker lane optional + code-identical (store-mode-only delta allowlist + lane-invariant assertion list).
- **ONTOLOGY unchanged.** Additive point props only (`seed: true`, `batch_id`, provenance tags, `ep_outcome`/`decide_cycles` in the log/read-out, never schema fields).
- **#2293 alignment:** event ordering owned by #2293; this arm's `event_log_path` is a correlation channel (per-run tmp), never a second write channel; event_ref ns:seq captured ns = graph_name.
