# Issue #1542 — R3: dense leg enabled (embedder in eval env, write-time point embeddings, vector strategy verified)

**Epic contract:** 03-scope R3 · **Test alignment:** E2E-1 · **Test-design:** #1515 surfaces 5 (sentence-transformers), 9 (vector index), 11 (FTS-vs-TFIDF dual stack / leg-mix) · **Dependencies:** P3 (#1531, rebase to origin/main + CI drift gate) · **Complexity:** standard · **Lane:** D (retrieval), **lands before R2 (#1541)**.

## Problem (confirmed)

1. **The eval env runs the dense leg silently degraded.** `tortoise/embeddings.py` `EmbeddingModel.get()` returns `None` when `sentence-transformers` is not installed (ImportError → `result["model"]=None` → None; also on >30s load timeout and during the 60s negative-cache cooldown). `sentence-transformers` lives in the `[embeddings]` optional extra (`pyproject.toml:42`, `>=3,<6`) — **`uv sync` does not install extras**. CI installs `.[test,embeddings]` and pre-caches the model (`python-ci.yml:256-311`), but the *eval env* (the machine running the 500-Q run via `python -m tools.longmem_eval.run`) is plain `uv sync` → embedder missing → every `create_point` writes no embedding and the vector strategy is skipped at query time.
2. **The skip is silent end-to-end.** In `tortoise_fts_query`, the query_vec block (worktree `sdk.py:9162-9172`) leaves `query_vec` as `None` when `EmbeddingModel.get()` is None → `degradation_chain` only submits the vector strategy `if strategies.get("vector") and query_vec` (`search_engine.py:764`) → the vector leg is dropped with no error, no report field, no warning beyond an `info` log. A published run cannot distinguish "dense leg measured" from "dense leg never ran". This is exactly surface 9's flag ("no embeddings → silent empty leg", #1515).
3. **Write-time embeddings exist but are unobserved.** `sdk.py create_point` (~1419-1430) already computes and stores the embedding: `compute_embedding(content)` → `SET n.embedding = vecf32($embedding)` — for *every* eval point (deterministic turn points, v2 extracted points, and raw verbatim transcript chunks — all go through `create_point`, see `ingest.py:117-150`, `ingest_v2.py:140-190`). Nothing in the eval measures whether embeddings actually landed. The evaluation writes ~hundreds of points per question and never checks coverage.
4. **No leg trace exists.** `retrieve.py` passes per-hit `match_source` through, but it is `"rrf"` whenever RRF fuses ≥2 strategies (the normal case), and `report.py` aggregates **nothing** about legs. Epic 04-plan line 140 states the E2E-1 precondition explicitly: *"per-leg contribution visible in the recorded leg-mix, never null (precondition: M7/R3 per-leg recording — the engine emits `rrf`/`tfidf` today)"*.

**MemDelta lesson (epic brief Tech Stack Research):** embedding choice is a ±6pp confound — keep it **fixed** across compared cells (all-MiniLM-L6-v2, the pinned model) and record its identity + version in the report methodology so a future swap is visible, not silent.

## Design decisions

### D1 — Eval env installs the pinned embedder; no new dependency

`sentence-transformers>=3,<6` + `scikit-learn>=1.0` are already declared (`[embeddings]` extra), already CI-verified, already baked into the hosted image (`Dockerfile.hosted`). R3 does **not** add or bump any dependency — the eval env runs the canonical install command, and the README documents it:

```bash
# eval env (repo root): dev tooling + the embeddings extra
uv sync --group dev --extra embeddings
# pre-download the 90MB model (first run downloads it on demand; pre-warm avoids a
# >30s cold-load during the run's first create_point)
uv run python -c "from sentence_transformers import SentenceTransformer; SentenceTransformer('all-MiniLM-L6-v2')"
```

Verification (must pass in the eval env):
```bash
uv run python -c "from tortoise.embeddings import EmbeddingModel; m = EmbeddingModel.get(load_timeout=600); assert m is not None; print('embedder OK')"
```

### D2 — Pre-flight embedder check: the dense leg can never silently degrade

`run.py` gains an embedder pre-flight (the first pre-flight in the harness; M2's provider ping is a separate lane and lands in the same startup block later). **Implementation base: origin/main post-P3 (#1531)** — the current `pr1467` checkout has a mangled `run.py` where `outcomes_to_report` is an empty stub (`reader_prompt_source` dead code); the restored `outcomes_to_report` (returning a live `build_report(...)`) sits on origin/main (`tools/longmem_eval/run.py:280` in the 1509-plans worktree). Confirm the R3 branch carries the restoration commits (882714a7, 2f7c3df8) before Task 2 — `test_outcomes_to_report_golden_shape` (`test_longmem_runner.py:86`) pins the live body and must run green first. `EmbeddingModel.get(load_timeout=...)` is called with a long timeout so the **first-ever cold download** succeeds instead of tripping the 30s request-path cap (same pattern as the hosted lifespan pre-warm).

- **The check verifies usability, not just loadability** — a loaded model can still be broken (corrupted HF cache, wrong-dimension model after a swap, encode-time OOM; `create_point` swallows `compute_embedding` exceptions and `tortoise_fts_query` swallows `encode` exceptions — see the query_vec block in `tortoise_fts_query`). After `get()` succeeds, the pre-flight runs **one probe encode** (`model.encode(["probe"])`) and asserts the output is a 384-dim vector. Probe failure → treated exactly like a missing embedder (`available=False`, `reason="encode_failed"` | `"dim_mismatch"`), so a run can never publish `vector_strategy="enabled"` with `embedding_coverage=0.0`.
- **Timeouts are mode-aware:** real (non-`--mock`) runs probe with `load_timeout=600` (cold-download window); `--mock` runs probe with a short `load_timeout=30` so an offline env without a cached model warns and continues in ~30s instead of stalling 10 minutes.
- **Real (non-`--mock`) run, embedder missing/broken → `SystemExit` with the exact remediation commands.** Refusing to start is cheaper than publishing a dense-less report.
- **`--mock` run, embedder missing/broken → loud warning, continue.** CI smoke stays runnable offline.
- The check returns a status dict `{model, sentence_transformers_version, available, reason}` that flows into the report methodology (D5), so even a degraded mock run records *why*. **Version lookup is guarded** — `importlib.metadata.version("sentence-transformers")` returns `null` (not an exception) when the extra is absent, so the status dict is well-formed in every env.
- Embedded-vs-real is unchanged: the eval still runs fresh per-question embedded graphs (`run.py:180`); the pre-flight gates the *embedder*, not the backend. The real-backend run protocol (surface 7) is out of lane (see Conditional-gate notes).

### D3 — Write-time embeddings verified + observable per question (`embedding_coverage`)

The write path already embeds (Problem 3) — R3 makes coverage measurable. `retrieve_for_question` gains one cheap aggregate query (it already runs a sibling count for evidence points in the same function):

```python
cov_rows = proj.g.query(
    "MATCH (p:Point) WHERE p.lme_question_id = $q "
    "RETURN count(p), count(p.embedding)",
    params={"q": qid}).result_set
total_pts, embedded_pts = cov_rows[0] if cov_rows else (0, 0)
embedding_coverage = (embedded_pts / total_pts) if total_pts else None
```

Recorded per question (`points_total`, `points_embedded`, `embedding_coverage`) in the outcome. In the fresh-graph protocol, every point for a question is written by this ingest, so coverage **is** write-time embedding coverage. Expected: `1.0` when the embedder is present; `0.0` (observable, never silent) when absent. A question with zero haystack sessions yields `embedding_coverage=None` (denominator zero) — pinned shape, not a crash.

**Checkpoint/resume compatibility (P1):** `outcomes_to_report`'s projection (worktree `run.py:280`; the `{k: o[k] ...}` literal) reads outcome keys strictly. Resuming a pre-R3 checkpoint (outcomes without the new keys) would `KeyError` at the final report build, after the whole run re-executed. The projection must read the new keys via `.get(k, default)` — `points_total`/`points_embedded`/`embedding_coverage` default `None`, `legs` default `[]` — so stale outcomes render (flagged as lacking data) instead of crashing. Semantics: a resumed run's `methodology.embedder` reflects the *current* pre-flight while resumed outcomes may carry no coverage/legs — recorded as `embedding_coverage: None`, visible, never silently mixed.

Note: transcript chunks >512 words embed only the first 512 words (`compute_embedding(max_tokens=512)`) — an accepted truncation for chunk-level semantic signal, not a blocker; the >512-word branch gets an explicit test (see Tests).

### D4 — Leg trace contract for the vector leg (E2E-1 "never null")

Adopt the exact contract R2's D5 (#1541) specifies, extended with R3's vector reasons. R3 **lands first** and defines/threads the plumbing; R2's step 7 becomes verify-only (the plumbing already exists) and R2 only enriches FTS-granular *scorer* detail (BM25) — see Cross-lane.

**Contract** — `tortoise_fts_query` gains a private, default-`None` kwarg `leg_trace: list[dict] | None` (the `_elevated_timeout_ms` pattern — default-off, zero behavior change for existing callers). Entries:

```python
{"leg": "fts" | "vector" | "structural" | "fallback",
 "ran": bool, "degraded": bool, "reason": str | None, "count": int}
```

- **`vector` reasons** (R3 extends R2's vocabulary with `no_embedder`/`encode_failed`/`no_embeddings`/`empty_results`): `None | "ok" | "no_embedder" | "encode_failed" | "no_embeddings" | "empty_results" | "breaker_open" | "index_missing" | "query_failed" | "timeout"`. **Pinned mapping (review-verified):** `{0-row result set with zero embedded points → "no_embeddings"}`, `{0-row result set with embedded points present → "empty_results"}`, `{malformed plain-list embedding node → "query_failed" (the vecf32 MATCH throws per-row)}`, `{driver exception → "query_failed"}`.
  - `no_embedder` — `tortoise_fts_query`'s query_vec block when `EmbeddingModel.get()` → None; the strategy is never submitted (`degradation_chain` guards on `query_vec`).
  - `encode_failed` — same block when `get()` returned a model but `model.encode(...)` raised (present-but-broken embedder — distinct from `no_embedder`; `tortoise_fts_query`'s query_vec block currently conflates both into `query_vec=None`).
  - `no_embeddings` — **explicit zero-row branch in `run_vector_query`'s success path**, not the exception-only catch at `search_engine.py:578` (an all-no-embedding graph returns `[]` *without raising* — the catch never fires for the real empty case; review P1). Implemented as: after the brute-force MATCH returns empty, run a cheap `count(p.embedding)` guard to distinguish `no_embeddings` from `empty_results`.
  - `breaker_open` — `search_engine.py:421`. `ok` — success path, `count = len(hits)`.
- **`fts` / `structural`** — recorded at the source (in the runner), **never reconstructed from the `results` dict in `degradation_chain`** — an absent strategy in `results` is indistinguishable from one that ran-and-returned-empty. R3 promotes the FTS index-missing catch (`run_fts_query`'s except block, `search_engine.py:364-372`) to `reason="index_missing"` (a two-line trace record alongside the existing log) so surface 11's owned negative ("fts skipped (no index)" vs "fts ran, no results") is truthful from R3 forward; `empty_results` for a clean zero-hit run.
- **`fallback`** — final entry when the whole chain fell through: `{"leg": "fallback", "degraded": True, "reason": "tfidf_snapshot" | "tfidf_legacy" | "no_fallback_applicable", "count": N}` — appended before **every** early return (`tfidf_snapshot` on the snapshot path, `tfidf_legacy` on the legacy `fallback_tfidf` path, `no_fallback_applicable` on the non-point `return []` path where no TF-IDF fallback runs). The shape rule "`reason` never null when `degraded` is true" holds for all branches.

**Threading (review P1 — data race):** `degradation_chain` runs strategies in a `ThreadPoolExecutor` under a 500ms collective deadline (`search_engine.py:759-779`); a cancelled-but-running worker thread can append to the shared list *after* `tortoise_fts_query` returned, mutating the outcome/checkpoint nondeterministically and potentially after the `fallback` entry. Therefore: runner threads record entries into a **per-strategy private list**; `degradation_chain` merges them in **fixed order (fts, vector, structural)** after `as_completed` returns — reading only `future.done()` futures via `result(timeout=0)` so the merge is **non-blocking** (a still-running worker is never joined past the deadline; on `TimeoutError` it is discarded and self-recorded as `reason="timeout", ran=True, degraded=True` — never absent). `tortoise_fts_query` appends the `fallback` entry last — **before every early return** (the snapshot TF-IDF path, the legacy `fallback_tfidf` path, and the non-point `return []` path all append it) — and returns a **snapshot copy** (`list(leg_trace)`) so late appends cannot mutate recorded outcomes. Per-hit `match_source` values stay unchanged (additive trace only). `tools/longmem_eval/retrieve.py` passes a list and surfaces it as `"legs"` in the per-question result (feeds M7 #1527's leg-mix report — surface 11 → 19/22).

### D5 — MemDelta pinning: embedder identity + vector status in report methodology

`build_report` gains an additive `embedder_status: dict | None = None` kwarg → `methodology["embedder"]` and `methodology["vector_strategy"]`. **The keys are ALWAYS emitted** — when `embedder_status` is omitted (programmatic `run_evaluation`/`outcomes_to_report` callers: existing tests, battery/parity, the capstone harness), the default is `methodology["embedder"] = {"model": "all-MiniLM-L6-v2", "sentence_transformers_version": null, "available": false, "reason": "not_checked"}` and `vector_strategy = "unavailable"` — a report can never be keyless about the dense leg. Recorded from the D2 pre-flight result. Any future run that swaps or drops the embedder is visible in the report before any accuracy comparison — the ±6pp confound stays controlled.

### D6 — Scope guardrails

- Vector-leg verification in this issue is against the **eval's current embedded path** (brute-force euclidean, the documented degradation). The HNSW-index path on real FalkorDB is covered by the existing `tests/test_hnsw_vector_index.py` and the run protocol's real-backend mode (surface 7/9 — out of lane). R3's write-time embeddings + pre-flight are the *precondition* that makes real-mode dense work.
- **No change to `create_point`'s optional-embedding contract.** Embeddings stay OPTIONAL in production (hosted pre-warm, deliberate degrade); the fail-fast guard lives in the *eval* pre-flight, not the SDK.
- **No new ontology.** `embedding` is an existing Point property (`docs/ONTOLOGY.md:318`). No kinds, edges, packs, or properties.
- Eval `--mock` and the existing test suite keep working without the embedder (skips/warns, never fails).
