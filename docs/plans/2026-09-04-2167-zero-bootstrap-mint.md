## 1. Problem statement

The hosted dashboard must have **zero automatic bootstrap-key mint paths**: all four `mintSessionKey('bootstrap')` callers — login mount (post-#2211 L2699), switchTeam (L3591), switchTeam 401 re-mint (L3610), revokeKey re-mint (L4208) — are removed together with the now-dead mintSessionKey machinery (post-#2211 L2292) and its dead mint-failure / mint-dependent UX copy (L2761 banner, L5694–5697 "the dashboard re-keys once a key can be minted" clause). The endpoint (`POST /v1/session/key`, bootstrap+recovery), selfhost/registry lane, key-login/claim/anon (`authMode 'apikey'` — no session JWT exists there) surfaces, and durable user flows (welcome A13 reveal, keys-tab create, regenerate, recover, #2211 wizard connect) keep their intent. In their place the browser holds **only deliberate durable keys**: the mount stored-key probe becomes an explicit 5a–f branch table (adopt-valid / drop-revoked-disabled / keep-suspended / keep-session-only-on-transient), switchTeam adopts a cached durable for the team or runs session-only, revokeKey clears slot-aware without re-minting, and every team-scoped read/write in session mode pins `?team_id=<selected>` with **no key header** (rule 1 api() merge L1152 + loadBackups L3866 + mintKey L918). Server behavior is unchanged (verified: session lane `_session_user_team` L1624 honors `?team_id=` with membership check + suspension 403 — zero server edits). **Indicator-3 closure (no drift to the stale original framing):** `fetchSessionDetail` / `GET /v1/sessions/{id}` needs NO change — LIVE + session-authed since #2002-W6 against a dual-auth endpoint; the issue body's "dead key-authed call" premise is obsolete, and "no live key-authed *product-data* call remains" holds at baseline modulo the mount-probe exemption. E2E fixtures that seeded the held key via mint mocks migrate to localStorage-seeded durables with zero-mint assertions.

**Steady-state invariant (post-classification):** While a Supabase session JWT is present: the dashboard never auto-mints, holds, sends, or embeds a bootstrap/expiring key; apiKey/apiKeyRef state never holds a revoked/dead key (incl. across regenerate); the apiKey state / teamKeysRef / localStorage KEY_STORAGE slot hold a DURABLE key only when one is deliberately held for the selected team; the slot NEVER holds `"undefined"`/`"null"`/a revoked/bootstrap key after the mount keys-list classification.
