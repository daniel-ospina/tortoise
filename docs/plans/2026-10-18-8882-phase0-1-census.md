# #8882 Phase 0 + Phase 1 — the snapshot, and what the census measured

**Issue:** `#8882` (P0-blocker) · **Predecessor:** PR #8897 (Phase 2 machinery: `tortoise/retype.py`)
**Instrument this adds:** `tortoise/graph_census.py` + `tools/graph_census.py` (Phase 1), DB-free
**This doc records:** Phase 0 (the snapshot) and Phase 1 (the census). Phases 3/4/5 (load, verify,
retire) are gated on the owner decisions at the end of this document.

> **Read this first — the premise is contradicted by the measurement.** The issue and its first
> correction comment describe the local graph as *hand-authored by agents, ~10,434 nodes, taken from
> the extractor*. Measured at HEAD it is **23,375 data nodes**, and **67.7% of them carry an
> extractor provenance pointer** — with sample content that is verbatim conversation transcript,
> chopped mid-sentence. The class of nodes that are *both typed and provenance-free* is **10**.
> This does not change the plan's mechanics (re-typing is still the fix for the flat-`:Point`
> defect), but it changes *what* is being ported, so it is an owner decision before Phase 3, not a
> footnote (Decision A below).

## Phase 1 — the measured census

```bash
.venv/bin/python tools/graph_census.py \
    --dump ~/.tortoise/backups/local-8882-phase0-20261018T002755Z.json \
    --samples 5 --out census.json
# nodes: 23375 · edges: 37458 · predicate keeps 5412 / drops 17963 (droppable 17963)
```

Two runs produce byte-identical output (`census_sha256` `443e62d6…` at the default cut) — the
evidence bar's "reproduces the same partition twice". The digest is a digest of the whole report,
so it moves when a reported KEY's meaning moves: `retains_topology` has been redefined twice since
this run — `kept_knowledge_edges > 0` → `severed_knowledge_edges == 0` → **`kept_knowledge_edges
== knowledge_edges`**, because an edge whose BOTH endpoints the predicate drops is in neither
`kept` nor `severed`, so the intermediate form reported "topology preserved" for a cut that
destroyed edges. The COUNTS below are unaffected (on this snapshot
`both_endpoints_dropped_edges` is 0 — every knowledge edge has an operator at one end), and only
the verdict column is restated under the tightened definition.

**Re-run at the review head (`a784e7d`), stated so the evidence bar is reproducible:** two runs
produce byte-identical output with `census_sha256` `76f4dc93711a7ab15f7f0ea62dc3e5e3e0c9a03d30d2d38d17b5b0283dd05afe`
at the default cut, over the same partition (`nodes 23375 · edges 37458 · keeps 5412 / drops 17963`,
same three warnings). The `443e62d6…` digest above belongs to the run that produced the COUNTS,
under the pre-fix verdict field — the redefinition moves the digest, never a count.

Provenance fields present: `provenanceSource` 19,929 · `authoredBy` 15,856 (every value `pi-agent`) ·
`extractedFrom` 15,822 · 448 distinct pointer values (all `YYYY-MM-DD-<hash>.md` capture files).
The `extracted` class is every node that carries a provenance pointer in EITHER form: the
`provenanceSource` / `extractedFrom` **property**, or an outgoing `extractedFrom` **edge**
(`classify_provenance` → `_pointer()`, which reads both). It is therefore not the edge set: the
property form is present on 19,929 nodes and the edge on 15,822, and the class measures 15,822 —
the 4,107-node difference is reconciled only by naming the class order: an `is_operator:true` node
is classified `operator` FIRST, so the count works out if **4,107 of the 5,412 operators** carry a
`provenanceSource` (19,929 = 15,822 + 4,107) — the unstated step the previous one-line definition
left out.

### The predicate, and its cost in EDGES

Knowledge edges (all types except the provenance pointer) total **21,636**: `INPUT` 10,814 · `NAND`
6,542 · `IMPL` 4,280. Every one of them has an operator at one end and a claim at the other.

| rules applied | keep | drop | kept edges | severed | retains topology (`kept == knowledge_edges`) |
|---|---:|---:|---:|---:|:--:|
| `extracted` | 7,553 | 15,822 | 5,192 / 21,636 | 16,444 | **no** |
| `untyped` | 21,244 | 2,131 | 16,452 / 21,636 | 5,184 | **no** |
| `fragment` | 19,226 | 4,149 | 18,380 / 21,636 | 3,256 | **no** |
| `duplicate` | 22,787 | 588 | 21,024 / 21,636 | 612 | **no** |
| **`isolated`** | **8,773** | **14,602** | **21,636 / 21,636** | **0** | **yes** |
| `untyped,fragment,isolated` | 7,586 | 15,789 | 14,072 / 21,636 | 7,564 | **no** |
| all five (default) | 5,412 | 17,963 | **0 / 21,636** | **21,636** | **NO** |

The verdict column reads `yes` only for a cut that keeps EVERY knowledge edge. It used to read
`kept_knowledge_edges > 0`, which stamped the `extracted` row — a cut that severs 16,444 of 21,636
knowledge edges — the same verdict as the `isolated` row that severs none; it then read
`severed_knowledge_edges == 0`, which counted only edges with exactly ONE dropped endpoint, so an
edge that lost BOTH endpoints made a cut read "preserved" with
`kept_knowledge_edge_fraction: 0.0`. The field is the column an owner picks a rule from, so it now
says what it means: `kept == total`. `kept_knowledge_edges`, `severed_knowledge_edges`,
`both_endpoints_dropped_edges` and `kept_knowledge_edge_fraction` carry the magnitudes. On this
snapshot `both_endpoints_dropped_edges` is 0 on every row (every knowledge edge has an operator at
one end, and operators are never droppable), so the column above is the pre-existing one.

**The single most important measurement in this document:** the all-five composite drops 17,963 nodes
and **severs every knowledge edge in the graph** — the 5,412 operators survive with nothing to point
at. A node-count report would have called that a clean 77% reduction. The instrument now refuses to
let it read that way: `predicate.topology.retains_topology == false` plus a warning naming the count.

And the cut that costs nothing: **`isolated` alone removes 14,602 nodes (62%) and severs ZERO edges** —
because a node with no knowledge edge is, by definition, not carrying any. That is the topology-free
cut, and it is the one a numeric predicate can defend without a judgement call about content.

The destructive rule is the **provenance** rule, not the size of the cut: dropping `extracted` removes
fewer nodes (15,822) than dropping `isolated` (14,602 — comparable) but severs 16,444 edges against 0.

### Warnings the census emitted

1. the default keep-set retains NONE of the 21,636 knowledge edges;
2. 21,636 knowledge edges have an endpoint the default predicate drops;
3. 447 node keys are shared by more than one node (2 distinct label sets).

## What this changes in the plan

1. **Phase 1's deliverable exists**: a field-based predicate, with counts, reproducing twice — and a
   cost model (edges severed) that a node count cannot express.
2. **The "noise" is not a tail.** The default cut drops 17,963 of the 17,963 non-operator nodes
   (100% — keep equals the 5,412 operators exactly) — and it is the claim population the operator
   topology depends on. Filtering is not the lever; re-modelling is.
3. **Phase 3's premise needs the owner again** (Decision A): if the asset is mostly extraction output,
   then re-typing it into Objects/Subjects/Events preserves extraction output in better-shaped labels,
   and "port what's useful" may mean something quite different from "port the graph".
4. **Phase 2 cannot run on this snapshot as it stands** (Decision C): 447 duplicate node keys mean a
   *total* decisions file cannot address those nodes — `retype.index_dump` refuses the dump. Measured,
   not assumed.

## Open owner decisions

- **A — Is the local graph still the source of truth?** Measured: 15,822 `extracted` + 2,131 `untyped`
  against 5,412 operators and **10** typed-and-provenance-free nodes. Options: (a) keep the plan as
  written and port it re-typed — the operators survive, the claims arrive re-typed but still
  transcript-shaped; (b) port only the **topology-preserving** keep-set (`isolated` cut, then
  re-type the 3,361 claims the operators actually reference); (c) re-affirm that the extractor
  output is noise and port only operator + referenced-claim structure, i.e. a curated subgraph
  rather than the graph. **Recommendation: (b)** — it is the only option whose keep-set is defined by
  the measurement rather than by taste, and it is the one the census can re-verify mechanically.
- **B — `vision` (94 nodes).** Keep as `:Point` for this pass, map it to an existing Object kind, or
  amend §5. Unchanged from the scoping; the count is now known. **Recommendation: keep as `:Point`.**
- **C — The 447 duplicate `:Source`/`Document` pairs.** A total decisions file cannot address them.
  Options: (a) dedupe the pairs offline before re-typing (one survivor per document, edges re-pointed
  — a mechanical merge the census can enumerate); (b) let `retype` address a node by
  `dump_id` alongside its key; (c) drop the duplicate `:Source` rows in the port. **Recommendation:
  (a)** — it is a real defect in the graph, it is enumerable from the snapshot, and fixing it during
  the port is cheaper than a second migration. Filed separately for the live write path.
- **D — whether Phase 4's verification bar is reachable at all** given that 76.8% of all nodes are
  extraction output; the fleet's real queries may be answerable from the 3,361 referenced claims plus
  the operator topology, which would make the port a *smaller* job than the issue assumes.
