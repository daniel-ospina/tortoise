# Epic Scope — #669 Control-Plane Consolidation into Supabase

**Date:** 2026-08-09 | **Stage:** epic-scope | **Parent:** #669 | **Inputs:** align (PROCEED), research v3 (converged)

## Scope Boundaries

### In Scope
1. **Supabase schema** (extend existing 0001–0004 + add `teams` + `api_keys`):
   - `teams` table — team-level props: id, name, tier, created_at, stripe_customer_id, subscription_id, backup_enabled, backup_latest_at, **backup_restored_at**, max_*, ops_allowance, graph_size_cap, email, onboarding_state (jsonb), github_token_enc (column-REVOKEd), github_org.
   - `api_keys` table — id, team_id FK, lookup_hash (SHA-256, unique index), key_prefix, created_via (provisioned|bootstrap|recovery), expires_at, revoked_at, **created_by (nullable — legacy keys predate it)**, created_at. Session keys land here.
   - **`apikey_verify` read paths (scope-mandate 2 — explicit):** long-lived provisioned key → `team_memberships.lookup_hash`; session/bootstrap/recovery keys → `api_keys.lookup_hash`; both indexed, both consulted by REST **and** MCP. Existing keys migrate with `created_via` NULL → `'provisioned'` default.
   - `team_memberships` extended — keeps the one-time-reveal `api_key` (column-REVOKEd, `reveal_api_key` RPC) + `key_hash`→`lookup_hash` migration; `role`, `status`, `invited_email`.
   - `invitations` table — id, team_id FK, lookup_hash (SHA-256 of raw token), **role (admin|member — carried from the invite to the accepted membership)**, **invited_by**, email, status, accepted_at, expires_at; **partial unique on pending (team_id, email)** (preserves the current `uq_team_invite_email` dedup).
   - `audit_events` stays (point `TORTOISE_AUDIT_DSN` at Supabase; GUC RLS policy already exists).
2. **Provisioning path rewrite** — Edge Function + `handle_new_user` trigger + `update_user_team` RPC + `reveal_api_key`: write teams/memberships/api_keys to Supabase (single home); emit `lookup_hash`; placeholder semantics reconciled.
3. **Auth flip** — `get_current_team` / `get_current_user` / `apikey_verify` (REST **and** MCP `TeamResolutionMiddleware`): resolve from Supabase (teams/memberships/api_keys) via indexed `lookup_hash`; tier/quota from `teams`.
4. **Backup seam (both directions)** — sweep enumerates from Supabase `teams`; `backup_latest_at` / `backup_restored_at` stamps write to `teams` in the same transaction.
5. **Invitations** — mint/accept/rescind via `invitations` + `lookup_hash`; `accept_invite` creates the real membership.
6. **Onboarding + email + GitHub connect** — onboarding_state/email read-patch from `teams`; github_token_enc in the column-protected table, `_github_index`/`github_status` read via the new path.
7. **Health endpoints** — `/health/security` reports the real lookup scheme; `/health/ready` probes Supabase.
8. **Cutover (single-deploy flip, owner decision v2 — 2026-08-09): the registry is DELETED in the flip, not frozen.** Zero users → nothing to preserve; rollback = redeploy (FalkorDB recreates an empty registry on demand; provisioning becomes the source of truth). Non-negotiables that remain: (1) pre-deploy tests on every flipped surface; (2) monitoring (#596) as the post-flip safety net for silent breaks. **Boundary locked: only the REGISTRY graphs are deleted — FalkorDB itself and the knowledge-graph data plane stay, and #596 backups keep protecting them.**
9. **Complete master-list writer inventory (review P1-1/P1-5)** — every writer either migrates to Supabase, is disabled at cutover, or is data-plane (stays):

| Writer | Fate |
|---|---|
| Edge Function `tenant-provision` (+ trigger + RPCs) | migrate → Supabase (item 2) |
| `/v1/register` | migrate (creates teams/keys via Supabase) |
| `/v1/agent/signup` (#663) | **migrate — identity decision required** (anon user_id violates `team_memberships.user_id uuid FK`): nullable `user_id` + identity column, or pending-row pattern; MUST be named (currently zero graph-write invariant would break on it) |
| `/v1/teams` + `sdk.team_create` | migrate (second team creation) |
| `/v1/session/key` | migrate (session keys → `api_keys`) |
| `/v1/internal/reconcile` | migrate (revoked_at expiry on `api_keys`) |
| `apps/graph-viz /api/provision` | migrate or disable at cutover |
| invite mint/accept/rescind | migrate (`invitations`) |
| github-callback | migrate (`teams.github_token_enc`) |
| backup stamps (`backup_latest_at`/`backup_restored_at`) | migrate (item 4) |
| demo / onboarding writers | migrate (teams/onboarding_state) |
10. **Tests** — pre-deploy gate suite + E2E proof (below).

### Out of Scope
- Knowledge graphs / data plane (points, operators, embeddings, vector search) — stays in FalkorDB.
- `analytics_events` — already Supabase, append-only, untouched.
- Usage metering / quota enforcement on data-plane operations — data-plane concern, stays.
- Stripe/billing/entitlement path (#296) — separate; schema has the columns, flow deferred.
- Team-sweep activation for beta (#655) — separate; enumeration seam now reads Supabase.
- GUC app-role RLS upgrade + per-user-JWT path — documented future options (decision 1), not built here.
- Registry retirement/removal — AFTER the flip is verified live (separate step).

### Boundary Rationale
The cut is "the master list and everything that reads/writes it" vs "the knowledge graphs and everything data-plane." Auth, provisioning, invitations, onboarding, backup metadata, and health all touch the master list → in scope together (no partial flips on security surfaces). Data-plane ops stay on FalkorDB (no reason to move them). Future RLS hardening is deferred deliberately — the honest benefit (constraints/transactions/PITR + defense-in-depth) ships now; the GUC upgrade lands when scale justifies it.

## High-Level E2E Test Cases

### E2E-1: Signup provisions the master list in Supabase only
**Given:** a new user signs up via Supabase Auth (email or Google/GitHub)
**When:** the auth hook + trigger + Edge Function run
**Then:** a `teams` row exists (RLS-visible), a `team_memberships` row exists with a pending one-time-reveal key, an `api_keys` row exists with a `lookup_hash`
**And:** the FalkorDB registry graph is NOT written (zero graph mutations)

### E2E-2: API-key auth resolves via instant lookup (REST and MCP)
**Given:** a provisioned team's API key
**When:** a REST call and an MCP tool call authenticate with it
**Then:** both resolve via the `lookup_hash` index (no scan), quota/tier come from `teams`
**And:** a revoked key is rejected on both paths
**And:** a bootstrap/recovery session key mints into `api_keys` (created_via, expires_at round-trip) and resolves via `api_keys.lookup_hash`

### E2E-3: Invitation flow works end-to-end
**Given:** an owner invites a user by email
**When:** the invite is minted, then accepted
**Then:** the invite verifies via `lookup_hash`, a real membership is created, the pending invite is consumed
**And:** a used/revoked invite cannot be re-accepted

### E2E-4: Backup sweep reads and stamps Supabase
**Given:** a team with knowledge-graph data
**When:** the hourly backup sweep runs
**Then:** the team is enumerated from Supabase `teams`, the archive is written to R2, and `teams.backup_latest_at` is stamped in Supabase
**And:** restore stamps `backup_restored_at` in Supabase

### E2E-5: Onboarding and GitHub connect survive the move
**Given:** a provisioned team in its onboarding state
**When:** onboarding state is read/patched and a GitHub connection is stored
**Then:** onboarding_state/email read-patch from `teams`; github_token_enc lands in the column-protected column; MCP github status/index read via the new path

### E2E-6: Welcome-page key reveal still works
**Given:** a freshly provisioned user on the welcome page
**When:** the page calls `reveal_api_key`
**Then:** the plaintext key is shown once and nulled; the API-key auth path accepts it

### E2E-7: Cutover flip is safe and reversible
**Given:** the pre-deploy gate — registry empty, Supabase contains only reconcilable placeholder rows (predicate: `team_id=''` / `key_hash='pending'`), test suite green on every flipped surface
**When:** the single-deploy flip lands
**Then:** all E2E-1..6 pass against production; the registry graph is deleted; knowledge-graph data plane + #596 backups untouched
**And:** if any test fails, rollback = redeploy prior; the registry auto-recreates empty (lossless at zero data)
**And (negative):** a registry-only key (absent from Supabase) returns 401 on REST and MCP paths — the registry no longer authenticates anything

### E2E-9: Audit events land in Supabase
**Given:** the migrated app with `TORTOISE_AUDIT_DSN` pointed at Supabase
**When:** a gated action executes (e.g., an API-key mint)
**Then:** an immutable `audit_events` row exists in Supabase with the GUC RLS policy intact

### E2E-8: Health reflects the new reality
**Given:** the migrated app
**When:** `/health/security` and `/health/ready` are queried
**Then:** security reports the SHA-256 lookup scheme; ready probes Supabase connectivity

## Source→Target Field Map (scope-mandate 1)
- Team (graph) → `teams` row (all fields; onboarding_state jsonb; github_token_enc column-REVOKEd).
- APIKey (graph) → `api_keys` row (lookup_hash = SHA-256(key); session keys `created_via=bootstrap|recovery` fold in).
- Membership (graph) → `team_memberships` row (user_id real UUID; invite placeholders eliminated — invites live in `invitations`).
- Invitation (graph) → `invitations` row (lookup_hash = SHA-256(token); partial unique on pending).
- Team.backup_latest_at / backup_restored_at → `teams` columns (same transaction as the backup/restore).
