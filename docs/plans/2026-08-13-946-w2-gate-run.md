# #946 Gate Run — Window #2 Rubric Validation (epic #909 THE GATE) Implementation Plan

> **For Pi:** Use `executing-plans` to implement this plan task-by-task.

**Goal:** Run the 2-window rubric validation gate on the #960 operational session with two independent OpenRouter judges, produce the GO/REVISE/NOT_GREEN decision with per-class agreement + min-signal, and post it to epic #909.

**Team:** epistemic-team
**Role:** product-implementer

**Architecture:** Window #2 = the #960 eval-metrics implementation session (65 turns, fully captured in `.tortoise/session-events/2026-08-12.jsonl`). Build an utterance-tagged transcript (1 turn = 1 EDU). Two independent OpenRouter judges (deepseek-v4-pro + qwen/qwen3.8-max — cross-vendor, temperature 0.0, max-tokens 8000) label it via the existing `tools/judge_harness.py`. Gate record written to `docs/drafts/`, verdict posted to epic #909 via REST.

### Pattern Research

> **Findings date:** 2026-08-13

**Bucket: LLM-judge agreement protocol (canonical).** Two independent raters + Cohen's κ + percent agreement reported together; κ is the chance-corrected reliability signal before deployment (arXiv 2406.12624, arXiv 2606.19544, Databricks Agent Evaluation blog, Galileo calibration guide). Applied: twin-judge design with per-class + nothing-verdict + PABAK cross-check in the gate record.

**Bucket: κ small-sample fragility (pitfalls).** N=25 single-window κ CI ≈ ±0.3; N≈65 CI ≈ ±0.15-0.25; imbalanced prevalence (process-heavy) depresses plain κ vs PABAK (PMC5712640 kappa paradox; PMC3900052). Applied: N, prevalence, κ CI, PABAK all recorded; NOT_GREEN at 0.50-0.60 = expand-labeling path (plan DE2E-1), not a red CI.

**Bucket: annotation contamination / anchoring (pitfalls).** Showing the model's labels before the human's own judgment biases review (human-in-the-loop rubber-stamp; criteria v1 §4 anchoring guard). Applied: transcript-first review order for the sample; adjudication happens after κ is locked; adjudicated labels marked "anchored, calibration-only, NOT gold".

> Bucket [Library docs lookup] skipped — the plan touches zero new third-party dependencies. The only registry change (qwen3.8-max) uses the existing `OpenRouterModel` adapter (in-repo precedent, used by the harness since PR #975); OpenRouter model IDs verified live via the catalog API during scoping.

**Step 4 (recovery policy — exit codes 0/1/2):**
- exit 2 = DEGENERATE (0 labels) → failed run; retry the model once.
- exit 1 = parse/model/network failure. Real failure modes: (a) truncation/reasoning budget → JSONDecodeError; (b) prose-wrapped JSON (`_strip_fences` only strips ``` fences; "Here is the JSON:" prefix fails); (c) miscounted labels (64/66) → `edu_index not in window` (66) hard error or `incomplete: true` (64, caught at Step 3 verification); (d) timeout (`adapter timeout=60`) or 401 (bad key). **To diagnose, temporarily instrument: wrap `model.complete(...)` in a short script that dumps the raw response to a file before `parse_labels` runs** — the harness prints only `raw[:200]` on parse errors and never emits the full raw response.
- Fixes per mode: (a) `--max-tokens 12000`; (b) re-run (stochasticity) or retry once; (c) re-run (judge should emit all 65; if persistent, record `incomplete` per fail-closed semantics); (d) verify key export + network, retry with backoff.

**Verdict composition rule (applies across Tasks 4-6):** the tool verdict (κ + nothing-verdict + min-signal) is PRIMARY. Owner acceptance ≥85% is NECESSARY but NOT SUFFICIENT: below 85% forces NOT_GREEN regardless of κ; ≥85% does NOT upgrade a tool NOT_GREEN/REVISE to GREEN.

**Step 3:** Compute the κ CI note (SE ≈ √(po(1-po)/N(1-pe)²)) and PABAK for the record.
