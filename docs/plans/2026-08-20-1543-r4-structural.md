# R4 — Structural Leg Wired (1-2 hop IMPL/NAND expansion, pass a kind) — Implementation Plan

> **For Pi:** Use `executing-plans` to implement this plan task-by-task.

**Goal:** Wire the structural retrieval leg in the LongMemEval read path: the eval passes a `kind` so `run_structural_query` stops returning `[]` (the graph is decorative in retrieval today), and text hits get 1-2 hop IMPL/NAND expansion so the graph acts as a recall amplifier (graphiti episode-mentions pattern).

**Team:** epistemic-team
**Role:** (not set)

**Architecture:** Two additive, default-off seams on the existing engine, activated by the eval:
1. **`structural_kind`** — a new keyword param on `TortoiseSDK.tortoise_fts_query` that flows *only* to the structural strategy (kind-scan) and deliberately does **not** trigger the existing post-retrieval kind filter. The eval's pool must mix kinds (turn points `event`, raw transcripts `session-transcript`, extracted points `statement` — the R1 union design); today's single `kind` param conflates "structural strategy kind" with "post-filter", so passing `kind="statement"` at the top level would silently drop the raw-chunk leg.
2. **`structural_hops`** — a new keyword param (default `0` = off) that, after `degradation_chain` returns, expands the FTS+vector hit ids over `[:IMPL|NAND*1..2]` edges and folds the neighbors into the `structural` strategy's ranked list (deduped). Folding keeps RRF fusion, `match_source`, and the E2E-1 leg vocabulary (`fts`/`vector`/`structural`/`tfidf`) unchanged — the expansion *is* the structural leg's contribution. Hop-1 neighbors score 1.0, hop-2 score 0.5 (the existing partial-match convention in `run_structural_query`).
3. The eval (`tools/longmem_eval/retrieve.py::hybrid_search`) passes `structural_kind=EXTRACTION_POINT_KIND` (`"statement"` — the v2 ingest's extracted-point kind) and `structural_hops=2` (owner: "could even be 2 steps").

No changes to `run_structural_query` itself — its no-filters gate is correct defensive behavior; the bug is that the caller never passed a kind.

## Design Decisions

### D1 — New `structural_kind` param on `tortoise_fts_query` (do NOT reuse `kind`)
`kind` today plays three roles: (1) the structural strategy's kind, (2) the post-retrieval kind filter (step 5 of `tortoise_fts_query`), (3) the full-scan trigger (`query=None, kind=X`). The eval needs role (1) without (2): its pool deliberately mixes `event` turn points, `session-transcript` raw chunks, and `statement` extracted points (R1 union). Passing `kind="statement"` top-level would filter out the raw-chunk leg and collapse session/turn recall. `structural_kind` (keyword-only, default `None`) flows *only* to `degradation_chain`'s existing `kind` argument (`struct_kind = structural_kind if structural_kind is not None else kind`) — the engine's `degradation_chain`/`run_structural_query` signatures are untouched. All legacy callers keep today's exact behavior.

### D2 — 1-2 hop IMPL/NAND expansion as a post-`degradation_chain` pass in the SDK, folded into `structural`
Expansion is *dependent* on text-leg results, so it cannot be a parallel strategy inside `degradation_chain` (which runs strategies concurrently). New engine function `expand_structural_hops(graph, seed_ids, ...)`; the SDK calls it after `degradation_chain` returns and folds the result (deduped) into `raw_results["structural"]`. Fold-in (rather than a 4th strategy key) keeps:
- `match_source` = `"rrf"` in fused mode (E2E-1's "never null" contract), and the E2E-1 leg vocabulary (fts/vector/structural/tfidf) unchanged,
- `SearchResult.scores.structural` populated (the SDK's score-copy loop reads `raw_results["structural"]`),
- the eval's future M7 leg-mix counts expansion as the structural leg's contribution.

The eval graph materializes IMPL/NAND edges operator-mediated (`(a)-[:IMPL]->(op {is_operator:true})-[:IMPL]->(b)`, per `ingest_v2`'s `create_operator`), with legacy direct `Point→Point` edges also possible (ONTOLOGY §3.1 note). A variable-length `-[:IMPL|NAND*1..2]-` pattern covers both: direct = 1 hop, via-operator = 2 hops. Hop-1 score 1.0, hop-2 score 0.5 — consistent with `run_structural_query`'s exact/partial-match convention.

### D3 — Expansion folds in the SDK, gated on `structural_hops > 0` (default 0)
Backward compatibility is the hard boundary: `structural_hops=0` (default) skips the expansion block entirely; production callers are byte-identical. The eval activates both seams. TF-IDF fallback (embedded mode with no FTS) returns *before* the expansion block, so degraded runs are unchanged.

### D4 — Eval passes `EXTRACTION_POINT_KIND` constant, single source of truth
The v2 ingest writes extracted points with hardcoded kind `"statement"` (`ingest_v2._write_payload`). Promote that literal to `EXTRACTION_POINT_KIND = "statement"` in `tools/longmem_eval/ingest.py`, used by both the writer (`ingest_v2`) and the reader (`retrieve.py::hybrid_search`). A drift here (write kind ≠ read kind) would silently re-introduce the empty structural leg — the exact failure R4 fixes.

### D5 — No `run_structural_query` change; the no-filters gate stays
`run_structural_query(graph, kind=None)` returning `[]` is correct — it's the "caller should use full-scan path instead" gate, and other surfaces (#1353 supersede-structure, full-scan kind queries) depend on the early return. The fix is the caller: pass a kind. This plan pins that contract in tests (already covered by `TestRunStructuralQuery::test_no_kind_returns_empty`).

```python
def expand_structural_hops(
    graph, seed_ids: list[str],
    *,
    max_hops: int = 2,
    limit: int = 40,
    excluded_statuses: tuple | None = None,
    timeout_ms: int = 500,
) -> list[tuple[str, float]]:
    """Expand seed point ids over IMPL/NAND edges (1-2 hops) — the
    graph-as-recall-amplifier pass (R4; graphiti episode-mentions pattern).

    A text hit (FTS/vector) seeds traversal of its epistemic neighborhood:
    hop-1 neighbors score 1.0, hop-2 neighbors 0.5 (the partial-match score
    convention from run_structural_query). The eval materializes IMPL/NAND
    edges operator-mediated (seed-[:IMPL]->op{is_operator:true}-[:IMPL]->peer,
    so seed→op→peer is exactly 2 hops); legacy direct Point→Point edges are
    1 hop. The variable-length pattern covers both.

    Shares the "structural" circuit breaker with run_structural_query (same
    leg). Terminal-status peers are excluded by default (#1391 posture);
    pass excluded_statuses=() to include them.
    """
    if not seed_ids:
        return []
    if not _breaker_allow("structural"):
        logger.warning("Structural circuit breaker OPEN — skipping hop expansion")
        return []
    try:
        start = time.monotonic()
        cypher = (
            "MATCH (seed:Point) WHERE seed.id IN $seeds "
            f"MATCH path = (seed)-[:IMPL|NAND*1..{max_hops}]-(n:Point) "
            "WHERE n.id <> seed.id AND n.is_operator <> true"
            + ("" if excluded_statuses == ()
               else f" AND {_exclude_status_clause('n', excluded_statuses or TERMINAL_EXCLUDED_STATUSES)}")
            + " WITH n, min(length(path)) AS hops "
            "RETURN n.id AS id, hops "
            "ORDER BY hops ASC "
            "LIMIT $limit"
        )
        rows = graph.query(
            cypher, params={"seeds": list(seed_ids), "limit": limit},
            timeout=timeout_ms,
        ).result_set
        elapsed = (time.monotonic() - start) * 1000
        if elapsed > timeout_ms:
            # same post-hoc latency warning posture as run_fts_query (#249)
            logger.warning(
                "Structural hop expansion exceeded timeout: %.0fms > %dms",
                elapsed, timeout_ms)
        results = [(row[0], 1.0 if int(row[1]) == 1 else 0.5) for row in rows]
        _breaker_record("structural", True)
        return results
    except Exception as e:
        msg = str(e).lower()
        if "index" in msg or "not found" in msg or "does not exist" in msg:
            logger.info("Structural hop expansion not available — skipping structural expansion")
            _breaker_record("structural", True)
        else:
            logger.warning("Structural hop expansion failed: %s", e)
            _breaker_record("structural", False)
        return []
```

## Conditional-gate Notes

⛔ **No ontology change required.** R4 reuses existing `IMPL`/`NAND` edges, the existing `pointKind` vocabulary, and the existing structural strategy — zero new kinds, edges, packs, or Point/SearchResult fields. The eval graph already materializes IMPL/NAND operators (`ingest_v2._write_payload`); R4 only *reads* them.

⛔ **Effectiveness depends on the extractor's operator emission (S12, graph writes).** The expansion is a recall amplifier over whatever IMPL/NAND edges exist. If the V3 extractor emits few/no operators for a session, expansion contributes nothing for that session (kind-scan still contributes). This is a graph-write dependency owned by E2/E3/E5's write path, not a retrieval defect — document in the run report if the pilot shows near-zero operator counts.

If the extractor's pointKind ever becomes domain-configurable (`minted_kinds` from domain config — the extractor_v2 prompt path), the eval constant must follow or the structural leg silently re-empties. Flagged; not in scope (the eval uses the default path).

⛔ **No new fields, no migration.** Both SDK params are additive keyword-only arguments with default-off values; no schema, projection, or index changes. The `_expand_kind` pack-aware machinery is deliberately NOT applied to `structural_kind` (eval kinds are exact registry values; pack expansion is a production-surface concern outside this issue).
