# #5095 (L3) — S3's failure policy: stop asserting an identity the lookup never established

**Issue:** daniel-ospina/tortoise#5095 (lane L3, `extractor_v2.py` family) · **Base:** `b101355a8`
**Status:** plan v3 — revised after PLAN-VERIFY rounds 1 and 2 (both recorded in §9).

## 0. What this slice is, and what it is not — stated first, because the difference is the whole claim

**It is a record-truthfulness slice.** Today the run asserts, in the prompt and in the caller-visible
record, that it *looked* and found nothing, when in fact it never looked. After this change both say
*"not established"*, and the run reports how much is unresolved and why.

**It is NOT I1's enforcement, and I1 remains violated in the operative sense: duplicates are still
minted.** What changes is that the run stops *claiming* otherwise. §4.4's `HOLD` ("never mint it") needs
a *create* gate inside S5, and v1's attempt at that seam was measured wrong (§2 C, §9); it is named as
the next slice in §8, with the finding attached so it is not re-derived.

## 1. The confirmed problem

`docs/architecture/EXTRACTOR-V4-ARCHITECTURE.md` §4.4 declares invariant **I1** — *"An unresolved
identity is NEVER asserted `new`"* — and says of itself that it is *"a SPEC, not a description of what
runs"*. The shipped code asserts the **inverse** in two places:

**(a) the prompt.** `tortoise/extractor_v2.py:2950-2952`:

```python
    if search.get("degraded"):
        return (f"(graph search DEGRADED — {search.get('reason') or 'skipped'}; "
                "no existing items available; assume everything is new)")
```

`"no existing items available"` is a fact it never measured — a degraded lookup **did not run** — and the
second clause instructs the model to act on it. That instruction reaches S4 (`render_s4_prompt`, `:3293`;
`run_s4`, `:3308`), the pass whose job is to **complete** the candidate list.

**(b) the record.** `execute_embed` never reads the embed list's own `link_before_create`; it builds its
own (`:7369`) from `_index_search(search)` — empty on an unresolved lookup — and emits
`{"found": False, "note": "no match — created"}` for every created candidate (`:7417`, `:7538`, `:7806`).
This list is **result-level**: it reaches the caller (`sdk.py` passes it through), **not** the Layer-1
commit payload (`:8335-8370` has no such key). So the artefact that outlives the run states *"searched,
found nothing"* for a search that never happened.

**What "degraded" actually means here — measured, not assumed** (v1 of this plan got this wrong; the
verifier's measurement is reproduced in §9):

- `degraded: True` ⟹ **zero priors, always.** `_fts_rows` (`:2752`) materialises and returns a *list*,
  so a failure cannot leak rows mid-query, and the outer handler is reachable **only** through
  `if first: raise` (`:2923`), where `first` is cleared only after a query *completes* (`:2926`).
- **A later query failure is swallowed** (`except Exception: continue`, `:2918`) and the run returns
  `degraded: False` with a genuinely **partial** prior set, which `_render_search_results` then presents
  as the complete one. **This is the reachable incomplete shape**, and a trigger keyed on `degraded`
  alone cannot see it.

**The narrowest true claim:** for a given batch, either the lookup **ran to completion** or it did not —
and in the second case the run knows it did not. Nothing here infers more than that.

## 2. Alternatives considered

| # | alternative | why it loses |
|---|---|---|
| **A** | Fix the prose only, leave the record | The caller-visible `link_before_create` still asserts `found: false`. This was v1's defect; the verifier named it. |
| **B** | Make the run **fail** when S3 degrades | I2 forbids it in the same table: *"a failure never silently drops memory"*. Also breaks every deployment whose S3 is skipped by configuration. |
| **C** | Suppress the mint when the lookup is unresolved (v1's `TORTOISE_S3_HOLD` + `execute_embed({})`) | **Measured wrong.** `execute_embed` is the sole carrier for retractions (`_resolve_retraction(...)`, call at `:8301` — the same-session leg needs no graph lookup), supersessions and chain notes, so `{}` silently drops all three and the run would report none of it. The seam I1 needs is a **create gate inside S5** — its own slice (§8). |
| **D** | **Chosen — record the truth on both sides, and report the disposition; no write is suppressed, no flag is added** | Every artefact the run emits distinguishes *"looked, found nothing"* from *"never looked"*. Nothing is dropped, so nothing is lost; and nothing is gated, so a truthful record is not optional. |

**Why no flag:** nothing is suppressed. A flag around *"do not state a falsehood"* would make the truthful
record optional, which is the defect.

**Why the model contract is NOT widened (round-2 finding 5, and this is a scope cut):** an earlier draft
declared `found: true|false|null` in `OUTPUT_CONTRACT`, accepted it in `_validate_output_shape` and made
`_merge_key` tri-state. Round 2 showed the model's `link_before_create` is **discarded** by
`execute_embed` (§8 item 4), so that widening bought nothing observable. The prompt therefore instructs
the model to **omit** a `link_before_create` entry for a check that did not happen — an omission needs no
schema change — and the third state lives only in **our own** record, where it has a producer.

## 7. Implementation steps, each with the test that proves it

1. `tortoise/failure_policy.py` — `lookup_state(search)`, `lookup_note(search)`,
   `created_record(searched_for, *, query_ran)`, `IdentityDisposition` + `plan_identity(search,
   candidates)`. → unit tests: state polarity (degraded / `queries_failed` / `queries_truncated` / clean),
   counts, invariants.
2. `search_graph` reports `query_coverage` (derived/ran/failed per leg) + `query_results` (the keys that ran / failed), and `_candidate_query_text` becomes the ONE home for a candidate's query text (strip, then the leg's width). → test: a client whose 2nd query raises
   returns `degraded=False, queries_failed=1`, which `lookup_state` reads as **unresolved** (the shape v1
   could not see); a mutation that drops `queries_failed` from the trigger reds it.
3. `_render_search_results` delegates. → tests: no `assume everything is new`; states the lookup did not
   run / identity unresolved; still requires the candidates to be emitted; the healthy render is
   byte-identical.
4. `execute_embed`'s three create records use `created_record`. → tests: unresolved ⇒ `found is None` +
   the unresolved note; resolved-and-absent ⇒ `found is False` + `no match — created`.
5. `extract_session_v2`: disposition + warning + `identity` on **both** return paths. → integration tests
   with a fake model and `sdk=None` (degraded by construction), plus an empty-conversation test asserting
   the key is present.
6. Docs + registry + `config/ci-surfaces.yml` registration. → the two pin tests + `ci_selection
   --integrity`.

## 8. Remaining slices and findings, named (never deferred silently)

1. **The mint gate (I1's "never mint it").** A *create* gate inside S5 — not `execute_embed({})`, which
   also drops retractions/supersessions/chain notes (§2 C). The `identity` block this change adds is its
   input.
2. **The carry-forward store.** §4.4's `HOLD` set is *"carried forward for a later run"*; nothing
   persists it, and there is no store to persist it into.
3. **I3's single transaction** — `sdk.py`'s family (lane L8).
4. **Filed (`#10449`):** the capture receipt's `_capture_step_witness` (`sdk.py:6957-7029`) publishes
   `search.degraded` with the claim that it *"says an ATTEMPTED search failed rather than resolved"* —
   which §1 shows is false for the swallowed-query shape — and neither `queries_failed` nor `identity`
   reaches the SDK result (`sdk.py:12282-12295` forwards a fixed key list), so the count is an instrument
   for direct `extract_session_v2` callers (the eval harness) only.
5. **Filed (`#10448`, pre-existing):** the embed list's own `link_before_create` (the model's self-report) is
   discarded by `execute_embed`.
6. **Not taken:** registering a recoverable census class for S3 degradation (`report.py:76-90`).
