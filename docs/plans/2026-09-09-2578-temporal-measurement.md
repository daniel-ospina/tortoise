# Temporal-13 Baseline + Admission-Widening Ablation Implementation Plan — #2578 (measurement lane)

> **For Pi:** Use `executing-plans` to implement this plan task-by-task. This is a MEASUREMENT plan — the product is a committed per-question report + failure taxonomy + a pre-registered knob ablation with an honest gate output. It does NOT build the assembler (#2165 lane 2 does). Lane independence: nothing here depends on #2165's assembler merging; it measures the deterministic lane with existing knobs + a v2-lane structural probe.

**Goal:** Replace the unreproducible "temporal 0/13" claim with a committed, decision-grade measurement: a census-enumerated per-question baseline (133-Q temporal class) whose every miss is attributed to ADMISSION (gold evidence absent from the effective reader context) vs CONVERSION (gold present, pinned reader wrong/refused — tracked separately), plus a pre-registered admission-widening ablation (rerank pool 40→120, per-session cap 2→3, C2 evidence-boost ON, flood-controlled `tr_top_k` 12→16/20/24 WITH reader-refusal tracking and an R5 rollback guard) and a v2-lane structural probe — so #2165 lane 2's R3/R15 "(A-widened) vs (B)" comparison and the density→answer follow-up decision rest on measured admission facts, not an uncommitted synthesis.

**Team:** epistemic-team
**Architecture:** **Facts-in-loop, decisions out-of-loop.** The committed eval path (`tools/longmem_eval/run.py` per-question loop + outcome projection) gains exactly three additive, raw per-question FACTS — the gold-id admission set (`gold_admitted_ids`, computed at the reader call where `_ret["context_points"]` is live — the POST-`_assemble_context` budget-walk + item-cap + TR time-ascending-sort effective reader context, NEVER `_ret["hits"]` which is the untruncated deduped pool; predicate identical to retrieve.py:1326), the forwarded `pool_depth` rank-band diagnostic (already computed at retrieve.py:1433, currently dropped at the projection boundary), and a raw reader-refusal marker (same clause-scoped product-vocabulary classifier the measure module uses — single source of abstention vocabulary, imported read-only, never a second matcher) — plus a `tr_top_k` fingerprint fix (the one verified arm-contamination hole: `tr_top_k` is NOT in `_build_fingerprint` run.py:1213-1345, so a 12↔16 cross-arm resume would be silently accepted). NO verdicts in committed code, NO report.py change (byte-stable). The three facts attach under a NAMED opt-in env/flag (tri-state precedent: `evidence_boost` resolution run.py:3150 / `retrieval_budget_ms` conditional presence): OFF ⇒ zero new keys anywhere — default-arms reports byte-identical to pre-change HEAD; ON ⇒ facts attach + project. The measure driver sets it for every run it launches (baseline AND arms) so no arm ships fact-less. Classification, arm orchestration, pre-registration and aggregation live in a NEW measurement module `tools/longmem_eval/measure_temporal.py` that (a) loads the census, (b) derives the pinned 55-Q analysis subset, (c) writes a pre-registration record BEFORE any arm runs, (d) drives each arm as an in-process `run_main` invocation with its own `--work-dir` checkpoint (inheriting the fingerprint/checkpoint/watchdog gates wholesale — never re-implemented), (e) classifies every miss into ADMISSION / CONVERSION / (refusal subclass) from the committed facts, (f) writes the per-arm committed reports + a 2×2 attribution summary + the runbook gate output, and (g) hosts the v2-lane structural probe as a subcommand restricted to the 55-Q subset (ingest_v2 LLM-extractor cost ~40-61 sessions/Q — never run on 133). Reader constancy is enforced by the existing fingerprint + M5 methodology (reader_model_spec/prompt hash pinned; reader spec default `openrouter:deepseek/deepseek-v4-flash` reader.py:83; temp 0 max_tokens 500 at tortoise/reader.py:~300); the measure module additionally asserts identical reader spec + prompt hash across arm reports before any comparison.
