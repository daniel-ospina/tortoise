# Plan — #3860: make the delete-survivor anchor identity (kind + id), not bare id

**Issue:** #3860 — "durability: the #3696 delete-survivor anchor is id-keyed and
label-blind — 'a delete survives rebuild_all' currently holds for namespaced ids
ONLY"
**Branch:** `fix/3860-anchor-label`
**Base:** `origin/main` @ `4a7b7202e`
**Tier:** `standard` (task-workflow-standard; Level field absent → fail-closed)
**Domain:** adversarial (durability gate — the bypass class is "a delete is
silently suppressed, or a foreign-kind node is destroyed, on replay")

---

## Problem diamond

### Alternative framings (diverge)

1. **Anchor-only framing (the issue's).** The `EntityMutated` survivor anchor
   (`last_recreate_seq.get(bare_id)`, `tortoise/projection/__init__.py`) is
   label-blind, so a hoisted Point/Operator creation with id `X` suppresses a
   *legitimate* delete of a different-kind node with id `X`. Fix = key the
   anchor by `(label, id)`.
2. **Identity-throughout framing (chosen).** The anchor is one half of one
   identity question. The **fold** it guards (`_fold_entity_mutation` →
   `_delete_entity_by_id`) is itself id-wide across all six labels, so even with
   a label-correct anchor a delete can still *match a node it does not own*.
   The guarantee only becomes unconditional when identity is `(label, id)` at
   **both** the suppression gate and the fold. This is the issue's own
   "one notion of ownership, taken as a parameter" (task item 4).
3. **Namespace-the-guard framing (rejected).** Keep bare-id matching and
   tighten id *minting* so no two kinds share an id. Rejected: it pushes the
   invariant onto every producer (the exact #3354/#1884 "guard that matches a
   name" class the issue names), cannot constrain raw/legacy producers, and
   leaves the guarantee conditional.

### Confirmed problem definition

The delete-survives-replay guarantee is **id-keyed and label-blind at two
points** — the survivor anchor and the replay fold — so an id shared across
kinds lets a journal line for one kind suppress or destroy a node of another
kind, and "a delete survives `rebuild_all`" holds only while id producers
happen to be namespaced.

**Falsification:** a journal where a `PointAdded` re-creates id `X` after an
`EntityMutated(op=delete, id=X, label="Event")`, replayed via `rebuild_all`,
must leave the Event absent. Today the anchor suppresses the delete and the
Event resurrects.

## Solution diamond

### Approaches

| # | Approach | Tradeoffs |
|---|---|---|
| A | Key `last_recreate_seq` by `(label, id)` only; leave the fold id-wide | Smallest diff; still lets a delete destroy a foreign-kind node (over-delete) |
| B | Key the anchor by `(label, id)` **and** scope `_fold_entity_mutation` to the record's `label` | Identity is consistent end-to-end; also removes the P2-2 spurious fold-miss warning for multi-label deletes (each record now matches its own label) |
| C | Store the full identity in a new `EntityMutated` field scheme / new record types | Breaks the single-record+`op` contract #3299 deliberately chose; more surface, no extra safety |

### Converge — chosen: **B**

Outcome quality, not diff size: B is the only option under which *neither*
direction of the collision (suppression of a real delete, destruction of a
foreign node) is reachable. It preserves every #3696/#3299 behaviour because
the public SDK emits one record per matched label, so label-scoped replay
reproduces live exactly (a live multi-label delete emits N records → N
label-scoped folds). C is rejected as unnecessary surface; A leaves the
guarantee conditional in the other direction.

The one notion of ownership is a single helper key `(kind, id)` used by the
anchor, the point re-stamp sweep, and the annotator drop boundary.

### Backward compatibility

- Known canonical label (`Point`/`Subject`/`Object`/`Document`/`Source`/`Event`)
  → label-scoped delete. This is the whole #3299+ journal population.
- Missing/unknown label (only a malformed or pre-#3299-shaped raw record) →
  fall back to the existing id-wide delete. The fold can only *over*-delete
  there, never *under*-delete, so the "a delete must survive" guarantee is
  preserved for every record shape. The anchor fallback (`last_recreate_seq_any`)
  is byte-identical to the pre-change bare-id anchor, so a label-less
  delete→recreate Point behaves exactly as it did before — including the
  legacy suppression it always had (that is not a new under-delete, and it is
  pinned by the fallback test).

## Adversarial threat surface (#3860)

In-scope bypass classes (each must be covered by a test):

| # | Adversarial input | Required behaviour |
|---|---|---|
| T1 | `PointAdded(id=X)` **after** `EntityMutated(op=delete, id=X, label="<non-Point kind>")` (previously Point X existed, or not) | The delete must **fold** — the foreign-kind node is absent after `rebuild_all` (**no suppression**) |
| T2 | `EntityMutated(op=delete, id=X, label="A")` while a *different* kind `B` node with id `X` is live/replayed | Only `A:X` is deleted; `B:X` survives (`op=delete` matches only the node it owns — **no foreign destruction**) |
| T3 | Legitimate Point delete→recreate (`PointAdded(X) … delete(X) … PointAdded(X)`) | Delete **suppressed** — second incarnation survives (the #3696/#3299 behaviour) |
| T4 | `EntityMutated(op=delete, id=X, label="<non-Point kind>")` followed by a bare `PointAdded(X)` re-emit, with an earlier live-valid Point annotation | The foreign-kind delete must not advance the POINT annotator drop boundary; the annotation survives (`pending_deleted` is `(kind, id)`-keyed) |

Out of scope: nothing keyed by a bare `id` that can confuse kinds remains.
The #3947 roster (`_journal_hard_deleted_ids`) is ALSO kind-gated in this
change — it exempts a Point id only for `label in (Point, missing/unknown)`,
so a foreign-kind delete can no longer hide an unrecreatable episodic Point
from the pre-wipe invariant (that was a *fail-open* direction: an over-broad
exemption lets the guard permit the silent destruction it exists to refuse).

## Acceptance criteria

1. For every id shape the beta can produce, a deleted entity is absent after
   `rebuild_all` — asserted per label (Point/Subject/Object/Document/Source/
   Event), not once.
2. The negative control: a delete of kind A with id `X` does not suppress a
   live kind-B node with id `X`, and does not destroy it.
3. The guard's mutation is stated and shown to fail.
4. All 12 existing `#3299` tests stay green.
