# Issue #1623 — In-dashboard Billing page + signup plan-selection step: Implementation Plan

> **For Pi:** Use `executing-plans` to implement this plan task-by-task.

**Goal:** Users can see and manage their subscription from a proper Billing page inside the dashboard (current plan, limits/usage, plan options, upgrade + Stripe portal access) and get a lightweight non-blocking plan-selection step right after signup (free by default, no card).

**Architecture:** Restore + extend the `/v1/team` billing surface AND the three auth dict sources that feed it (`subscription_status`, `customer_email`, `checkout_price_id`, NEW `checkout_price_ids` map — all server-resolved from `STRIPE_PRICE_IDS` via `PriceCatalog.price_for`, never hardcoded in the client); add a `billing` tab to the dashboard React SPA (no router — `tab` state) that renders a current-plan card + plan grid from `product/pricing.json` bundled at build (vite JSON import); add a free-default, skippable "Choose your plan" section to the first-timer welcome card after the key reveal (with a `refreshTeam` fetch so paid Upgrade CTAs have price ids). Existing checkout/portal endpoints, session gating, and popup-block fallbacks are reused — no new endpoints, no new auth surface.

### Pattern Research

> **Findings date:** 2026-08-22
> **Gate skipped — plan touches zero third-party deps.** The dashboard uses its existing react/vite build (no new libraries); `product/pricing.json` is a repo file imported as JSON (vite-native, verified by the plan reviewer with an actual build — the outside-root import compiles and the JSON is inlined); the backend uses the existing `tortoise.billing.PriceCatalog` in-repo wrapper (used 2+ times). Prior research from the issue body + scoping doc is the source for the UX decisions (free-tier-first, portal-for-active-subscribers).
> **Note (plan reviewer P4):** the dashboard's build-time JSON import is TRUE single-source (better than product.html's hand-maintained `const PRICING = {...}` mirror at website/product.html:646, which exists precisely because it needs a parity test — tests/test_website_static.py). Do NOT copy the mirror approach here.

### Journey Test Map

### Journey: A new user signs up and picks a plan
1. **Step:** signup → welcome card provisioning → key revealed → "Choose your plan" step shows → **Acceptance:** free selected by default, paid tiers shown → **Test:** welcome plan-step e2e (Task 6)
2. **Step:** click "Start free" → **Acceptance:** lands in the dashboard (URL reset to `/`) → **Test:** welcome plan-step e2e
3. **Step:** click "Upgrade" on a paid card → **Acceptance:** POST /v1/billing/checkout with that tier's price_id → **Test:** welcome plan-step e2e (Task 6 — asserts the Pro Upgrade POSTs, not just the Start-free path)

### Journey: An existing user views and manages their plan
1. **Step:** open the Billing tab → **Acceptance:** current plan (tier, status, limits, usage bar) + plan grid render → **Test:** billing e2e (Task 5)
2. **Step:** click Upgrade on a paid plan (free, no subscription) → **Acceptance:** POST /v1/billing/checkout with the right price_id, popup opens → **Test:** billing e2e
3. **Step:** active subscriber clicks "Manage subscription" → **Acceptance:** POST /v1/billing/portal, popup opens → **Test:** billing e2e (second wiring with `subscription_status: active`)

### Failure Modes
- Metering unconfigured (`write_ops_limit` absent/0) → usage bar shows "—" → billing e2e free-tier mock
- No Stripe env (`checkout_price_ids` empty) → "See pricing" fallback link, no Upgrade buttons → backend degrade test
- Auth dict missing billing fields (drift) → None → "See pricing" fallback; never 500 → backend degrade tests + existing supabase_control drift tests stay green
- Popup blocked → error banner + 90s reset timer → existing Round-13/14/16 logic reused
- Returning user hits /welcome (`welcomeKey` empty) → no plan step → existing welcome e2e
- Welcome mode before `/v1/team` resolves (`team` null) → paid Upgrade buttons render as "See pricing" fallback until team arrives (P1-2 fix)

### UX Design Decisions

| # | Decision Type | User Choice | Rationale |
|---|---|---|---|
| 1 | Layout | Billing as a nav tab (`tab === 'billing'`), not a route | No router in the SPA; tabs are the established pattern (Overview/Keys/Graphs/Members) |
| 2 | Layout | Plan grid mirrors product.html pricing cards | Single pricing mental model across marketing + dashboard |
| 3 | Copy | "Choose your plan" step after key reveal, "Start free" primary | Free-tier-first research; non-blocking; skippable |
| 4 | Gating | Plan changes for active subscribers route through the Stripe portal | Checkout 409s on active subs by design; portal handles upgrade/downgrade/cancel |
| 5 | Affordance | Current tier shows a "Current plan" badge (disabled CTA) | No-op upgrade CTAs are a UX trap |
| 6 | Degrade | Paid Upgrade buttons fall back to "See pricing" when `checkout_price_ids` is empty | Mirrors the existing capNotice fallback; no dead CTAs |
