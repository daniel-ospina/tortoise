# Implementation plan — state, lifecycle and pipelines

**Design of record:** `docs/plans/2026-11-15-state-lifecycle-and-pipelines.md` · **Issue of record:** #11824 · **Tracker:** #11081

This is the *plan to build* the approved model. The design says what the model is; this says what changes, in what order, and what proves each change. The design's owner approval (2026-11-16, PR #12895) is the ruling that makes its reversals of earlier recorded positions stand — a lane landing S2–S5 depends on that ruling, not on its own reading of the code.

**Status: drafted, five review rounds on the text.** Both former conflicts are resolved (see §8), and resolving the **first** one **re-ordered the plan**: the write door is now S0, because every vocabulary change below is only safe once a word outside a kind's set can no longer land. The design text has **landed** (#12954, merged 2026-11-16T03:51:54Z). Do not dispatch a slice whose §4 gate is still open: the two rows marked **not gated yet** (the `status` write vocabulary, S0/S2–S4; the read-tool scope parameter, S6), the S5 `GOAL_STATE_VALUES` record, and the `ONTOLOGY.md` exact text.

**What is NOT true, and the plan must not assume:** there is **no Object status write vocabulary**. A shared `OBJECT_STATUS_VALUES` was explicitly **foreclosed** (`commit_ops.py:114-122`; `sdk.py:49406-49429` — *"ONE RULE, AND IT IS NOT A VOCABULARY"*, the guard asks the transition question only). Subject has `SUBJECT_STATUS_VALUES` (`commit_ops.py:123`); Point has `POINT_STATUS_VALUES` (`sdk.py:277`), which **omits `deprecated`** and has no `deprecated` entry in `_ALLOWED_TRANSITIONS` (`:4643-4657`).

## 1. Non-goals

- **No backfill, no migration, no compatibility shim.** A legacy word survives only as a **read delta** over stored rows — which is why the legacy `outdated` **flag** keeps being read (see §6).
- **No new public surface** except those named in §4, each gated there.
- **No `status` on `:Source`** until it has a writer and a reader (its own approval).
- **No general rule engine**; **no priority/importance design**.

## 2. Slices, in dependency order

### S0 — the write door validates the status

**Failure it prevents (live, and the reason every later slice is ordered behind it):** **any string can be written as an Object's or a pack kind's `status`.** The Point and Subject families already have a write-side guard (`sdk.py:15273` and `:49211` for Points, `:49879` and `:50451` for Subjects) — the Object family has no **vocabulary** guard: `commit_ops.py:114` says so plainly (*"The OBJECT family STILL has no write-side vocabulary guard"*), and the guard the Object arm *does* carry asks the **transition** question only (`sdk.py:49662-49665`, over `_OBJECT_TERMINAL_STATUSES`). S0 adds the vocabulary guard, and it runs **first**: a word that is not a lifecycle word for the kind cannot be a legible transition target, so the other order would let the transition guard answer for a word it never validated. `status` is not a server-managed prop, and `_update_entity` issues an unvalidated `SET n += $props`, so `tortoise_create_entity` / `tortoise_update_entity` accept `status='outdated'`, `'archived'` or `'garbage'` on an Object today. There is no `OBJECT_STATUS_VALUES` anywhere in `tortoise/`, only comments recording that it was considered and rejected (`sdk.py:49407`, `commit_ops.py:118`).

**Why it is first.** A filter set is correct when it covers every value the writes can produce. Today a write can produce `status='outdated'` on an Object, which is exactly why `assembly._RECALL_OBJECT_EXCLUDED_STATUSES` carries `outdated` (`assembly.py:4370-4381` says so in its own comment: *"Dropping the member would flip such a successor from recall-excluded … to a verified link"*). **Removing a value from a filter before removing it from the write path does not narrow the vocabulary — it moves the failure from the door to the reader.** So the door goes first, and every drop below is then a deletion of provably unreachable weight.

**Change:** give the Object/pack family the guard the other two families already have, and make its vocabulary **the words that family can legitimately hold today** — for a core Object the seven `ONTOLOGY.md` §4.3 lists (`draft`, `live`, `superseded`, `deprecated`, `archived`, `in_progress`, `completed`), for a pack kind its own declared `statuses`, and for a Point or Subject the sets they already declare. **Nothing is removed from any of those lists in this slice**, so no live writer is refused: the built-in connector folds that write `in_progress`/`completed` (`status_folds.py:82-88`) keep working, and a pack keeps its words until S3 moves them onto the position axis.

**The no-declaration case has to be stated, because most packs are in it:** five of the seven shipped packs declare **no** `statuses:` at all — `packs/dev` (twelve object kinds, the largest), `product-strategy` (nine), `marketing` (six), `project-management` (four) and `agent-ops` (one); only `venture` and `investment-portfolio-manager` declare a vocabulary. So "its own declared `statuses`" is an empty list for most kinds in the pack tree, and the fallback's population is **every Object kind that declares none** — which is exactly the population the built-in connector fold is guarded to (`projection/entities.py:5816-5817`, *"guarded to Objects whose kind declares NO lifecycle"*, enforced by the `NOT (kind IN $declared)` test above its write at `:6102`). ⚠️ `packs/dev` matters most here: its `issue` kind is `equivalentTo: pm:issue`, so it is what `github.issue.open`/`closed` actually folds onto — a lane that validated the fallback against `project-management` alone would miss it. Those kinds fall back to the seven core words — which is the same list the folds write, so the two rules agree. ⛔ **And the fold does not go through this door:** the one Object-status fold dispatcher (`_fold_object_status`, `projection/entities.py:5800`) projects through raw Cypher in **both** its halves — the pack-declared loop at `:5940` (`SET o.status = $status`) and the built-in connector fold (`status_folds.BUILTIN_CONNECTOR_FOLDS`, `status_folds.py:82-88`) at `projection/entities.py:6102` (`SET o.status=$status`) — never through `_update_entity`. So "the folds keep working" is true for a reason worth writing down — **the guard goes on the write door, and the projection path is left alone**. Move it onto the shared object writer instead and replay is the first thing it refuses, which is a decision, not an accident.

**Precedence, stated so the retired-word rows below cannot be read against a kind that still declares the word:** the **declared set wins**, and it is each kind's list **as it stands** — nothing narrows here. So a word a kind declares today is accepted verbatim at S0, and the shaping/refusing rows take effect **per word, when that word leaves that kind's list**: `retracted`/`outdated` on Points after S2; `archived` on Objects, **and on Points and Subjects**, at S4 — because S4 says `archived` leaves the write surface *everywhere*, and both `sdk.py:277` and `commit_ops.py:123` still carry it. At S0 those rows are the **target behaviour of the guard**, not S0's acceptance. Two consequences worth stating: `outdated` and `retracted` are **not** in the Object declared vocabulary (§4.3 says so), so on an Object they are already refused at S0 — which is why `assembly`'s `outdated` member is dead once this lands, and why the pinned test in this slice breaks; and a plain Object is **not** validated against the four-word base here, because `in_progress`/`completed` are §4.3's own declared Object words (`ONTOLOGY.md:449`) and callers do write them **through this door** (`hosted_api.py:13407` sets `props["status"] = body.status`, `:13414` passes it into `sdk.create_object`). The fold path is **not** the reason and must not be cited as one — it never reaches this door (⛔ above), so naming it would let an implementer read the fold route as a constraint on the door's word list.

⚠️ **Pinned test this slice deliberately breaks:** `tests/test_11926_derived_invalidation.py:310-313` writes `update_entity(..., status='outdated')` on an Object and reads it back — the pin `commit_ops.py:53-56` names as today's behaviour. It is updated in the same commit, with the reason, exactly as S2 handles its own pin. ⚠️ **And it is not the only write S0 refuses that a test relies on** (a census measured at this plan's head, not a generated one — a slice re-measures, exactly as it re-derives a line cite). `retracted`-on-an-Object, which row 4 refuses because `retracted` is not an Object word: `tests/test_11826_object_supersession_instrument.py:1063`, `:2815` and `:2737` (the `("operator", "retracted")` lane of that parametrize list). The object door's *"validates nothing"* premise, which S0 inverts: `tests/test_kind_guards_12060.py:1126` and `tests/test_kind_layer_partition_9964.py:215`, both writing `status="active"` — a `packs/venture` word, not one of the seven. Their fixtures move to a declared word, and the instrument's `'retracted'` message assertions move with them. ⛔ **Pick the replacement word per fixture, because the two groups need opposite things.** For the two `status="active"` fixtures it must be Object-legal **and** Subject-illegal, i.e. `in_progress`/`completed` — `live` there would invert `test_kind_guards_12060`'s own `SKIP_STATUS_NOT_LEGAL_ON_SUBJECT` assertion — and S3 removes those two words from the Object axis, so that fixture expires a second time. For the instrument's `retracted` fixtures (`tests/test_11826_object_supersession_instrument.py:1063`, `:2815`, `:2737`) the successor must instead stay **currency-excluded**, because the test's premise is a NON-LIVE successor: `in_progress` is absent from `TERMINAL_EXCLUDED_STATUSES` (`live.py:104-105`) and would make the successor current again. Use a terminal word there — `deprecated`, `superseded` or `archived`.

**The guard follows the AX principles (`docs/ax/ax-principles.md`), and its shape is already shipped in `tortoise/validity.py`** — `validate_validity_precision` and `read_caller_end` apply exactly this pattern, and their `END_WRITE_OUTCOMES = {"shaped": …, "refused": …}` is the counting device S0 copies. Four outcomes, in this order:

| the write | outcome | reporting |
|---|---|---|
| a **spelling** of a declared word — case, surrounding whitespace (`'LIVE'`, `' Live '`) | normalise to the declared word, proceed | **silent** — a receipt for a re-spelling asks the caller to re-express something we already understood (AX §1) |
| a **retired word with one legible meaning**, where **this kind's list used to carry it** — `retracted` (withdrawn, nothing replaced it) | shape it onto `deprecated`, proceed | **echoed in the reply** — supplying a meaning must be visible (AX §1) |
| a **retired word carrying more than one meaning**, where **this kind's list used to carry it** — `outdated` (ended, but who knows which kind) / `archived` (**three**: ended with no successor; ended with one; or not ended at all but hidden from a view) | **refuse**, third part naming every choice the word could have meant, **each with the word that writes it** | `outdated`: *"resubmit as `deprecated` (nothing replaced it) or `superseded` (name the successor)"*. `archived`: meaning 1 → **`deprecated`**; meaning 2 → **`superseded`** + its successor; meaning 3 needs no word at all. ⛔ **The successor is named by the FAMILY's mechanism, not one prop:** `supersededBy` is an Object and Subject field (§4.3 `ONTOLOGY.md:451`, §4.2 `:431`) and **no Point field declares it** — §4.1's table has none, and `supersede_point` records the successor as a `CORRECTS` edge (`sdk.py:24292`), which is why §7's Point verbs carry the successor as an argument (`invalidate_point(corrected_by_id=…)`). `outdated` is a Point word and `archived` is declared for **three** families — Points (`sdk.py:277`), Subjects (`commit_ops.py:123`, and `ONTOLOGY.md:430`) and Objects (`ONTOLOGY.md:449`) — so row 3 is exercised at all three doors and must name each door's own successor mechanism, not one prop — offering `supersededBy` there would name a prop nothing writes and nothing reads as a successor, i.e. the successor-less `superseded` ONTOLOGY §5 defines the state against. **Meaning 3's third part is:** *"if it has not ended and you only want it out of the way, write no `status`, because hiding is a reader filter set at read time"*. ⛔ Meaning 1 is the one that must not be left implicit: `ONTOLOGY.md` §4.3 defines `archived` itself as *"a retirement with no successor"*, so once the word goes that section owes an edit naming `deprecated` as its replacement — an S4 item, not an S0 one. AX §2: **never pick** a meaning for the caller — but every meaning here has a writable repair, so AX §5's admission test passes |
| **anything else** — including a **retired word this kind never carried** (`outdated`/`retracted` on an Object, which §4.3 excludes from that vocabulary), so rows 2–3 do not fire there and this row is what refuses them | **refuse**, third part naming the kind's declared words | *"`status` <?> is not a lifecycle word for a <kind> — it accepts <that kind's declared words>"* — the list is the **kind's own**, never a fixed four, or the repair would itself be refused on a pack kind. ⛔ No "another case is fine" reassurance here: row 1 already normalised case and surrounding whitespace, so anything reaching this row **is** the word, not its spelling, and telling the caller otherwise would name a retry that is refused again |

**The admission test (AX §5) is what makes this admissible:** every row above has a **writable third part** — the caller recovers by resubmitting a legal word or by choosing between two named ones. No row refuses where the fix cannot be written, and no row refuses on a spelling.

**Count the outcomes separately** — `STATUS_WRITE_OUTCOMES = {"normalised": …, "shaped": …, "refused-ambiguous": …, "refused-not-a-word": …}` — **one key per row**, because a silent re-spelling and a refusal are different facts, and so are the two refusals: row 3 refuses a word the kind used to accept and can offer the caller a choice, row 4 refuses a word this kind never had and can offer only the list. Flattening either pair is the AX §2 failure ("the reported state must not flatten different failures into one label").

**Acceptance:** `status='garbage'` is refused **on an Object and on a pack kind**, and the third part names **that kind's** declared words; `in_progress`/`completed` still write on an Object through the connector folds (and a pack kind that declares no `statuses` accepts the seven core words); `' Live '` is accepted without a receipt on every kind **that declares `live`** — not on every kind, because a pack Object kind declares only its own words (`packs/venture/manifest.yaml:107` is `[prospective, invested, active, written-off]`, and `sdk.py:49422-49423` records exactly that); each kind accepts exactly its declared list **as it stands today**; on an Object `outdated` and `retracted` are refused by row 4, never shaped; nothing is dropped from any filter here. The retired-word rows are **not** S0 acceptance: a Point still declares `retracted`/`outdated`/`archived` (`sdk.py:277`) and is correctly accepted verbatim until S2 narrows that set, and `archived` on an Object until S4.

### S1 — the predicate reads the position axis, and every consumer uses it

**Failure it prevents (live):** a row ended by a `terminal` stage or by `isClosed` is served as current, because the predicate reads only `status` + the legacy `outdated` flag — and **five** consumers do not use it at all: `mcp_server.py:4931` (tag arm, `!= "retracted"`, #12502), `hosted_api.py:13702`/`:13725`/`:13878`, `topic_summarization.py:231`/`:253`/`:289-290`, `sdk.py:37435` (`_hydrate_evidence` — a superseded claim's ghost votes in EP), and `derived_invalidation.py:381-386`, which answers currency itself and never reads `isClosed` or the terminal slot (`grep isClosed tortoise/derived_invalidation.py` → 0 hits).

**Change:** the Cypher twin reads the durable `isClosed` marker **or** a resolved stage in the `terminal` slot; the Python mirror gains the same input at its 22 call sites **plus the two reached through an alias** — `hosted_api.py:22720` imports `is_terminal_status as _is_terminal_status` and calls it at `:22766` / `:22779`, so the real population is **24**; an input added as a defaulted parameter leaves those two compiling while silently *not* supplying it, which is the exact `hosted_api` gap this slice exists to close. The five consumers are converted or declared as deltas.

**Acceptance:** an Object ended **by `isClosed` or a `terminal` slot while `status` is still `live`** is not served and its derived caches are treated as retired — that is the case no test covers today (the `status`-based case is already pinned by `tests/test_11926_derived_invalidation.py:238`). A slot reclassification cannot resurrect a closed Object (both `test_pipeline_2792` shapes). No converted module keeps a hand-written **currency** comparison — the criterion is scoped to currency deliberately, because `sdk.py` keeps two hand-written `status != "retracted"` filters inside `if include_superseded:` (`sdk.py:45298`, `:45724`) and those are the **#1391/#689 tombstone guard**, not a currency test: removing them would serve retracted rows under `include_superseded`. They are a declared delta, which is the shape S1 already uses for every consumer it does not convert.

### S2 — a Point can end, and stops ending five ways

**Failure it prevents:** `deprecated` **cannot be written on a Point** — missing from `POINT_STATUS_VALUES` (`sdk.py:277`), so the vocabulary gate raises before `_ALLOWED_TRANSITIONS` (`:4643-4657`) is consulted; and a Point can still be `retracted` and `outdated` through verbs, so one ending has five spellings.

**Change:** add `deprecated` to the Point write set **and** its transition entry; **remove `retracted` from `POINT_STATUS_VALUES` (`sdk.py:277`), from the `live` row of `_ALLOWED_TRANSITIONS` (`:4648`, `frozenset({"retracted", "superseded"})`), from the `draft` row (`:4647`, `frozenset({"live", "retracted", "superseded"})`) and from its own terminal entry (`:4649`, `frozenset()`), and remove `outdated` from `POINT_STATUS_VALUES` and from its own terminal entry (`:4655`, `"outdated": frozenset()`, the `#2498` shared-guard key)** — without that removal the slice's own acceptance is unreachable. ⛔ **All four carriers, not two:** leaving `retracted` in `:4647`/`:4649` leaves the transition map declaring `draft → retracted` for a word the write set no longer contains, and `tests/test_claim_lifecycle.py:211-220` asserts that key set **in both directions** (`"retracted" in _ALLOWED_TRANSITIONS but not in POINT_STATUS_VALUES`), so a literal two-carrier edit reddens it; `retract_point` (`sdk.py:24325`, takes no successor) targets `deprecated`. ⛔ **And `deprecated` must become a declared TARGET, not only a key:** the generic door's transition guard reads `_ALLOWED_TRANSITIONS.get(_stored)` and refuses any `_status` outside that set (`sdk.py:49298-49299`, raising at `:49344-49359`), so with only `deprecated`'s own row added, `update_entity(<live Point>, status='deprecated')` is refused — which makes S0's row 2 ("shape it onto `deprecated`, proceed") unimplementable at the door that shapes it, and leaves S5's precondition ("a Point goal cannot be `abandoned` until `deprecated` is writable on a Point") permanently false. ### S3 — pack words become pipeline stages

**Failure it prevents:** nine pack `statuses:` declarations, thirty distinct words, one overlapping the base set — and a `venture:investment` at `written-off` (`packs/venture/manifest.yaml:107`) is current to every reader because nothing declares that stage terminal; while `status_folds.py:215-219`/`:294` refuses a fold whose target is not a declared status, so the words cannot simply be deleted.

**Change:** a pack's `statuses:` list becomes that kind's **pipeline stage declaration**, each stage carrying a slot (including a `terminal` one); `folds[].status` targets move with it; the built-in connector folds (`status_folds.py:82-88`, targets `in_progress`/`completed`, writer `projection/entities.py:5800` `_fold_object_status`) move onto stages of a **declared core default pipeline** — this slice names the pipeline key, the stage ids, and which writer advances the stage instead of setting a status (`advance_stage(..., reopen=True)` for the reopening fold).

**Acceptance:** `written-off` is terminal **by slot**; a kind declaring stages without slots is refused at install; each built-in closing fold lands on a terminal stage the reopen path clears; the core default pipeline is named in this repo, not deferred.

## 7. The ending verbs, resolved (was: a design-doc correction)

The design's §3.1 maps **`invalidate` → `deprecated`**, but `invalidate_point` (`sdk.py:22569`) takes a **required** `corrected_by_id` and always writes `CORRECTS` — so by §3's own defining rule (*"`superseded` names its successor; if nothing replaced it, the word is `deprecated`"*) it is a supersede. Rather than patch one row, the verbs are now aligned on a single rule, and **`invalidate` is not a word-producing verb at all**: it names *our record* going out of date — the `expiredAt` bookkeeping `invalidate_point` and `supersede_point` write — which is exactly how W3C PROV splits it (`prov:Invalidation` ends the entity and says nothing about a replacement; `prov:wasRevisionOf` is a separate relation).

So: `retract_point` (no successor, `sdk.py:24325`) → `deprecated`; `invalidate_point` (required successor) → `superseded`; and **the rule, not the verb, picks the word**. The exact replacement text for §3.1 is recorded on #11824 (issuecomment-6906427754). Renaming `invalidate_point` is a surface change and is not proposed.

⚠️ **One gap this surfaced in today's code:** `invalidate_point` and `supersede_point` both stamp the dedicated expiry prop (`expiredAt`, `sdk.py:22694`, `:24283`), but **`retract_point` does not** — it writes `status`, the belief halves, `updatedAt = $now` and an optional `validTo` (`sdk.py:24456-24458`; the replay fold agrees, `projection/__init__.py:10256-10257`). So a retracted claim's ending instant survives **only in the generic `updatedAt`**, which any later write moves, rather than in the expiry prop the other two endings write (`sdk.py`'s own `:22617`: *"`expiredAt`/`updatedAt` record when the graph LEARNED of the end, not when the claim ended"*). S2 closes it: retraction stamps `expiredAt` like every other ending. Until then, "invalidation is the bookkeeping, not a word" describes the intended model rather than all of today's code.

## 8. The two former conflicts, and how each closed
