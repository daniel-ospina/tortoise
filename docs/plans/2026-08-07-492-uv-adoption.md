# Decision — #492: uv as canonical dev package manager

## Decision

**uv is the canonical dev package manager for this repo.** Local dev install/test/run flows use `uv sync` / `uv run`; the committed `uv.lock` is the dev-environment source of truth. pip remains only the published-package (PyPI consumers) and legacy CI path.

## Why

- uv was already the de-facto workflow (`.venv` created, `uv.lock` generated across multiple checkouts on 2026-08-07, tests run from the uv venv) but nothing documented or enforced it — `uv.lock` sat untracked and conventions drifted.
- `pyproject.toml` requires Python >=3.12; AGENTS.md still said 3.11+ with pip commands — the docs contradicted the runtime contract.
- A committed, CI-gated lockfile gives deterministic dev environments; `uv lock --check` prevents silent drift between `pyproject.toml` and `uv.lock`.

## What was done

1. **`uv.lock` committed** (130 pinned packages) — regenerated from `pyproject.toml`, coherent under `uv lock --check`.
2. **`.python-version` = `3.12`** — matches `pyproject.toml` `requires-python = ">=3.12"` and the CI-pinned Python.
3. **AGENTS.md** — Python conventions updated: Python 3.12+, `uv sync` for install, `uv run pytest tests/ -v` for tests; `pip install -e .` noted as legacy/CI path. Testing section commands updated to `uv run pytest`.
4. **README.md** — quickstart updated from `pip install -e .` / `python -m tortoise.selfhost` to `uv sync` / `uv run python -m tortoise.selfhost`.
5. **`.gitignore`** — added `.venv/` (uv venv artifacts stay untracked).
6. **`tests/test_gmm_proofs.py`** — added `pytest.importorskip("sklearn")` before the module-level sklearn import so the module skips cleanly when scikit-learn isn't installed.

## Why pip CI was kept (deferred switch)

The Python test suite runs in `python-ci.yml` (pip-based, from the shared agent-infra template). It was NOT switched to uv in this change:

- The workflow lives in the shared `agent-infra` template — switching it has cross-repo impact and belongs to a dedicated change (#493).
- Instead, `ci.yml` gained a `uv-lock-check` job (uv pinned 0.12.3) that runs `uv lock --check` + `uv sync --frozen --group dev` + collect-only, enforcing the lockfile contract so it never silently drifts again (see the job comment in `.github/workflows/ci.yml`).
- `deploy-hosted.yml` also runs `uv lock --check` and verifies `requirements.txt` parity via `uv export`.
