# Ask Reader Answer Surface Implementation Plan (#1987)

> **For Pi:** Use `executing-plans` to implement this plan task-by-task.

**Goal:** Ship the benchmarked retrieve-then-read answer pipeline (LongMemEval 0.83, integrity-valid) as the product's measured answer surface — hosted `POST /v1/ask`, `TortoiseSDK.ask()`, MCP `tortoise_ask`, self-host REST parity — with prompt ownership wholesale in new `tortoise/reader.py`, reader-level two-phase abstention (always exactly one LLM call), per-query cost metering with a per-team per-minute budget bound, and the eval harness re-exporting the product reader (the #1983 inversion pattern).

**Team:** epistemic-team
**Role:** product-implementer

**Architecture:** Retrieve-then-read (Approach A). Every ask is one bounded RAG pass: `tortoise_fts_query` (pool floor 120) → ask-path-local annotation (session-date join + speaker surfacing) → `dedup_pool` → `assemble_context` (pinned 8000/40) → deterministic `detect_question_type` (or caller override) → ONE `LLMReader.answer` (deepseek-v4-flash, 500 tok, temp 0, JSON-mode pinned OFF structurally) with the A1 two-phase presence-commit/abstention prompt → record-only metering + per-minute budget. The response carries the annotated evidence the reader saw (`evidence` field — the G7 trust property as a response field, not a second contract). The eval reader becomes a thin re-export — prompt drift impossible by construction.

### Bug Pattern Flags

- **Conditional guards** — `_should_send_json_mode` is a content-flippable guard (fires on "json" substring in user-controlled context). Required: boundary test both sides ("json" in context + env=1 → ask lane still no `response_format`; extraction lane still sends it).
- **Silent function skips** — the LLM-skip pre-gate class. Required: regression asserting exactly ONE model call on empty/decoy/near-miss context (no pre-gate in v1) — scheduled as `tests/test_ask_sdk.py::test_decoy_near_miss_exactly_one_call` (Task 5 Step 1, counted `complete()` on an injected fake).
- **Race conditions** — adapter `last_completion_tokens` is a mutable instance field on a shared model. Required: per-namespace (team) reader-model cache + synchronous same-call-frame usage capture; concurrency tests scheduled in Task 5 Step 1 (tokens-race: 2–3 in-flight through one cached instance + cache-key isolation) and Task 7 Step 1 (budget-bucket race, in-flight cap, semaphore bounds).
- **N+1 queries** — the annotation pass. Required: batch Cypher (one `MATCH … WHERE n.id IN $ids`), not per-hit queries.

## Scoping Decisions (double-diamond summary)

### Problem diamond (confirmed)
**"Make the product's retrieval output reader-ready and measured."** The product ends at retrieval (audit G1); the eval's two-phase reader never shipped. The port is NOT a module move — the product's retrieval output is reader-unready:
1. **Annotation gap (verified):** product search hits carry `sessionId` but no `session_date`/`speaker` surfaced for the reader context; the eval derives dates from the dataset's `haystack_dates`, not the graph. → ask-path-local annotation (session-date join via `:Session`/`:Event` `startedAt` + speaker surfacing) is IN SCOPE.
2. **Type gap (verified):** `question_type` has zero occurrences in `tortoise/`; the accuracy-carrying fragments are keyed by it. Verified facts: 6 dataset types / 4 prompt fragments / only the single-session-user subset was graded → the benchmarked prompt IS generic+abstention. → product default = deterministic `detect_question_type` (4 fragment types, on by default, parity-verified, explicit override).
3. **Lane gap (verified):** eval ran `openrouter:deepseek/deepseek-v4-flash` via `OpenAICompatModel`; product uses `build_extractor_model` (deepseek-direct primary, thinking disabled) + the JSON-mode content-flip hazard (`_should_send_json_mode` fires on "json" in retrieved context). → structural `json_mode=False` pin.
4. **Trust gap (verified):** `abstention_n=0` in graded runs; the vacuity finding (vacuous-retrieval questions are still mostly answered correctly — legacy 0.889 vs #1901 re-calibrated 0.778, both > 0.5) means a naive LLM-skip pre-gate kills correct answers. → NO LLM-skip pre-gate in v1; abstention measurement is a **hard pre-ship gate** (Task 12).
5. **Measurement gap (verified):** metering.py is write-op-only; no read-side LLM cost accounting. → record-only ask meter + per-team per-minute budget (#329 pattern).
6. **Inversion gap (verified):** the eval reader carries eval-only baggage (MockReader, READER_MODEL pin, preflight import, prompt-hash gap #1773). → thin-adapter re-export (keeps eval lane; product owns prompts + `LLMReader`).

**Falsification:** this definition is wrong if (a) a graded product-lane run scores ≥ 0.8 with zero annotation work (dates/types not needed), (b) product hits already surfaced session dates, or (c) the two-phase clause fails on real graphs (forces calibration, reframing the trust target — not the shipping decision).

### Solution diamond (converged)
**Approach (a) retrieve-then-read with evidence-in-response** — the only approach where the shipped pipeline is byte-identical to what the benchmark measured, eval unification is drift-proof, and abstention is reader-level two-phase exactly as #1775 calibrated. Evidence-in-response (the budget-capped assembled context the reader saw returns as `evidence`) delivers the G7/context-first trust property as a response field — one contract, no second surface. (d) `GET /v1/context` remains the documented G7 follow-up. (b) pre-computed digests and (e) hybrid are **unbenchmarked second surfaces** (staleness = hallucination vector; write-path invalidation) — rejected for v1, documented as the (b) enhancement trigger if traffic is personalization-shaped. ## Abstention Pre-Gate Design (the user-requested #3)

- **v1: NO LLM-skip pre-gate.** Every ask is exactly one LLM call — including empty/decoy/near-miss context (regression-asserted). Rationale: (a) the vacuity finding — vacuous-retrieval questions are still answered correctly at high rates (legacy-predicate 0.889 > non-vacuous 0.857 on the integrity-invalid reval3; the #1901 re-calibrated predicate concentrates failures at 0.778 vs 0.902, per the unmerged #1943 analysis — both predicates > 0.5), so skipping the LLM on low-signal retrieval would kill correct answers; (b) abstention is ungraded (`abstention_n=0`) → no calibrated skip threshold exists; (c) cost is already bounded (~$0.0014–0.0023/query ≤ $0.01 target, structural caps).
- **The reader-level two-phase abstention IS the no-evidence answer** (presence-commit → abstain on genuine absence, #1775). The `abstained` field is a best-effort heuristic label over the answer text (phrase list: "does not contain", "absent", "no information", "do not know", etc.) — measurement/UX sugar, NEVER a gate; the two-phase prompt is authoritative.
- **Documented follow-up (not in v1):** an OPT-IN empty-pool-only skip — fires only when the deduped pool is empty (the one "clear no-evidence" case where the reader would abstain anyway, so the skip is behaviorally consistent), gated on an abstention-grading arm proving the skip doesn't mislabel abstentions, citing the #1901 re-calibrated predicate. This is the research doc's "one real cost lever," deferred until it is measured.
- **Hard pre-ship gate (Task 12):** the answer-surface merge is BLOCKED until (a) the graded `_abs` run returns an acceptable abstain-only-on-genuine-absence verdict, (b) a product-lane known-answer smoke passes (known-answer fixture through `build_reader_model`, the RoutingModel transport delta vs the eval's OpenAICompatModel), (c) the detector-parity branch is recorded. No marketing of abstention as a trust guarantee before this gate passes.
