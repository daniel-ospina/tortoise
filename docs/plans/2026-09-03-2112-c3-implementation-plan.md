## Scope (IN)
1. **Mint** — extend the existing `POST /v1/team/keys` (create_api_key) to accept `{graph_id?, scopes?, name?}` and mint SCOPED keys (owner-class deleg NULL when session/owner-key caller; delegation stamping matrix D13). Graph-bound (graph_id set → tk_ + namespace-bound) or team-wide (graph_id absent → default graph).
2. **List** — `GET /v1/team/keys` already returns keys; ADD `graph_id`/`delegation_depth`/`scopes`/`created_by_key_id` fields to the response rows (additive, both lanes) + optional `?graph_id=` filter (surface 12 API-side).
3. **Shrink** — `PATCH /v1/team/keys/{key_id}` scope-shrink: subset the scopes allowlist (write→read); expand-attempt (superset) → 422. Must NOT collide with the existing `toggle_api_key_enabled` PATCH (that's enable/disable+rename on the same path — C3 co-locates: the existing PATCH handles `{enabled?, name?}`; C3's shrink handles `{scopes?}`; a body with scopes routes to shrink logic).
4. **Revoke** — `DELETE /v1/team/keys/{key_id}` exists (revoke_api_key, audit); verify cross-surface instant 401 (REST + MCP), per-graph revocation path parity.
5. **max_api_keys cap** — 409 (the C2 `_KeyCapExceeded` semantic — NOT the legacy 402 from `_check_team_limit(...,"api_keys")`; the D3 asymmetry is deliberate and documented; C3 unifies the SCOPED mint path onto `_KeyCapExceeded` → 409, leaves the legacy owner-mint 402 alone for back-compat, records why).
6. **Delegation** — key-minted keys (caller is a key) stamped deleg=0 + created_by_key_id (D13 matrix); session-minted keys deleg NULL.

## Decisions
- **D13 — mint delegation matrix (resolves the epic §5.4/J2 "keys:manage mints children" ambiguity for THIS codebase):**
  - **Session caller** (any member — D12 parity, no epic tightening) → minted key **deleg NULL** (owner class), scopes = requested ∩ full allowlist {graphs:read, graphs:write, graphs:create, graphs:delete, team:manage, keys:manage}; escalation scopes ALLOWED (owner mint).
  - **Legacy full-access key caller** (deleg NULL, scopes=[] — C1 legacy_full_access=True, the OWNER class) → minted key **deleg NULL** (owner class), any allowlisted scopes. Back-compat: C1/E2E-5 treats legacy keys as owners (legacy_full_access); an owner minting an owner key is normal J2 rotation — one-level-deep protects against a compromised SCOPED key, not the owner class (a compromised owner key can already do anything). No in-repo consumer key-mints via REST today (dashboard=session, CLI=SDK-direct), so this is behavior-preserving for the suite.
  - **Scoped deleg-NULL key caller WITH keys:manage** (J7 DevOps) → minted key **deleg 0** + **created_by_key_id = caller key id**; scopes = requested ∩ child policy (`graphs:read`, `graphs:write` — never escalation; the C2 `_MINTABLE_SCOPES` constant + the registry apikey_create backstop + the DB CHECK `chk_minted_key_no_escalation` all enforce). Escalation-scope request → 403 (§6.3: "403 escalation scopes on MINTED key" — never silently stripped).
  - **Scoped deleg-NULL key caller WITHOUT keys:manage** → 403 (no mint capability; J2 grants mint only to keys:manage).
  - **Deleg-0 caller** → 403 (C2's central deleg gate already fires in get_current_team_session before this body — retained endpoint check is defense-in-depth).
- **D14 — mint implementation = generalize `_mint_graph_key`, never re-implement (D0).** The C2 helper is graph-bound + deleg=0 + tk_ only. C3 generalizes the LOW-LEVEL write into `_mint_key(...)` (graph_id: str | None, delegation_depth: int | None, scopes passed through pre-filtered, prefix tk_) and keeps `_mint_graph_key` as the thin provisioning wrapper (graph-bound, deleg=0, child policy) C2/C3 callers already use — C2's provisioning code path unchanged. Standalone create_api_key gains the scope/graph_id/delegation kwargs through the SAME low-level writer (one implementation, no divergence — D0 record honored).
- **D15 — tk_ for scoped keys, tt_ for legacy-shape mints.** A mint that carries scopes OR graph_id → tk_ prefix (the epic's single scoped key type). A plain `{}`-body owner mint (legacy shape, no scopes) keeps tt_ (existing dashboard/CLI callers byte-identical). Both prefixes resolve through the SAME auth gates (C2 widened them).
- **D16 — shrink = PATCH co-location.** The existing `PATCH /v1/team/keys/{key_id}` (toggle_api_key_enabled, #1148, session+owner/admin) keeps `{enabled?, name?}`. C3 adds scope-shrink handling to the SAME endpoint: body containing `scopes` → validate subset → PATCH the row's scopes (both lanes) → 200 with new scopes. Superset/identical-with-additions → 422 (expand = revoke+recreate, documented in the error detail). Auth for the scopes branch: session OR deleg-NULL key with keys:manage (the endpoint's session dep is unchanged for {enabled,name}; the scopes branch reads the same team dict). Never touches a revoked key (404/409 — revoked keys are terminal; shrink of a disabled key is allowed — disabled ≠ revoked).
- **D17 — list enrichment is additive.** Response rows gain `graph_id`, `scopes`, `delegation_depth`, `created_by_key_id` (null-tolerant for legacy rows — the registry list already tolerates missing props; Supabase rows carry them post-C1). `?graph_id=` filter narrows (default = all keys, dashboard unchanged). Keys are ordered created_at DESC (existing).
- **D18 — E2E-12's create-without-delete** needs an owner-session minted scoped key with `graphs:create` only. C3's session mint path produces it; delete-graph's 403 for missing graphs:delete is ALREADY the C2 behavior (scope check in delete_graph) — C3 only asserts it end-to-end.

## Tasks
1. **Low-level mint refactor** `_mint_key` (registry + Supabase lanes): params {team_id, graph_id=None, scopes=None (already child-policy-filtered or full-allowlist per caller class), delegation_depth=None, caller_key_id=None, session_user_id=None, prefix auto (tk_ when scopes or graph_id, else tt_)}; max_api_keys pre-check → `_KeyCapExceeded`; hash-only; reveal-once; created_by = session_user_id or "api"; created_by_key_id + delegation_depth stamped when key-minted; analytics `api_key_created` + `_abuse_evaluate_keys` stay at the endpoint (not in the low-level writer — C2's provisioning endpoints fire them). `_mint_graph_key` becomes a thin wrapper passing graph_id + deleg=0 + child-policy-filtered scopes. Regression: C2's provisioning tests unchanged (envelope id == node id; plaintext verifies).
2. **create_api_key extension** (D13): parse {graph_id?, scopes?, name?}; caller-class resolution (session vs key vs deleg); scope validation against the allowlist (invalid → 422); escalation-on-key-mint → 403; graph_id existence check → 404; mint via `_mint_key`; response unchanged for {} bodies, extended for scoped mints (returns {id, key, key_prefix, created_at, name, scopes, graph_id, delegation_depth}).
3. **List enrichment** (D17): both lanes' row mapping + graph_id query filter.
4. **Shrink PATCH** (D16): scopes branch in toggle_api_key_enabled (or a co-located handler); subset validation → PATCH both lanes (supabase api_keys row PATCH scopes; registry SET scopes); 200 new scopes; 422 on expansion. Never on revoked (terminal). Shrink reflects in resolve_api_key (scopes read from row/node).
5. **E2E tests** (both modes): E2E-9 (owner T scoped key mints/revokes; create-without-delete C; legacy L reads/writes default; multi-key-per-graph independence), E2E-12 (list last_used_at after use; shrink read+write→read → shrunken write 403 IS C5's assertion — C3 asserts the shrink REFLECTS in resolve_api_key scopes + a shrunken key's revocation works; expand → 422), E2E-4 half (minted deleg=0 key → create/revoke/shrink 403). max_api_keys 409 on scoped mint. Registry apikey_create escalation backstop test (deleg=0 + keys:manage → ControlPlaneError).
6. **Sweep** — ruff, py_compile, carve-out + docker-lane touched files, markers routing if a new test file lands in ROUTED_NAMESPACES.
