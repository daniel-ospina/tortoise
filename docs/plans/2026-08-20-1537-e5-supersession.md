# #1537 E5 — Supersession End-to-End via supersede() Implementation Plan

> **For Pi:** Use `executing-plans` to implement this plan task-by-task.

**Goal:** Make supersession survive end-to-end for the V3 build — fact-value contradictions are detected at extraction, persist through the payload + `client_commit_id` at all 3 compute sites, materialize as CORRECTS edges via the EXISTING canonical `supersede()` (no new SDK tool), co-retrieve with the superseding claim, and render `[SUPERSEDED BY]` even in embedded mode (E2E-6).

**Team:** epistemic-team
**Role:** product-implementer

**Architecture:** The write path (S5 `execute_embed` → hosted commit / eval ingest) gains point-level supersession records riding the EXISTING `payload.supersessions` field (content-addressed `pt_*` refs, dispatched by prefix at the write sites); all three `client_commit_id` compute sites agree on a canonical that includes supersessions. The read path (eval `hybrid_search` + embedded TF-IDF fallback) surfaces superseded points via `include_terminal=True` and decorates them with the promoted `superseded_by`/`supersedes` state (the `fetch_point_epistemic_state` D8 machinery) so `[SUPERSEDED BY: …]` renders in embedded AND full-path modes. No new kinds, no new edge types, no new payload fields — the ontology invariant holds (04-plan §4).

**Contract context:** issue #1537 (epic child of #1509) — epic contract 03-scope E5, 04-plan §4/§6, detailed E2E-6/E2E-9 in 05-detailed-e2e.md, test-design surface map #1515 (surfaces 13/23/24 owned by E5). This issue has no `issue-scoping` comment: it is an epic-decompose child whose scope artifact IS the epic doc + the issue's verification checklist; complexity:complex (per the label).

### Bug Pattern Flags

- **Conditional guards** — every threshold is a guard: 0.6 overlap (BVA both sides: 0.59/0.60), 0.5 contradiction frame (0.49/0.50), ≥2 shared-token floor (1/2), terminal-status exclusion (live vs superseded/retracted/archived). Each gets a both-sides BVA test (mirrors the #1515 flag list "0.6/0.85/clamp/self-supersede").
- **N+1 queries** — the embedded decoration must be ONE batch `fetch_point_epistemic_state` call over result ids, never per-hit.
- **Silent skips** — unresolvable/terminal supersession refs at both write sites MUST warn (hosted pattern already fail-open-warns; eval ingest must too) and be counted, never silently dropped.
- **Silent-fallback regression** — the existing `test_retrieve_for_question_surfaces_supersession_annotation` comment ("embedded CI itself can't decorate") becomes STALE by design — the test suite must be updated to assert the new embedded decoration instead of pinning its absence.

### Checklist Notes

- Atomicity: `supersede()` is already multi-query but guard-before-write (all validation precedes mutation, #329/#330) — write sites rely on that; no new transactions.
- Idempotency: supersede re-asserts idempotently (MERGE keeps a single CORRECTS edge) but `supersede_point` RAISES on already-terminal old — the eval re-ingest path must pre-check status (Task 4 guard) to stay idempotent.
- Ordering: hosted §6b runs after the reconcile point writes (new point exists); eval `_write_payload` must materialize supersessions AFTER the points loop for the same reason.
- Boundary values: empty `supersessions` list (pre-#1350 id stability), 1 record, N records; `pt_` vs `obj-` vs bare-name refs.

## Design Decisions

### DD-1 — Length-guarded `_token_overlap` (fix false-REVISES ≥ 0.6)

`extractor_v2.py:725` divides by `min(len(ta), len(tb))` — a 5-token point sharing 3 tokens with a 50-token point scores 3/5 = 0.6 and falsely REVISES (E2E-6 owned negative). Fix: divide by `max(len(ta), len(tb))` (3/50 = 0.06 → no REVISES) AND require a minimum shared-token floor of 2 content tokens (a single shared token is never a revision). BVA: "gym at 6pm" vs "gym at 5pm" → {gym, at} shared / 3 = 0.67 ≥ 0.6 → still REVISES ✓.

### DD-2 — Fact-value contradiction detection (same entity + attribute frame + value diff + later date)

`_find_point_match` gains a third pass (after exact/overlap): `_fact_value_contradiction(new_content, about_entities, existing)` returns True when:
1. **Same entity** — the new point's `about_entities` name(s) co-mention in the existing point's content (content proxy; S3 point rows carry only `{id, content, kind}` today — see CG-3 for the aboutObject-edge upgrade path).
2. **Attribute frame** — stopword-stripped token overlap on the LONGER side ≥ 0.5 (the shared non-value frame, e.g. {gym, at} in "gym at 6pm" vs "gym at 5pm").
3. **Value differs** — the new content has at least one token the old lacks (`t_new - t_old ≠ ∅`). Identical-content re-assertions are deduped by the exact-match pass BEFORE the contradiction pass (E2E-6 negative: no new supersession; NOOP is E2E-11's job). Reworded-identical values ("6:00 PM" vs "6pm") may pass the value-diff — the E5→E7 boundary owns that case (Open Q5).
4. **Later date** — guarded by the caller: the new point's date (`when`, E1) must be ≥ the existing point's (`when`/`createdAt`); when E1's `when` slot is absent (CG-2), session ingest order supplies the invariant (the eval ingests sessions chronologically).

This catches short-value changes that the length guard would otherwise reject ("gym 6pm" → "gym 5pm": 1 shared token but entity-grounded). Emits a point supersession record (DD-3).

### DD-3 — Point supersession records ride the EXISTING `payload["supersessions"]` field

Point-level supersessions are appended to the same records list as the entity-level ones (`_supersession_records` output), as `{superseded: <existing pt_ id>, supersedes_by: <new pt_ id>, evidence: "fact-value contradiction (later session value change)"}`. Content-addressed point ids are always `pt_<sha>` while entity ids are `obj-<sha>` — the write sites dispatch on the `pt_` prefix. `CommitPayload`/`SupersessionRecord` have `extra="forbid"` (commit_schema.py:356-386), so NO new field is possible without a schema change; prefix dispatch on the existing fields is the zero-schema design. The SupersessionRecord docstring is updated (entity-only wording → point refs included) — a doc touch only.

### DD-4 — `client_commit_id` 3-site agreement (fix site 1)

`execute_embed` computes the id WITHOUT supersessions today (extractor_v2.py:1272-1277) while `_post_commit` (sdk.py:14016) and hosted validation (commit_schema.py:652) include them — any non-empty supersessions list produces a 422 `commit_id_mismatch` on the hosted path. Fix: `execute_embed` sets `payload["supersessions"]` and passes it into `compute_client_commit_id`. Backward compat is preserved by the existing `canonical_payload` rule (#1350): the `supersessions` key is emitted ONLY when non-empty, so a payload that never had supersessions keeps its pre-#1350 id.

### DD-5 — Write sites call the EXISTING canonical `supersede()` (no new SDK tool)

Both materialization sites (hosted §6b loop, eval `_write_payload`) resolve point refs and call `sdk.supersede(old_id, new_id)` (transfer_edges=True → `supersede_point`: CORRECTS + outdated + edge transfer). `correct_point`/`supersede_point`/`invalidate_point` are all absorbed by the unified tool (#888 W2); the correct_point misattribution was corrected upstream — this plan never introduces a new SDK surface. Guards reused from the SDK's own contract (#330/#432): old exists, old != new, old not terminal (idempotent skip), new exists.

### DD-6 — Co-retrieval + embedded decoration (read path)

Two changes make E2E-6's read side work:
1. `retrieve.py:hybrid_search` passes `include_terminal=True` so superseded points survive the base retrieval (terminal exclusion, #1391, hides them today).
2. BOTH embedded fallback branches in `tortoise_fts_query` (search_snapshot + fallback_tfidf) decorate their result dicts with `fetch_point_epistemic_state(graph, ids)` — one batch call at the single call site (sdk.py), leaving `search_engine.py`/`fallback_snapshot.py` untouched. The D8 keys (`status`/`superseded_by`/`supersedes`) already flow through `_annotate_hits` → `_supersede_marker` → `render_context` (retrieve.py), so `[SUPERSEDED BY: …]` renders in embedded mode exactly as it does on the full path.

```python
_MIN_OVERLAP_TOKENS = 2  # a single shared token is never a revision

def _token_overlap(a: str, b: str) -> float:
    ta = set(_norm(a).split())
    tb = set(_norm(b).split())
    if not ta or not tb:
        return 0.0
    shared = len(ta & tb)
    if shared < _MIN_OVERLAP_TOKENS:
        return 0.0
    # length-guard: ratio against the LONGER side — a 5-token point sharing
    # 3 tokens with a 50-token point is 3/50=0.06, not 3/5=0.6 (false REVISES)
    return shared / max(len(ta), len(tb))
```

Add `_fact_value_contradiction` (per DD-2; stopword set mirrors `ingest_v2._STOPWORDS` — import the shared `_STOPWORDS` from `tools/longmem_eval/ingest_v2` is NOT acceptable in `tortoise/` (layering); keep a small local content-token set) and wire it into `_find_point_match` as the third pass:

```python
def _find_point_match(points, content, *, about_entities=None) -> tuple[str, str]:
    norm = _norm(content)
    for p in points:
        if _norm(p.get("content", "")) == norm:
            return "exact", p.get("id", "")
    for p in points:
        if _token_overlap(p.get("content", ""), content) >= 0.6:
            return "revises", p.get("id", "")
    for p in points:
        if _fact_value_contradiction(content, about_entities, p):
            return "revises", p.get("id", "")
    return "none", ""
```

> **CG-2 — E1 `when` dependency (later-date guard).** `extractor_v2.py` has no `when` slot today (E1 not landed on the branch this plan was drafted against). > **CG-3 — E3 aboutObject wiring for entity-grounded detection.** S3 point rows return `{id, content, kind}` only, and the eval `_write_payload` writes no aboutObject edges — so the "same entity" check uses the content proxy (entity name ∈ existing content). > **CG-4 — `include_terminal=True` is global to the eval pool.** It applies to every `retrieve_for_question` call (all questions, not just supersession ones).
