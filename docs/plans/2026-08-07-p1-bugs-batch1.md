# P1 Bugs Batch 1 — Data Divergence, Stale Cache, Missing Error Handling — Implementation Plan

> **For Pi:** Use `executing-plans` to implement this plan task-by-task.

**Goal:** Fix 7 P1 defects in the tortoise projection/EP/SDK layers with surgical parity-focused changes and regression tests.

**Team:** organisation-design-team
**Role:** engineer

**Architecture:** All fixes preserve existing contracts and are scoped to the named files. The projection fix extracts a shared `_upsert_point_props` helper so `rebuild_all` and `apply()` can never drift (single source of truth for Point property writes). The EP fixes make run()-level state call-scoped (evidence, caches) and add zero-division guards. The SDK fixes add truthfulness (invalidate_point), observability (checkpoint), and honest ingest counters. No EP propagation math, no Source credibility model changes, no new EP features.

## Task 1: Projection parity — extract `_upsert_point_props` + fix `rebuild_all`

**Intent:** `rebuild_all()` currently hand-rolls a Point MERGE that drops 6 property writes and all provenance edge wiring vs `apply()`→`_upsert()` — rebuilt graphs lose live properties and the `(Point)-[:extractedFrom]->(Source)` chain (ONTOLOGY v3.1 §3.3), which silently breaks credibility inheritance and calibration downstream. Extract the shared property-write helper so divergence is structurally impossible.

**Acceptance:** `rebuild_all` on a log dir produces, for every Point, exactly the same node properties AND edges as replaying the same events through `apply()`. SourceCreated events are replayed (pass 1b). Existing rebuild tests (counts) still pass.

**Files:**
- Modify: `tortoise/projection/entities.py` (`_upsert` → extract `_upsert_point_props`)
- Modify: `tortoise/projection/__init__.py` (`rebuild_all` passes)
- Test: `tests/test_projection.py`

**Step 1: Write the failing parity test** — `test_falkor_rebuild_all_parity_with_apply`. Build a log by appending event DICTS directly to an `EventLog` (EventAPI cannot emit SourceCreated/extractedFrom — verified; `EventLog.append(dict)` is a plain JSON round-trip and `read_all()` returns dicts as-is; rebuild_all reads `ev["point"]` nested, so use the NESTED shape exactly as api.py `_emit` emits: `{"event_id":..., "ts":..., "type":"PointAdded", "initiated_by":"extractor", "agent_id":"test", "point":{...}, "projection_version":2}`). CONVERGENT ORDER (critical — see Step 3 note): `IngestStarted` → `SourceCreated` (url, sourceKind, contentHash, title, externalId) → `PointAdded` for two points each carrying `authoredBy`, `validFrom`, `validTo`, `confidence`, `extractedFrom` (the Source url), `aboutEntities` (["alice"]), `provenance: {"speaker": "bob", "source_id": "s1"}` → `OperatorAdded` (IMPL, inputs [b, a]) → `PointRevised` (id=a, new_content). Replay through `apply()` into projA; `rebuild_all(d)` into projB. Assert: `properties(n)` maps per Point ID (excluding `updatedAt`/`embedding`) are IDENTICAL; edge maps `(src_id, type, dst_id)` are IDENTICAL; `extractedFrom` edges exist in BOTH; Source node has `version=1` and `id=url` in BOTH (assert Source props SELECTIVELY: url/sourceKind/contentHash/title/version/id — `ingestedAt` differs between the two write times and must be excluded).

**Step 2: Run to verify it fails** — `python -m pytest tests/test_projection.py::test_falkor_rebuild_all_parity_with_apply -v` → FAIL (pre-fix rebuild drops authoredBy/validFrom/validTo/extractedFrom/provenanceSource props + extractedFrom/about edges).

**Step 3: Extract `_upsert_point_props` in entities.py** — property writes move into `_upsert_point_props(self, p)`: the main MERGE+SET query (content/is_operator/op_type/pointKind/status/authoredBy/embedding-vecf32-CASE/confidence/createdAt/validFrom/validTo/updatedAt), the `n.extractedFrom = $ref` property write (when p.extractedFrom), and the `n.provenanceSource` write (when provenance.source_id). `_upsert` becomes: `_upsert_point_props(p)` + `_link_source` edge (if extractedFrom) + `_create_about_edges` (if aboutEntities) + `_create_edges` (if operator). Helper preserves the `if not op` embedding skip and the vecf32 CASE-WHEN. **The v2 context-strip (`if ev.get("projection_version",0) >= 2: p.pop("context", None)`) stays in the EVENT LOOPS (apply() and rebuild_all pass 1a) BEFORE the helper call — NOT inside the helper** (both paths strip identically; drift risk if moved).

**Step 4: Rewrite `rebuild_all` passes** — pass 1a: keep the v2 context-strip, then `self._upsert_point_props(ev["point"])` for each PointAdded/OperatorAdded. Pass 1b: add `elif t == "SourceCreated": self._upsert_source(ev)`; change `self._revise_point(ev)` → `self._revise_point(ev, set_updated_at=True)` (parity with apply()). Pass 2: for every PointAdded/OperatorAdded wire `_link_source` (if extractedFrom) + about edges (if aboutEntities) + `_create_edges` (if operator). NOTE: the parity test's log order (SourceCreated BEFORE extractedFrom-bearing points) makes `_upsert_source` ON CREATE fire in both paths → Source `version=1`/`id` converge; a reversed order would diverge (stub-then-ON-MATCH → version stays null) — documented as a known pre-existing ordering divergence, NOT normalized in this batch.

**Step 5: Run** — `python -m pytest tests/test_projection.py -q` → all pass.

**Step 6: Commit** — `fix(projection): rebuild_all parity with apply — shared _upsert_point_props + provenance edges (#330)`

## Task 2: EP evidence per-run + cache lifecycle (ep.py)

**Intent:** `ep.run()` permanently mutates `self._evidence` with run-level evidence (leaks into later runs and re-writes stale priors to the graph) and leaves `_node_cache`/`_msg_cache` stale when a run early-returns — public reads then serve stale in-memory values. Make run()-level state call-scoped.

**Acceptance:** (a) run(evidence=X) then run() without evidence does NOT re-apply X; (b) after any run (incl. early-return), `compute_confidence` reads fresh graph values; (c) `test_ep_accepts_evidence` + `test_run_evidence_overrides` (tests/test_extractor_priors.py) still pass; (d) constructor evidence still applies on EVERY run.

**Files:**
- Modify: `tortoise/ep.py` (`run`, `_update_claim_posterior`)
- Test: `tests/test_sdk_ep.py`

**Step 1: Write failing tests** (new classes `TestEvidenceLeak` + `TestCacheFreshness` in tests/test_sdk_ep.py):
- `test_run_evidence_does_not_leak_to_next_run`: run([op]) with evidence={b:(10,1)}; reset b's graph params to (1,1) directly; run([op]) again with NO evidence; assert b's graph ep_alpha != 10.0 (leak would re-write 10) AND `b["id"] not in ep._evidence`.
- `test_run_evidence_overrides_constructor_in_posterior`: TortoiseEP(proj, evidence={b:(3,1)}); run([op], evidence={b:(1,3)}); compute_confidence(b) → mean < 0.5 (run overrides constructor in the real posterior); `ep._evidence[b] == (3.0, 1.0)` (constructor dict untouched).
- `test_constructor_evidence_applies_every_run`: TortoiseEP(proj, evidence={b:(10,1)}); run([op]) twice with NO run-evidence → b's graph params reflect (10,1) both times (pre-write uses constructor evidence each run); then run with run-evidence for a DIFFERENT claim c → b still (10,1).
- `test_early_return_clears_stale_cache`: run([op]) with evidence; externally SET b to (4,4); run(["does-not-exist-op"]) (early return); compute_confidence(b) → alpha==4.0, beta==4.0 (fresh, not stale (10,1)).

**Step 2: Run to verify they fail** — `python -m pytest tests/test_sdk_ep.py::TestEvidenceLeak tests/test_sdk_ep.py::TestCacheFreshness -v` → FAIL.

**Step 3: Fix `run()` + `_update_claim_posterior`**:
- At entry: `run_evidence = dict(self._evidence); if evidence: run_evidence.update(evidence)`.
- Cache lifecycle: `if hasattr(self, "_node_cache"): delattr(self, "_node_cache")` (same for `_msg_cache`) — AT ENTRY (before evidence pre-write + early returns) and AFTER `_flush_cache()`. Use `delattr` (NOT `= {}`) so the `hasattr` guards in `_read_node`/`_write_node`/`_is_strong` route to direct graph I/O (an empty dict would silently trap `_write_node` writes post-run).
- Evidence pre-write UNWIND uses `run_evidence`.
- `_update_claim_posterior(self, claim_id, run_evidence)` reads `run_evidence.get(claim_id)` instead of `self._evidence.get(claim_id)`. Only caller is run()'s loop (ep.py ~line 470 — verified no other callers; svbp.py has its own separate method).

**Step 4: Run** — `python -m pytest tests/test_sdk_ep.py tests/test_extractor_priors.py -q` → all pass.

**Step 5: Commit** — `fix(ep): per-run evidence + cache lifecycle — no leaks, no stale reads (#330)`

## Task 3: ZeroDivision guards (ep.py, svbp.py)

**Intent:** `a/(a+b)` crashes when stored ep params are (0,0) (reachable via `set_point_baseline(id, 0, 0)` → `get_confidence`). Guard all division sites with the uniform fallback.

**Acceptance:** `set_point_baseline(id, 0.0, 0.0)` + `get_confidence(id)` returns `{mean: 0.5, variance: 1/12, alpha: 0.0, beta: 0.0, effective_n: 0}` instead of raising. `_is_strong` and `_flush_cache` do not raise on (0,0).

**Files:**
- Modify: `tortoise/ep.py` (`compute_confidence`, `_flush_cache`, `_write_node`, `_is_strong`)
- Modify: `tortoise/svbp.py` (`compute_confidence`)
- Test: `tests/test_sdk_ep.py`

**Step 1: Write failing tests**:
- `test_compute_confidence_zero_total_does_not_crash`: create claim, `set_point_baseline(id, 0.0, 0.0)`, `get_confidence` → mean 0.5, variance 1/12, effective_n 0 (was ZeroDivisionError).
- `test_is_strong_zero_total_no_crash`: store ep_alpha=ep_beta=0 on a claim via graph write, `ep._is_strong(claim_id)` → False (no ZDE).
- `test_flush_cache_zero_total_no_crash`: set `ep._node_cache = {cid: (0.0, 0.0)}` for a graph node, call `ep._flush_cache()` → writes c=0.5, no ZDE.

**Step 2: Run to verify they fail** — `python -m pytest tests/test_sdk_ep.py -k "zero_total" -v` → FAIL (ZeroDivisionError).

**Step 3: Guard the division sites** (all use `total <= 0` / `(a+b) > 0` predicates, consistent with `_is_strong`'s existing cache-path guard):
- `ep.compute_confidence`: `if total <= 0: return {"mean": 0.5, "variance": 1/12, "alpha": a, "beta": b, "effective_n": 0}`
- `ep._flush_cache`: `"c": round(a/(a+b), 4) if (a+b) > 0 else 0.5`
- `ep._write_node`: `mean = round(alpha / (alpha + beta), 4) if (alpha + beta) > 0 else 0.5`
- `ep._is_strong` graph path: `return a / (a + b) >= threshold if (a + b) > 0 else False`
- `svbp.compute_confidence`: `if total <= 0: return {"mean": 0.5, "variance": 1/12, "alpha": a, "beta": b}` (native shape — no effective_n)

`get_contested_claims` Cypher division is null-safe (WHERE v > $t excludes null/0 totals) — no change.

**Step 4: Run** — `python -m pytest tests/test_sdk_ep.py tests/test_projection.py -q` → all pass.

**Step 5: Commit** — `fix(ep): guard zero-division in confidence/mean computations (#330)`

## Task 4: invalidate_point truthfulness (sdk.py)

**Intent:** `invalidate_point` reports `{"invalidated": True}` even when one or both endpoints don't exist — silent partial failure that can orphan an outdated point with no CORRECTS edge. Validate before write; make CORRECTS idempotent.

**Acceptance:** missing old → `{"invalidated": False, "id", "corrected_by"}` with no writes; missing new → `ValueError`; `id == corrected_by_id` → `ValueError` (no self-CORRECTS edge); re-invalidating the same pair does not duplicate CORRECTS. Existing `TestInvalidateSupersede` + `test_invalidate_marks_dirty` pass.

**Files:**
- Modify: `tortoise/sdk.py` (`invalidate_point`)
- Test: `tests/test_sdk.py` (new tests live INSIDE the existing `TestInvalidateSupersede` class so the Step-4 selector runs them)

**Step 1: Write failing tests** (inside `TestInvalidateSupersede`):
- `test_invalidate_missing_old_is_false`: `invalidate_point("missing-old", new_id)` → `{"invalidated": False, "id": "missing-old", "corrected_by": new_id}`; no CORRECTS edge created (traverse new_id outgoing CORRECTS → 0).
- `test_invalidate_missing_new_raises`: `pytest.raises(ValueError)` on `invalidate_point(old_id, "missing-new")`; old point NOT marked outdated (no partial write).
- `test_invalidate_self_raises`: `pytest.raises(ValueError)` on `invalidate_point(old_id, old_id)`; no self-CORRECTS edge.
- `test_invalidate_idempotent_corrects_edge`: invalidate twice → exactly 1 CORRECTS edge.

**Step 2: Run to verify they fail** — `python -m pytest tests/test_sdk.py::TestInvalidateSupersede -v` → all four fail (invalidated:True / no raise / self-edge / duplicate edge).

**Step 3: Fix `invalidate_point`** — validate BEFORE any write, in order: (1) `id == corrected_by_id` → `ValueError` (self-CORRECTS poisons traversal/credibility); (2) old missing → return `{"invalidated": False, "id": id, "corrected_by": corrected_by_id}` (idempotent retry semantics — no writes, no `_mark_dirty`); (3) new missing → `ValueError` (structural failure — would orphan an outdated point). Then: SET outdated + updatedAt; CORRECTS CREATE→MERGE (idempotent); `_mark_dirty([id, corrected_by_id])`. Docstring documents the trichotomy (self → ValueError; missing old → False; missing new → ValueError). `supersede_point` OUT OF SCOPE (same family — separate follow-up issue).

**Step 4: Run** — `python -m pytest tests/test_sdk.py::TestInvalidateSupersede tests/test_dream.py -q` → all pass.

**Step 5: Commit** — `fix(sdk): invalidate_point validates endpoints + idempotent CORRECTS (#330)`

## Task 6: ingest_corpus honest counters (sdk.py)

**Intent:** DocumentCreated mode (the default) has NO skip path — re-ingesting a byte-identical doc counts as `updated`, so `skipped` is always 0. AgentSession's skip is gated on keyword-population. Make counters honest: byte-identical → skipped; any change → updated; preserve the AgentSession metadata-enrich path.

**Acceptance:** (a) DocumentCreated: identical re-ingest → `skipped == N`, `updated == 0`; modified doc → `updated`; NEW doc → `ingested`; legacy no-hash event → `updated` + hash backfilled. (b) AgentSession: identical + complete → skipped; identical + incomplete → enrich path (updated only if state changed, else skipped); changed → updated with arc accumulation. (c) AgentSession skips append to `completed_files`.

**Files:**
- Modify: `tortoise/sdk.py` (`ingest_corpus`)
- Modify: `tests/test_sdk_group3.py` (update `test_reingest_updates`, add tests)

**Step 1: Update + write tests** (in `TestIngestCorpus`):
- REPLACE `test_reingest_updates` with `test_reingest_unchanged_skipped`: identical corpus re-ingest → ingested 0, updated 0, skipped 3.
- `test_reingest_changed_updates`: modify doc1.md body → updated 1, skipped 2.
- `test_reingest_new_doc_ingested`: add doc3.md → ingested 1, skipped 3.
- `test_reingest_legacy_no_hash_backfills`: create the Event node directly WITHOUT file_hash (proj.g.query CREATE), re-ingest the identical file → updated 1 AND stored file_hash now set.
- `test_agentsession_reingest_unchanged_skipped`: AgentSession mode, identical → skipped 1, updated 0.
- `test_agentsession_changed_updates_with_arc`: AgentSession mode, changed file → updated 1, skipped 0.
- `test_ingest_agentsession_progress_resume_skips`: ingest with progress_file, then re-ingest same dir with progress_file → completed files counted skipped, no re-write. (AgentSession mode only — DocumentCreated never appends to completed_files by design.)

**Step 2: Run to verify they fail** — `python -m pytest tests/test_sdk_group3.py::TestIngestCorpus -v` → `test_reingest_unchanged_skipped` fails (updated==3 currently); changed/new/legacy/AgentSession/resume tests fail.

**Step 3: Fix `ingest_corpus`**:
- `hashlib` is already module-imported (sdk.py:8). Compute `file_hash = hashlib.sha256(text.encode()).hexdigest()` once per file iteration, BEFORE the eventKind branch (shared by both modes).
- **DocumentCreated branch** — CHANGE the exists-query from `RETURN count(e) > 0` to `RETURN e.file_hash` (three-way branch on ROW PRESENCE, not hash truthiness — legacy events return a row with `[None]`, new docs return ZERO rows):
  1. `not rows` (new doc) → CREATE + `ingested += 1` (add `"file_hash": file_hash` to props).
  2. `rows[0][0] == file_hash` (byte-identical) → `skipped += 1; continue` (no writes).
  3. `rows[0][0] != file_hash` (changed OR legacy-no-hash None) → `SET e += $props` (props include file_hash → backfills) + `updated += 1`.
- **AgentSession branch**:
  - Fast path: `existing_props.get("file_hash") == file_hash AND has_keywords` → `skipped += 1; completed_files.append(rel_path); continue`. (has_keywords is the SOLE completeness signal — do NOT add an eventStatus disjunct; pipeline-created sessions always carry `eventStatus="completed"`, so a disjunct would skip incomplete sessions and kill the enrich path.)
  - Enrich path (hash matches + no keywords): keep the existing extract + merge (LLM retry preserved); normalize stored `content_metadata` (JSON string → dict via json.loads); compare merged vs stored — changed when `set(merged_keywords) != set(stored_keywords)` OR `set(metadata topics) != set(stored topics)` OR normalized content_metadata differs; changed → write + `updated += 1`; unchanged → NO write + `skipped += 1`; both append `completed_files`. narrative_arc merge gains dedup+cap: `new_phases = list(dict.fromkeys(existing_arc.get("narrative_arc", []) + metadata.get("narrative_arc", [])))[:50]`.
  - Hash MISMATCH (content changed): unchanged existing update flow (write + `updated += 1` + append).

**Step 4: Run** — `python -m pytest tests/test_sdk_group3.py -q` → all pass.

**Step 5: Commit** — `fix(sdk): ingest_corpus honest skipped counter — hash-based skip in both modes (#330)`

## Acceptance Criteria

- [ ] `rebuild_all` ≡ `apply()` for Point node properties and edges (parity test covers extractedFrom/about/IMPL edges, SourceCreated, PointRevised).
- [ ] EP run-level evidence does not leak to subsequent runs; `_evidence` never mutated by `run()`; constructor evidence applies every run.
- [ ] EP caches are per-run; `compute_confidence` after any run reads fresh graph values.
- [ ] `set_point_baseline(id,0,0)` + `get_confidence` returns uniform fallback, no crash (ep + svbp); `_is_strong`/`_flush_cache` guarded.
- [ ] `invalidate_point` is truthful (self/missing-new → ValueError; missing-old → False) and idempotent (MERGE).
- [ ] checkpoint dedup failures are logged (INFO for ImportError, WARNING otherwise).
- [ ] ingest_corpus `skipped` counter is honest in both DocumentCreated and AgentSession modes; legacy no-hash backfills; progress resume counts skips.

## Known Limitations (documented, NOT fixed in this batch)

- `supersede_point` shares invalidate_point's pre-fix pattern (no validation, CREATE CORRECTS) — separate follow-up issue.
- SDK-created points never reach the JSONL log (`backup.py` documents this) — rebuild_all can only rebuild what the log contains; separate follow-up (architectural).
- `_apply_one` (in-memory fold) flattens `provenance.speaker` into the stored point; `_upsert`/`rebuild_all` do not write `speaker` to the Falkor node — residual fold-vs-apply divergence, out of scope.
- Source node property parity is order-dependent when `extractedFrom`-bearing PointAdded precedes SourceCreated (`version`/`id` differ) — not normalized in this batch.
- `rebuild_all` is non-atomic (wipe + rebuild; a crash leaves a partial graph) and `ingest_corpus` has no concurrency lock — pre-existing, documented.
