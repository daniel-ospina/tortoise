# P4 — Capture-Path Parity Fixes Implementation Plan

> **For Pi:** Use `executing-plans` to implement this plan task-by-task.

**Goal:** Make the capture path (SDK `capture_session` + hosted `POST /v1/sessions`) behaviorally identical to the commit path on five axes — v2-aware quota estimation, 5000-char truncation parity, `client_commit_id` capture-parity assertion, MITIGATES written on capture, and hosted-capture `speaker` parity.

**Team:** epistemic-team (from issue #1532 `team:epistemic-team`)
**Role:** product-implementer

**Architecture:** The capture path (tortoise/sdk.py `capture_session` and tortoise/hosted_api.py `POST /v1/sessions`) and the commit path share an extraction core (`extractor_v2.extract_session_v2` → Layer-1 payload) but diverge in write semantics: SDK writes `speaker` on turn Points and truncates >5000 silently; hosted rejects >5000 (422), writes no `speaker`, and gates quota with an M2-shaped pre-write estimate; neither path applies MITIGATES operators (the commit path's `mitigate_operator` mechanism); and the capture path's `client_commit_id` is unasserted. This plan (a) extracts the divergent semantics into three shared primitives (capture-window truncation, role normalization, payload-operator application), (b) wires both capture loops through them, (c) makes the hosted quota estimate v2-shaped, and (d) adds the capture-parity `client_commit_id` assertion. No ontology, schema, or new-field changes.

**Dependency chain:** P4 lands after P3 (#1531, done) and P2 (#1530), and its MITIGATES/quota/truncation items are written against P1's capture-v2 wiring (#1529, Lane C order: P2 → P1 → P4). The `client_commit_id` capture-parity assertion rides E5's functional 3-site fix (#1537). See ⛔ Conditional Gate notes.

## Design Decisions

### D1 — The 5000-char window is a capture-side concern, computed once, shared by store + extraction

The stored turn is `f"[{role}] {content[:5000]}"` (both loops). Parity = the extraction input must be the **same window** — a phrase past the cut has no home in any stored turn and must not reach the LLM. Today:
- **SDK:** stores `content[:5000]` and feeds `_session_llm_transcript` (M2), which truncates internally to `content[:5000]` — parity holds (pinned by `tests/test_capture_session.py` truncation test).
- **Hosted:** rejects >5000 with 422 (Pydantic validator) — no silent divergence, but no capture either.
- **v2 wiring (post-P1):** `extractor_v2._edus_from_conversation` uses **raw** `str(t.get("content", ""))` — the S1/S2/S4 LLM stages would see full content while stored turns are truncated → parity break the moment capture routes through v2.

**Decision:** introduce `_capture_turn_window(conversation, cap=5000)` in `tortoise/sdk.py` — returns a new list with each turn's content truncated to `cap` chars (only when non-`str`, coerce first — same semantics as the store loop). Both capture loops call it **once** and use the result for (a) the store loop and (b) the extraction call (`_extract_session_llm` / P1's `_extract_session_v2`). `_session_llm_transcript`'s internal truncation becomes an idempotent no-op. `extractor_v2._edus_from_conversation` is **not** changed — the **commit** path (`_commit_session_v2`) feeds raw conversations with no stored turns and must keep full fidelity. This deliberately scopes truncation to capture.

**Contract change (flagged):** hosted's per-turn >5000 422 is removed — hosted accepts and truncates like the SDK. This is the parity end-state the issue names ("5000-char truncation parity (stored window fed to LLM)"); the SDK's truncate-and-store semantics are the codebase's established philosophy (`summary[:2000]`, `story_arc[:4000]`, pinned SDK test). Callers that relied on 422 for oversized turns now get 200 with a truncated window.

### D2 — Speaker parity: hosted adopts the SDK's role normalization and writes `speaker`

SDK normalizes `role` (`None → "unknown"`, truthy non-string → `str()`), writes `t.speaker=$speaker` on turn Points, and embeds the normalized role in the stored text. Hosted uses `turn.get("role", "unknown")` (stores `None` as-is, no coercion, no `speaker` property).

**Decision:** extract the normalization as `_normalize_turn_role(raw) -> str` in `tortoise/sdk.py`; both loops use it and hosted writes `t.speaker=$speaker`. After D1+D2, for identical input the SDK and hosted produce **byte-identical stored turns** — a direct parity test. Extracted points' speaker is **out of scope**: E3 (#1535) owns read-time speaker derivation from `source_turn_id`; P4 must not clobber `source_turn_id` (cross-lane interface #2).

### D3 — MITIGATES-on-capture: extract the commit path's operator application into a shared helper

The commit endpoint applies payload operators inline (`_execute_commit_writes` §7): IMPL/NAND via `sdk.create_operator(op_type, src, [dst], direction=..., promote_source=False)`, then MITIGATES via `sdk.mitigate_operator(op_id, reason, strength)` with target-IMPL lookup (same-commit map → Cypher fallback → **deep-miss drop** when the target IMPL edge is absent). The capture path writes **no** operators today: M2's `EventAPI.add_operator` gates MITIGATES (`unknown gate`), and M2's relations prompt only emits NAND/IMPL; after P1's v2 wiring, the v2 payload carries MITIGATES in `operators` (two-pass assembly in `execute_embed`) but the capture write never applies them.

**Decision:** extract the operator-application block from `_execute_commit_writes` into a shared module-level helper `apply_payload_operators(proj, sdk, operators, *, point_content_by_id=None) -> None` (new `tortoise/commit_ops.py`, or a sdk method if module placement conflicts — prefer module for a pure helper). The helper consumes **raw payload operator dicts** (`{src, dst, op_type, target, strength}` — the exact v2 `execute_embed` shape). The commit endpoint refactors to call it with `[op.operator for op in reconcile.operators if op.action == "new"]`; the capture path (post-P1 v2 wiring) calls it with the payload's `operators`. Both paths now write MITIGATES with the **identical** mitigation artifact: mitigation Point + `(m)-[:IMPL]->(op)` + `(op)-[:mitigated_by]->(m)` + `mitigation_strength`. Existing commit MITIGATES tests (`tests/test_commit_endpoint.py::TestMitigates`) must pass unchanged — refactor-safety gate.

### D4 — v2-aware quota estimate: deterministic sentence-based ceiling scaled by v2's node classes

Today hosted's 402 gate uses `_session_llm_extraction_estimate` = M2's shape: `2 × Σ_turns min(sentences, MAX_EXTRACTIONS_PER_TURN)` (points + operator allowance). v2's payload produces four non-episodic node classes — points, operators (≤ points via Layer-1 drop), entities, events — from the S2/S4 embed list, which is model-driven and not deterministically capped by conversation size.

**Decision:** replace the M2-only estimator with `_session_extraction_estimate(conversation, *, extractor=None) -> int`:
- `extractor="m2"` → existing `2 × Σ min(sentences, MAX_EXTRACTIONS_PER_TURN)` (unchanged).
- `extractor="v2"` (default, mirrors `commit_session`'s `TORTOISE_EXTRACTOR` selection) → `3 × Σ min(sentences, MAX_EXTRACTIONS_PER_TURN)`: the ×2 (points+operators) plus a ×1 allowance for entities+events, each bounded ≈ points in the embed list. Deterministic, fail-closed (over-counts), preserves the 402 gate's zero-write property.
- Residual risk: v2's S2/S4 could theoretically emit more points than sentences (no hard prompt cap). Mitigated by (i) the commit-side budget adjudication (held >25 / fail >50) the capture write inherits, and (ii) Layer-1 operator drops. **Calibration TODO:** tighten the factor against real v2 production after the 500-Q run (run protocol step 6) — record in `### Open Questions`.

Hosted's gate switches to the v2 shape when capture routes v2 (post-P1). Existing flood-gate tests (`TestSessionFloodGate`) stay green for the M2-mode path and get a v2-mode variant.

### D5 — `client_commit_id` capture-parity is an assertion, not a re-implementation (MECE)

E5 (#1537) owns the **functional** 3-site supersessions inclusion (execute_embed / `_post_commit` / ingest — `extractor_v2.execute_embed` currently omits the `supersessions` arg to `compute_client_commit_id`, `sdk._post_commit` includes it). P4's scope (MECE fix on #1532) is the **capture-path parity assertion only**: a test that pins the capture path through the **same** `compute_client_commit_id(session_id, points, entities, operators, summary, story_arc, events, supersessions)` computation the commit path uses, so capture cannot silently drift to a different id. Concretely: run capture → take the produced payload → assert its `client_commit_id` equals the supersessions-inclusive computation (and re-stamping through the commit path's `_post_commit` signature reproduces the same id). If E5 has not landed when P4 executes, the execute_embed-side of the 3-site agreement is E5's to fix; P4's assertion is written against the post-E5 signature and is gated (see Conditional Gate G2).

```python
def _normalize_turn_role(raw) -> str:
    """Shared turn-role normalization (#1532 D2): None -> 'unknown', truthy
    non-strings -> str() — never a raw non-string stored as `speaker`
    (#721) and never None stored as-is (SDK/hosted drift)."""
    if isinstance(raw, str):
        return raw
    return "unknown" if raw is None else str(raw)


def _capture_turn_window(conversation: list[dict], cap: int = 5000) -> list[dict]:
    """Truncate each turn's content to the stored-window cap (#1532 D1).

    Returns a NEW list; the windowed conversation feeds BOTH the turn-store
    loop and the extraction call so the LLM never sees a phrase with no home
    in any stored turn (stored-source parity, #721). Content coercion matches
    the store loop: None -> '', truthy non-strings -> str() (isinstance-first,
    #721). Idempotent when the caller already truncated."""
    out: list[dict] = []
    for turn in conversation:
        t = dict(turn)
        raw = t.get("content")
        content = raw if isinstance(raw, str) else ("" if raw is None else str(raw))
        t["content"] = content[:cap]
        out.append(t)
    return out
```
