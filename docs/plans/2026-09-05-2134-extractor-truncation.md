# Plan — #2134: v2 extractor truncation (measurement-first + cost-bounded escalation net)

> **For Pi:** Use `executing-plans` to implement this plan task-by-task.

**Goal:** Make v2-mode ingest (`--ingest-mode v2`, the production 5-stage pipeline) stop silently truncating the S2/S4 embed list on large multi-session haystacks — via a **measurement-first** revalidation of the CURRENT 16K cap, then a **cost-bounded one-shot escalation** at the S2/S4 + S1 seams (mirroring #2280) with **permanent telemetry** so the later "bigger budget upfront vs escalate-on-demand" cost optimization is data-driven, and a **fail-loud** residual policy (partial lists never silently pass; the raw-chunk leg stands).

**Team:** epistemic-team
**Tier:** standard (`complexity:standard` — Architecture domain)

**Architecture:** Two legs, sequenced by DATA not assumption. **Leg 1 (measure):** re-run the truncation census at the CURRENT 16K cap on the #2134 recorded-failure set + a fresh mini-set (the deferred #1787 revalidation, made real) to establish the true residual and drive a go/no-go decision. **Leg 2 (escalation net):** on `finish_reason == "length"` at S2/S4 (`_complete_parsed`) and the S1 seam (`run_s1`), re-attempt ONCE at an escalated output budget (`TORTOISE_EXTRACTOR_ESCALATION_TOKENS`, default 32000, valid range [16000..64000]) before any partial-accept or raise — mirroring `_ask_reader_complete` (sdk.py:181-241) + `ask_env_int` (retrieval.py:147). Residual truncation after the one escalation **fails loud** (`truncated_parse_error`, `valid=false`), never a silent partial — the raw-chunk leg (phase-A retention) keeps the session retrievable. Permanent telemetry (escalation count, escalated-recovered, residual-after-escalation, cost delta) makes the upfront-vs-escalation cost question answerable from real runs. **Explicitly NOT built here:** the structural S4 gaps-only delta (#1778, trigger-gated), WS1 read-side ordering, question-type routing.

## Design decisions

### D1 — Escalation trigger + seam: fire ONCE on `finish_reason == "length"`
Trigger = `finish_reason == "length"` at ANY pre-escalation attempt (attempt 1 OR the base-cap error-informed re-prompt attempt 2, P2-10a), regardless of parse outcome — because `length` is the deterministic signal the model exhausted its output budget, and a rung-1 "successful" parse of a truncated JSON is NOT proof of completeness (tail-cut recovery can turn a mid-list cut into a valid shorter list — the silent-loss class). Seams: S2/S4 via `_complete_parsed` (both call it), S1 via `run_s1` (which calls `_complete` directly, bypassing the ladder), and — the THIRD production `_complete_parsed` caller — the classify-later **kind_classifier adjudication** path (kind_classifier.py:405, `max_tokens=ADJUDICATION_MAX_TOKENS=1500`, inside `extract_session_v2`'s classify(S2)/classify(union) passes). **Escalation is SCOPED OUT of the kind_classifier seam (P1-30):** `_complete_parsed` gains an `escalate: bool = True` parameter and `kind_classifier._adjudicate_batches` passes `escalate=False`. Rationale: (a) 32000 ≈ 21× the 1500 adjudication budget — a 40-item batch's closed-vocab kind map is genuinely length-reachable at 1500 but that headroom is disproportionate; (b) a residual fail-loud `_ParseError` would be swallowed by the adjudicator's fail-open `except Exception` → kNN top-1 fallback (kind_classifier.py:409-416) — the damage would be invisible-by-design while burning 21× budget for an outcome the fail-open already provides; (c) the telemetry would be DROPPED at the seam anyway — the adjudicator's `finally` block (kind_classifier.py:418-434) forwards only `attempts`/`retries`/`truncated`/`deadline_aborts` from `batch_stats` into `usage` → `stats["llm"]` → `_rollup_llm` (`llm_stats`), NEVER into `_rollup_recovery` (`recovery_stats`), so `recovery.*` escalation counters would never reach `recovery_stats` → `run.py` `recovery`. A length-truncated adjudication therefore keeps TODAY's behavior verbatim: one `_complete_parsed` call, the #1746 ladder (rung-4 partial-accept → `stats["partial"]`, or `_ParseError` → `except Exception` → kNN fail-open) — pinned by `test_kind_classifier_adjudication_length_no_escalation` (calls==1, direct kNN fail-open, guard pin). Fire **once** (the `escalated` flag) on the FIRST `length` at ANY pre-escalation attempt — attempt 1 OR the base-cap error-informed re-prompt attempt 2 (P2-10a) — and never on a post-escalation attempt.

### D2 — Escalation budget: `TORTOISE_EXTRACTOR_ESCALATION_TOKENS`, default 32000, valid range [16000..64000]
New helper `_extractor_escalation_tokens(base: int | None) -> int` in `extractor_v2.py`, mirroring `ask_env_int` (retrieval.py:147-160) **exactly** — `ask_env_int` NEVER saturates: a valid value in [16000, 64000] is used AS-IS; a value below 16000, above 64000, or garbage falls back to the default 32000. There is NO "clamp to 16000" arm — 15999 and 64001 are BOTH out-of-range, never saturated to a bound. `_stage_cap`'s inline env-read pattern supplies the fail-open warning (invalid/out-of-range env never crashes). The caller escalates **only when `esc > (base or 0)`**. **When `esc ≤ base` (e.g. Option B raises `TORTOISE_EXTRACTOR_MAX_TOKENS` to ~32K while the escalation knob stays 32000), the length-truncation is RESIDUAL — fail-loud `truncated_parse_error`, never rung-4 partial-accept** (P2-15: the un-escalatable truncation must be honest; the escalation knob must move in lockstep with any base-cap raise — see the go/no-go note). A disabled/unavailable escalation therefore degrades to fail-loud, NOT to the old silent partial — the owner mandate ("partial lists never silently pass") holds on every config.

**Lane policy (P2-17):** escalation is **default-ON on every lane** that calls `extract_session_v2` — eval (`tools/longmem_eval/ingest_v2.py`), SDK capture (`sdk.py:2213` + `_extract_session_v2` :2818), and hosted capture (`hosted_api.py:6228`). The mandate is lane-agnostic (a silent partial tail-drop on the capture lane is the same damage as on the eval lane), and escalation fires only on `finish=="length"` (the same pathological truncation the fix targets), so the capture-lane cost/latency delta is accepted by design. **Hosted-capture kill model (P2-26, verified):** there is NO in-code or platform "outer request envelope" timeout — `capture_session` (hosted_api.py:5879) runs `sdk._extract_session_v2` SYNCHRONOUSLY in the async handler (plain uvicorn, no per-request timeout middleware), and `fly.toml` carries only a 15s HEALTH-check timeout. A platform/worker kill mid-escalation therefore records NOTHING (the same honesty class as today's long extractions — the escalation budget extends the killable window to 2×0.05×esc per stage = 3200s at the default, 6400s at the 64000 bound). The D3b fallback is tied ONLY to the actual triggers — `_complete` raising after deadline kill / adapter stall / transient exhaustion — not to any envelope.

### D3 — Residual policy: fail-loud, never a silent partial (owner direction)
After the ONE escalation, if `finish_reason` is STILL `"length"` (residual truncation): **do NOT partial-accept — and do NOT let any ladder rung clean-parse a shorter parse.** The reviewers' gap: rungs 1-3 (`_parse_json` progressive tail-cuts at :4334, `_repair_candidates` `}`-closers at :4559, `_validate_output_shape` treating ABSENT sections as valid at :4428) can clean-parse a TRUNCATED response cut at a section boundary → a silent tail-drop with `valid=true`, no census class, and neither `escalated_recovered` nor `escalated_residual` bumped. The fix makes the invariant airtight: **a residual (`escalated and finish == "length"`) is treated as truncated UNCONDITIONALLY — the residual branch has NO parse-acceptance path** (P1-7). The escalated return with `finish=="length"` ALWAYS bumps `escalated_residual` and raises `_ParseError(truncated=True)` → census `truncated_parse_error`, `valid=false` — regardless of whether its text is balanced complete-but-shorter JSON, a mid-list cut, or garbage. A strict canonical full-parse (`_parse_canonical_strict` — fence-strip + brace-balanced `json.loads`; NO progressive tail-cut loop, NO sanitize, NO repair closers, NO absent-section shape gate, NO rung-4) is run **only to enrich the error `excerpt`, never to accept** — so a balanced complete-but-shorter residual text can never return a shorter dict (`escalated_recovered==0` AND `escalated_residual==1` always; the 4-bucket invariant holds).

**Mechanism (P2-9):** the canonical-only residual parse is a NEW named helper `_parse_canonical_strict(response) -> dict | None` (raises nothing; returns the parsed dict or `None`), NOT `allow_partial=False` — `allow_partial=False` would only gate rung-4 while rungs 1-3 (`_parse_json`'s tail-cut loop, `_repair_candidates`, `_validate_output_shape`'s absent-section validity) STILL clean-parse a section-boundary cut, so it is provably insufficient as the residual gate. `_complete_parsed` calls `_parse_canonical_strict` in the residual branch purely for the excerpt; the raise is unconditional. All non-`length` paths stay byte-identical (their tests stay green); the ~7 length-path fixtures are re-pinned by the Task 0/1 migration step (P1-20). For an S2 residual, `embed_list` is empty and S4 re-emits over the empty base — an S4 recovery rescues the session (recoverable `truncated_parse_error`); `empty_embed_list` fires only on the S2+S4 double residual (D7/P2-18). For an S4 residual, the S2 output stands (existing "S4 failed — kept S2 output" graceful degradation). The raw-chunk leg (phase-A retention, ingest_v2.py:506-518) keeps the session retrievable. `partial_parse` therefore trends toward **zero** on the recorded set.

**Escalation accounting invariant (P1-1, P2-1, P2-46):** every escalation event lands in EXACTLY one bucket — the return is never unaccounted:
`escalated == escalated_recovered + escalated_residual + escalated_abort + escalated_sloppy`
**The invariant holds at every RETURN and every projected outcome. The accepted exception (cross-ref P2-26): a process/platform kill mid-escalation on the hosted-capture lane (no outer request envelope — `capture_session` runs `_extract_session_v2` synchronously) bumps `escalated` in-memory but produces NO outcome row, so all four buckets read 0 — the one case a live escalation event goes unaccounted, and it is accepted (same honesty class as today's long extractions).**
- `escalated_recovered` ⟺ the escalated call returned AND `finish != "length"` AND the final return is FULL — on S2/S4: `not stats["partial"]`; on S1: the full summary returned (S1 has no parse/partial ladder — P2-29).
- `escalated_residual` ⟺ the escalated call returned AND `finish == "length"` (unconditionally truncated → fail-loud).
- `escalated_abort` ⟺ the escalated `_complete` call OR the esc-budget re-prompt RAISED (transient-after-retries / deadline kill / fatal 4xx / adapter read-timeout) — see D3b (S2/S4: head-reparse fallback; S1: return attempt-1's retained summary, P1-21; the re-prompt raise returns the esc response's rung-4 head, P1-40).
- `escalated_sloppy` ⟺ the escalated call returned `finish != "length"` but the final parse is STILL partial/failed after `_PARSE_RETRIES` (headroom granted, model still emitted malformed JSON). **Terminal semantics (P2-33/P2-47): the sloppy terminal has TWO subcases — (a) a rung-4 head EXISTS (a valid embed prefix was found): RETURN the rung-4 partial-accept head with `partial_parse` recorded (`stats["partial"]=True`) + `escalated_sloppy` bumped — NOT a `_ParseError` raise and NOT a head-discard; (b) NO valid prefix (rung-4 also fails — no embed prefix at all): bump `escalated_sloppy` FIRST (the 4-bucket invariant must hold even on a raise), then `_parse_json_robust` raises `_ParseError(truncated=False)` → census `parse_error` — the ONLY sloppy terminal that raises.** The raise+head-discard alternative for the head-EXISTS subcase is REJECTED as a behavior REGRESSION vs today's recoverable `partial_parse` for a stop+cut response (the head-usage is renamed honestly `sloppy` instead of silently `recovered`). NOT recovered, NOT residual. The 4th bucket makes "escalated − recovered − residual" explicit instead of a derived residual (the reviewers' airtightness point).

**`stats["partial"]` lifecycle (P2-31):** rung-4 sets `stats["partial"]=True` and NOTHING clears it. A terminal FULL parse must OVERRIDE it: when the sloppy arm's error-informed re-prompt at the esc budget returns a FULL list, `_complete_parsed` clears/overrides `stats["partial"]=False` (or resets it before each parse attempt) — otherwise (a) the recovered-bucket condition `not stats["partial"]` fails on a SUCCESS arm (the 4-bucket invariant breaks: a full dict returned with `escalated_recovered` never bumped) and (b) the stage caller's unconditional `if stage_stats.get("partial")` (extractor_v2.py:3668/:3729) fires `partial_parse` + `errors.append` on the FULL recovered list → `valid=false`, inverting D6's "escalation-recovered stays valid=true". **Post-escalation length (P2-31/P2-42):** a length on the esc-budget re-prompt (the `length→stop-malformed→length` 3-call arm) is RESIDUAL — `escalated_residual` + `truncated_parse_error` — because the residual rule `escalated and finish=='length'` re-evaluates `finish` on EVERY post-escalation attempt, never only the first escalated return; **the residual branch ALSO CLEARS `stats["partial"]=False` BEFORE the raise — the sticky rung-4 flag from the sloppy intermediate head must not leak onto the residual terminal (P2-42: without the clear, the S2/S4 callers' post-except `if stage_stats.get("partial")` fires a phantom `partial_parse` bump + "output partial" error string on a head that was DISCARDED — `error_census == {truncated_parse_error:1, partial_parse:1}` for ONE terminal, contradicting D7's seam split + Task 6's ZERO `partial_parse`).**

### D3b — Escalation-episode failure policy (abort bucket; the escalated call AND the esc-budget re-prompt can raise)
The escalated `_complete` call — and, on the sloppy arm, the esc-budget re-prompt (call 3) — can raise: transient 429/5xx exhausted its retries, a deadline kill, a fatal 4xx, or the fixed adapter read timeout (model_adapters.py:149/:254 `timeout=(10, 60)` — a stalled socket read dies at a fixed 60s). Without a policy, the truncating pre-escalation attempt's retained response is never parsed, the recoverable head is discarded, and the census shifts `partial_parse` → `transient_*`/`empty_embed_list` KILLER for a transient failure. **The re-prompt raise is the SAME hazard one call later (P1-40): on `[base length → esc stop rung-4 partial → re-prompt RAISES]`, the intermediate rung-4 head (`stats["partial"]=True`, :4703) is discarded with no fallback, `recovery["escalated"]==1` with all four buckets 0 (the airtight invariant breaks), and the raise propagates unguarded because `_complete_parsed` places `_complete` OUTSIDE the parse try (:1045 vs :1061). FIX (three parts):

1. **Fallback = re-parse the truncating pre-escalation attempt's ALREADY-CAPTURED retained response under a TRUNCATED-HEAD parse — canonical-then-rung-4 ONLY, ALWAYS classed partial** (P1-5, closing cycle-1's silent-tail-drop re-open): run `_parse_canonical_strict` (D3 — canonical brace-balanced `json.loads`, NO progressive tail-cut loop, NO sanitize, NO repair closers, NO shape gate) on that retained `response`; if that yields nothing, fall to `_longest_valid_prefix` (rung-4). Rungs 1-3 must NEVER run on a KNOWN length-truncated input (a section-boundary cut would clean-parse to a shorter valid dict — the exact silent tail-drop). The recovered head is ALWAYS recorded `partial_parse` (RECOVERABLE, `stats["partial"]=True` set UNCONDITIONALLY — the input is known `finish=="length"`) and `escalated_abort` is bumped — never a silent `valid=true` return. If BOTH parses yield nothing → fail-loud `truncated_parse_error` + the raw-chunk leg stands.
