## Design decisions (with alternatives considered)

### D1 — Error-class taxonomy: single source, consumed from P2 (`tortoise/llm_errors.py`)
**Decision:** M2 does NOT define its own error taxonomy. P2 (#1530) owns the taxonomy module at **`tortoise/llm_errors.py`**, exporting `classify_llm_error(exc) -> "fatal" | "transient"` and `is_fatal_status(status: int) -> bool`. Fatal class = **401/402/403**; transient = **429/5xx/timeout/connection** (the MECE-fix contract). M2 imports `from tortoise.llm_errors import classify_llm_error` — one taxonomy, no divergence.
- **Ordering hedge (documented, review-gated):** if P2 is not yet merged when M2 is implemented, M2 drops a provisional 8-line copy into `tools/longmem_eval/preflight.py` marked `# TODO(#1530): import from tortoise.llm_errors when P2 lands`, with a unit test pinning the exact fatal/transient status mapping. The plan-review gate **flips the import to P2's module before merge** — the provisional copy must never ship as the long-term source. This is the verify-gate-sanctioned "or consume the taxonomy module directly" branch.
- *Alternatives rejected:* (a) M2 defines its own taxonomy — violates the MECE serialization fix ("one taxonomy, no divergence"); (b) P2 consumes a harness-local module — backwards, the production module lives in `tortoise/`, the harness already imports from `tortoise/` (reader.py imports `tortoise.ingest._PROVIDERS`, `tortoise.models`).

### D2 — Pre-flight mechanism: dedicated `tools/longmem_eval/preflight.py`, gated before the loop in `run_main`
**Decision:** a new module `tools/longmem_eval/preflight.py` with `run_preflight(*, reader, judge, extractor_model, mock=False) -> dict`. `run_main` calls it after building reader/judge/extractor_model and **before `run_evaluation`** — nothing in the 500-Q loop starts until the gate passes. `--mock` → pre-flight is a no-op (`{"status": "skipped", "mock": true}`); new `--skip-preflight` flag bypasses the gate for debugging (mirrors the `--no-download` precedent). Per-model pings run **once each** (single attempt, no retry at gate time — a gate that can't ping won't survive 500 questions; the run's per-question backoff handles transients later). All checks run and **aggregate** results before raising, so the operator fixes keys once, not iteratively.
- Pre-flight checks, in order: (1) judge key presence (config-only, no network — fastest fail), (2) extractor billing probe (S1-sized, D3), (3) reader ping, (4) judge ping. Any fatal-class result → `PreflightError` listing **all** failures → `run_main` exits non-zero with an actionable message.
- Ping interface: add a `ping(probe)` method to the `LLMReader` / `LLMJudge` wrappers (they know their underlying transport) and to nothing else — the extractor adapter's `complete(system=, user=)` IS the ping interface. `preflight.py` calls only public methods.
- *Alternatives rejected:* (a) pinging through `reader.answer(...)`/`judge.judge(...)` — those need context hits / golden answers and would exercise prompt logic, not key+endpoint health; (b) pre-flight inside `run_evaluation` — the gate must fire before the dataset-driven loop and before checkpoint writes; (c) stop-at-first-failure — worse ops UX (multiple key fixes = multiple reruns).

### D3 — Billing probe = realistic S1-sized call on the extractor model
**Decision:** the extractor ping **is** the billing probe. It sends one completion shaped like a real S1 story-digest call (system prompt mirroring `S1_TMPL`'s digest instruction at ~1/10 scale + a 2–3-turn transcript as user) through the extractor model's provider (DeepSeek-direct primary after P2 / OpenRouter today — surfaces 1/2). Constants `PROBE_SYSTEM` / `PROBE_USER` live in `preflight.py`. Budget: system ≤ ~2000 tokens, user ≤ ~500 tokens (asserted in a unit test). Cost: one tiny completion per run.
- **Why S1-sized** (epic contract: "distinguish balance vs per-request cap"): if the probe with a realistic S1 request shape succeeds, then a mid-run 402 is a **balance** problem (fatal, abort); if the provider/model would reject S1-shaped requests (per-request cap, content filter, wrong model id), the probe fails with a **config** error distinct from 402 — the operator sees which before spending a run. A token-budget-blowout S1 call is what the 500-Q run actually performs, so the probe de-risks the true call shape.
- *Alternatives rejected:* (a) bare `/models` endpoint ping — doesn't exercise the completion path (no balance/cap signal); (b) minimal "hello" completion — too small to surface a per-request cap on S1-sized requests; (c) a real full-size S1 call — wastes tokens and couples preflight to `extractor_v2` internals (M3 owns `_complete`).

### D4 — Mid-run fail-fast: classification-aware retry + fatal abort at the run-loop level
**Decision:** two changes to the existing loop, keeping the current per-question isolation semantics for transients:
1. **`_call_with_backoff`** (run.py): on exception, `classify_llm_error(e)`; **fatal → re-raise immediately** (no backoff sleep — retrying a 401/402/403 is pointless), transient → retry with exponential backoff exactly as today.
2. **Per-question guard** in `run_evaluation`: the `except Exception` block re-raises when `classify_llm_error(e) == "fatal"` as `FatalProviderError` (new, in `preflight.py`) — **aborting the run** instead of recording a per-question failure. Rationale: pre-flight already proved the keys at run start; a mid-run 401/402/403 means the key died (billing cap hit, revocation) — continuing would silently produce 500 garbage questions, exactly what E2E-2 ("a run cannot silently degrade") forbids. `run_main` catches `FatalProviderError` → clear message → non-zero exit. Transient-exhausted exceptions still record into `failures` and continue (existing behavior — `test_single_question_failure_does_not_abort_run` must keep passing).
- **Verify-gate fix covered (judge reliability):** classification only ADDS fatal-abort; judge gpt-4o timeouts/5xx/429 continue to be retried by `_call_with_backoff` before a question is marked failed — mid-run judge failures are retried then recorded (never silent). D4 makes this behavior explicit and tested.
- **M3 boundary (S15):** M3's `_complete` (extractor_v2) handles retry/backoff + bounded `max_tokens` INSIDE the extractor. M2's run-loop guard is the eval-level counterpart: when the extractor's non-retryable 4xx propagates out of `extract_session_v2`, M2's guard classifies it fatal → abort. Both consume the same taxonomy (Cross-lane).
- *Alternatives rejected:* (a) treat fatal like any failure (record + continue) — silent 500-Q degradation, defeats M2's purpose; (b) a global `--abort-on-fatal` flag — fail-fast is the contract default, no opt-out.

### D5 — Capture-path warm-up ping: **delegated to P2 explicitly** (MECE fix)
**Decision:** M2 ships the reusable primitive (`preflight.ping_model`) and an explicit interface contract; **P2 (#1530) wires the capture-path warm-up**, because P2 owns provider selection (`TORTOISE_EXTRACTOR_PROVIDER`) and the adapter — the warm-up belongs where the provider is chosen, before S1. Contract for P2: on capture/extraction start, call `ping_model(provider_adapter, what="capture-extraction")`; a fatal-class result surfaces through P1's fail-closed error contract (non-200 or additive `warnings`, never silent `extracted: 0`) — never retried as if transient, never ignored.
- *Alternatives rejected:* (a) M2 wires it into `extract_session_v2` directly — the production capture path is P1/P2 territory; an unconditional extra network call per session in `extract_session_v2` needs P1's error-surfacing contract (not yet landed) and the provider router (not yet landed); (b) M2 silently drops the warm-up — the MECE fix requires the plan to address it; delegation is the sanctioned option ("or delegate to P1/P2 explicitly").

### D6 — Report recording: additive `extra["preflight"]`, no report.py changes
**Decision:** the pre-flight result dict rides the existing `extra` passthrough in `outcomes_to_report` → `build_report` (`extra["preflight"] = {...}`). `report.py` is untouched (M7 owns the report shape; M7 may later promote preflight into `methodology`). `_print_summary` prints a one-line preflight status so the gate result is visible in the run's stdout. `run_evaluation`/`outcomes_to_report` gain an additive `preflight: dict | None = None` kwarg (default `None`) — all existing callers/tests stay compatible.

## Implementation steps (ordered)

Each step is independent-verifiable; steps 3–5 are the code delta, step 6 is delegation-only.

### Step 1 — Verify P2's taxonomy module is consumable (`tortoise/llm_errors.py`)
- **File:** no change in this step (consumption check).
- Confirm `from tortoise.llm_errors import classify_llm_error, is_fatal_status` resolves on the 1509-plans base (P2 #1530 landed). Pin the contract in a comment at the import site: `classify_llm_error(exc) -> "fatal" | "transient"`; fatal = 401/402/403 (urllib `HTTPError` status, provider-typed 402 variants), transient = 429/5xx/`TimeoutError`/`URLError`/connection.
- **If not landed:** create the provisional copy per D1 (in `tools/longmem_eval/preflight.py`, `# TODO(#1530)` flag) + pin the mapping in a unit test. The plan-review gate flips to the P2 import.

### Step 2 — `tools/longmem_eval/preflight.py` (NEW)
- `PreflightError(Exception)` — fields `checks: list[dict]` (aggregate failures) and a formatted message.
- `FatalProviderError(PreflightError)` — raised mid-run by the loop guard (D4); `run_main` catches it for a clean exit.
- `PROBE_SYSTEM` / `PROBE_USER` constants (D3 — S1-sized; comment referencing `S1_TMPL`'s shape).
- `ping_model(model, *, what: str) -> dict` — one realistic completion via the model's public interface (`complete(system=, user=)` for the extractor adapter; `ping(probe)` for reader/judge wrappers). Returns `{"what", "model_id", "provider", "key_env", "status": "ok" | "fatal" | "transient", "latency_ms", "detail"}`. Fatal → included in the aggregate failure list.
- `check_judge_key(judge) -> dict` — **explicit key-presence check**: resolve the judge's provider from its model spec (default `openai:gpt-4o-2024-08-06` → **`OPENAI_API_KEY`**) and verify the env var is set; message must name the expected key env var (e.g. `"judge key missing: OPENAI_API_KEY (judge model openai:gpt-4o-2024-08-06)"`). No network.
- `run_preflight(*, reader, judge, extractor_model, mock=False) -> dict` — orchestration: mock → skipped dict; else run the four checks (D2 order), aggregate, raise `PreflightError` on any fatal (message lists all failures); else return the per-check dict + `{"status": "ok"}`.
- Export `ping_model` for P2's capture-path wiring (D5).

### Step 3 — `tools/longmem_eval/run.py` — classification-aware retry + fatal abort
- `_call_with_backoff`: on `except Exception`, `cls = classify_llm_error(e)`; `if cls == "fatal": raise` (no sleep); else current retry path unchanged.
- `run_evaluation` per-question guard: in the `except Exception as e` block, `if classify_llm_error(e) == "fatal": raise FatalProviderError(...) from e` — aborts the run; transient-exhausted continues to record into `failures` (unchanged).
- `run_evaluation(...)` / `outcomes_to_report(...)`: additive `preflight: dict | None = None` kwarg; thread it into `extra={"preflight": ...}` (only when not None).
- `run_main`: after building models, `if args.mock or args.skip_preflight: preflight = {"status": "skipped", ...} else: preflight = run_preflight(...)`; wrap the `run_evaluation` call in `try/except FatalProviderError → print message → raise SystemExit(1)`; pass `preflight` through; `_print_summary` prints a preflight status line.
- CLI: add `--skip-preflight` (help: "bypass the pre-flight API gate (debugging/offline only — the run-protocol gate must be ON for pilot/500 runs)").

### Step 4 — `tools/longmem_eval/reader.py` + `tools/longmem_eval/judge.py` — additive `ping(probe)`
- `LLMReader.ping(probe: str) -> str` — delegates to `self._model.complete(system=PROBE_SYSTEM, user=probe)`-style minimal call (probe text passed by preflight; returns raw text; HTTP status errors propagate for classification). Same for `LLMJudge.ping(probe: str) -> str` via `self._model.complete(user=probe)`. Pure additions — no behavior change to `answer`/`judge`. MockReader/MockJudge return a constant (preflight never pings them in mock mode, but the protocol stays total).

### Step 5 — Tests (see Tests section) in `tests/test_longmem_preflight.py` (NEW) + one edit to `tests/test_longmem_runner.py` (guard: existing transient test must still pass).

### Step 6 — Capture-path warm-up: delegation handoff (NO M2 code)
- Deliverable is the exported `ping_model` + the interface contract recorded in **Cross-lane interfaces** below for P2 (#1530) to implement. M2's plan-review gate verifies the delegation is recorded and P2's issue references it — M2 itself does not touch `extract_session_v2` / `sdk._extract_session_llm` / `hosted_api.py`.
