## 1.3 Journey detail (flows with entry/exit + edge cases)

### J1 — Integrate `/v1/context` into an app (P1)

1. **Entry:** P1 has a team namespace and a per-graph API key (`tt_…`, Bearer) — per #2083 joint contract co-design; the contract is reversible to per-user slices without breaking (D3).
2. **Provision:** read the contract spec (`POST /v1/context` request/response shape — see Interfaces §6) and the SDK signature (`volunteer_context(window, session_id=None, prior_context=None, min_confidence=0.7, max_pointers=3, why=True)`).
3. **Per-turn call:** build `{window: [Turn], session_id?, prior_context?, min_confidence?, max_pointers?, why?}` (≤ 15 KB, ≤ 1000 turns) → POST → receive `200 {pointers, why, surfaced, block, degraded_reason}`.
4. **Inject:** default silent — place `block` into model context (Claude Code `additionalContext`-style); optional `surfaced` one-line marker for consent/disclosure surfaces ("memory surfaced 3 items").
5. **Handle outcomes:** empty `pointers` + `degraded_reason` (fail-open content — never break the turn); auth failure 401/403 (fail-closed — never cross-team); 429 (backoff, not hard failure); 503 (reflex read path is zero-LLM — must NOT 503; if it ever does, degrade).
6. **Continuity:** pass `session_id` + `prior_context` for re-mention suppression and cross-turn dedupe.
7. **Exit:** app injection loop is stable under the latency budget (≤ 300 ms p95) and the SLO is met; degraded runs are observable via `degraded_reason`.

**Edge cases (J1):** empty graph (clean empty: `{pointers: [], why: [], block: "", surfaced: [], degraded_reason: null}` — NOT a degradation); first recall on a fresh graph (empty, no error); window > 1000 turns OR empty window `[]` (422 — SDK validates before sending); `min_confidence` boundary (0.0 / 0.7 / 1.0); pointer budget (0 / 1 / 3 default / 5 max); 15 KB request cap + ≤ 8 KB block cap; latency breach (degraded_reason `"timeout"` — fail-open); concurrent re-POST same `session_id` (idempotent — 0 new nodes); cross-team key (401/403 — fail-closed auth).

### J2 — Live inside an app with memory (P2)

1. **Entry:** P2 opens a conversation in an app whose agent polls `POST /v1/context` per turn.
2. **Routine turn:** no pointer fires (reflex precision-bias: courtesy turns, re-mentions, below-notability openers never fire) → no marker, no injection — P2 experiences zero noise.
3. **Belief-touching turn:** a state is recalled → the app injects the block silently and renders the one-line marker "memory surfaced N items" **on consent/disclosure surfaces (required there — what makes W5's disclosure-visible consent real at the point of use; silent-only rendering is permitted only in pure model-context surfaces, and the contract exposes `surfaced` unconditionally so the disclosure layer can never be dropped — see J6/S11)**.
4. **Contested turn:** the app renders the why-block for a contested state — **flag-first**: the `contested` badge rides the belief line, conflict block renders immediately after the belief (never buried under "dig deeper"); banded confidence for humans ("high/medium/low"), raw numbers for agents in the contract.
5. **Superseded turn:** "see what changed" pointer appears; the superseded predecessor never reads as the current belief.
6. **Dig-deeper:** P2 (or the agent on P2's behalf) follows a labeled pointer ("read supports" / "read the counterargument (NAND)" / "see what changed (superseded)") — resolving through existing tools, no new navigation surface.
7. **Exit:** P2 either trusts the belief (visible support chain) or challenges it (visible counterargument); the memory is legible — poisoned memory shows its bad source.

**Edge cases (J2):** uncontested point carries no conflict noise (all W4 keys optional); empty graph (no marker — clean silence, not an error); first-ever recall (marker appears for the first time — expectation-setting); error state (no marker + quiet `degraded_reason` — fail-open, never a broken turn); superseded point (never current-belief framing); highly contended but most-believed state (badge + belief together — flag-first, not conflict-drama).

### J3 — Recall a contested state on an existing surface (P3)

1. **Entry:** P3 queries through an EXISTING surface (`tortoise_search`, `tortoise_analyze`, `tortoise_ask` — ask now unblocked per #2013 MERGED — or MCP `recall_state`).
2. **Enriched item:** the recalled item carries the additive W4 keys (§6 interface): `why` (support chain ≤ 3 + EP weight), `conflicts` (active NANDs ≤ 2, contested flag), `supersession` (status + superseded_by + supersedes, bi-temporal), `tradeoffs` (decision alternatives + EP weights + mitigations), `dig_deeper` (≤ 3 labeled pointers).
3. **Flag-first:** `contested: true` + `variance` are TOP-OF-ITEM fields (agents parsing top-down see the dispute first); a `warnings: ["contested"]` array for agents.
4. **Reasoning:** P3 (or the agent) answers "why is this believed?" (support chain + EP weight), "what contradicts this?" (conflict block), "which alternative does EP favor, and what are the mitigations?" (trade-offs, decision points), "where do I dig deeper?" (labeled pointers) — from the surfaced context alone (A11 invariant).
5. **Ranking participation:** when the query touches the conflict, contentiousness participates as a scored ranking signal (boost when conflict is RELEVANT), not just a why-trigger.
6. **Exit:** P3 follows a dig-deeper pointer (resolves through existing tools) or proceeds with belief + conflict in hand.

**Edge cases (J3):** uncontested point (no conflict noise — empty `conflicts`, absent keys); empty graph (search returns empty; ask abstains with measured vacuity — `abstained` + `NO_EVIDENCE_TEXT`); first recall of a new point (no support chain yet — low EP weight, no conflict); superseded predecessor recalled (shows superseded + "see what changed"); retracted point (tombstone — excluded by default, per ONTOLOGY); error states (search fail-open `_safe` wrapper; ask gated config); latency budget (enriched assembly must stay within ≤ 300 ms p95 — bounded traversal `_select_subgraph`, persisted EP reads, no LLM in hot path); N+1 (batch EP reads via `get_contested_claims`, never per-result variance queries).

### J4 — Run the W2 write-path benchmark + fix-wave (P3 eval)

1. **Entry:** frozen planted-gold corpus (fictional sessions, 173-class salient units with verbatim anchors, true-but-routine distractors, attribution hazards) + sealed answer key + committed CI baseline (`main.json` + justification discipline).
2. **Run:** ingest gold sessions through the REAL session→graph pipeline (`session_import` parsers → point/operator write-back → `dream()` EP updates → provenance stamping → REPHRASE-linked dedup). BPRE default; `--full` opt-in; HARD_STOP_USD cost bound.
3. **Grade:** mechanical checks authoritative (anchor-present substring, quote fidelity, hallucination denominator, distractor scan, provenance field presence); blind judges (salience judge never sees verbatim anchors); verbatim control lane calibrates the judge ceiling.
4. **Compare:** `--compare` gate vs committed baseline → PASS or **FAIL** (a stripped provenance field FAILS CI — the benchmark can fail).
5. **Publish or fix:** pass → publish number + receipt. Fail → **publish the bad number** (fix-wave protocol) → name failure classes → ship targeted fix → re-run SAME frozen corpus + pinned judge → bless-with-justification (or corpus-bless for intentional fixture change).
6. **Exit:** committed baseline updated with justification; published number + receipt naming commit/hash/pin; failure classes named.

**Edge cases (J4):** 100% sessions-emitting invariant (silent-skip pattern in parsers is the #1 detection target); distractor leakage ≤ 1/run tolerance; quote fidelity (ungrounded quote = hallucination); gold-only edit invalidates baselines (fixtures_hash covers fixture AND gold files); judge-blindness violation (lexical matching degrades); cost blowup (BPRE default + HARD_STOP_USD); CI gate degradation to rubber-stamp (justification REQUIRED to bless regressions — "without that discipline the gate degrades within months").

### J5 — Run the W3 harness suites + why-layer suite (P3 eval)

1. **Entry:** fixture set + sealed gold (gold dir separate; `gold` key in a fixture = validation error) + `fixtures_hash` + holdout split (~15%) + hermetic one-DB-per-run (TORTOISE_TEST_MODE, per-session 48-bit graph-name nonce) + env-key stripping (no ambient LLM/reranker).
2. **Replay:** replay fixtures through REAL seams — MCP tools (`tortoise_search`/`tortoise_ask`/`recall_state`), `tortoise/claude-hooks/session-{start,end}.sh`, `session_import`. Deterministic seed.
3. **Grade:** per-turn injection decision vs sealed gold — know-to-ask failure (inject exactly when gold says `should_retrieve`, silent otherwise), false-fire rate (courtesy/re-mention turns must NOT fire), push precision/recall under the pointer budget, write-back fidelity + provenance, continuity pairs (writer fixture → read in reader fixture), source-isolation violations = 0.
4. **Why-layer suite (Tortoise-original):** given ONLY the surfaced context for a state with planted conflicts (NANDs, superseded predecessors, contested alternatives), grade "what contradicts this?" / "why is this believed?" / "where do I dig deeper?" — conflict-surfacing rate + dig-deeper navigation accuracy (A11).
5. **Gate:** `--compare` vs committed baseline; a regression fails CI; config mismatch → `inconclusive`, never rubber-stamp.
6. **Exit:** committed baseline + published numbers on the real seams.

**Edge cases (J5):** seam-vs-contract drift (harness MUST grade real seams — gbrain codex cautionary tale: "contract rows do NOT measure third-party harness behavior"); env-key leak (silent LLM path confound — A3); source-isolation across team namespaces; preamble-slug anti-gaming (preamble injections must not count); re-mention suppression; below-notability openers never fire; superseded facts never surface as current; holdout leakage; judge blindness; cost bounds.

### J6 — Opt in/out of automatic ingestion (P3; UI to #1976)

1. **Entry:** `session_recording` flag (default ON, ToS-covered per onboarding Q3 / #1927); UI surfaces (onboarding toggle, Settings → Memory sources) are #1976's, this epic ships only the toggle CONTRACT (S11) + the engine quality.
2. **Capture on:** `POST /v1/sessions` gate order 409 (recording off) → 422 (invalid harness) → 503 (no LLM provider) → 402 (quota); 2xx receipt `session_capture_receipt_{harness}`; `session_id` idempotency (re-POST = 0 new nodes).
3. **Write-back (the W5 QUALITY gap):** parsers → points/operators → `dream()` EP updates → **provenance stamping on every point** → REPHRASE-linked dedup; triage-with-verified-segment rescue (anti-hallucination gate — only admit sub-gate content the judge's own quotes verify); frozen version-stamped write verb (`protocol_version` in every response).
4. **Toggle off:** server rejects new capture with **409** (state-conflict: recording policy off); existing data untouched; per-harness last-error surfaces the message on the dashboard row; disclosure-visible.
5. **Disclosure:** "memory surfaced N items" marker at the consumer surface (J2) — what makes consent real at the point of use.
6. **Exit:** capture + write-back speak the frozen verb; toggle honored on BOTH REST and MCP paths (shared `_capture_session_impl` — can never drift).

**Edge cases (J6):** flag checked on one path only (REST vs MCP drift — shared impl prevents); gate precedence per verified code order (boundary 422 → 409 → 503 → 400 turn-cap → 422 empty/blank → 402 quota); 409 not honored; toggle contract not exposed for #1976's UI; disclosure marker missing; concurrent re-POST same session_id (idempotency under concurrency — race); concurrent ingestion with content-hash dedup (no duplicate points); EP updates on concurrent ingestion (no α/β corruption).

### J7 — Audit a published benchmark run (P4)

1. **Entry:** published report (LongMemEval 500-Q sealed run; W2/W3 numbers) + receipt + `comparison-systems.md`.
2. **Verify receipt:** run_status, verdict, failure_origin; names the EXACT commit, corpus hash, judge pin; sealed answer keys at the boundary.
3. **Verify metrics:** official `recall_all@5` semantics (NOT any-hit); Tortoise's 4 documented divergences (dataset_audit.py) explicitly labeled as variants — never mixed.
4. **Verify comparison table:** mechanism-named rows vs MemPalace/gbrain/Supermemory/Mem0; neutral cited tables; NO win claims on benchmarks not run.
5. **Errata:** any divergence → annotated, never silently edited; historical numbers preserved.
6. **Exit:** auditor trusts or files an issue; the claim is auditable end-to-end.

**Edge cases (J7):** metric variant mixing (QA-acc ≠ R@k ≠ recall_all@k); unsealed keys; receipt missing commit/hash/pin; unpinned judge (silent judge drift); missing audit record (report gate raises); win claim on an unrun benchmark; silent errata edit.

## 5.3 Phase-1 delivery — one pipeline, two transports

**Design (D1/D2 + delivery-shape recommendation):** ONE deterministic pipeline with a **CANONICAL stage order** (pinned — matches gbrain `volunteer.ts`, delivery-shape raw notes): **window parse → candidate extraction → resolve → confidence gate → re-mention suppression → pointer budget → why-block assembly**. Exposed as:

2. **`POST /v1/context`** — the same code path wrapped in a FastAPI route on the hosted API AND the self-host container (one shared implementation, not hosted-only — D1).

**Why-block assembly (read-only, bounded):** `_select_subgraph(anchors, max_hops)` bounds traversal; `compute_confidence` is a persisted single-node α/β read (never full propagation on the hot path); `get_contested_claims` batches EP variance reads (no N+1); ranking contentiousness uses persisted annotations. **Zero LLM on the hot path** — the why-block is graph reads, not generation.

## 5.4 Reflex decision layer (EP-scored, graded via harness)
