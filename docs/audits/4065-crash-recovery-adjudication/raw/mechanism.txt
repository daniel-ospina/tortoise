## 1. The product code speaks camelCase; the stale tests spoke snake_case

```
$ git -C main show HEAD:tortoise/shared_state/event_log.py | sed -n '106p;128p'
            if card_id and ev.get("type", "") in ("cardCompleted", "cardFailed"):

PR head (and the PR's pre-PR base d7c102559) — test_event_log.py:
```

        "card_created", "step_started", "step_completed",
        "gate_passed", "gate_blocked", "card_completed", "card_failed",

origin/main (after #4229 b49f5d6a0) — test_event_log.py:

        "gatePassed", "gateBlocked", "cardCompleted", "cardFailed",
```
append_event stores the type VERBATIM (EventCodec.encode: event['type'] = type_name),
so a snake_case append is never recognised by the camelCase completion check.

```
$ sed -n '48,50p' /tmp/j3-4065/head/tortoise/tortoise_client.py

module in the half can then `import shared_state` and reach tortoise/shared_state/.
Standalone, that trigger is absent, so the stale file module-skips (collected 0 items).
