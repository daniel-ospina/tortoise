## 1. The problem restated precisely

#2519 = the **evidence-completeness retrieval loop** (program doc C3): replace the
one-shot top-k retrieve with a bounded retrieve → **coverage-check** → targeted
second-pass **expand** → merge, so that a question needing ALL N evidence pieces can
actually receive all N — not merely the best k.

The graded semantics make this all-or-nothing. Per `tools/longmem_eval/w7_publish.py`
(the pinned official projection) and the retrieval grading in
`tools/longmem_eval/retrieve.py::_recall_metrics`:

- Per-question `session_recall@k` = `|answer_sessions ∩ sessions(hits[:k])| / |answer_sessions|`
  where `hits` is the **deduped retrieval pool in rank order** (the pinned "recall over
  the pool" contract), and `answer_sessions` = the question's ground-truth answer
  `answer_session_ids`.
- Official `recall_all@5 == (session_recall@5 == 1.0)` — **every** answer session must
  be represented in the pool's top 5 ranks. `_abs` questions excluded; aggregate =
  mean over non-`_abs`.

So a question with N=3 evidence sessions scores 0 at `recall_all@5` when the pool's
top-5 contains only 2 of them. **Partial is not nearly-good on the official binary; it
is a complete miss.** The measured cohort: 47 misses on the 100-Q type tail — 53%
(≈25) had *partial* evidence (k<N surfaced), 34% (≈16) full-evidence-but-reader-wrong,
13% (≈6) evidence never reached the reader. The dominant loss is the retrieval surface.

### Why key expansion (#2518) alone cannot close it

#2518's mechanism (verified on the `opt/2518-entity-keys` branch, commit
`3f5b7b29a`): resolve the query's entities through the Object-name index
(`_ENTITY_ANCHOR_LIMIT`=3 anchors), harvest the anchors' names + every
`aboutObject`-linked point's E3 `search_keys`, and additively re-run the sparse leg
(`build_or_query(expansion_terms=…)`, original tokens keep their slots, bounded
8-term expansion tail per `tortoise/sparse.py` `DEFAULT_MAX_EXPANSION_TERMS`).
It is a **query-side recall lever**: it raises how many subject-matching sessions
*enter the pool*. Three structural reasons it cannot by itself move the
all-or-nothing number:

1. **The metric is a windowed all-set property, not a recall@k mean.** Expansion
   raises `evidence_recall@k` / session coverage in the pool (the +9.4% recall@k
   external claim is a recall@k delta), but `recall_all@5` still requires the *complete
   set inside 5 slots* — the k-window (5) and the reader caps (40 items / 8k tokens,
   §2) still bound the *joined* evidence regardless of how many matching sessions the
   pool admits. k<N stays 0 when the top-5 clusters within one session.
2. **The rank cut is not session-diverse.** `dedup_pool` caps raw *chunks* per session
   (C5, 3) but never caps *points* (D3 — the compact epistemic surface is exempt by
   design). A monopolizing session's points can therefore occupy pool ranks 1..5 alone
   and starve the other N−1 answer sessions out of the window even when they are in the
   pool. Expansion cannot fix a selection step it never touches.
3. **Coverage is never checked.** Neither the product's `tortoise_fts_query` nor the
   eval's `retrieve_for_question` computes "all contributing sessions were found"
   (verified: no completeness check or iteration exists anywhere in the retrieval
   path — see §3 realness column). Expansion optimizes an unmeasured intermediate;
   nothing declares the all-set property that the official binary grades.

The loop is the only mechanism that targets the all-or-nothing semantics *by
construction*: detect incompleteness on the pool's facet/session census and re-query
the missing facet, so the merged pool can enumerate N. It is **incremental on top of**
#2518 (whose anchors are its cheapest facet vocabulary), never a substitute.

## 3. Mechanism candidates — a MECE stack

The decision space = **where the completeness assurance is added between one query and
the reader**. Four mutually exclusive mechanisms, jointly exhaustive over the
pipeline stages (query-side / pool-side / selection-side / window-side). Realness
verified against the code; "real-as-new" = the substrate exists but the mechanism does
not.

| # | Mechanism (sketch) | Miss-class targeted | Cost / complexity | Risk (latency · tokens · hallucination) | A/B shape | Realness |
|---|---|---|---|---|---|---|
| **(a) CHECK-then-EXPAND loop** | Retrieve one-shot (with #2518 keys) → run a *coverage check* over the pool's facet/session census (query's named-entity + date-range facets vs sessions actually surfaced) → when incomplete, run ONE targeted second pass for the missing facet (re-query with facet terms through the same `build_or_query` seam) → merge (additive union, second-pass ids appended per the A4 merge contract) → iterate ≤ 1 extra pass (hard cap). Sits above `retrieve_for_question`'s one-shot `hybrid_search`, before `_recall_metrics`/context assembly. | **PARTIAL evidence (53%)** — by construction: k<N triggers the expand until N or budget | Complex (shell + census + merge + bounds + instrumentation); deterministic — no LLM in the loop | Latency: +1 bounded FTS/vector pass per iteration (fits the 1500 ms eval budget; must fit the 300 ms ask E2E with the pool-depth floor kept). Tokens: none added to the reader context (assembly caps 40/8000 unchanged; merged pool ≤ context, skip-not-starve). Hallucination surface: none new (deterministic re-query, no generation). | Loop ON vs OFF, shared questions, per-outcome arm marker + iteration census (0/1/2 passes + fired-facet). Covariate: #2518 ON/OFF (2×2). | **Real-as-new.** No completeness check or loop anywhere (verified: one `hybrid_search` per question; post-pool transforms are boost/rerank/TR-render only). Tokens: 2× reader spend on the failing class (must be metered + capped). Hallucination surface: **new risk — a second reader pass on more context can fabricate**; needs the A1 abstention discipline preserved + judge re-run. **Semantics caveat:** `recall_all@5` grades the pool's top-5, NOT the reader window — a raised window can move QA/`reader_surface` but can NEVER move the official binary. ## 4. Recommended stack order

Order = evidence-to-cost with the measurement gate first, and **every delta measured
against the best one-shot arm** (the loop must beat #2518-ON + boost-ON, not the bare
baseline):

1. **P0 — the loop shell with a minimal deterministic coverage check** (mechanism (a),
   minus the #2521 router): the retrieve→check→expand plumbing, the facet census
   (named-entity facets via the #2518 anchor seam + date-range facets via the R5
   `detect_time_constraint` seam — both already in the engine), the additive merge
   contract, the hard iteration bound (≤1 extra pass), and the eval A/B (default OFF).
   This is the only mechanism that attacks `recall_all@5` *by construction*, and it is
   the seam every later slice rides. Not blocked: its census and merge are rule-based
   and hermetic; the A/B runs as a 2×2 covariate with #2518 so it is not invalidated
   by the running A/B's outcome.
2. **P1 — source-session re-injection** (mechanism (b)): cheap, orthogonal, directly
   attacks the 13% never-reached class and gives the loop its cheapest "expand"
   operator when the missing facet is *within an already-seeded session*. If #2513's
   plan keeps C4 separate, land it there and have P0 consume the seam.
3. **P2 — coverage-signal routing** (mechanism (a)'s check upgrade): wire the #2521
   aggregative-intent detector + counting-intent into the coverage check so
   aggregation/spread questions (the primary MSR miss shape) get per-facet coverage
   checks *before* the loop expands. **Blocked on #2521** (not merged — no code, no
   branch). Until it lands, P0's rule proxy stands; the swap is a contained seam.
4. **P3 — stratified window reconciliation** (mechanism (c)): reader-facing, moves
   QA/`reader_surface`, labeled-variant only (never the official binary — §3(c)
   semantics caveat). Last because it needs the abstention census the sealed baseline
   + P0 produce, and it carries the only new generation cost.

Mechanism (d) is **not** a separate phase: its session-diverse top-k selection is
folded into P0's merge step as the mandatory rank discipline (§3(d): naive union can
regress the binary), and its speculative multi-arm remains a documented future
extension of P0 once P0 proves the coverage signal is worth paying for.

**Blocked-on summary:** P0 and P1 are buildable now (hermetic, default-OFF, A/B-armed)
but their *acceptance deltas* are denominated on the #2513 C1 sealed baseline and their
facet vocabulary is finalized by the #2518 A/B result — freeze the loop ON-default and
the anchor-harvest default only after (a)+(b) land. P2 is blocked on #2521. P3's gate
needs P0's iteration/abstention census.

## 5. First slice + honest acceptance gate

**First slice = P0 (the loop shell).** Scope: product-side loop primitive
(`tortoise/` — per the product-cohesion rule, the loop lands in the product and the
eval measures it), default OFF (the #1745 fail-safe decision), tri-state env +
CLI (`--coverage-loop` / `TORTOISE_LME_COVERAGE_LOOP`), fingerprinted + methodology +
per-outcome arm marker (`loop_iterations`, `loop_fired_facet`, `loop_merged_added`),
hermetic tests (loop fires only on facet-mismatch; OFF == byte-identical one-shot;
iteration cap honored; additive merge preserves the original tokens' slots; bounds
under budget). **No LLM in the loop.**

Acceptance gate (deltas vs the sealed baseline on shared questions; re-anchored when
the #2518 A/B and C1 baseline land — the targets below are sized from measured
anchors, not promises):

- **Primary metric:** official `recall_all@5` on the **71-Q multi-session slice**
  (paired, shared questions). **Minimum delta: ≥ +0.06 absolute** over the best
  one-shot arm. Sizing (arithmetic on measured anchors, not a measurement): 71 Q ⇒ 1
  flip ≈ +0.014; +0.06 ≈ 4–5 questions moved 0→1. The 100-Q cohort holds ≈25
  partial-evidence misses, majority MSR; repairing a third of the MSR partial misses
  (~6 Q ≈ +0.08) already clears the floor — the floor is deliberately **under half the
  recoverable headroom** (honest, not heroic) and **≥4× the per-question flip
  granularity** (material, not noise).
- **Variance band:** Wilson 95% CI over the paired binary delta; acceptance requires
  CI lower bound ≥ **+0.02** AND a net flip census ≥ 4 from per-outcome arm markers
  (a CI alone on n=71 is too coarse — the flip census is the reconstructability
  guard, per the M8 #1528 shared-question discipline).
- **Companion signals (no regression):** `evidence_recall@5` (MSR) not down; QA
  guardrails single-session-user ≥ 0.94, full-mix ≥ 0.66, tail QA ≥ baseline − 0.02;
  mean reader-context tokens not up > 5% (assembly caps hold); eval P95 retrieval
  latency inside the 1500 ms budget with the loop ON; product hot path inside the
  300 ms E2E guardrail when the ask lane opts in.
- **A/B framing:** 2×2 {loop OFF/ON} × {#2518 OFF/ON} on the same slice; the loop's
  claimed delta is vs the best ON/OFF one-shot arm, so a #2518 win cannot masquerade
  as a loop win (and vice versa).

   expand→merge loop in `tortoise/` with a rule-based facet census and hard iteration

   *Issues:* failing-class detection from outcome fields + budget-stratified re-run +
   variant reporting. *Ties:* QA/`reader_surface`; never claims the official binary.
   Complexity **standard**.

Not filed as children (tracked in the parent program): C1 baseline seal (#2513),

## 7. Risks / falsification (loop-specific)

- **Coverage-check circularity** (inherited): the check must not re-rank the same pool
  that missed — it must be *facet-based* (missing entity/date-range facets re-queried
  directly). Falsified if the loop's `recall_all@5` delta vs one-shot is not material
  on the sealed MSR slice (§5 gate).
- **Iteration cost creep:** hard ≤1-extra-pass cap + per-outcome iteration census;
  never-starve fallbacks inherit the R5 posture. Falsified by P95 latency/token
  regressions on the budget guardrails.
- **Merge dilution** (mechanism (d) failure mode, applicable to the loop's merge too):
  an additive union can regress the binary if same-session near-dupes crowd the top-5
  — the session-diverse rank discipline is mandatory in the merge step.
- **Reader-window illusion:** pool completeness (the binary) ≠ reader completeness
  (QA). A pool win can be eaten by the 40/8000 assembly caps — `reader_surface@k` and
  `reader_evidence@k` ride every outcome so a P0 win is never claimed on the pool
  alone.

## 8. Metrics to gate on (mirrors #2513 §6 + loop additions)

Primary: official `recall_all@5` (MSR; the all-pieces semantics this issue exists to
move), `evidence_recall@5` (MSR), `reader_surface@k`/`reader_evidence@5`. Secondary:
QA tail categories read through the pinned reader lens; regression guards
(single-session-user ≥ 0.94, full-mix ≥ 0.66, write-path/eval integrity gates);
budget (hot path inside the 300 ms ask E2E; loop iterations ≤ 1 per question,
reported per outcome). Loop-specific additions: `loop_iterations`, `loop_fired_facet`,
`loop_merged_added`, arm markers — all fingerprinted + methodology-recorded so the
2×2 with #2518 stays reconstructable.
