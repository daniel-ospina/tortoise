# Scoping — #4408: no reap path exists for worktrees and branches

**Date:** 2026-09-20 · **Tier:** standard · **Worktree:** `chore/4408-branch-reaper`
**Full scoping artifact (plan + verification log):** the `issue-scoping` comment on
[#4408](https://github.com/daniel-ospina/tortoise/issues/4408).

This doc records the **double-diamond** derivation so the divergence is auditable
from the repo, not only from the issue thread.

## Confirmed problem

The issue's premise ("no reap path exists for worktrees and branches") is **half
false**, and its classification rule is **unsafe as written**.

- **Worktree checkouts already have a reviewed reap engine.**
  `scripts/pi-reap-worktrees.sh` (agent-infra [#1095](https://github.com/daniel-ospina/agent-infra/issues/1095),
  ~1,413 lines + a 1,407-line test suite) is dry-run by default, never passes
  `--force`, and **never calls `git branch -D`** — it removes checkouts only and
  retains the branch. It is **unscheduled** (no launchd/cron) and its one real
  pass was a dry-run (`2026-09-16: WORKTREES=231 REMOVE=8 PRESERVE=223 REMOVED=0`).
- **Local branches have no general reap path.** `scan-orphans.sh` deletes only
  branches recorded in `~/.pi/agent/worktrees.jsonl` (59 records); 
  `cleanup-stale-branches.sh` is remote-only; `cleanup-worktree.sh` is
  single-branch post-merge ceremony.

**Root cause:** unrecorded local branches accumulate because nothing classifies
them from GitHub PR state. The existing worktree engine is correct but unscheduled.

**The issue's name-only rule is unsafe.** "The branch name appears in a
merged/closed PR" deletes branches whose local tip has **advanced beyond the PR
head** — local commits not provably landed. Measured on 2026-09-20 (1,473 local
branches): the name-only rule destroys **63 advanced** branches; the corrected
tip-equality rule preserves them.

| class | count | verdict |
|---|---|---|
| ancestor of `origin/main` | 652 | SAFE |
| PR merged, tip == PR head | 508 | SAFE |
| PR closed-unmerged, tip == PR head | 66 | PRESERVE by default (opt-in) |
| open PR | 76 | PRESERVE |
| advanced beyond PR tip | 63 | PRESERVE |
| no PR, non-ancestor | 107 | JUDGEMENT (report only) |
| detached-HEAD worktree | 51 | JUDGEMENT (report only) |

## Problem-diverge — alternative framings

| framing | verdict |
|---|---|
| **A.** "no reap path at all" (the issue) | **falsified for worktrees** (engine exists), true for local branches |
| **B.** the root cause is the *creation* policy (no lifecycle owner; `/private/tmp` worktrees) | partially validated (52 worktrees live outside `.worktrees/`) but a symptom of C |
| **C.** the root cause is *scheduling/ownership* — the mechanism exists but nothing runs it | **strongest** for the growth (no launchd unit; one dry-run pass ever) |
| **D.** the hazard is unlanded-work destruction; the problem is safe classification | adopted for the branch half |

## Solution-diverge — approaches

| approach | where | worktree engines | blast radius | verdict |
|---|---|---|---|---|
| **A. tortoise-local `tools/branch_reaper.py`**, delegate teardown to the reviewed engine | tortoise | 1 (reused) | tortoise | **CHOSEN** |
| **B.** extend the agent-infra engine with a branch mode | agent-infra | 1 (extended) | fleet-wide | rejected — edits a 1,413-line adversarially-reviewed artifact; bash JSON fragility; disproportionate first pass |
| **C.** tortoise-local self-contained (reimplements teardown) | tortoise | **2 (duplicated)** | tortoise | rejected — two engines diverge; duplicates a safety-critical reviewed policy |
| **D.** loop the per-branch `scripts/cleanup-worktree.sh` | tortoise | 1 (reused) | tortoise | rejected — ceremony script, no aging/liveness/batch lock, refuses ignored-only (`.venv`) dirt |

**Why A won:** it keeps the deliverable in this repo's diff, reuses the reviewed
teardown engine (no duplication), and confines a classifier bug to one repo. The
"post-teardown re-read" ordering is belt-and-braces on top of `git branch -D`'s
own refusal to delete a branch checked out in any worktree.

## Rejected on the contradiction test (not adopted)

The branch-cleanup field (`git-trim`, `git-delete-merged-branches`, GitHub
auto-delete) decides safety by **content-containment** (patch-id / a synthetic
squash-tree probe), not exact tip equality. Adopting the squash probe **for the
no-PR judgement set** would contradict #4408's recorded decision *"do not touch
the 183 no-PR cases"* — it is a **reopen** to argue with the owner, never a quiet
fold-in. The deliberate departure that *is* adopted (exact tip-equality) carries
the `OVERRIDES:` line on the issue.

## Adversarial pre-mortem → hardening

| failure | mitigation in the design |
|---|---|
| incomplete PR list lets the ancestor rule delete an open-PR branch | completeness proof; truncation ⇒ INCOMPLETE, **zero** deletions |
| tip advanced beyond the PR head | tip-equality (rule 4/5), advanced ⇒ PRESERVE |
| branch checked out in a dirty worktree | teardown delegated to the engine (never `--force`); branch deletion gated on the checkout being gone |
| ref moved between classify and delete (TOCTOU / name reuse) | re-verify the ref OID immediately before `git branch -D` |
| `refs/reaped/*` backup refs collide with the delegate's `refs/heads/*`-only survival doctrine | **no backup refs**; report recovery record + opt-in `git bundle` |
| delegate absent/failing swallowed | exit-code translation table; delegate 3 → INCOMPLETE (nothing deleted) |
| squash-merge then revert | **documented limitation** (a `git cherry` probe is invalid for squash and would preserve all 508); mitigated only by the recovery record |
