The one hit is the POSITIVE CONTROL point, which shares the "capstone-9664" token — the
NEGATIVE probe's text (`…explicit non-default graph (must not exist)`) appears in no result.
So the refusal is not cosmetic AND the check is not vacuous: the same query space demonstrably
returns points that exist.

The verdict is mechanical and consults EVERY control — `neg_absent` requires that the search
SUCCEEDED and returned the positive-control point, so a dead index or an error payload cannot
be mistaken for an absence. (Review round 2 caught the first version: it checked only the
negative half, so a stubbed failing search still printed `REFUSED-AND-ABSENT` and exited 0 —
an unmeasured fail-open half reported as measured. Review round 3 caught the pair of
mislabelled `status` variables that made this block self-contradicting when a search errored.)

MEASUREMENT — 5. why U1's accept arm / U2 / U4 still cannot be measured (the 402, verbatim)
-------------------------------------------------------------------------------------------
U1's accept arm, U2 (a duplicate graph NAME) and U4 (a soft-deleted graph) each need a SECOND
graph, and a minted free org cannot hold one. Measured, not inferred:

POST /v1/organizations/<org_id>/graphs  {"name":"capstone-u2-dup"}
    -> 402 {"detail":"Custom graphs require the Builder plan. Upgrade to create multiple graphs.
    [wrapped here for width; the payload has no newline] Need more? Contact support@premiselabs.co."}

So the missing thing on those rows is named exactly: a paid tier that permits a second graph
(Builder), or an owner-provided org that already has two. It is NOT a credential — a credential
exists and was used above — and it is not a defect in the resolver.
