## What the assembler is (locked from issue-scoping economics review, 2026-09-08)
Deterministic (zero-LLM) read path: question → resolve subject(s) → walk the connected subgraph (Object state/lifecycle + dated Events + aboutObject-linked Points with EP/provenance) → render one dense structured block (state + timeline + evidence) → hand to the single existing reader LLM. Marginal runtime cost ≈ 0 LLM calls added. Value: information density per token, deterministic state correctness (via landed #2242 fold), provenance/EP surfacing (nobody else has EP).

## Hard evidence constraints (top findings)

1. **Structured + dated + ordered beats loose snippets.** LongMemEval's own reader uses timestamp-sorted structured JSON + "Current Date" header (+~10 pts claimed for JSON+Chain-of-Note — benchmark-author source). Chronological/forward order measurably best for temporal tasks (2402.08939); models cannot self-order at length (2505.12891, 2511.14214 — coarse OK, exact month-level order fails). [EVIDENCE] → the assembler MUST emit fully date-sorted, explicitly-dated lines; never leave ordering to the reader. [DESIGN]

2. **Two-layer shape (projected state + dated evidence) is the convergent pattern.** Zep/Graphiti entity summaries (2–6 dense sentences) + dated fact edges; Mem0 dated memory JSON + state_key resolution. Tortoise's Object status/lifecycle IS the summary layer; Events/Points are the dated evidence. [EVIDENCE] → state lines first ("as of now: X superseded by Y on D"), then dated evidence beneath. [DESIGN]

3. **Supersession must be rendered explicitly, never left implicit.** Conflicting/contradictory evidence degrades readers and triggers hedging/refusal (2504.13079); Mem0 admits KU is hardest; Tortoise's own 9/18 TR losses were refusals with perfect recall. [EVIDENCE] → mark validity/as-of on every state-changing line; filter superseded from current-state view by default; keep history available for point-in-time. Deterministic interval math on status (no endedAt → active) is the Mem0/Graphiti active-fact rule, and Tortoise's schema already owns it. [DESIGN]

4. **Near-relevant distractors are the #1 documented killer — not token volume.** Answerless-but-top-retrieved same-entity/wrong-time content actively hurts while random content doesn't (2401.14887); RankRAG k=5; AuthTrace near-miss benchmark. [EVIDENCE] → over-assembly (all events for an entity when the question needs one window) is the poison; the assembler needs a question-relevance gate per block section, not blind BFS breadth. Depth ≤ 1–2 hops with in-chain priority (GraphRAG local: in-network-before-out, 2× oversample entities, typed budgets under one hard cap). [EVIDENCE+DESIGN]

5. **Budget discipline is mandatory; reader instruction-following decays >16–32k tokens** (LIFBench, EACL-2026) — matches Tortoise's ~40k refusal line. [EVIDENCE] → hard token cap per typed slice (anchors 8–12k total from GraphRAG local); the assembled block must stay well under the refusal band. Aggregation/summaries beat raw dumps for bulk, but aggressive compression erodes citation/provenance grounding faster than correctness (customnlp4u-2026) — since Tortoise's differentiator IS provenance, filter-verbatim over summarize. [DESIGN]

6. **Both halves of a comparison must be in the context by construction.** ChronoQA: retrieval failure = 72% of wrong answers; RTQA: comparison questions collapse 0.424→0.214 without decomposition; Mem0's multi-session gain is mechanistically co-retrieving both dated instances. RERC: read each side, then compare separately. [EVIDENCE] → compare/ordering shape ("which came first", "days between") should be detectably routed to fetch BOTH subjects' dated timelines and (optionally) precompute the ordering/diff deterministically — no LLM decomposition needed for this class (deterministic entity assembly = the decomposition). ~32 "ago"-relative questions: resolve relative→absolute against session/current anchor at assembly; never send "two weeks ago" arithmetic to the reader. Date arithmetic out of the reader: extract in LLM, compute in date lib (DateLogicQA). [EVIDENCE+DESIGN]

7. **Entity resolution: recall-first with explicit confidence tags, not silent single-match.** DEG-RAG: −40–50% of extracted entities improves QA (extraction noise is the top correctable defect); recall-first beats precision-first (ISWC'25); wrong-merge cascades are invisible in rendered text (over-merge = silent contamination, under-merge = silent gaps). [EVIDENCE] → subject resolution from query should return candidates with confidence, prefer deterministic/rule-based matching (HippoRAG2 fallback pattern: LLM fallback only if deterministic resolution fails). [DESIGN]

8. **Evaluation: reader_evidence@k is valid and necessary-not-sufficient.** Answer-in-context separates EM 4.6× even at full recall (2607.00725); evidence recall is the strongest answer predictor r=0.96 (AuthTrace). [EVIDENCE] → metric pair: (a) does the needed evidence reach the reader, (b) does the pinned reader convert it; pre-registered arms with matched controls isolating ONE property each (same facts wrong order / same block + superseded facts / same block + duplicates); oracle (evidence-sessions-only) tier as upper bound. Two-reader check where feasible (weak reader hides assembler gains). [EVIDENCE+DESIGN]

9. **Anti-patterns to reject.** Type-blind BFS without question gating (Graphiti's own admitted drift); embedding-gated pools (a certain graph hit must not starve behind weak vectors); precomputed community summaries (wrong abstraction for a small dated graph); LLM consolidation at write that deletes history (Bedrock) — Tortoise's append-only + supersession fold is correct. Zero-LLM structured assembly has NO shipping precedent — the flat-facts-everyone pattern is what we're beating, not copying. [EVIDENCE]

## Open design decisions the scoping must resolve (with evidence pointers)
- **Subject resolution surface:** deterministic name/alias match → disambiguation via question context → LLM fallback only on failure (constraint 7). Which resolver primitives exist in-tree (search_engine? FTS? entity name-id determinism sdk.py:1233-1240)?
- **Block layout + token budget:** state header / dated event spine (chronological) / evidence points with EP + provenance quote; per-slice caps; total cap target <~12k (constraint 5). Flag-off or additive to existing point-only path (backward compat).
- **Which question shapes route to assembly:** compare/ordering/interval (constraint 6), current-state (constraint 3), absolute-date; defer N-ary LLM decomposition + "ago"-relative resolution as follow-ups where evidence says deterministic assembly suffices.
- **Timeline source:** Events (dated) are the spine — but the deterministic eval lane writes no Object structure; product/v2 lane does. Assembler acceptance = synthetic multi-session graph with Object structure (v2 lane shape), NOT the 13-Q (that's lane 1, #2578).
- **Superseded handling in evidence layer:** default current-state view excludes superseded (constraint 3); history preserved for "as of" queries (validity-window semantics on status/supersededAt — Graphiti interval containment).
