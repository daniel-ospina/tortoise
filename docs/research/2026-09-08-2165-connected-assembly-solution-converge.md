## Independent verification of the load-bearing facts (before the pick)

- **[V] The v2-lane Event spine has NO aboutObject edges.** `tools/longmem_eval/ingest_v2.py` event loop (~246–290) creates Events via `sdk.create_event(...)` with only `lme_event_id`/`startedAt`/session props; the aboutObject MERGE exists ONLY on the point loop (~209–218, `(p)-[:aboutObject]->(o)`). **Any pure Event-spine walk returns ZERO rows on the eval lane.** Hosted Events carry aboutObject; the assembler must be lane-agnostic.
- **[V] The Point→Event session join is the product's own date decoration.** `annotate_ask_hits` (sdk.py 11418) joins `(ev:Event) WHERE ev.eventId = n.eventId` → `session_date = startedAt[:10]` / `session_id` / `speaker`. D8 validity/supersession keys are attached to point hits elsewhere in `tortoise_fts_query` and must ride through untouched.
- **[V] `ask()` order** (sdk.py 12606): validate → resolve `question_date` → retrieve (`tortoise_fts_query`, `entity_type="point"`, `include_terminal=True`) → `annotate_ask_hits` → `dedup_pool` → A5 boost → A7 rerank → `assemble_context` (8000 est-token + 32 KiB byte caps, whole-hit drop) → `detect_question_type` (~12812, AFTER assembly) → ONE reader call → W4 additive `why` key (absent when flag off — the established flag-off-additive precedent).
- **[V] The budget/alignment invariant is per-hit and exact.** `assemble_context` (retrieval.py 471) accounts each hit with `_render_block` (the SAME function `render_context` renders with) so `context_tokens == estimate_tokens(render_context(...))` holds by construction; pinned by `tests/test_retrieval.py::test_context_reader_alignment_invariant` and by `tests/test_ask_sdk.py::test_local_lane_pipeline`'s `context_tokens == estimate_tokens_ask(evidence)`. `_validity_marker`/`_render_block` render `[SUPERSEDED BY: …]`, `[valid since/→]`, session date, speaker from hit keys alone — **any hit dict carrying those keys renders the markers with zero renderer changes**.
- **[V] Embedded/no-FTS posture is real.** Object range indexes on `id`/`name` are created at EVERY FalkorDB version (projection/__init__.py ~2117); Object-name FTS+vector creation is gated ≥ 4.x (~2139+). `tortoise_fts_query`'s degraded fallback is Point-only — a non-point `entity_type` with empty results returns `[]` on embedded. **A resolver built on `run_fts_query(entity_type="object")` is a docker-only cliff.** An index-backed equality probe (`WHERE o.name IN $candidates`) works on every version.
- **[V] Golden-hash blast radius is real.** `tests/test_reader.py::test_golden_constant_hashes` pins `_SYSTEM_PROMPT`, `_ABSTRACTION_FRAGMENT`, all four `_TYPE_FRAGMENTS` entries, and full-prompt combos (`system_prompt_for(None)` + `system_prompt_for("temporal-reasoning")`). Any new fragment (or edit to an existing one) trips the snapshot; an intentional prompt change requires a reviewed re-capture (runbook precedent exists).
- **[V] Object supersession fold fields.** `commit_ops.apply_supersessions` → `_fold_object_superseded` stamps `status='superseded'`, `supersededBy` (successor NAME, truncated 200), `supersededAt`. Object rows fetched by the search path carry `id/name/objectKind/status/superseded_by` (sdk.py 12121). The successor chain must therefore be walked BY NAME probe, not by id.

## Chosen Approach (name + architecture)

**X1 — "Connected-Assembly Replace Branch (CARB): a standalone pure assembler surface + pre-retrieval shape router + pool-replacing ask() branch that renders through the EXISTING annotated-hit schema."** It is the A3/B1/A2 composite where each element earns its place on the failure modes below: **A3's shape** (new pure `tortoise/assembly.py` module with an injected projection + a standalone `sdk.ask_assembled()` retrieval/evidence surface — the recall_* precedent — so the eval and the product ask() consume ONE block builder, and the flag-off guarantee is structural because the branch sits before retrieval and simply does not run when unrouted), **B1's posture** (a private, pre-retrieval deterministic shape router — current-state / ordering / interval / date-lookup — whose fired branch REPLACES the point pool with one dense assembled block under the same single reader call; no qtype-enum, no reader-fragment, no wire-field change), and **A2's rendering insight** (the assembled block is materialized as ordinary annotated hit dicts — state rows, dated spine rows, evidence points — fed through the UNCHANGED `assemble_context`/`render_context`/byte-caps machinery, so byte-accounting, the alignment invariant, whole-line drops, and the D8 `[SUPERSEDED BY]`/`[valid …]` markers are inherited, not re-implemented). Subject resolution is index-backed exact-name IN-probe first (embedded-safe at every version), search_keys aliases second, docker-only Object FTS as the third fuzzy surface; the dated spine is anchored on aboutObject-linked **Points** + their **eventId session-joined Events** (never a pure Event walk — the v2 lane writes none), with Event-aboutObject edges probed only when present; compare/interval shapes resolve ALL confident subject candidates and precompute ordering/diffs in date arithmetic at render. Degradation contract: no shape fire OR no resolved subject OR env flag off → the legacy point-only lane runs byte-identically (never an error, never an empty answer, never a name-scan).

## Why (rejected alternatives + when each would win)

- **A1 (qtype-native contract + per-shape reader fragments) — rejected.** It makes the NEW reader fragments the primary accuracy lever — precisely the golden-hash blast radius the mandate warns about — and extends the closed `ASK_QUESTION_TYPES` enum (schemas.py), rippling into hosted validation, `_post_ask`, and answer-surface docs for a wire value whose consumer (hosted ask) is #2013-gated OFF. The evidence (constraint 3/5) is satisfied by explicit markers + ordering in the BLOCK, which needs no new instruction fragment v1. **Would win when**: synthetic-graph reader-conversion measurement shows the generic/TR prompts still hedge on explicit markers — then ONE deliberately added connected fragment (with reviewed hash re-capture, runbook precedent) becomes the follow-up, and A1's contract-visible wiring is the vehicle.
- **A2 (synthesized hits injected INTO the legacy pool, additive) — rejected as primary; its hit-schema insight is kept.** Additive interleaving rebuilds the near-relevant-distractor geometry the issue is trying to kill (structure competes with the rank list inside one reader context), and a state header as a pool member must fight the per-session dedup cap with synthetic session keys. The load-bearing half of A2 — "render the block as ordinary annotated hits so caps/byte-accounting/markers/alignment are inherited" — is adopted in X1 in REPLACE posture (no dedup interplay because the legacy pool never runs on fired shapes). **Would win when**: the team distrusts the shape router's precision and wants the RRF pool retained under the block as a safety net — a documented knob (`append-legacy`) for a later measurement, not v1.
- **A3 (standalone surface) / B1 (private pre-router + replace) — each alone is incomplete; the composite is strictly better.** A3 alone defers the product-ask value (the issue's checklist demands ask-lane wiring in scope) and underspecifies rendering; B1 alone lacks the standalone dict surface the eval needs for per-slice admission measurement, describes the spine as Event-aboutObject (fails (v) on the eval lane), and leans docker Object FTS for resolution (fails (iii) on embedded). X1 = A3's module/surface discipline + B1's pre-retrieval replace posture + a lane-correct Point-anchored spine + an embedded-first resolver.
- **B2 (fold-time lifecycle snapshot store) — rejected.** It couples the WRITE path (fold code with a documented hardening history — #2193/#2194/#2309) with new drift invariants (snapshot vs live graph, read-miss lazy rebuild, lane-coverage gaps on fold-less writers) to save a read-time walk over a small dated graph — the issue is read-path, and the walk is bounded and cheap. It is also a second source of truth for state the fold already owns. **Would win when**: p95 latency becomes the dominant constraint at graph scale, and when the record-axis whole-graph-as-of (#2349) needs the same materialized store — a distinct future issue, not this one.
- **B3 (pool-seeded AEP append via typed SubgraphExpander) — rejected.** The presence gate is pool-recall-dependent — and the issue's own diagnosis is that gold lands at pool rank 48–68, so a pool-seeded gate structurally cannot fire where assembly is needed (weakest option on (ii)); additive budget coupling shrinks the pool's admitted points on exactly the questions where the pool already failed; extending `SubgraphExpander` risks the #898 recall surface. **Would win when**: graphs with zero Object structure dominate (the deterministic 13-Q lane) and morphology routing is too risky — i.e., it is the right shape for lane #2578, not for this Object-structured synthetic-graph issue.

## Implementation Plan DRAFT (phased TDD; each phase red-first)

**Env / contract invariants (whole plan):** `TORTOISE_ASK_CONNECTED_ASSEMBLY` (default OFF — structural legacy; on = product/selfhost/eval assembly). No new env is required to fire shapes beyond the master flag; optional later knobs for per-slice caps. NO changes to: `schemas.py` `ASK_QUESTION_TYPES`, `reader.py` fragments/`detect_question_type`/`system_prompt_for`, the 12-field response, or the golden-hash constants.

### Phase 0 — Fixture + flag scaffolding (tests first)
- New `tests/test_assembly_fixtures.py` + `tests/_assembly_graph.py` helper: build the synthetic multi-session graph via the SDK mirroring the ingest_v2 shape — `create_entity("object", ...)` / `create_object` (≥3 Objects: a live one, a superseded one with successor, one with no events), dated Points with `aboutObject` MERGE + EP/quote + `when`, Events with `startedAt`/sessionId and **NO aboutObject edges** (v2-lane shape), supersession fold via `commit_ops.apply_supersessions`, spanning ≥2 sessions with distinct dates. Tests pin the fixture itself (Object count, fold fields `status='superseded'`/`supersededBy`/`supersededAt`, Point counts, aboutObject edge counts, Event edge count == 0).

### Phase 1 — Pure module: shape router + resolver (no SDK)
- New `tortoise/assembly.py` (pure; injected projection): `detect_assembly_shape(question) -> str|None` (ordered, high-precision regexes: current-state / ordering / interval / date-lookup; preference/vague → None) and `resolve_subjects(proj, question) -> list[SubjectCandidate]` (n-gram harvest → index-backed `WHERE o.name IN $candidates` exact probe FIRST → search_keys alias harvest → docker-only Object FTS third, fail-open; confidence = match specificity + connected-item count; multi-candidate admit, never single-silent).
- New `tests/test_assembly_pure.py`: shape precision/recall table (compare "which came first — X or Y" → ordering; "how many days between" → interval; "what is the status of X" → current-state; preference/decoy questions → None); resolver returns BOTH halves on compare questions; exact-probe works with the FTS absent (mock the FTS surface to raise/empty); alias resolution; no-LLM assertion (spy: no model call made); over-resolution ordering (longest n-gram first).

### Phase 2 — Pure module: typed walk + slices + derivations
- Extend `tortoise/assembly.py`: `collect_slices(proj, subjects, shape, question_date) -> AssemblySlices` — state rows from the Object fold chain (live/superseded-by-name/at-date, validity windows, as-of filter), dated spine rows = aboutObject-linked Points ∪ their eventId-session-joined Events (reuse the annotate join shape; OPTIONAL Event-aboutObject surface probed once, used only when rows exist), evidence = aboutObject Points EP-annotated id-keyed + verbatim quote; ordering/diff derived rows computed in date arithmetic (interval N days / earlier-later from spine dates; relative "ago" → absolute at assembly). Per-slice item caps; fully date-sorted; superseded excluded per shape; no blind BFS (≤2 typed hops).
- Extend `tests/test_assembly_pure.py`: spine completeness on the v2-lane fixture (zero Event-aboutObject edges) — all gold dated rows land; identical graph WITH Event-aboutObject edges returns a superset; supersession fold → state rows exclude superseded by default and restore as-of `question_date`; interval math equals the test's own date-lib arithmetic; "which came first" derived ordering line present for both halves; caps truncate lowest-priority whole rows.

### Phase 3 — Hit synthesis + budget + ask() branch (SDK wiring)
- Extend `tortoise/assembly.py`: `synthesize_hits(slices) -> list[dict]` — rows become annotated-hit dicts: state rows carry `superseded_by: {"content_snippet": "<successor> (status …, since <date>)"}` + `valid_from/valid_to` so `_validity_marker` renders `[SUPERSEDED BY: …]`/`[valid …]` unchanged; spine rows carry `session_date`/`speaker`; evidence points pass through as real point hits (D8 keys from the existing point-decoration helper — verify name against the `tortoise_fts_query` decoration path at implementation). No retrieval.py edits.
- `tortoise/sdk.py`: new `ask_assembled(question, *, question_date, shape=None) -> dict` (retrieval/evidence surface, recall_* precedent; NOT metered) returning `{fired, subjects, shape, slices, hits, block}` for eval/tests; private shared `_assemble_connected(...) -> list[dict] | None`; `ask()` gains the branch between `question_date` resolution and step 2: env ON + shape fires + ≥1 resolved subject → decorate evidence points (reuse `annotate_ask_hits`) → `assemble_context(assembled_hits, caps)` → steps 5–8 unchanged (qtype = legacy detector output, ONE reader call); else fall through byte-identically.

## Acceptance criteria (concrete, verifiable, synthetic-graph-based)

- **AC1 — compare both-halves (indicator 2):** on the fixture graph, `ask_assembled("which came first — <A> or <B>?")` (A, B from DIFFERENT sessions) returns `fired=True`, subjects == [A, B], and the timeline slice contains ≥2 gold dated rows from ≥2 different sessions; the derived ordering row (earlier/later by ISO date) is present; spine rows are ascending-date-sorted. Same via `ask()` with a stub reader: the evidence the reader received contains those ≥2 gold rows (indicator 2 satisfied on the product path).
- **AC2 — supersession explicit (constraint 3):** a current-state question on the superseded Object fires; the state slice's live view excludes it; the fold-chain row names the successor + date; rendered evidence contains `[SUPERSEDED BY: …]`; the SAME question with `question_date` before `supersededAt` renders the Object live (as-of restore by validity window).
- **AC3 — interval math out of the reader (constraint 6):** "how many days between …" yields a derived N-days row equal to the test's own date-lib arithmetic; no date arithmetic text is present in the question the stub reader receives beyond the derived row.
- **AC4 — v2-lane spine (constraint 6 + fact (v)):** the fixture's Events carry ZERO aboutObject edges; the full dated spine still assembles (Point-aboutObject + eventId session join). A variant fixture WITH Event-aboutObject edges returns a superset of rows.
- **AC5 — flag-off structural byte-identity:** with the flag OFF, a question that WOULD fire returns evidence byte-identical to the pre-change legacy response (recorded in the same test process); with the flag ON, unrouted questions (no shape / no subject / zero-Object graph) are byte-identical to legacy — no error, no empty answer.
- **AC6 — embedded/no-FTS:** the assembly suite passes against the embedded projection; exact-name resolution fires; an alias-only paraphrase with no FTS degrades cleanly to the legacy lane; the resolver never depends on `run_fts_query(entity_type="object")`.
- **AC7 — alignment + budget (constraint 5, invariant (vii)):** on the fired ask() path, `context_tokens == estimate_tokens_ask(evidence)`, `context_tokens ≤ 8000`, `len(evidence.encode("utf-8")) ≤ 32768`, whole-line drops only, and exactly ONE model call.
- **AC8 — no regression:** `tests/test_ask_sdk.py`, `tests/test_ask_api.py`, `tests/test_reader.py` (golden hashes pass unmodified), `tests/test_retrieval.py`, `tests/test_ask_retrieval_levers.py` all green; `tortoise/reader.py`, `tortoise/schemas.py`, `tortoise/retrieval.py` unmodified.
- **AC9 — eval hook:** the synthetic-graph eval arm consumes `ask_assembled` slices and reports per-slice gold admission ≥ 2 on the multi-session questions (pre-registered arm; NOT the 13-Q lane).
