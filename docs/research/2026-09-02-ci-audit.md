## 0. Problem reframing (research-protocol Step 0)

Narrative: *"ship time has been growing exponentially; CI runs unnecessary tests / is misconfigured."*

5-Whys root-causes that the evidence supports:

1. Every PR runs the **entire slow suite + the entire 23-file embedded carve-out** regardless of diff (`python=true` is unconditional).
2. Every PR also runs **all 17 ci.yml jobs** (playwright E2Es, wheel builds, ruff+mypy, uv sync) regardless of diff — zero path filters.
3. Engine PRs touching `sdk.py`/`ep.py`/`conftest.py`/`pyproject.toml`/any `.github/workflows/*.yml`/unknown path **fail-closed into the full 437-file matrix**.
4. The suite grew **7.6× in one month** (57 → 437 test files); new files auto-register into the 198-file `core` surface, so even "tier-2" PRs select 187–269 files (~50%+ of the suite).
5. Runner capacity is a shared 20-job account cap on free public runners — ~60 runner-hours/day across 6 per-PR workflows → queueing (observed in their own #964 notes).

**Reframed problem:** *"The team wants a fast, diff-proportional pre-merge gate, but the gate is suite-proportional: two always-on jobs (test-slow, test-carve-out) plus an unfiltered 16-job workflow make every PR pay for the whole repo's regression surface. Costs are runner-time (free $, but throughput-capped) and wall-clock developer wait (the real 'ship time')."*

**Contradictions found (narrative vs reality) — verified, not assumed:**

- ✅ Path-aware **tiering EXISTS** in python-ci.yml (`changes` job + `tools/ci_selection.py`, tier-1 smoke / tier-2 surface / tier-3 full) — the team is NOT naively running "everything on every change."
- ❌ But tiering is **incomplete**: `python=true` is set unconditionally on PRs, so `test-slow` (both legs, full 30-file list), `test-carve-out` (23-file), `test-concurrency-falkor`, `test-track-b`, and `packs-compile` run on **every** PR — including docs-only.
- ❌ ci.yml has **no path filtering at all** (`on: pull_request` bare; zero `if:` conditions on 17 jobs).
- ⚠️ Full-matrix triggers are **broad** (sdk.py, ep.py, conftest.py, pyproject.toml, any unknown path incl. `.github/workflows/*.yml`), so most real engine PRs and even CI-fix PRs pay the full matrix.

## 6. Findings (severity / evidence / savings / fix)

### F1 — P0: `test-carve-out` (23–24 min, 1/3 of python-ci minutes) runs on every PR and every push, diff-unaware

- **Evidence:** python-ci.yml `test-carve-out:` `if: always() && needs.changes.result == 'success'`; run 33585912789 (docs-only PR #2132): 23 m 31 s; max job of all 12 sampled push runs (23 m 22 s–24 m 01 s).
- **Why it costs:** it is the critical path of every main push *and* adds 23 min to PRs whose diff cannot touch the embedded-recovery/reaper/migration surface.
- **Fix:** gate on `needs.changes.outputs.full == 'true'` OR a python-code diff (the carve-out files are also selected per-surface; the tier-2 legs already exclude them); keep it as a nightly/schedule + push backstop. If kept per-push, **split into 2 legs** (files are ~even count) to cut the push critical path in half.
- **Savings:** docs-only PR −23 min wall & runner; main push critical path −11 min (next-longest: test (b) ~15–17 m) if split.

### F2 — P0: `test-slow` (a/b) runs the full committed slow list (24 files = slow_files(30) − 6 carve-out slow files) on every PR — docs PRs paid 29+29 min embedded

- **Evidence:** `python=true` echoed unconditionally in the `changes` job ("tier-1 smoke runs on every PR"); test-slow's matrix.files is the committed full slow list with no `full`/surface gate (run step `for f in ${{ matrix.files }}`); run 33585912789: test-slow (a) 29 m 43 s, (b) 29 m 08 s on a **docs-only** PR. Only `test_files`/`slow_files` outputs are diff-selected for the *fast* gate; slow files have no matched-surface filtering.
- **Fix:** make the slow legs consume the selector's surface-matched slow output (already emitted as `slow_files` on every path) instead of the committed list; docs-only/website-only PRs run zero slow files; tier-2 PRs run only their surface's slow files. Keep `full`/push/schedule running the whole list. The drift-guard union check keeps coverage honest. Note the wording precision: `test-slow`'s committed legs = 24 files (slow_files minus the 6 slow carve-out files, which run inside test-carve-out) — a PR pays the *entire 30-file slow surface* across the two jobs regardless of diff.
- **Savings:** docs PR −58.7 runner-min; tier-2 PR −10–14 min; no coverage lost (trunk/nightly still full).

### F3 — P0: ci.yml (17 jobs / ~15.1 runner-min / 3 m 10 s wall) has zero path filtering

- **Evidence:** ci.yml lines 8–9 `on: pull_request` (bare); no `paths:`, no `paths-ignore:`, no job-level `if:` anywhere in 548 lines; run 33626630779 (2-file CI PR #2135): all 17 job definitions ran (23 rows incl. reusable expansions), incl. legal-e2e (playwright chromium install), welcome-e2e (chromium install + wrangler dev), hosted-e2e, flip-gate, client-build, packaging-smoke, agent-infra ruff+mypy, uv-lock-check. A docs-only PR pays the same.
- **Fix:** add a cheap change-detection step (reuse `tools/ci_selection.py` output or `dorny/paths-filter`) and gate jobs by owning path: legal-e2e/welcome-e2e/flip-gate ↔ `website/|tests/e2e/`; client-build/packaging-smoke ↔ `client/|tortoise/packs/|MANIFEST.in`; migration guards ↔ `supabase/migrations/`; dashboard ↔ `website/apps/dashboard/`; agent-infra-ci ↔ `tortoise/|pyproject.toml`. Required checks (`pricing-artifact`, `docs`, `test-isolation`, `license-surface`, `legal-e2e`) stay always-run (cheap: 7–51 s each) or become aggregates — do NOT path-filter required jobs at workflow level (skipped = blocked-PR trap; use job-level `if:` + aggregators, which this repo already models in python-ci-gate).
- **Savings:** docs-only PR −~14 runner-min; website-only PR −~10; every backend-only PR −~6–10; wall −2–3 min on most PRs.

### F4 — P1: Full-matrix trigger surface is too broad (sdk.py, ep.py, conftest.py, pyproject, `.github/workflows/*`, any unknown path)

- **Evidence:** ci_selection.py `SHARED_MODULES` + fail-closed `unknown` branch; real PR #2135 (`.github/workflows/ci.yml` + e2e conftest) selected `full=true` (run 33626630173 selection log); PR #2063-class sdk.py edits → full; simulation table §4 shows sdk/conftest/pyproject/ci-file PRs → full. Test-infra PRs (conftest.py, skip-guard.py — the #2090/#2108 class) always pay full because conftest.py is shared.
- **Fix:** shrink `SHARED_MODULES` to genuinely cross-cutting files (conftest.py, exceptions.py, ep.py stay); route `tortoise/sdk.py`/`api.py`/`reader.py` to their surfaces (tier-2) — trunk/nightly full runs (already exist) keep the safety net; treat `tests/**` infrastructure changes as tier-2 + targeted slow set, not full. Add `.github/workflows/*` to `NON_PYTHON_PREFIXES` (CI-metadata changes are already covered by the workflow-parse drift guards + python-ci-gate integrity step).
- **Savings:** every shared-file PR that stops being full: −~30 runner-min and −~12 min wall (full ≈ 72–76 vs tier-2 ≈ 40–45 runner-min incl. slow legs).

### F5 — P1: No dependency caching; 7 jobs cold-install per run (~104 s measured on one leg)

- **Evidence:** run 33629666505 steps: "Install package + test extras" = 104 s (fast leg); test-slow/carve-out/concurrency/track-b/packs each reinstall; only HF-model cache + one `setup-python cache: pip` (track-b). Local dev + deploy-hosted already use `uv sync` (uv is 4–8× faster warm, astral benchmarks; setup-uv supports cache).
- **Fix:** per-job `actions/cache` on the uv/pip env keyed by `uv.lock` hash (or `setup-uv` global cache), switch install steps to `uv pip install --system` / `uv sync --frozen` (pre-warm already exists in fast legs), cache playwright browsers keyed by browser version.
