# Research — #1845 source-scope selector (repo + branch for docs AND issues)

Date: 2026-08-28. Research-first pass before implementation.

## A. Codebase — what exists to borrow

### The MemorySources component (`website/apps/dashboard/src/main.jsx`)
- Rows: issues (role=switch) / docs (role=switch) / sessions. `MemorySources` is a
  single shared implementation mounted in wizard step-1 AND the Overview panel
  (props threaded from App-level state).
- `indexDocs()` currently sends `{org}` (or `{}`) to `POST /v1/index/docs`; `org`
  is fetched from `GET /v1/onboarding/github/status`.
- `reindexGithub()` currently sends **no body** to `POST /v1/index/github/re-poll`.
- Bounded-poll pattern: `startBoundedPoll(ref, {url, interval, maxTries, isTerminal, onStatus, onDone})`
  with per-team staleness + 404→"expired" + `timeout` terminal states.
- `wizardConnectGithub()`: OAuth connect → `window.open(auth_url)` → bounded poll on
  `/v1/onboarding/github/status` until `connected`, then PATCH state + `reindexGithub()`.
- A11y conventions to preserve: `role="switch"` + `aria-checked`, `aria-live="polite"`
  on status lines, `role="alert"` on per-row errors, `aria-label` on switches.

### API surface (`tortoise/hosted_api.py`)
- `GET /v1/onboarding/github/status` → `{connected, org, repos_count}`. Uses
  `_github_credentials(team_id)` → decrypt → `_github_repos_count(token)`.
- **`_github_repos_count` returns a COUNT ONLY** (via `user/repos?per_page=1` +
  `Link: rel="last"` header). It does **NOT** return repo names.
- `POST /v1/index/docs` (`DocsIndexRequest: org, repo, branch`) → `_run_docs_indexing`
  already handles `repo` (`repos = [f"{org}/{repo}"]`) and `branch` (default `main`,
  `walk_repo` → `_get_tree` falls back main→master). **repo + branch EXIST server-side.**
- `POST /v1/index/github` (`GitHubIndexRequest: org, repo`) → `_run_indexing` handles
  `repo` the same way (`repos = [f"{org}/{repo}"]`).
- `POST /v1/index/github/re-poll` — **takes NO body today**; reads org from stored
  creds and always passes `repo=None` (full-org diff).
- `tortoise/indexer/github_indexer.py` `GitHubIndexer.resolve_repos(org)` returns
  repo **`full_name`s** (`org/repo`) via `orgs/{org}/repos?per_page=100` with a
  `users/{org}/repos` fallback. `GitHubDocsIndexer` extends `GitHubIndexer`, so it
  inherits `resolve_repos`.

### KEY CONSTRAINT (resolved)
The GitHub token is server-side **encrypted** (`tortoise.crypto.encrypt_token`),
stored on the Team record, and never sent to the client. The UI therefore **cannot**
enumerate repos via the GitHub API directly. No existing endpoint returns repo names
(`status` → count only). `resolve_repos` already does the fetch server-side.

→ **Decision: add a small `GET /v1/onboarding/github/repos` endpoint** (team-scoped,
non-gated, mirrors `/status`), reusing `decrypt_token` + `GitHubIndexer.resolve_repos`.
This is justified by the issue's explicit "list of the org repos" indicator and is
small — the server already has every piece.

### Pre-existing UI components
- The monolith has **no repo/dropdown-picker component**. There are three bare
  `<select>`s (graph selector on API Keys page `.page-graph-selector`, invite role).
- `.page-graph-selector` CSS (label + `<select>`, accent focus ring) is the reusable
  visual pattern. No searchable combobox / listbox / list-picker exists.
- `input, textarea, select` already share a base style at the bottom of `index.css`.

## B. External UX patterns (cited)

1. **GitHub App installation scope — "All repositories" vs "Only select repositories"**
   is the canonical privacy/scope model. Vercel's KB + GitHub discussion #5755 describe
   the same pattern: a repo picker whose default is "all", with a per-repo restriction
   path. (https://vercel.com/kb/guide/unable-to-find-github-repository,
   https://github.com/vercel/vercel/discussions/5755)
2. **Vercel/Netlify import flow** — searchable repo picker; missing repos surface a
   "Configure GitHub App" affordance to widen "only select" → "all". (Vercel docs)
3. **GitHub Copilot content exclusions** — fnmatch-style glob patterns exclude repos
   **and paths** (exclude-list model). This is the established shape for folder/subpath
   scoping and "keep private" exclusion. (https://learn.microsoft.com/en-us/training/modules/github-copilot-management-and-customizations/4-manage-content-exclusions)
4. **Default branch** — `main` is the modern GitHub default, `master` the legacy
   fallback (also encoded in the issue and server-side `walk_repo` fallback).
5. **Picker accessibility** — native `<select>` + visible `<label>` is the a11y-safe
   baseline; searchable comboboxes (Backstage `RepoUrlPicker` `AccessibilityLabel`,
   Power Platform Picker) are the large-list upgrade path.

## C. Design (v1)

### Repo names come from a NEW endpoint
`GET /v1/onboarding/github/repos` (team-scoped, `get_current_team_session_ungated`),
returns `{connected, org, repos: [short-name, ...]}`. Short names (owner prefix
stripped) because the index endpoints already construct `f"{org}/{repo}"`. Resolve
failure → `repos: []` (selector still renders "All repos"; never a 500).

### Shared selector (docs + issues rows)
- Repo `<select>`: "All repos" (default, value `""`) + each repo name, populated from
  the endpoint when connected. Issues row = repo only; docs row = repo + branch.
- Branch `<select>` (docs only): `main` (default) + `master` (server falls back).
- Privacy note (dim small): "Parts you want to keep private stay out — scope the index
  to the repos you choose." (folder/exclusion deferred).
- Count/preview: when "All repos", "N repos will be indexed"; single repo, "repo X".

### Wiring (no breakage of connect/toggle/index)
- `indexDocs()` → `POST /v1/index/docs` with `{org, repo?, branch?}` (repo/branch
  omitted when "all"/default).
- `reindexGithub()` → `POST /v1/index/github/re-poll` with optional `{repo}` (the
  handler gains an optional body; org still read server-side). Backward compatible
  (no body = full-org diff, same as today).
- Connect flow, bounded poll, `role=switch`/`aria-live`/`role=alert` all unchanged.

### v1 vs deferred
- **v1:** repo selector (all + per-repo) for both rows; branch selector (main/master)
  for docs; repo-list endpoint; privacy note; count/preview; docs status shows
  "across N repos".
- **Deferred (NOT built):** folder/subpath scoping (fnmatch exclude-list per Copilot
  pattern); include/exclude-list privacy beyond per-repo; searchable combobox for
  large orgs (native `<select>` suffices at v1).
