## 2. The run — three arms on the C2 shape

Pool: **139 hits** — 103 for the flooded fact (79 statement restatements +
13 flood points entangled with the content-less class + 3 own-source turns +
8 raw chunks), **24 content-less
operator hits** (#2978's class), 4 value-critical claims (two same-frame
different-value pairs: `300`/`400`, `12`/`60`), 8 unrelated facts. Window:
**40 items** (wave §1's window), token budget far above the cap so the ITEM
bound is what binds. `pre_2978` is a **reconstruction** — the shipped
`assemble_context` with the pre-#2978 predicate restored (`_has_claim_text`
forced True, which removes exactly the one `continue` #2978 added).

| Arm | admitted | content-less slots | slots for the ONE flooded fact | value claims in the window |
|---|---|---|---|---|
| `pre_2978` *(reconstructed)* | 40 | **24 (60.0%)** | **16 (40.0%)** | **0/4** |
| `post_2978` *(shipped predicate)* | 40 | 0 | **40 (100.0%)** | **0/4** |
| `post_2978_assembly` (**A6 arm ON**) | 14 | 0 | **2** (= 1 + `max_verbatim`) | **4/4** |
| `post_2978_assembly_value_marked` | 14 | 0 | 2 | 4/4 (value-first: 4 packages) |
| `provenance_free_assembly` (**#8658** shape) | 24 | 0 | **12** | 4/4 |

Control: a duplicate-free, provenance-bearing pool of 8 facts comes back
**byte-identical** from the arm (0 collapsed, same ids, same order) — the
no-regression leg.

### What the numbers say

1. **The baseline expired, and it expired in a measurable direction.** The
   pre-#2978 predicate spends **60%** of the C2 window on hits that render
   nothing — the measured `61.3%` class of #2978. That composition cannot be
   reproduced today: the pipeline no longer admits those hits.
2. **#2978 did NOT bound the flood.** Removing the empty hits **reallocates**
   the freed slots to the highest-ranked *real* hits — and on a coverage-loop
   flood those are the duplicates: the shipped predicate alone gives **100%**
   of the window to **one fact**, and the value-critical claims get **no** slot.
   The #2683 defect is undiminished on this shape; it is a different defect from
   #2978's.
3. **The assembly is what bounds it** — one fact to `1 + max_verbatim` slots,
   with the freed slots going to distinct evidence, and **4/4** value-critical
   claims admitted. That is the product claim Slice A makes, measured.
4. **The bound is lane-scoped, and the instrument measures the limit rather
   than assuming it away.** Without `quote`/`source_turn_id`, pass 2 (a point's
   OWN source chunks/turns) is inert: 12 flood slots instead of 2. Pass 1's
   content legs are provenance-independent and still dedup the *statement*
   flood. **#8658** is that state on the product ask lane.

> ⚠️ **The number this is NOT.** `2 vs 100%` is a *window composition* result,
> not a QA result. The old T wanted "the 2 C2 flooding regressions recover" — an
> **answer-accuracy** delta under a frozen reader. Nothing here substitutes for
> it, and no reader/judge number may be derived from this receipt.

### 4.2 The re-specified gate

| Leg | Statement | State |
|---|---|---|
| **T-1** *(structural)* | On a **provenance-bearing** C2-shaped pool, the shipped window admits **no** content-less slot; the A6/A8 assembly holds any one fact to `≤ 1 + max_verbatim` slots; **no** value-critical claim is lost; a duplicate-free pool is returned byte-identically. (The provenance-free ask-lane shape is measured separately at 12 slots — #8658.) | **RUN** — this document + the receipt + `tests/longmem_eval/test_slice_a_flood_bound.py`. |
| **T-2** *(end-to-end, post-#2978)* | Same frozen reader + judge on the frozen 50 qids: the A6 arm **ON vs OFF**, reported as an **ON/OFF delta against the post-#2978 OFF arm** (never against C1's 0.780). | **NOT RUN here** — re-homed, §4.4. |

**Why T-1 is the right re-specification and not a substitute dressed up as
one:** it measures the exact property the old T's second clause was protecting
("Slice A must make the product robust" to a flooding window) and it is the
part that never needed a reader. What it cannot do — and does not claim — is
produce an answer-quality number. That is T-2's job, kept separate on purpose.

### 4.3 Why the two arms were **NOT** retired

The issue offers withdrawal as the alternative ("the arms are OFF everywhere, so
nothing regresses on withdrawal") — and the arms **are** OFF everywhere
(re-measured §1). It was **not** taken, deliberately:

* withdrawing would reverse a delivered, evidence-backed, hermetically tested
  capability (`docs/scoping/2026-09-09-evidence-assembly-wave.md` §4; 25 tests
  in `tests/test_evidence_assembly.py` + the guard here) **on the grounds that a
  measurement was hard to run** — the easy path, not the good one;
* the measurement is not hard any more: `TORTOISE_LME_EVIDENCE_ASSEMBLY` is
  **read only at retrieval time** — one read site, `tools/longmem_eval/
  retrieve.py` (A6); the ask lane's product-side sibling
  `TORTOISE_ASK_EVIDENCE_ASSEMBLY` is likewise read only in `retrieve`-time
  code (A8, `tortoise/ask_lane.py`) — and none of the ingest cache's own inputs
  changes when either flips (`ingest_cache_fingerprint`: extractor code
  version, extraction model id, extraction prompt digest, the question JSON,
  `chunk_turns`, `session_workers` — no such flag among them; both are also
  absent from the read-side knob list the run fingerprint records), so flipping
  the LME flag **alone** does not invalidate the ingest cache. The ON/OFF A/B therefore costs **2× reader+judge calls and
  0 extra ingest** — the cheapest end-to-end arm available.
* withdrawing is trivially reversible later; re-deriving the capability is not.
