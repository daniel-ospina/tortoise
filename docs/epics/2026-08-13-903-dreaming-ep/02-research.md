## Strategy Context

**Market:** Agent-memory is a crowded, fast-moving market (Zep/Graphiti, Letta, Mem0, MemGPT lineage, Hindsight, plus framework-native stores). Competitors differ on *what* they store and *how* retrieval works; almost all are **silent on consolidation policy** — the "background maintenance" layer. Hindsight's field review: *"Most agent memory systems are explicit about retrieval architecture and silent about consolidation policy. That silence is where production failures live."* This is the competitive white space #903 occupies.

**Key precedent — Graphiti/Zep (arXiv:2501.13956):** bi-temporal knowledge graph (`valid_at` / `invalid_at` / `expired_at` fields), facts *invalidated* not deleted, point-in-time queries. Benchmarks: LongMemEval up to 18.5% improvement, LoCoMo 94.7% accuracy @ 155ms, DMR 94.8% vs 93.4%. **Graphiti handles *fact* freshness via temporal validity windows — it does NOT do belief propagation or background confidence recomputation.** No competitor runs a loopy-BP freshness scheduler. Tortoise's dreaming is differentiated: it refreshes *derived beliefs* (confidence), not just stored facts. The state-centric model (issue comments: confidence derived from points) makes this the mechanism that keeps derived state honest.

**Staleness is the documented #1 failure mode** (multiple independent sources):
- n26modi head-to-head: staleness error 87%→20% with temporal-KG memory (single-engineer experiment — treat magnitude as unverified).
- 2026 field reports (memory-drift / reconciliation articles): *"The world simply moved while the agent was looking elsewhere… drift is a thermodynamic property"*; the fix pattern is **reconciliation = watermark + change-feed + lazy revalidation**, exactly the cache-invalidation primitives that make replicas honest.
- MemFail (arXiv 2605.26667): memory systems fail by architecture, not by model quality — **no single backend dominates**; graph-based systems excel at causal reasoning but collapse on coexisting-fact retrieval.

**Business-model implication:** dreaming is not a user-facing feature; it is the quality floor under every user-facing belief query (recall, decide, confidence). Its profit chain is retention/trust, and its failure mode is silent degradation (see Workflow Patterns — dead background jobs look like "nothing to do").

## UX Pattern Research

- **Freshness must be queryable, not just automatic.** The memory-drift pattern: every read compares a watermark (`lastDreamedAt`) against a trust budget; reads of stale regions either trigger refresh or return annotated "may be stale, last reconciled at T". For Tortoise: expose staleness on `get_confidence` / recall surfaces (`staleAfter`/`lastDreamedAt` fields, and a `staleness_report` endpoint).
- **Selectable modes are a settings/API concern, not UI** — the epic's Indicator 2 (full-graph vs expanding-window selectable) maps to an SDK/MCP `dream(mode=...)` parameter plus hosted config. No new UI surface needed (engine epic).
- **Anti-pattern — recency as retrieval multiplier:** one field report warns against post-multiplying relevance by recency ("this week's chatter beats last year's decisive answer"). For Tortoise, freshness should *flag* confidence, not reorder retrieval.
- **TTL/mutability typing:** uniform staleness thresholds guarantee over-refresh of stable data + under-refresh of volatile data simultaneously. Type regions/claims by mutability class (stamped-immutable vs slowly-mutable vs volatile) and apply per-class decay — "getting it roughly right matters more than perfect."

## Workflow Pattern Research

- **Sleep-time compute (Letta, arXiv:2504.13171):** background inference between interactions; raw context → "learned context"; **anytime writes** so readers never wait for the background pass; a primary agent + a dedicated sleep-time agent split. Direct analogues: Tortoise's fast path (primary) + dreaming (sleep-time), and the #85 design already has the latency-budget + lazy-read fallback.
- **Memory consolidation failures are silent.** Field catalog: a dead background job looks identical to "nothing to do" — the fix is **alerting on task failure rate and zero-output-when-output-expected**, plus bounded retries per call (failure compounds across fan-out: 14 calls at 5% failure ≈ 50% job failure). Dreaming needs observability: dream health metrics, last-pass timestamps, per-region coverage — or a silently dead dreamer is indistinguishable from a converged one.
- **Consolidation is a policy layer.** Hindsight's levers: importance scoring at write, entity resolution at write-time, decay, merge-not-delete, eviction only for compliance. Tortoise already has supersede/merge writes marking dirty roots (`_mark_dirty([old_id, new_id])` / `[id, corrected_by_id]`) — the policy layer exists; dreaming must *absorb* those events as freshness inputs (state-centric model: lifecycle events change what propagates).
- **Compaction-trap caution:** "why-not" records and negative constraints get lost in lossy compression. Not directly applicable (Tortoise doesn't summarize), but a warning against using summaries as the memory record — aligned with the graph-as-memory hypothesis.

## Tech Stack Research

**Incremental EP — the core algorithmic opportunity.** Three strong precedents for re-running loopy BP without full recompute:

1. **EFBP — Expanding Frontier Belief Propagation (Nath & Domingos, AAAI 2010).** Reuses the previous run's final messages; maintains a frontier set Δ of affected nodes; only nodes in Δ send messages; neighbors enter Δ when received-message change exceeds threshold γ; bounded difference vs standard BP proven; experiments show orders-of-magnitude speedups. **This is the direct blueprint for Indicator 4 (bounded cost)**: TortoiseEP's per-run caches become *persisted between runs* (cross-run message cache keyed by operator/edge), and the dream seeds Δ with the dirty roots instead of recomputing from scratch. Worst case degenerates to full BP (already handled).
2. **AdaBP (Papachristoudis & Fisher, 2015)** — minimal messaging schedule for adaptive inference; exact on trees; Gaussian-loopy extension. (Informative, less directly applicable to Bernoulli-Beta loopy EP.)
3. **Dynamic-inference theory (Sumer et al. NeurIPS 2007; Feng et al. ITCS 2021)** — dynamic updates with cost proportional to change magnitude; theoretical floor confirming the approach is sound.

**Freshness-aware scheduling — the trigger pattern.** CPU-aware materialized-view refresh (2026 defensive pub, MV001): refresh triggers on **staleness threshold + CPU budget + concurrency limit**; graceful degradation under load; adaptive intervals. MAUVE (1998): more-frequent online view updates reduce staleness, and an *optimal* frequency exists (neither too slow nor thrashing). Incremental view maintenance (IVM) in graph DBs: dirty flags + Update/Delete/Create maintenance phases; incremental wins by orders of magnitude until updates touch a large fraction (then full recompute wins — a decision rule worth encoding).

**Region/windowing — do NOT reach for community detection.** Louvain-based partitioning works for distributed RDF but has a documented pathology: strongly-connected partitions create **workload imbalance** (some regions hot, others idle), and real-world ontologies produce huge partitions. Tortoise's natural region primitive already exists: **BFS neighborhood from stale anchors** (`_bfs_select_operators` with max_hops) — the same primitive the fast path and `_mark_dirty` use. Windows = ranked batches of stale-anchor neighborhoods, deduped by operator set. Workload-aware partitioning literature also warns: partitioning quality depends heavily on workload coverage — another reason to use the write/dirty workload itself as the window selector.

**Consolidation interplay.** Merge/supersede already mark both endpoint ids dirty. Dreaming absorbs them by (a) treating the merged region as dirty, (b) re-deriving confidence for the surviving node (its priors come from the merged points), (c) **deduping operator sets across windows/batches** — the current `dream_all` re-BFSes each batch independently, so overlapping subgraphs recompute repeatedly (confirmed gap in `tortoise/dream.py`). Operator-set dedup + cross-run message cache are the two concrete cost fixes.

**Staleness-error evaluation (Indicator 3).** No existing eval measures stale-belief-vs-ground-truth error (G7 is a grounding regression gate, |Δconf| ≤ 0.01, not staleness). Precedents: MemFail (failure-mode benchmark taxonomy — summary/storage/retrieval), Graphiti's point-in-time query benchmarks, and the epistemic-layer eval spec's scenario pattern (R1–R8 with exact acceptance numbers). Design: point-in-time retrieval error — freeze ground truth, apply a change, measure error of un-dreamed confidence vs dreamed confidence, assert decaying error as windows expand.
