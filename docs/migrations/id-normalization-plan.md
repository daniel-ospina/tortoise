> **Status:** Planning only — NO destructive migration runs without explicit human approval.
>
> **Issue:** [#52](https://github.com/daniel-ospina/tortoise/issues/52)
>
> **Date:** 2026-08-04
>
> **Team:** capability

---

## 1. Problem

The Tortoise graph (~5500 points in `falkordb-personal`) contains fragmented Point ID formats:

| Format | Pattern | Description |
|--------|---------|-------------|
| **ULID** | `[0-9a-f]+-[0-9a-f]{12}` | Canonical — auto-generated by `create_point` |
| **19fc-hash** | `19fc[0-9a-f]+` | Hash-style IDs from pipeline agents |
| **numeric** | `^\d+$` | Early points and internal traverse leaks (#44) |
| **letta-\*** | `letta-*` | Letta agent prefix |
| **op-\*** | `op-*` | Operator prefix |
| **ARCH_\*** | `ARCH_*` | Architecture decisions |
| **SVBP_\*** | `SVBP_*` | Strategy/value prop |
| **STRATEGY\*** | `STRATEGY*` | Strategy documents |
| **RESCORE_\*** | `RESCORE_*` | EP rescoring passes |
| **EP_PASS_\*** | `EP_PASS_*` | EP propagation passes |
| **GATE\*** | `GATE*` | Gate evaluations |
| **UC\*** | `UC*` | Use case identifiers |
| **C\*** | `C\d+` | C-prefixed identifiers |

**Impact:** Cross-tool identity is unreliable. The traverse ID leak (#44) is the worst symptom — internal numeric IDs leak out. Search/query/EP work across schemes (matching on content/context) but cross-tool references fail.

## 2. Pre-Migration

### 2.1 Backup

Run existing backup tool before any migration step:

```bash
tortoise backup --output /backup/tortoise-pre-id-normalization-$(date +%Y%m%d).rdb
```

Verification: restore the backup to a staging instance and confirm all Points are present.

### 2.2 Audit

Run the audit script to establish the baseline:

```bash
TORTOISE_DB_URI=docker://:@localhost:16379/tortoise python3 graph-scripts/audit_ids.py
```

Save the full output as `docs/migrations/id-normalization-baseline-YYYYMMDD.txt`.

### 2.3 Dry-Run

Use a copy of the graph or a staging instance. The same `TORTOISE_DB_URI` format with a different database index:

```bash
# On staging DB (port 16380 or index 15 on same instance)
TORTOISE_DB_URI=docker://:@localhost:16380/tortoise python3 graph-scripts/migrate_ids.py --dry-run
```

## 3. Migration Steps

### 3.1 Generate ULID for Each Non-ULID Point

For every Point whose `id` does not match the canonical ULID format:
1. Generate a new ULID via `tortoise.ids.ulid()`
2. Store the mapping: `{old_id: new_ulid}` in a migration tracking set in Redis

### 3.2 Rewrite Point IDs (per-format batches)

Process one format at a time to limit blast radius:

| Batch | Format | Approach |
|-------|--------|----------|
| 1 | numeric | Smallest batch, test the pipeline |
| 2 | 19fc-hash | Second batch, verify edge rewrite |
| 3 | letta-* | Third batch |
| 4 | op-* | Fourth batch |
| 5 | ARCH_* | … |
| 6 | SVBP_* | … |
| 7 | STRATEGY* | … |
| 8 | RESCORE_* | … |
| 9 | EP_PASS_* | … |
| 10 | GATE* | … |
| 11 | UC* | … |
| 12 | C* | … |

Each format batch: migrate → verify → commit (proceed to next batch only after verification passes).

### 3.3 Edge Endpoint Rewrite

**Critical:** FalkorDB edges reference Point IDs in their endpoints (source and target are node IDs stored in the edge). Every edge involving a migrated Point MUST be rewritten.

For each `old_id → new_ulid` mapping:
```cypher
-- Create the new Point node with the ULID id
-- Copy all properties from old node
-- For every edge (old)-[r]->(other): CREATE (new)-[r2:type_of_r]->(other), copy properties
-- For every edge (other)-[r]->(old): CREATE (other)-[r2:type_of_r]->(new), copy properties
-- Delete old node and its edges
```

This MUST be atomic per Point — a single Redis transaction (MULTI/EXEC) or Cypher batch per migration unit.

### 3.4 Add `legacy_id` Property

For auditability, add a `legacy_id` property to each migrated Point storing its old ID:

```cypher
MATCH (n:Point {id: $new_ulid}) SET n.legacy_id = $old_id
```

This enables the `resolve_id` helper to map legacy IDs to canonical ULIDs post-migration.

## 4. Verification Gates

### 4.1 Point Count

Before and after each batch:

```bash
python3 -c "
from tortoise.sdk import TortoiseSDK
from tortoise.projection import FalkorProjection
sdk = TortoiseSDK()
sdk._proj = FalkorProjection.from_uri('docker://:@localhost:16379/tortoise')
r = sdk._proj.g.query('MATCH (n:Point) RETURN count(n)').result_set
print('Points:', r[0][0])
"
```

Count must be identical before/after (no point creation or deletion, only ID rewrite).

### 4.2 Edge Count

Same check for edges:
```cypher
MATCH ()-[r]->() RETURN count(r)
```

### 4.3 ID Format Audit

After migration, re-run `graph-scripts/audit_ids.py`. All Points should now be in the `ULID` category. Non-ULID entries indicate a missed batch.

### 4.4 resolve_id Verification

For a random sample of migrated legacy IDs:
```python
point = sdk.resolve_id("old_legacy_id")
assert point is not None, f"resolve_id failed for old_legacy_id"
assert _is_ulid(point["id"]), f"resolved id {point['id']} is not ULID"
```

### 4.5 EP Propagation

Run an EP propagation pass after migration to confirm no weight corruption:
```bash
TORTOISE_DB_URI=docker://:@localhost:16379/tortoise python3 -c "
from tortoise.sdk import TortoiseSDK
from tortoise.projection import FalkorProjection
sdk = TortoiseSDK()
sdk._proj = FalkorProjection.from_uri('docker://:@localhost:16379/tortoise')
# Run EP pass and check for anomalies
"
```

## 5. Rollback

### 5.1 Restore from Backup

If any verification gate fails, restore from the pre-migration backup:

```bash
tortoise restore --input /backup/tortoise-pre-id-normalization-YYYYMMDD.rdb
```

### 5.2 Per-Batch Rollback

Each batch stores its mapping. Rolling back a single batch:
1. Load the batch's `{old_id: new_ulid}` mapping
2. Reverse the migration: rewrite edges back to old IDs, delete ULID nodes
3. Restore `legacy_id` property removal

---

## 6. Post-Migration

### 6.1 Cleanup

After all batches pass verification:
1. Remove `legacy_id` properties (optional — keep for audit trail)
2. Update `resolve_id` to use legacy_id property for lookups
3. Run full audit again, commit final baseline

### 6.2 create_point Enforcement

After migration, `create_point` already warns on non-ULID IDs (Issue #52, implemented in `tortoise/sdk.py`). No further action needed — the warning stops accumulation of new legacy IDs.

### 6.3 Traverse ID Leak Fix (#44)

Fix the traverse operation to never expose internal numeric IDs. This is the root cause of new numeric IDs entering the graph.

---

## 7. Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Edge rewrite corrupts graph topology | Medium | High | Atomic per-Point transactions, per-batch verification |
| EP weights shift due to edge re-creation | Low | Medium | Pre/post EP pass comparison |
| Migration takes too long (~5500 points) | Medium | Low | Batch processing, can be run incrementally |
| resolve_id fails for old IDs post-migration | Low | Medium | `legacy_id` property preserves old ID for resolution |
| Concurrent writes during migration | Low | High | Run during maintenance window, take DB offline |
