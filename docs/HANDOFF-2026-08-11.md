## 4. The architecture decisions (all recorded in scope.md + docs/drafts/)

- **Value-first extraction** — ontology defines value; extractor may return nothing; regex rejected (measured 88% noise, ~160 nodes/turn).
- **Four-node model** (owner-confirmed, ontology-grounded): `Event (agentSession) → produces → Document (transcript: summary/arc/sessionId) ← references ← Source (provenance bridge: kind/tier/url/hash) ← extractedFrom ← Points`. Source is the bridge, not the content holder.
- **Local intelligence / remote graph** (the capture architecture): extraction runs on the user's machine with THEIR key/model; hosted receives derived commits only. **BYOK is THE default** (owner: "their agent does the extraction, we provide the process; in-housing comes later"). Raw-upload + managed-key = explicit opt-ins; **managed-key NOT in v1**.
- **NAND**: bidirectional default (logical mutual, #807); directed attack = agent-declared `unidirectional` (no back-pressure). **Extraction-emitted NANDs = always `unidirectional`** (new-claim-attacks-existing; the surfacing feature depends on it — P9/A8 gate).
- **No per-turn nodes** (conversation = one Document/Source).
- **Warrants/implicit premises deferred** (dangerous, research-grade) — at most user-opted toggle later.
- **Pricing**: tiers = feature baselines; usage metered separately; no capture caps; break-even via cost cut (warrants out of default → capture cost ~$0.011 < write-op revenue $0.02). DeepSeek V4 Flash = the managed-path model if ever in-housed.
- **Economics**: local extraction → 85-96% GM on default path; storage ~$1/mo heavy user; bytes/node is the one swing variable to instrument.
