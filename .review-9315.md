### P2-1 — `test_a_shadowed_builtin_CALLEE_is_reported_not_blessed`'s LOCAL half is vacuous (would pass on the pre-fix helper)

`tests/test_9124_declared_live_doors.py:2764-2782`

```python
local = (
    ...
    '        parts = _parts\n'                      # :2769
    '        query += f"{format(parts())}"\n'          # :2771
    ...)
offenders = _offenders_for(local, with_module=True)
assert any("could not be read out" in offender for offender in offenders), (
    "a LOCAL binding of a builtin-shaped name was blessed as the builtin, ...")
```

The trap the test is named for is `format` shadowed by a **local** binding. In the fixture as written `format` is **not** bound anywhere: `parts = _parts` binds `parts`, not `format`. Trace of `_fragments_of` over `f"{format(parts())}"`:

* outer `Call` `format(...)` → `_resolve_callee("format", …)` is `None`; the report arm's guard is `id not in _BUILTIN_NAMES or id in bindings or id in _module_bindings(module)` — `format` is a builtin, is not in `bindings` (`{parts, query}`), and this fixture has **no module-level assignment at all**, so the guard is False and nothing is reported;
* inner `Call` `parts()` → `parts` is not a builtin and resolves to no def → `unread.add("parts()")`.

So the offending entry is `parts()`, contributed by the **unresolvable-callee** arm, and `unread` is non-empty for a reason that has nothing to do with the builtin-shadow clause. Mutation check: change that arm's `or sub.func.id in bindings` to `or False` — `format` was already unblessed-by-absence, `parts()` still reports, **this test stays green**. Proven from the source; it needs no execution.

Non-vacuous form (what makes the arm discriminating, and what the description says was done): bind the shadow so the callee name itself is the offender —

```python
'        format = _parts\n'
'        query += f"{format()}"\n'
```

Then the only reportable entry is `format()`, and reverting the binding-table clause reds the test. The module-level half (`next = _parts`, `next()`) *is* non-vacuous — it exercises the `_module_bindings` clause — so only the LOCAL half, which is the half its own failure message names, is unguarded.
