Raw things that bite mid-code. Not an implementation log, not a docs index.
Format: `[category]: [what broke] → [root cause] → [the fix]`. Cap: 150 lines.

[env]: `uv run python /tmp/probe.py` from a worktree imported `tortoise` from a **different worktree** → the shared `.venv` has an editable install, and `uv run` without `--no-sync` re-resolves it → always `PYTHONPATH=$PWD uv run --no-sync python ...`, and print `tortoise.__file__` to confirm before trusting any result.

[io]: A size-BOUNDED append-only ledger grew past its own bound because the `capped` marker was re-written on EVERY later event (each one satisfied `size >= cap` and appended another marker): 60 markers turned a 300 B cap into a 5.5 KB file → decide the marker from the FILE's tail (check the last line for the marker another process already wrote), never from a process latch: the marker is written ONCE per cap, and a ROTATED file that caps again still says so; and bound on `path.stat().st_size`, not `fh.tell()` — `tell()` reports THIS handle's position at open and cannot see another appender's bytes (measured 52 vs 60), which is the case a multi-process ledger exists for.
[grep]: `git grep -E` is POSIX ERE and has **no** `\b`, so a census pattern carrying `\b(...)\b` matches NOTHING and prints a clean "no matches" — a false negative indistinguishable from the real answer it was asked for (a read-instrument census nearly reported "no instrument exists" for the wrong reason) → drop `\b` (the names are specific enough) or use `-P`, and print the grep's exit code beside every result so an empty answer is visibly an answer.
[retry]: A retry "witness" defined as "did at least ONE row match" reports a HALF-LANDED multi-target write as success → a multi-target statement (per-key `SET` loop, tag-name set) matches some of its targets, so at-least-one is satisfied while the rest are still un-replayed → the witness must answer "did this statement do what it was ASKED for": ALL-of-N for a multi-target write, at-least-one only for a single-target one; a multi-statement `fn` whose return value is not a landing proof, or any witness that READS THE GRAPH to classify a zero row, may answer that way but must never mutate; a witness MAY answer True on a zero row when the zero row is EXPLAINED — the state SATISFIES the ask (idempotent promote), REFUSES it (terminal/NULL against a literal-status CAS), or nothing was asked (vacuous) — and may RAISE the caller's documented error to end the retry at once (#7405 / PR #8884 review).
[compensate]: A compensating write (rollback of the stamps a failed operation had already applied) must CLASSIFY the landing, never infer it from the exception: `except: rollback()` assumes "nothing was written", but a raise from a post-CAS tail (`_mark_dirty`, a dedup wire, the snapshot read an event emit makes) means the write LANDED, so the rollback destroys a correct record — the inverse of the limbo it exists to fix, and — for a temporal candidate, when auto-accept is enabled and the EP posterior clears the threshold — `sweep()` (which filters on the stamp, not on status) then journals a SECOND `DedupeRecorded` for one logical merge (below the bar it is merely re-queued) → re-read the node after the raise and roll back only when it is NOT in the landed state; and a cleanup that fails must log, never replace the exception it was cleaning up (#8884 review P1/P2).
