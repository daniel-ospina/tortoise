# MEMORY.md — coding gotchas

Raw things that bite mid-code. Not an implementation log, not a docs index.
Format: `[category]: [what broke] → [root cause] → [the fix]`. Cap: strictly UNDER 150 lines, checked as `len(lines) < 150`, so 149 is the LARGEST legal size — and `tests/test_memory_md_hygiene.py::test_memory_md_stays_under_the_line_cap` reds the required `test` lane at 150, so retire a row before you add one.

[template]: A CHAIN of `str.replace()` passes over a template rescans what each earlier pass inserted, so a VALUE that contains a placeholder token gets expanded inside the JSON/HTML literal meant to hold it — and because the injected text is itself JSON, its own quotes close that literal early (hard `SyntaxError`, whole block discarded; `state` was never shape-validated and `client_name` is DCR-controlled, so no crafted link is needed) → escaping FIRST does not help: the later pass re-interprets the text *carrying* the value, which is why every pre-existing escape assertion stayed green on a dead page → substitute in ONE pass, `re.sub(pattern, lambda m: mapping[m.group(0)], template)` (the FUNCTION form also keeps re's backslash processing off the replacement text — a string replacement mangles an escaped value's literal `\u003c`), and derive the pattern from the mapping's keys so a new placeholder has one place to be declared (#6001).
