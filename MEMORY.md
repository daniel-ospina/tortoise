- [tests]: `subagent-integration.test.ts` uses process.cwd()-relative paths (`join(process.cwd(), "extensions", ...)`) → run from the REPO ROOT (`npx tsx extensions/builtin-tools/subagent-integration.test.ts`); running from inside `extensions/builtin-tools/` yields a doubled-path ENOENT.
- [watchdog]: a child's background-timer tick proves process liveness, NOT work progress — a hung provider request keeps ticking; only work-loop signals (message/tool events) prove progress. Distinguish the three questions (liveness/activity/downstream) in separate watchdog clauses (K8s three-probe lesson; dora-rs "busy-but-silent" incident).
- [subagents]: `resolveUndefined = !hasOutput` per kill — a cut with only non-marker startup stderr resolves a DEFINED partial (not retryable); a zero-output cut is retryable-undefined (feeds the retry wrapper + circuit breaker, which trips at 3 undefined strikes session-wide).
- [research]: Tortoise memory unavailable vs never configured — `tortoise-memory.mjs` prints `status: "not_configured"` (no usable `TORTOISE_API_KEY` — unset OR rejected with HTTP 401/403) or `status: "tortoise_unavailable"` (the store could not be reached, incl. a 5xx); an answered 4xx other than 401/403 exits 2 with NO `status` field (frozen three-word vocabulary). Data subcommands still exit 0, only the `status` probe exits 4/3 (#1182).
- [gh]: GraphQL rate limit resets independently of REST — when `gh issue comment`/`gh pr merge` fails with "GraphQL: API rate limit exceeded", fall back to REST (`api.github.com/repos/.../issues/N/comments` POST, PATCH issues/N) which shares the core REST quota.
- [git]: `git stash pop` can silently drop a stash whose diff doesn't re-apply to a moved base — recover from the dangling stash commit (`git fsck --no-reflogs | grep dangling`, `git show <hash>:<path>`).
- [commit]: the review-enforcer merge gate needs `scripts/record-review.sh <PR> <head_sha> clean <owner/repo> --evidence <artifact>` BEFORE `gh pr merge` — run code-review to convergence, record the verdict naming the review artifact (`comment:<id>`), then merge (never `--delete-branch`; delete the branch separately). Since tortoise#7391 a fresh `clean` without `--evidence` exits 3.
- [git]: main-worktree-guard mis-parses compound bash commands — unexpanded `$VAR` and pipes/redirects (`2>&1 | tail`) get parsed as push refspecs → run git ops as SIMPLE single commands, never `&&`-chains with variables. (In-hub `git checkout -b` is blocked outright since #626 — create branches in a worktree.)
- [git]: verification-gate hashes staged file CONTENT with sha256 — a [VGATE] verifier returning sha1 hashes fails "Hash mismatch"; have it run `shasum -a 256` and echo the exact hex digests. In a task sub-agent session the gate registers verification ONLY from a response that is the exact JSON schema ({"status":"PASS","verified_files":[{path,hash sha256}]}) with the full file list in the prompt — a prose "PASS" report with no per-file hex digests leaves the registry empty and the git op still blocked (PR #459).
- [git]: `git worktree list --porcelain -z` needs git ≥ 2.36 (the `-z` option landed in 2.36.0, not 2.25) — on older git the command fails → treat the cross-check as skipped. git ACCEPTS worktree paths with trailing spaces and embedded newlines (porcelain prints them raw) → never trim path whitespace and never line-split porcelain (NUL-split only) or legit worktrees false-block (main-worktree-guard #351).
- [bash]: real bash resolves the FIRST non-flag positional as the interpreter's script — later tokens are that script's argv, never bash flags (so LAST-positional resolution mis-gates arg-taking invocations: `bash hub-worktree.sh salvage feat/x <repo>` resolves <repo> → non-file → content gate skipped; #444). `-s`/+s and letter-runs containing `s` demote positionals to $0/$1 (stdin script); `-c`/+c = inline (no file); operand-taking options (`-O`/`-o`/`--rcfile` space+`=` forms) skip one operand word; `--` ends option scanning; `+`-toggles mirror `-` runs; mixed-sign words (`-+e`) are rejected by real shells → over-resolving those is harmless. Verify against real bash (dash/bash/zsh) — POSIX doc reading misleads (classify-git extractScriptPath, #520).
- [cache]: negative-TTL retry was dead code — a `x !== undefined` sentinel on a `string | null | undefined` cache short-circuits on a cached FAILED (null) resolution, making a transient failure terminal for the session → distinguish resolved-null from unresolved with `typeof x === "string"` (or a separate resolved flag) and pin the failure→retry sequence in tests (main-worktree-guard #350).

- [liveness]: `cmux list-workspaces --json`'s `latest_submitted_at`/`latest_submitted_message` are INBOUND — the last turn submitted TO a workspace, NOT output produced BY it (measured: the orchestrator's is its own heartbeat, a marketing lane's is the OWNER asking a question, a rail lane's is a dispatch someone sent it) → reading it as a liveness signal let it VETO any verdict, including `WEDGED`, which would hide a real wedge (one lane was genuinely wedged that night) → it discounts the IDLE family ONLY ("do not call this idle" when a work order landed 0.03h earlier) and its AGE is reported per row; ACTUAL liveness stays the session JSONL mtime/size (`~/.pi/agent/sessions/--<mangled-cwd>--/<ts>_<session-id>.jsonl`), which is OUTPUT and advances only while the lane works. - [launchd]: `launchctl bootout gui/<uid>/<label>` resolves the LABEL in the real user domain and IGNORES `$HOME`, and `bootout <domain> <path>` only uses that path to READ THE LABEL out of the plist before removing the service BY LABEL (measured: removing via a copy at a different path killed the job bootstrapped from the first, rc=0) — so no path-keyed form is sandbox-safe by itself; before mutating, require the loaded job's `path =` (from `launchctl print`) to equal the plist, AND refuse when `$HOME` is not the real home (#446), then remove by plist path (#1975).
- [launchd]: a start assertion cannot read "the current heartbeat" as its baseline — `orch-loop.sh`'s `heartbeat()` runs FIRST in the cycle, so a baseline taken after the start already contains the bump the wait is looking for and a healthy start reads as a timeout (the tempting "fix" is a bigger timeout); capture the value BEFORE the start and pass it in, and never treat `unload -w` as a reload (`-w` writes a persistent Disabled override whose re-enable depends on a bootstrap that can fail: measured 48+19 min of dead dispatch, #1975).

- [heartbeat]: a clause appended to the beat `MSG` in the ROLE/MAP/PRIORITY block is DISCARDED on every quiet beat → the SHORT FORM rebuilds `MSG` from scratch further down, so an order appended only above it never reaches the pane exactly when nothing is actionable → EMBED the order INSIDE both body literals rather than appending (no append statement to lose by deleting a line, or to make conditional by wrapping it), pin the single `cmux send` statement and forbid slicing/substitution of `MSG` anywhere (a send-site `${MSG:0:400}` or `${MSG/…/}` needs no new line), and make the test's expectations FIXED in the test with an empty needle REFUSED — `case "$x" in *""*)` matches everything, so an undefined expectation passes silently (five reword-mutants went green that way) (`tests/heartbeat-fleet-advance/run.sh`, #1991/#1994).
- [gates]: review-enforcer classifies a bash call by SCANNING ITS TEXT, so a heredoc or helper script that merely MENTIONS the word `admin` next to the word `merge` (e.g. a file named `admin-merge-detector.yml`) is refused as a raw privileged merge — and the refusal executes NOTHING, so a blocked call is not evidence the command was wrong → write the helper with the `write` tool and run it as a bare command, and read a refusal on a READ-ONLY command as a scanner false positive (measured twice in one session, #2055).
