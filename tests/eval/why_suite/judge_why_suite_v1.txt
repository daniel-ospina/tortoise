    "point_id": "<id>",
    "support_chain": [{"point_id", "content_snippet", "edge", "weight"}...],  // <=3
    "ep": {"confidence_mean", "variance", "contested", "has_ep"},
    "conflicts": {"contested": bool, "nands": [{"point_id", "content_snippet", "severity"}]},  // OPTIONAL: absent = no conflict surfaced
    "supersession": {"status", "superseded_by", "supersedes", "successor_label"},
    "tradeoffs": [{"point_id", "label", "ep_weight", "mitigation"}...],  // OPTIONAL: decision points only
    "dig_deeper": [{"label", "kind", "target"}...]  // <=3; kinds: supports | nand | superseded | tradeoff
  }

THE FOUR WHY-QUESTIONS — answer each from the surfaced context ALONE:

Q1 (conflict-surfacing) "What contradicts this point?"
   - The context SURFACES the contradiction iff "conflicts" is present with
     contested:true AND >= 1 entry in conflicts.nands AND a dig_deeper
     pointer of kind "nand" is present. If the context lacks any of the
     three, the contradiction was NOT surfaced.
   - NEVER invent a contradiction from topic similarity alone: no conflicts
     key / contested:false / no nand-kind pointer = no contradiction surfaced.

Q2 (dig-deeper navigation) "Where do I dig deeper?"
   - Each labeled dig_deeper pointer {label, kind, target} must resolve to a
     point of the kind's class: supports -> a point IN support_chain;
     nand -> a point IN conflicts.nands; tradeoff -> a point IN tradeoffs;
     superseded -> supersession.superseded_by. A pointer whose target does
     not belong to its kind's class is a broken pointer.
   - A clean context (no conflicts, no supersession) must not carry a nand or
     superseded pointer (fabricated navigation).

Q3 (support-chain sufficiency) "Why is this point believed?"
   - ANSWERABLE iff support_chain is non-empty (each entry carries point_id +
     content_snippet + weight) AND ep is present with has_ep:true (the
     belief is measured). An empty support_chain with ep absent = NOT
     answerable (no graph access is allowed to fill it).

Q4 (trade-off sufficiency, decision points only) "Which alternative does EP favor?"
   - For a DECISION point the context must carry tradeoffs with >= 2
     alternatives, each with ep_weight (+ mitigation), and the alternative
     EP favors is the max-ep_weight entry. Non-decision points never
     fabricate tradeoffs.

OUTPUT (closed vocabulary — return ONLY JSON):

    "support_chain_sufficient": true|false,

  }
