## ⛔ The arm is READ BACK, not labelled (`#14774` review P1)

**The first version of this doc defined the control arm as
`env -u TORTOISE_VET -u TORTOISE_VALUE_GATE` — and that is the ON arm.** Since
`#10996` the mechanical value gate is **ON unless it says otherwise**
(`tortoise/value_gate.py::resolve_enabled`: *"Absent (`None`) ⇒ ON"*), and
`extractor_v2` ORs it into the pass: `vet_enabled = (arbiter or
_vet_enabled() or _value_gate_enabled())`. So unsetting `TORTOISE_VALUE_GATE`
arms the S2.2 pass exactly as `=1` does, the "control" arm was a second
realization of the treatment, and the comparison was a run against itself —
the `#10610` defect verbatim, which `docs/evidence/7949-capstone/probes/e1_paired_arm.py`
already refuses on a sibling path (`DEFAULT_ON_KEYS` / `off_arm_readback`).

Two consequences, both recorded rather than tidied away:

1. **The two receipts that spelling produced are pass-armed realizations.** They
   are committed **byte-identically** under `on-3` / `on-4`, which is the arm
   their own run resolved. Only the label moved; nothing was re-run to relabel
   them.
2. **The control arm was re-run with the real kill-switch** — `TORTOISE_VALUE_GATE=0`,
   set rather than omitted — and is committed as `off-1` / `off-2`.

The runner now writes the arm into every receipt it produces
(`tests/eval/write_path/runner.py::extractor_arm_readback`): the raw spelling of
each arming switch **and** the `vet_enabled` boolean the production resolvers
computed from it, so a receipt carries the proof of its own arm instead of
leaving it to its filename. `tests/test_state_value_verbatim_10360.py` §25 reads
that block back per receipt, requires the two arms to resolve **different**
`vet_enabled`, and resolves the two commands above through the same readback
(`test_the_e2_off_arm_definition_uses_the_REAL_kill_switch`) — so the doc and the
receipts cannot disagree about what the control was.

## Why four draws on one arm and two on the other

Under stochastic decoding a single run is one draw, and the per-session spread
here is larger than any aggregate delta anyone has claimed from these arms (a
session swings by 2–3 units between runs on identical code). The repetition
guidance for non-deterministic LLM benchmarks is a *minimum* of n ≥ 2 with the
between-run variance reported and the runs **not** pooled as independent
observations; a run count sufficient to resolve a 5-point gap needs a power
analysis, which the corpus size (90 units) does not supply.

So these six receipts support **exactly three** claims:

1. the pass-armed arm's strict-verbatim survival, over four draws;
2. the control arm's, over two; and
3. that every failed unit in every run is `content_missing`.

They do **not** support "the flags cost survival" or "the flags buy it" — the
between-run range is as large as the arms' mean separation.
