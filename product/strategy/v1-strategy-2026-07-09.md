# Epistemic Core — V1 Strategy

> **Version:** 0.1.0
> **Status:** Draft — active design
> **Target:** July–August 2026

## 1. What we are building

A **modular memory + epistemic reasoning core** that ingests conversations, documents, and events, builds a tortoise-style point graph, and enables semantic retrieval, belief propagation, and epistemic querying. Three applications consume the same core:

| Application | User | Core capability used |
|---|---|---|
| **Agent Assistant** | Coding/knowledge work agents | Point extraction from sessions, retrieval across past work, epistemic conflict detection |
| **DMer Reply Guy** | Instagram DM + Twitter automation | Memory-augmented replies — what do we know about this person/topic? |
| **Meeting Recorder** | Transcript -> memory pipeline | Real-time point extraction, speaker attribution, event generation |

## 2. Modular boundaries

The core is a library, not a monolith. Every component has an interface; every dependency is swappable.

```
                    Application Layer
                    (agent assistant, DMer, meeting recorder)
                                   |
                    Core Library
                                   |
   Extractor           Store            Retrieval
   transcript          event log        hybrid vector +
   -> points           -> graph         graph query
       |                   |                |
   LLM                Graph DB          Embedding
   (interface)        (interface)       (interface)
```

### Swappable interfaces

| Component | Interface | Current impl | Alternatives |
|-----------|-----------|-------------|--------------|
| **LLM** | `extract(segment) -> points` | DeepSeek V4 Flash (OpenRouter) | OpenAI, Anthropic, local model |
| **Graph DB** | `append(event)`, `query(cypher)`, `vector_search(vec)` | FalkorDB(Lite) | Neo4j, pgvector, Mem0 |
| **Embedding** | `embed(texts) -> ndarray` | fastembed (all-MiniLM-L6-v2) | OpenAI embeddings, Cohere, local ONNX |
| **Event log** | `append(event)`, `replay() -> events` | JSONL file | Kafka, Postgres WAL, SQLite |
| **Extraction** | `extract(segment, frame) -> {points, operators}` | Tortoise prompt contract | Graphiti episodes, instructor-json |

### What we drop

| Component | Why |
|-----------|-----|
| LightRAG | Semantic doc search via core retrieval layer |
| Graphiti | Episode model replaced by tortoise event log |
| MemPalace KG | FalkorDB is the canonical graph |
| Our enrichment scripts | Extraction is the core pipeline, not a batch script |

## 3. V1 scope

**In scope:**
- Tortoise M0 spike -> M2 (extraction, event log, projection, basic retrieval)
- 3-tier embedding/retrieval per `embedding-retrieval.md`
- Belief propagation scaffolding (NAND/IMPL resolution, grounding computation)
- Single-user, single-writer. Local-first (FalkorDBLite, JSONL log).
- Python library with clean interfaces

**Out of scope for V1:**
- Multi-party / multi-writer (sync, CRDT)
- Market mechanisms (LMSR, doubt, signal -- Carroll layer)
- Tauri shell / desktop app packaging
- Real-time streaming (batch-first)
- DMer app integration

## 4. Competitive landscape

| Product | What they do | Our edge |
|---------|-------------|----------|
| **Mem0** | LLM memory layer, user profiles | We model relevance as contestable (operators), not assumed |
| **Zep / Graphiti** | Temporal KG, episode-based | Their graph is flat; ours has NAND/IMPL structure + belief propagation |
| **Hindsight** | Agent memory, session recall | Retrieval-only; no epistemic reasoning |
| **LangChain Memory** | Conversation buffer, summary | Thin wrapper; no graph, no structure |
| **MemPalace** | Agent diary + KG + semantic search | Capture/archive, not epistemic reasoning |

Our differentiation: **relevance is a first-class, contestable object** (Carroll's tortoise). No competitor models "why should I believe this?" as a queryable graph structure.

## 5. V1 success criteria

1. A real transcript produces a visible point+operator graph (M0)
2. Semantic queries return relevant points with provenance (M2)
3. Epistemic conflicts (two NANDs on same point) are detectable and queryable
4. The core runs embedded (FalkorDBLite, no Docker, no cloud dependency)
5. Any component (LLM, graph DB, embedder) can be swapped via its interface without touching the others
