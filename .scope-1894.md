# Scope — #1894: docs memory-source switch state, last-indexed timestamp, index-job ETA

**Level:** task · **Complexity:** standard · **Workflow:** task-workflow-standard
**Date:** 2026-08-28

## Phase 1/2 — Problem Diamond (diverge → converge)

### Alternative framings explored (2 parallel diverge agents, adversarial)

1. **Control-model framing** — the docs switch is terminal (#1835) and can never be flipped off; the dimmed switch is a symptom of a control that lies. (Rejected as THE framing: reversing terminality is a product decision explicitly out of scope; issue targets legibility, not control.)
2. **Derived-state incoherence** — `docsOn = docsWantOn || docsIndexed` mixes client intent (unpersisted) + server fact + connection fact, producing an impossible state (issues-off + docs-indexed → switch ON + "Connect GitHub first" in the same row). (Noted; the disconnect-while-indexed path is rare; fixing it is beyond this issue's targets.)
3. **Ephemeral job-status architecture** — `_INDEX_JOBS` is a 1h-TTL in-process dict, wiped on deploy; durable job records would fix persistence at the root. (Rejected as THE framing: a DB-backed job store is a separate epic; the issue is explicitly a standalone UX slice.)
4. **Original (confirmed)** — the visible defects are real and independently fixable: (a) dimmed indexed switch misreads as off; (b) no persisted "last indexed"; (c) indeterminate "Indexing…" with no progress/ETA.

### Confirmed problem

The memory-source panel cannot communicate *indexed state* or *indexing progress* truthfully:

- **P1** An indexed docs source renders a `disabled` switch at `opacity: 0.6` — visually indistinguishable from off (aria is already correct; the visual is wrong). The docs row's existing "Docs are indexed and active as a source" copy exists but is small/dim.
- **P1** There is no persisted "last indexed" record: `github_docs_indexed` (bool) exists but no `*_indexed_at`; after reload the UI cannot say when indexing last ran. `github_connected_at` (timestamp key) exists ONLY in `DEFAULT_ONBOARDING_STATE` and is dead (never written/rendered) — the registration discipline is known and test-enforced for capture keys, but `github_indexed_at`/`github_docs_indexed_at` must be registered in ALL FOUR surfaces (both default dicts + derived allowlist + PATCH model) or the allowlist filter silently drops them.
- **P2** Jobs write progress ONLY at terminal states (`progress` 0 → 100) — no live intermediate progress; the UI renders an indeterminate "Indexing in progress…". Elapsed time is computable client-side (`created_at`/`started_at` already ride the poll response) but unrendered.

### Falsification check
- If `github_docs_indexed=False` teams show the same dimmed-switch confusion → problem misdiagnosed (not a state-render defect). Not observed — only indexed teams report the issue.
- If the timestamp still fails to survive reload after registration in all 4 surfaces + PATCH model → persistence diagnosis wrong. The parametrized registration test + PATCH round-trip will catch it.

### Confidence: 90

## Phase 1.5 — External Research (UX axis; ontology low)

Trigger assessment: UX axis rated **standard** (accessibility-sensitive state-model change) → fired. Ontology axis low → covered by codebase-first precedent (registered-state-key pattern, `_STATE_KEY_TABLE` test, `github_docs_indexed` registration in `test_index_docs_api.py`). No third-party deps introduced.

Findings (source-tagged):

- **[canonical — atomica11y.com/accessible-web/toggle-switch]** A `disabled` switch stays in the accessibility tree; `aria-disabled="true"` is the exception case where a disabled toggle must remain perceivable. Critical: if `aria-checked` is not kept truthful, a switch is announced as permanently "off" — an accessibility failure. → Our fix must keep `aria-checked={docsOn}` truthful (it is) and fix the *visual* (CSS) rather than remove the switch.
- **[canonical — accessibility.build/guides/accessible-switch]** Disabled switch state must remain discoverable in the a11y tree; dimming alone is not a state signal.
- **[canonical — nngroup.com/articles/designing-for-waits-and-interruptions]** Communicate percentage/time-remaining only for waits >10s; use step-based progress when accurate percentage cannot be provided. Fake precise progress misleads more than an indeterminate spinner.
- **[canonical — cloudfour.com/thinks/truth-lies-and-progress-bars]** When the total is not knowable, counting completed steps reassures; an ETA is not always feasible or appropriate — never fake it.
- **[canonical — codemia.io smart-progress-bar ETA]** Show percentage immediately; wait a few updates before showing ETA; suppress ETA when rate is noisy; use real work rate, not percent alone.
- **[precedent — Apple HIG progress-indicators]** Be as accurate as possible; 90%-fast-then-slow reads as deceptive.

**Design implication:** ETA must be *derived from real per-repo progress* (backend must write live per-repo `_job(...)` progress during the walk — it currently does not), and the frontend must suppress ETA when `progress=0` (e.g., the github first-run ONE-repo bound sits at 0% for the whole walk). Show elapsed time always; show ETA only when progress > 0.

## Phase 4/5 — Solution Diamond (diverge → converge)

### Approaches (1 diverge agent, distinct by architecture)

- **A. Persisted-state + render (confirmed).** Register `github_indexed_at`/`github_docs_indexed_at` in all 4 registration surfaces; stamp at completion in both `finally` blocks; frontend renders "Indexed · <relative time> · Re-index docs" with truthful `data-on`/`aria-checked` + CSS fix for the disabled-on switch; add per-repo live `_job(...)` progress writes + elapsed/ETA status line; `refreshOnboarding()` on poll completion. Tests: extend `_STATE_KEY_TABLE` + lifecycle tests + new pure-module frontend test.
- **B. Durable job store (rejected).** Persist `_INDEX_JOBS` to DB / onboarding_state; resume after deploy. Rejected: separate epic scope; the issue is a standalone UX slice; the 1h TTL + eviction design is intentional and tested.
- **C. Frontend-only cosmetic (rejected).** CSS + copy only, no new state keys. Rejected: target "timestamp survives reload" is impossible without a persisted key; the reload trap stays.

### Converged design (quality over convenience)

**Backend (`tortoise/hosted_api.py`):**
1. Register `github_indexed_at: None` + `github_docs_indexed_at: None` in `_ONBOARDING_DEFAULT_STATE` + `DEFAULT_ONBOARDING_STATE` (derived `_ALLOWED_STATE_KEYS` covers allowlist automatically) + `OnboardingStatePatchRequest` as `str | None` fields (ISO timestamps, matching `install_probe_*` str-key precedent).
2. `_run_indexing` finally: when `totals["repos_processed"] > 0`, also write `github_indexed_at=datetime.now(UTC).isoformat()` alongside `github_indexed=True`.
3. `_run_docs_indexing` finally: when `totals["repos_processed"] > 0`, also write `github_docs_indexed_at=datetime.now(UTC).isoformat()` alongside `github_docs_indexed=True`.
   **Stamp policy (scope-verify cycle-1 P2, resolved):** timestamp semantics = *parity with the bool* — `*_indexed_at` is stamped in the SAME branch that flips `*_indexed` True (progress-run semantics, incl. quota-partial / mid-walk-error runs with ≥1 repo processed, matching today's `github_indexed=True` resumable-cursor behavior). The timestamp means "last time indexing ran and made progress", exactly what the bool already claims. Deliberate and documented; NOT gated on `status=="completed"`. Partial-ness is surfaced in-session by the existing job-card "(plan quota reached)" copy; the persisted label stays honest to the bool pair.
4. Live progress: in `_run_indexing` walk loop, `_job(...)` **immediately AFTER `totals["repos_processed"] += 1`** (scope-verify cycle-1 P4: placement after the increment matches terminal counting — the github quota-hit repo breaks BEFORE incrementing, so it must not be counted as processed): `_job(progress=round(repos_processed/repos_total*100), points_created=..., repos_processed=..., repos_total=...)`. Same in `_run_docs_indexing` with `documents_indexed=...`. Terminal `_job` calls unchanged (already include the totals). **No new deps, no schema change, no migration.**

**Frontend (`main.jsx` + `index.css` + new `memorySourcesStatus.js`):**
5. New pure module `website/apps/dashboard/src/memorySourcesStatus.js`:
   - `formatRelativeTime(isoAt, now)` → "just now / N min ago / N hr ago / date" (ISO → relative; unknown/missing → null).
   - `docsIndexedLabel(state, now)` → "Indexed" (+ " · <rel time>" only when `github_docs_indexed_at` present — honest for legacy indexed teams without a timestamp: no fabricated time).
   - `jobStatusLine(job, now)` → in-progress: "Indexing… · <elapsed> · <progress% or repos N/M> · <ETA when progress>0>" with ETA suppressed at progress 0; terminal copy unchanged (delegates to existing component logic).
   - `jobElapsedSecs(job, now)` → from `started_at`/`created_at`.
6. `MemorySources` docs row: when `docsIndexed`, render label `docsIndexedLabel(...)` **unconditionally — NOT gated on `githubConnected`** (scope-verify cycle-1 P2, resolved: the current copy is gated `docsIndexed && githubConnected` at main.jsx:4656; a disconnected-but-indexed team would show the brightened ON switch + "Connect GitHub first" — the exact ambiguity this issue targets. The indexed label is a historical claim about indexing, not connectivity; render it whenever `docsIndexed`, keep the Re-index affordance. #1835 control deferral unchanged). Github row: append "Last indexed <rel time>" to the "Connected — N repos" line **only when `state.github_indexed_at` is non-null** (absent → no suffix; mirrors `docsIndexedLabel`'s absent→null contract).
7. CSS: add `.switch[disabled][data-on='true'] { opacity: 1; cursor: not-allowed; }` (or a `locked-on` class) so the indexed switch reads ON.
8. `GithubIndexStatus`/`DocsIndexStatus` in-progress branches: render `jobStatusLine(...)` with elapsed + progress + ETA instead of the bare "Indexing in progress…". A lightweight `now` ticker (setInterval ~30s in the MemorySources host or a `useNow` in the status components) keeps relative time fresh.
   **`jobStatusLine` field-absence contract (scope-verify cycle-1 P3, resolved):** the client-minted `{status:'starting'}` pre-POST job has NO `created_at`/`started_at` → elapsed omitted (not "NaN/undefined"); a github job mid-walk may lack `repos_processed`/`repos_total` until the first live `_job` write, and the first-run ONE-repo bound has no intermediate write below 100% → progress/% omitted when fields absent, not rendered as "0". Module contract + tests cover both.
9. `indexDocs`/`reindexGithub`: call `refreshOnboarding()` in `onDone` (after job terminal) so the newly-stamped `*_indexed_at` appears without a manual reload. The wizard connect poll's onDone already calls `reindexGithub()` → funnels through the same onDone choke point (transitive coverage, no extra wiring). **Poll ceiling (scope-verify cycle-1 P2, resolved):** raise `maxTries` to 100 (300s) for the two index-job polls only (docs re-index ≈90s is within 120s but tight; org-wide walks exceed it) — bounded, honest, and required for the live-progress surface to be useful. The `timeout` synthetic state still renders "Still running — check back in a moment" + fires `refreshOnboarding()` (late-stamp refresh). Runs beyond 300s degrade to the existing honest timeout copy (documented known limitation).

**Tests:**
10. Backend: extend `_STATE_KEY_TABLE` in `test_onboarding_endpoints.py` with `github_indexed_at` + `github_docs_indexed_at` (parametrized registration + PATCH round-trip — the table already parametrizes ISO-string values, zero test-logic change); extend `test_github_index_lifecycle.py::test_state_keys_registered`; extend `test_cursor_and_backfill_marker_persisted` to assert `github_indexed_at` present; extend `test_index_docs_api.py::test_docs_job_poll_completed` to assert `github_docs_indexed_at` present; new test asserting live per-repo `_job(...)` progress during the walk — **patch `GitHubIndexer.index_repo` (or `walk_repo` for docs) itself with a barrier/sleep on the first repo, then assert `_INDEX_JOBS[job_id]["repos_processed"]/["progress"]` mid-flight before settling the run** (scope-verify cycle-1 P4: the counting-wrapper hold in `test_in_flight_single_flight_reuses` keeps the run in the minted state and does NOT exercise mid-walk writes).

Frontend: new `memorySourcesStatus.test.js` (node --test, zero-dep): relative-time formatting (fresh/stale/absent), docs-indexed label (with/without timestamp; disconnected-but-indexed), job status line (progress 0 → no ETA; progress>0 → ETA present; elapsed rendering; **missing `started_at`/`created_at` → elapsed omitted; missing repos fields → progress omitted**). **Render-layer verification (scope-verify cycle-1 P2, resolved):** (a) the node --test file ALSO asserts the CSS rule exists — read `index.css`, assert `.switch[disabled][data-on='true']` present with opacity not 0.6 (text-level assertion, zero deps); (b) `vite build` runs in VERIFY (catches wiring/import errors from the new module); (c) manual clickthrough of both MemorySources call sites (wizard step-1 + Overview) per app-test skill for connected+indexed / un-indexed / running-job states. **Adaptation note (explicit):** the issue's "component test" row is infeasible as written — the dashboard has NO vitest/jsdom and main.jsx is not importable in node; the repo's established convention is pure-module node --test. The checklist row is renegotiated to: pure-module derivation tests + CSS-rule assertion + vite build + manual clickthrough gate.

### Rejected alternatives
- Durable job store (approach B) — separate epic; out of scope.
- Frontend-only cosmetic (approach C) — cannot satisfy reload-persistence target.
- Turning docs off / restoring toggle control — product decision, #1835 terminality explicitly out of scope.
- Backfilling `*_indexed_at` for existing indexed teams — no truthful value exists (in-memory jobs evicted); honest render omits the time.
- Persisting `docsWantOn` toggle intent (issue context: "toggleDocs persists nothing at toggle time") — **deferred, explicit boundary** (scope-verify cycle-1 P3): intent persistence is a separate state-model change; this issue targets indexed-state legibility, and a failed pre-walk run (quota/base-unset) losing `docsWantOn` on reload is a pre-existing edge, not a regression this slice introduces.
- Stamping `*_indexed_at` only on `status=="completed"` — rejected (resolved P2 above): parity with the bool is the truthful semantics; a "failed" run with ≥1 repo processed DID index content, and `github_indexed=True` already claims it.
